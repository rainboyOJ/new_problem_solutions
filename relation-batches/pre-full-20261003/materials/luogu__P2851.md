   9| ## 题目解析（原文摘录）
  10| 
  11| ### 题意
  12| 
  13| 要买一件价格为 `T` 的商品。
  14| 
  15| - 农夫手里的每种硬币数量有限
  16| - 店家手里的每种硬币数量无限
  17| - 希望“农夫付出的硬币数 + 店家找回的硬币数”最少
  18| 
  19| 要求输出这个最小值。
  20| 
  21| ### 思路
  22| 
  23| 先看一个可以直接验证想法的小数据暴力：
  24| 
  25| @include-code(./brute.cpp, cpp)
  26| 
  27| 暴力版直接做两件事：
  28| 
  29| 1. 用有限硬币 DP 求出“农夫恰好付出 `s` 元时最少要几枚硬币”
  30| 2. 用无限硬币 DP 求出“店家恰好找 `d` 元时最少要几枚硬币”
  31| 
  32| 最后枚举实付金额 `s >= T`，把两部分加起来取最小值。
  33| 
  34| 这个想法本身就是正解的骨架，真正的问题只在于第一步。
  35| 
  36| #### 为什么要拆成两个 DP
  37| 
  38| 如果农夫最终付了 `s` 元，那么店家就必须找：
  39| 
  40| - `s - T`
  41| 
  42| 于是总硬币数就是：
  43| 
  44| - `pay[s] + change[s - T]`
  45| 
  46| 其中：
  47| 
  48| - `pay[s]`：农夫用自己手里有限的硬币，恰好凑出 `s` 的最少张数
  49| - `change[d]`：店家用无限硬币，恰好找出 `d` 的最少张数
  50| 
  51| 第二部分是很标准的完全背包最小值。  
  52| 难点在第一部分：每种硬币数量有限，而且我们要求的是**最少张数**，这是一个多重背包最小值问题。
  53| 
  54| #### 付款方 DP
  55| 
  56| 设：
  57| 
  58| - `pay[s]` 表示恰好凑出 `s` 元时，最少要用多少枚自己的硬币
  59| 
  60| 如果当前处理面值 `v`、数量 `c` 的硬币，那么转移是：
  61| 
  62| - `new[s] = min(old[s - k * v] + k)`，其中 `0 <= k <= c`
  63| 
  64| 这就是最朴素的多重背包。
  65| 
  66| 如果直接枚举 `k`，复杂度会很高。  
  67| 这里和“多重背包单调队列优化”是同一个套路：按 `mod v` 的余数分组。
  68| 
  69| 把：
  70| 
  71| - `s = q * v + r`
  72| 
  73| 代进去，就得到：
  74| 
  75| - `new[q * v + r] = min(old[t * v + r] + (q - t))`
  76| 
  77| 其中 `t` 落在一个长度为 `c + 1` 的滑动窗口里。
  78| 
  79| 于是对每个余数类，只要维护：
  80| 
  81| - `old[t * v + r] - t`
  82| 
  83| 的窗口最小值，就能把这一层转移优化到线性。
  84| 
  85| #### 找零方 DP
  86| 
  87| 店家硬币无限，所以是完全背包最小值：
  88| 
  89| - `change[d] = min(change[d], change[d - v] + 1)`
  90| 
  91| 这一部分很直接。
  92| 
  93| #### 为什么只需要枚举到 `T + Vmax^2`
  94| 
  95| 设最大面值是 `Vmax`。这题的经典结论是：
  96| 
  97| - 最优方案中，多付的钱不需要超过 `Vmax^2`
  98| 
  99| 因此只要把农夫实付金额枚举到：
 100| 
 101| - `T + Vmax^2`
 102| 
 103| 就够了。
 104| 
 105| 在本题里 `Vmax <= 120`，所以这个范围最多就是：
 106| 
 107| - `10000 + 120^2 = 24400`
 108| 
 109| 完全可以做 DP。
 110| 
 111| 这也是为什么正解能稳稳落在 $O(NW)$ 级别。
