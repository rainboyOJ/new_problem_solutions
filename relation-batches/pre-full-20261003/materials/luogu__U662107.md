  10| 
  11| ### 题意
  12| 
  13| $N \le 100$ 个物品，01 背包，容量 $V \le 100$。要求**恰好装满**容量 V，输出此时最大价值的方案总数，对 $10^9+7$ 取模。若无法恰好装满则输出 0。
  14| 
  15| ### 思路
  16| 
  17| **一句话本质**：恰好装满与不要求装满的唯一区别在 DP 初值——只有 `dp[0]=0` 可达，其余 `dp[c]=-INF` 不可达，计数也只在可达状态之间转移。
  18| 
  19| 先看枚举法确认题意：
  20| 
  21| @include-code(./brute.py, python)
  22| 
  23| 枚举所有方案，只统计体积恰好等于 V 的，再从中挑出价值最大的计数。
  24| 
  25| **普通 01 背包的 `dp[c]` 含义是"容量不超过 c 的最大价值"，初值全 0。为什么恰好装满不能这样初始化？**
  26| 
  27| 因为全 0 初值意味着"容量 c 的价值至少是 0（不选任何物品）"，它隐含了"可以不满"的自由。要强制恰好装满，必须让非零容量的"空集"变成非法状态——用 `-INF` 表示"这个容量在当前没有任何合法方案可达"。
  28| 
  29| **`dp[0]=0, dp[1..V]=-INF` 后转移公式变了吗？**
  30| 
  31| 公式写法不变：`dp[c] = max(dp[c], dp[c-v] + w)`。但前提是 `dp[c-v] != -INF`——前驱必须可达。如果 `dp[c-v]` 是 `-INF`，`dp[c-v] + w` 是一个同样没有意义的数（负数极大值的加法），必须跳过。
  32| 
  33| **计数怎么配合？**
  34| 
  35| 同样只有可达状态才有计数。初始化：`cnt[0]=1`，`cnt[1..V]=0`。转移逻辑与方案总数题一致，但必须加一层可达性判断：
  36| 
  37| ```text
  38| 如果 dp[c-v] == -INF：跳过，前驱不可达。
  39| 否则 val = dp[c-v] + w：
  40|   如果 val > dp[c]: dp[c]=val, cnt[c]=cnt[c-v]
  41|   如果 val == dp[c]: cnt[c]=(cnt[c]+cnt[c-v]) % MOD
  42| ```
  43| 
  44| **最后答案怎么取？**
  45| 
  46| 若 `dp[V] == -INF`，说明没有任何方案能恰好装满 V，输出 0。否则输出 `cnt[V]`。
