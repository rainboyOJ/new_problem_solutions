  11| ### 题意
  12| 
  13| $N \le 100$ 个物品，01 背包，容量 $V \le 100$。求达到最大价值的方案总数，对 $10^9+7$ 取模。
  14| 
  15| ### 思路
  16| 
  17| **一句话本质**：在 DP 最优值的同时维护一个平行数组 `cnt[c]`——DP 值被"更大"覆盖时，计数也被覆盖；DP 值"相等"时，计数累加。
  18| 
  19| 先看一个朴素做法理解题意：
  20| 
  21| @include-code(./brute.py, python)
  22| 
  23| 枚举所有 $2^N$ 种选法，统计最优值对应的方案数。N 到 20 就受不了了。
  24| 
  25| **DP 滚动数组算最优值大家都会：`dp[c] = max(dp[c], dp[c-v]+w)`。方案数怎么跟上来？**
  26| 
  27| 维护一个跟 `dp` 一样长的数组 `cnt[c]`，表示"达到 `dp[c]` 的方案数"。对于物品 i（体积 v、价值 w），从 c = V 倒序到 v：
  28| 
  29| - 算一遍候选值：`val = dp[c-v] + w`。
  30| - 如果 `val > dp[c]`：发现更大的值，`dp[c] = val`，计数也要更新为前驱的位置的计数：`cnt[c] = cnt[c-v]`。
  31| - 如果 `val == dp[c]`：发现了另一条达到相同最优值的路，`cnt[c] = (cnt[c] + cnt[c-v]) % MOD`。
  32| - 如果 `val < dp[c]`：什么都不做。
  33| 
  34| **为什么不用二维数组，直接用滚动数组？**
  35| 
  36| 因为计数只关心最终的 `cnt[V]`，不关心过程路径。滚动数组在正确的逆序下，计数逻辑完全正确——`cnt[c-v]` 恰好是考虑前 i−1 件的方案数。
  37| 
  38| **`cnt` 的初值怎么设？**
  39| 
  40| `cnt[0..V]` 全部初始化为 1。因为空集（不选任何物品）对于任何一个容量 c 来说，都是价值为 0 的方案。当后面加入物品后，`dp[c]` 可能变成更大的值，对应的 `cnt[c]` 会被覆盖或累加。
