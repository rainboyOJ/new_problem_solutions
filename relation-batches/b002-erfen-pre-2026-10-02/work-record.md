## 1. 与 common 的本质差异

| | common（b001） | pre（本批） |
| --- | --- | --- |
| 语义 | 对称相似 | **有向递进**：前置更基础、其技巧是当前题解法的组成部分 |
| 存法 | 双侧互写 | **单侧**（与仓库既有 87 条 pre 惯例一致） |
| 判断维度 | 相似性 1 维 | 台阶性 + 难度序 + 核心模型同族 3 维 |
| 仓库惯例 | 同难度即可 | 允许同一题对同时是 pre 和 common（P1873~4135） |

## 3. 五轮校准（判断设计迭代）

判断问题模板经 **5 次迭代**，每轮原始结果留档（`pre-calibration-results-v1..v5.jsonl`）：

| 版本 | 设计 | 结果 |
| --- | --- | --- |
| v1 | prereq_needed / target_contained / difficulty_up / direction_ok | 失败：`difficulty_up`、`prereq_needed` 在反例上分数反而更高（0.95/0.91 vs 正例 0.48/0.74），无判别力 |
| v2 | 显式排除「仅共享通用技巧」 | 失败：矫枉过正，把「A 教技巧、B 应用它」判为不包含——而这正是 pre 的本质（与 common 相反） |
| v3 | Choice 直接判关系类型（A_pre_B / parallel / unrelated） | 失败：模型对**全部**候选都判 A_pre_B，含反例 |
| v4 | 在选项描述中强调「B 核心难点需 A 未教的新知识则选 parallel」 | 失败：反转过度，把仓库已确认的 pre 判成 parallel |
| v5 | 拆为 3 个独立 Noul（台阶性 / 难度提升 / 核心模型同族） | 校准集仍无零误连零漏连组合，但**真实候选分布显示模型确实在区分**（`A_is_step_to_B` 中位数 0.32，仅 15% ≥0.7） |

**根因（重要）**：校准集失败源于标注口径与仓库惯例不一致，而非模型能力——仓库允许同一题对同时 pre 与 common，「台阶」边界本身模糊。故改用**真实候选分布 + 用户裁定阈值**。
