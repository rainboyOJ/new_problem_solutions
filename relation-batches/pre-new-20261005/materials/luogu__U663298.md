   9| ## 题目解析（原文摘录）
  10| 
  11| ### 题意
  12| 
  13| N 件物品，每件一个体积 v_i，每件只能选一次。问有多少种不同的选法使总体积**恰好等于** V。答案对 10^9+7 取模。
  14| 
  15| ### 思路
  16| 
  17| **一句话本质**：数一数有多少种不同的物品集合，使它们的总体积恰好等于 V。
  18| 
  19| **brute.py 的瓶颈在哪？**
  20| 
  21| brute.py 枚举 2^N 种选法，对总体积等于 V 的进行计数。N=1000 时 2^1000 不可能跑完——不是"慢"，是根本不可行。
  22| 
  23| **从可行性问题的 dp[c]=true/false，如何推到计数？**
  24| 
  25| 可行性问题是"容量 c 能不能凑出来"。现在进一步问"能凑出来有几种方案"。布尔值不够用了，需要用整数来累加方案数。
  26| 
  27| **凑出容量 c 的方案数怎么算？**
  28| 
  29| 假设我们已经知道容量 c-v 有 k 种方案。每一种方案加上体积为 v 的物品，就得到一种容量为 c 的新方案（物品集合不同，所以是不同的方案）。因此 dp[c] 应该加上 dp[c-v]。
  30| 
  31| **状态定义和转移是什么？**
  32| 
  33| 定义 dp[c] = 恰好凑出容量 c 的方案数（对 MOD 取模）。
  34| 
  35| 初始 dp[0] = 1（不选任何物品是凑出容量 0 的唯一方案）。
  36| 
  37| 对于每件物品体积 v，容量 c 从 V 到 v 倒序：
  38| 
  39| ```
  40| dp[c] = (dp[c] + dp[c - v]) % MOD
  41| ```
  42| 
  43| **为什么 dp[0] = 1？**
  44| 
  45| 因为"一件都不选"本身就是一种方案，它凑出了容量 0。如果没有这个基础值，所有 c=v 的容量都加不上——dp[v] = dp[v] + dp[0] 需要 dp[0] = 1。
  46| 
  47| **为什么容量倒序？**
  48| 
  49| 每件物品只能在方案中出现一次（01 背包）。如果正序，物品可能被重复计入方案——一旦 dp[v] 被当前物品更新了，dp[2v] 又会从 dp[v] 转移，等于同一件物品用了两次。
