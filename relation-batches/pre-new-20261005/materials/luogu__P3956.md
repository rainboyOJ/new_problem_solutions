   9| ## 题目解析（原文摘录）
  10| 
  11| ### 题意
  12| 
  13| 给一个 `m x m` 棋盘，部分格子本来就有颜色，部分格子无色。
  14| 
  15| 你要从 `(1,1)` 走到 `(m,m)`，每次只能上下左右移动。
  16| 
  17| 如果走向本来就有颜色的格子：
  18| 
  19| - 同色花费 `0`
  20| - 异色花费 `1`
  21| 
  22| 如果走向无色格子：
  23| 
  24| - 必须先施法把它临时染色，花费 `2`
  25| - 并且魔法不能连续使用
  26| 
  27| 求最少花费，无法到达输出 `-1`。
  28| 
  29| ### 思路
  30| 
  31| 先看一个可以直接验证想法的朴素解：
  32| 
  33| @include-code(./brute.cpp, cpp)
  34| 
  35| 这题表面上像网格最短路，但一个格子不能只看坐标。
  36| 
  37| 因为到达同一个格子时，后续决策还取决于两件事：
  38| 
  39| 1. 当前脚下格子的颜色是什么；
  40| 2. 当前脚下格子是不是刚用魔法临时染出来的。
  41| 
  42| 所以状态要写成：
  43| 
  44| - `(x, y, color, magic)`
  45| 
  46| 其中：
  47| 
  48| - `color` 表示当前所在格的颜色；
  49| - `magic = 1` 表示当前格子是临时染色格；
  50| - `magic = 0` 表示当前格子本来就有颜色。
  51| 
  52| 接下来分两类转移。
  53| 
  54| 第一类，下一格本来就有颜色。
  55| 
  56| 设下一格颜色是 `next_color`，那么：
  57| 
  58| - `color == next_color`，花费加 `0`
  59| - `color != next_color`，花费加 `1`
  60| 
  61| 并且走过去后 `magic` 一定变成 `0`。
  62| 
  63| 第二类，下一格是无色格。
  64| 
  65| 这时只有当前 `magic == 0` 才允许施法。
  66| 你可以把下一格染成红色或黄色中的任意一种：
  67| 
  68| - 施法固定花费 `2`
  69| - 若染出来的颜色和当前颜色不同，再额外花 `1`
  70| 
  71| 所以总代价是：
  72| 
  73| - `2 + (color != next_color)`
  74| 
  75| 走过去后，新的状态 `magic = 1`。
  76| 
  77| 所有边权都非负，因此直接在这张状态图上跑 Dijkstra 即可。
