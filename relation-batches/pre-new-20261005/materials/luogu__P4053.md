  11| ## 思路
  12| 
  13| **先看一个可以直接验证想法的朴素解：**
  14| 
  15| @include-code(./brute.cpp, cpp)
  16| 
  17| 暴力枚举所有子集，对每个子集按截止时间排序后检查可行性。瓶颈是 $O(2^n)$，仅适用于 $n \le 20$ 的小数据。
  18| 
  19| **为什么按截止时间排序是最优顺序？**
  20| 
  21| 假设选定了一组任务要完成，怎样安排顺序最不容易超时？直觉上截止时间早的先做。严格证明用交换论证：若存在任务 A、B 满足 $d_A < d_B$ 但 B 排在 A 前面，交换它们——A 更早完成、B 推迟不超时，因此不劣。由此按截止时间升序排列对任何固定任务子集都是最优顺序。
  22| 
  23| 这个观察的意义：一旦确定了顺序，问题就变成了"从左到右，选不选当前任务"的决策问题。
  24| 
  25| **装不下时，删掉耗时最长的那个——为什么对？**
  26| 
  27| 处理到第 $i$ 个任务，已选集合总耗时为 $T$。若 $T + t_i \le d_i$，选它；否则装不下，删掉已选中耗时最长的任务。理由：剩余任务数不变，但总耗时减少最多，给后续留下最大时间余量。
  28| 
  29| 严格证明用归纳不变量：
  30| 
  31| > 处理完前 $k$ 个任务（按截止时间排序）后，算法维护的集合 $S_k$ 是 $\{1..k\}$ 的所有可行子集中**数量最大的**，且在数量最大的所有可行子集中**总耗时最小的**。
  32| 
  33| **情况 A：$T + t \le d$。** $S_{k+1} = S_k \cup \{k+1\}$。$\{1..k+1\}$ 的任何可行子集限制到 $\{1..k\}$ 最多 $|S_k|$ 个，所以最多 $|S_k|+1$ 个。$S_{k+1}$ 恰好达到。
  34| 
  35| **情况 B：$T + t > d$。** 从 $S_k \cup \{k+1\}$ 中去掉耗时最长的任务 $m$。假设存在可行子集 $O \subseteq \{1..k+1\}$ 且 $|O| = |S_k|+1$。$O$ 必含 $k+1$（否则 $|O| > |S_k|$ 与归纳假设矛盾）。于是 $O \setminus \{k+1\} \subseteq \{1..k\}$ 且 $|O \setminus \{k+1\}| = |S_k|$。由归纳假设 $T \le \text{total}(O \setminus \{k+1\})$，又 $O$ 可行要求 $\text{total}(O \setminus \{k+1\}) + t \le d$，得 $T + t \le d$，与 $T + t > d$ 矛盾。因此 $|S_k|$ 就是 $\{1..k+1\}$ 的最大可行子集数量。总耗时最小性同理可证。
  36| 
  37| **为什么超时后只需删一次，不用循环删到不超时？**
  38| 
  39| 因为一次删除必然足够，第二次永远不会发生：
  40| 
  41| - 处理第 $i$ 个任务前，已选集合是可行的，即总耗时 $T \le d_{i-1}$（或之前的某个截止时间）。
  42| - 按截止时间升序处理，所以 $d_{i-1} \le d_i$，于是 $T \le d_i$。
  43| - 加入 $t_i$ 后可能超时，但弹出的 $m$ 是堆里最大的工期，而堆里包含 $t_i$，所以 $m \ge t_i$。
  44| - 删掉后总耗时变为 $T + t_i - m \le T \le d_i$，一次删除就回到不超时。
  45| 
  46| C++ 版使用 STL `priority_queue`（默认大根堆）维护已选任务中最长的工期，堆顶就是需要替换的目标。
  47| 
  48| 如果想对齐 rbook 的 `heap` 模板，也可以手写 `up`/`down` 完成同样的操作，见 `main2.cpp`。
