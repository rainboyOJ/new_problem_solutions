  11| ## 思路
  12| 
  13| 先看一个可以直接验证想法的朴素解：
  14| 
  15| @include-code(./brute.cpp, cpp)
  16| 
  17| `brute.cpp` 直接维护数组 `lamp[]`：区间翻转逐盏取反，区间查询逐盏计数，单次操作 $O(n)$，总复杂度 $O(nm)$，无法通过 $10^5$ 的数据。
  18| 
  19| 关键观察有两点：
  20| 
  21| 1. **翻转的自逆性**：同一个位置翻转两次等于不翻，所以懒标记只要一个 `bool`，合并规则就是异或。
  22| 2. **整段翻转可以整体结算**：长度为 `len` 的区间亮灯数量为 `sum`，整体取反后数量变成 `len - sum`，不需要逐个访问叶子。
  23| 
  24| 于是用线段树 + 懒标记：每个节点存这段区间内亮灯的数量；区间翻转完全覆盖一个节点时，只改这个节点的数量和标记，把翻转“欠”在节点上；之后要进入它的子树时，再把标记下传给两个儿子。
  25| 
  26| ### 数学视角：为什么懒标记能成立
  27| 
  28| 把上面的观察用代数语言压缩，可以得到懒标记成立的精确条件：
  29| 
  30| - **查询信息构成幺半群**：区间和用 $+$ 合并，$+$ 满足结合律，且存在单位元 $0$（空区间的和、查询累加的初始值），所以区间和构成交换幺半群 $(\mathbb{Z}, +, 0)$。
  31| - **翻转是摘要上的自同态**：翻转可以仅凭节点摘要结算，$\text{flip}(\text{sum}) = \text{len} - \text{sum}$，并且能与合并操作交换：
  32| 
  33| $$\text{flip}(a+b) = \text{len} - (a+b) = (\text{len}_A - a) + (\text{len}_B - b) = \text{flip}(a) + \text{flip}(b)$$
  34| 
  35|   这就是“翻转不必下到叶子”的数学原因。又因为 $\text{flip} \circ \text{flip} = \text{id}$（翻转自逆），懒标记可以用 `bool` 异或合并。
  36| 
  37| 一句话概括：**查询信息构成幺半群，且区间更新是幺半群上的自同态，就可以用懒标记线段树维护**。反过来，如果更新依赖区间内部的具体值（例如“把区间内每个数换成它的后继”），它就不是摘要自同态，懒标记会失效。
  38| 
  39| 下面这张图展示一棵规模为 4 的线段树，节点上的数字是它代表的区间：
  40| 
  41| ![线段树区间分解](./segment-tree.svg)
  42| 
  43| 任意操作区间都能拆成 $O(\log n)$ 个“整段节点”。例如查询/翻转 $[2,4]$ 会命中 `[2,2]` 和 `[3,4]` 这两个整段节点，各花 $O(1)$ 结算，这就是 $O(\log n)$ 的来源：不需要访问区间内的每个点。
  44| 
  45| 以样例为例，4 盏灯每次操作后的真实状态如下：
  46| 
  47| | 操作 | 灯 1 2 3 4 | 输出 |
  48| | --- | --- | --- |
  49| | 初始 | 0 0 0 0 |  |
  50| | 翻转 [1,2] | 1 1 0 0 |  |
  51| | 翻转 [2,4] | 1 0 1 1 |  |
  52| | 查询 [2,3] | 1 0 1 1 | 1 |
  53| | 翻转 [2,4] | 1 1 0 0 |  |
  54| | 查询 [1,4] | 1 1 0 0 | 2 |
  55| 
  56| 观察表中两次翻转 $[2,4]$：第一次后该段从 `0 1 1` 变 `1 0 0`，第二次又恢复原样。这正是节点数量公式 `len - sum` 和懒标记异或（翻两次抵消）在样例上的直接体现。
