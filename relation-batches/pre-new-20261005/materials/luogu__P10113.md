   9| ## 题目解析（原文摘录）
  10| 
  11| ### 题意
  12| 
  13| 公司组织结构是一棵以 `0` 为根的树：
  14| 
  15| - `0` 号员工是老板
  16| - 其余每个员工都有一个直接领导
  17| 
  18| 员工 `x` 能管理员工 `y`，当且仅当：
  19| 
  20| - `x = y`
  21| - 或者 `x` 是 `y` 的祖先
  22| 
  23| 每次给出一组要合作的员工，要求找一个主持人，使得他能管理这组里的所有人。
  24| 
  25| 如果满足条件的人有很多个，要输出：
  26| 
  27| - 编号最大的那个
  28| 
  29| #### 样例树
  30| 
  31| 样例一的树结构是：
  32| 
  33| ```dot
  34| digraph G {
  35|   0 -> 1;
  36|   0 -> 2;
  37|   2 -> 3;
  38|   2 -> 4;
  39| }
  40| ```
  41| 
  42| 对于员工集合 `{3,4}`：
  43| 
  44| - 公共祖先有 `2` 和 `0`
  45| - 其中编号更大的是 `2`
  46| 
  47| 所以答案是 `2`。
  48| 
  49| ### 思路
  50| 
  51| 先看一个最直接的暴力：
  52| 
  53| @include-code(./brute.cpp, cpp)
  54| 
  55| 暴力做法是：
  56| 
  57| 1. 枚举谁来当主持人
  58| 2. 逐个判断他是不是所有参与者的祖先
  59| 3. 在所有合法人里取编号最大
  60| 
  61| 这个办法很直观，但一次查询最坏要把整棵树都扫一遍。
  62| 
  63| 关键观察有两层。
  64| 
  65| 第一层：
  66| 
  67| - 能管理所有参与者的人，必须是这组点的公共祖先
  68| 
  69| 第二层：
  70| 
  71| - 所有公共祖先，恰好就是“这组点的 LCA 到根这条链上的所有点”
  72| 
  73| 因为：
  74| 
  75| - 最低的那个公共祖先就是这组点的 LCA
  76| - 比它更高的祖先也都能管理所有人
  77| - 而 LCA 以下的人不可能同时管理不同分支上的参与者
  78| 
  79| 所以题目并不是“输出 LCA”，而是：
  80| 
  81| 1. 先求出这一组员工的 LCA
  82| 2. 再在“根到 LCA”的路径上找编号最大的点
  83| 
  84| 第二步也很容易预处理。
  85| 设：
  86| 
  87| - `path_max_id[u]` 表示从根走到 `u` 这条路径上的最大编号
  88| 
  89| 那么每次查询的答案就是：
  90| 
  91| - `path_max_id[lca(这一组人)]`
  92| 
  93| 于是整题就变成了标准的倍增 LCA 预处理，再把一组点不断两两合并成一个总 LCA。
