  11| ## 题目解析
  12| 
  13| 
  14| 这是一个非常经典的算法题目，源自 **POJ 1521 - Entropy**。
  15| 
  16| 题目的核心本质是要求你实现 **哈夫曼编码（Huffman Coding）** 算法，并将其压缩效果与定长的 8位 ASCII 编码进行对比。
  17| 
  18| 
  19| ## 1. 题目核心概念解析
  20| 
  21| - **原始编码（ASCII）**：固定长度编码。无论字符出现的频率如何，每个字符都占用 **8 bits**。
  22|   - 计算公式：$Original\_Size = \text{字符串长度} \times 8$。
  23| - **最优无前缀变长编码（Entropy/Huffman）**：根据字符出现的频率构建编码。
  24|   - 频率高的字符用短的比特串表示。
  25|   - 频率低的字符用长的比特串表示。
  26|   - **无前缀（Prefix-free）**：没有任何一个字符的编码是另一个字符编码的前缀（例如，如果 A 是 `0`，那么 B 不可能是 `01`，否则解码会有歧义）。这正是哈夫曼树的特性。
  27| 
  28| ## 2. 算法思路：哈夫曼树（Huffman Tree）
  29| 
  30| 要计算最优编码的总长度，我们不需要真正生成每个字符的编码（如 "00", "01"），只需要计算**带权路径长度之和（WPL）**。
  31| 
  32| **具体步骤：**
  33| 
  34| 1. **统计频率**：遍历输入字符串，统计每个字符（包括下划线）出现的次数。
  35| 2. **构建优先队列**：将所有出现过的字符的频率放入一个**小顶堆**（Min-Priority Queue）。
  36| 3. **贪心策略构建树**：
  37|    - 从小顶堆中取出两个最小的频率值，设为 $a$ 和 $b$。
  38|    - 将它们合并，产生一个新的节点，频率为 $a + b$。
  39|    - 这个 $a + b$ 就是这两个节点在树中产生的“代价”（即编码长度贡献）。
  40|    - 将 $a + b$ 重新放入堆中。
  41|    - **累加代价**：将 $a + b$ 加到总的压缩位长度变量中。
  42|    - 重复上述步骤，直到堆中只剩下一个节点。
  43| 4. **特殊情况处理**：
  44|    - 如果字符串中只有一种字符（例如 "AAAAA"），哈夫曼树逻辑会直接结束。但在这种情况下，我们需要 1 个比特来表示该字符。
  45|    - 所以，如果字符种类数为 1，压缩后的长度 = 字符串长度 $\times$ 1。
  46| 
  47| ## 3. 样例分析
  48| 
  49| 以输入 `AAAAABCD` 为例：
  50| 
  51| 1. **统计**：A:5, B:1, C:1, D:1。
  52| 2. **堆**：`{1, 1, 1, 5}`。
  53| 3. **合并 1**：取出两个最小的 `1` `(B)` 和 `1` `(C)`。合并得 `2`。
  54|    - 当前代价累加：2。
  55|    - 堆变成：`{1, 2, 5}` （剩下的D和新合成的BC）。
  56| 4. **合并 2**：取出 `1` (D) 和 `2` (BC)。合并得 `3`。
  57|    - 当前代价累加：$2 + 3 = 5$。
  58|    - 堆变成：`{3, 5}`。
  59| 5. **合并 3**：取出 `3` 和 `5` (A)。合并得 `8`。
  60|    - 当前代价累加：$5 + 8 = 13$。
  61|    - 堆变成：`{8}`。停止。
  62| 6. **结果**：
  63|    - ASCII长度：$8 \times 8 = 64$。
  64|    - 哈夫曼长度：13。
  65|    - 比率：$64 / 13 \approx 4.9$。
  66| 
  67| ## 4. C++ 代码实现
  68| 
  69| 
  70| ```cpp
  71| #include <iostream>
  72| #include <string>
  73| #include <queue>
  74| #include <map>
  75| #include <vector>
  76| #include <cstdio> // 用于 printf
  77| 
  78| using namespace std;
  79| 
  80| int main() {
  81|     string s;
  82|     while (cin >> s && s != "END") {
  83|         map<char, int> freq;
  84|         // 1. 统计字符频率
  85|         for (char c : s) {
  86|             freq[c]++;
  87|         }
  88| 
  89|         // 2. 将频率放入小顶堆
  90|         // priority_queue 默认是大顶堆，使用 greater 变成小顶堆
  91|         priority_queue<int, vector<int>, greater<int>> pq;
  92|         
  93|         for (auto const& [key, val] : freq) {
  94|             pq.push(val);
  95|         }
  96| 
  97|         long long original_len = s.length() * 8;
  98|         long long compressed_len = 0;
  99| 
 100|         // 3. 特殊情况：只有一种字符
 101|         if (pq.size() == 1) {
 102|             compressed_len = s.length(); // 每个字符用1位表示
 103|         } else {
 104|             // 4. 哈夫曼树构建过程
 105|             while (pq.size() > 1) {
 106|                 int a = pq.top(); pq.pop();
 107|                 int b = pq.top(); pq.pop();
 108|                 
 109|                 int combined = a + b;
 110|                 compressed_len += combined; // 累加代价
 111|                 
 112|                 pq.push(combined);
 113|             }
 114|         }
 115| 
 116|         // 5. 输出结果
 117|         // %.1f 保留一位小数
 118|         printf("%lld %lld %.1f\n", original_len, compressed_len, (double)original_len / compressed_len);
 119|     }
 120|     return 0;
 121| }
 122| ```
 123| 
 124| ## 5. 代码关键点说明
 125| 
 126| 1. **数据类型**：虽然题目描述的字符串长度通常不会溢出 `int`，但在累加过程中使用 `long long` 是个好习惯，防止溢出。
 127| 2. **小顶堆**：`priority_queue<int, vector<int>, greater<int>>` 是 C++ STL 实现哈夫曼编码最方便的数据结构。它能保证每次 `pop()` 出来的都是当前频率最小的两个节点。
 128| 3. **计算逻辑**：
 129|    - 传统的哈夫曼编码计算通常是：$\sum (\text{频率} \times \text{深度})$。
 130|    - 代码中的简便算法利用了一个数学性质：**非叶子节点的权值之和等于所有叶子节点的带权路径长度之和**。每次合并操作 `a+b` 实际上就是生成了一个内部节点，所以直接累加 `a+b` 即可得到最终总长度。
 131| 4. **Corner Case (边界情况)**：
 132|    - 务必注意 `if (pq.size() == 1)` 的判断。如果没有这个判断，`while (pq.size() > 1)` 循环一次都不会执行，导致 `compressed_len` 为 0，最终计算比率时会出现除以零错误（Runtime Error 或 NaN）。
 133| 
 134| ## 6. 复杂度分析
 135| 
 136| - **时间复杂度**：
 137|   - 统计频率：$O(N)$，其中 $N$ 是字符串长度。
 138|   - 堆操作：假设字符集大小为 $C$（这里是大写字母+数字+下划线，最多约 40 种）。构建堆和循环合并的复杂度为 $O(C \log C)$。
 139|   - 由于 $C$ 很小，整体复杂度主要取决于字符串长度，即 $O(N)$。
 140| - **空间复杂度**：$O(C)$，用于存储字符频率映射和优先队列。
