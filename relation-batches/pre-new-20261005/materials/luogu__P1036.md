  11| ## 思路
  12| 
  13| 先看一个可以直接验证想法的朴素解：
  14| 
  15| @include-code(./brute.cpp, cpp)
  16| 
  17| 这个暴力把问题看成一串 01 选择：`choose[i] = 0/1` 表示第 `i` 个数不选或选。递归先生成完整的 `choose[]`，到叶子节点再检查是否恰好选了 $k$ 个、和是否为素数。这种写法要枚举全部 $2^n$ 个子集，其中大量序列根本不满足“选 $k$ 个”的要求，是枚举对象的浪费。
  18| 
  19| 关键观察是**组合不关心顺序，下标递增可以天然去重**：规定“每次新选的下标必须大于上一次选的下标”，那么每个 $k$ 元集合只会按下标升序出现一次，既不重复也不遗漏。
  20| 
  21| 于是主解直接用组合枚举 DFS：`dfs(dep, last, sum)` 表示正在选第 `dep` 个数、上一个选中下标是 `last`、当前和为 `sum`；每层枚举下标 $i$ 从 `last + 1` 到 $n-(k-dep)$（上界保证后面还能选满 $k$ 个），选满 $k$ 个时用试除法判断 `sum` 是否为素数并计数。这正好把全部 $\binom{n}{k}$ 个组合生成一遍，$n \leqslant 20$ 时最多 $\binom{20}{10}=184756$ 个，规模很小。
  22| 
  23| ### 样例搜索树
  24| 
  25| 这张图展示样例 $n=4,k=3$ 时递增下标 DFS 的完整分支过程，叶子标注组合与和：
  26| 
  27| ```text
  28| dfs(1, 0, 0)                            上界 i ≤ n-(k-1) = 2
  29| ├─ i=1 (选 3) → dfs(2, 1, 3)            上界 i ≤ 3
  30| │   ├─ i=2 (选 7) → dfs(3, 2, 10)       上界 i ≤ 4
  31| │   │   ├─ i=3 (选 12) → 组合和 22      合数
  32| │   │   └─ i=4 (选 19) → 组合和 29      素数 ✓
  33| │   └─ i=3 (选 12) → dfs(3, 3, 15)      上界 i ≤ 4
  34| │       └─ i=4 (选 19) → 组合和 34      合数
  35| └─ i=2 (选 7) → dfs(2, 2, 7)            上界 i ≤ 3
  36|     └─ i=3 (选 12) → dfs(3, 3, 19)      上界 i ≤ 4
  37|         └─ i=4 (选 19) → 组合和 38      合数
  38| ```
  39| 
  40| 观察要点：每条路径的下标都严格递增，所以 $[3,7,12]$ 只会出现一次、绝不会出现 $[7,3,12]$；第一层只枚举到 $i=2$，因为选了 3 号或 4 号后剩余下标凑不满 $k=3$ 个，这类分支被上界直接剪掉。四片叶子正好对应全部 4 个组合，其中只有 $3+7+19=29$ 是素数。
