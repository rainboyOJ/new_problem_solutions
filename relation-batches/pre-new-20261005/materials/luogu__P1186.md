   9| ## 题目解析（原文摘录）
  10| 
  11| ### 题意
  12| 
  13| 给你一张无向带权图，起点是 `1`，终点是 `N`。
  14| 
  15| 现在有一条路会因为维修而完全不能走，但不知道具体是哪一条。  
  16| 题目保证：无论封掉哪条边，从 `1` 仍然能到 `N`。
  17| 
  18| 玛丽卡会在剩下的边里重新走最短路。  
  19| 要求输出最糟糕情况下，这条最短路会变成多长。
  20| 
  21| #### 样例直觉图
  22| 
  23| 这张图展示了“封掉原最短路上的一条边后，被迫绕路”的现象：
  24| 
  25| ```dot
  26| graph G {
  27|   rankdir=LR;
  28|   1 -- 2 [label="8"];
  29|   2 -- 5 [label="1", color="red", penwidth=2];
  30|   2 -- 3 [label="9"];
  31|   3 -- 5 [label="10"];
  32| }
  33| ```
  34| 
  35| 如果红边 `2-5` 被封掉，原来的最短路就失效了，只能走更长的替代路线。  
  36| 所以关键不在“封哪条边”，而在“哪些边真的有能力把当前最短路挤掉”。
  37| 
  38| ### 思路
  39| 
  40| 先看一个最直接的小数据暴力：
  41| 
  42| @include-code(./brute.cpp, cpp)
  43| 
  44| 暴力做法就是：
  45| 
  46| 1. 枚举每一条边
  47| 2. 把它临时删掉
  48| 3. 重算 `1 -> N` 的最短路
  49| 4. 取这些最短路里的最大值
  50| 
  51| 这个做法最贴题意，但把所有边都删一遍没有必要。
  52| 
  53| 关键观察和 `P2176` 很像：
  54| 
  55| - 如果某条边不在我们当前求出的一条最短路上
  56| - 那么把它封掉之后，这条最短路本身仍然完整存在
  57| 
  58| 既然原来的这条最短路还在，那么新的最短路长度就不可能变大。  
  59| 所以只有一类边值得枚举：
  60| 
  61| - 某条已知最短路上的边
  62| 
  63| 于是正式做法变成：
  64| 
  65| 1. 第一次 Dijkstra，求出从 `1` 到 `N` 的一条最短路
  66| 2. 记录每个点的前驱点和前驱边
  67| 3. 从 `N` 倒着回溯，恢复出这条最短路上的所有边编号
  68| 4. 依次禁用这些边，再跑一次 Dijkstra
  69| 5. 取得到的最短路长度最大值
  70| 
  71| 和代码的对应关系：
  72| 
  73| - `parent_node`、`parent_edge`：第一次最短路时记录路径
  74| - `path_edges`：回溯出的那条最短路
  75| - `banned_id`：当前被封掉的边
  76| - `dijkstra(1, false, banned_id)`：忽略这条边重新算最短路
