  11| ## 思路
  12| 
  13| 先看一个可以直接验证想法的朴素解：
  14| 
  15| @include-code(./brute.cpp, cpp)
  16| 
  17| `brute.cpp` 每次询问从 $u$ 沿父亲链向上爬，遇到第一个标记就输出，单次询问最坏 $O(n)$（链形树），总复杂度 $O(nq)$，无法通过 $10^5$ 的数据。
  18| 
  19| 关键观察有两点：
  20| 
  21| 1. **重链剖分把路径拆成 $O(\log n)$ 段**：从任意节点到根的路径，按"链头跳链头"的方式只跨 $O(\log n)$ 条轻边，每段是一条重链上的连续 dfn 区间。
  22| 2. **同一重链上"最近"就是"dfn 最大"**：链上深度随 dfn 严格递增，所以一段链内离 $u$ 最近的已标记节点就是区间内已标记 dfn 最大的那个。
  23| 
  24| 于是用重链剖分 + 线段树：线段树维护每个 dfn 位置的最大已标记 dfn（0 表示无标记）。标记操作是幂等的点更新；询问从 $u$ 出发逐链向上——查 `[dfn[top[u]], dfn[u]]` 的区间最大值，非 0 就还原成节点输出，否则跳过整段跳到链头的父亲，直到进入包含根的重链（根 1 永远有标记，答案必然存在）。
  25| 
  26| 下面这张 ASCII 图展示样例的查找过程（树形：`1-(2,3)`、`2-(4,5)`，重链为 `1 -> 2 -> 4`，`3`、`5` 是轻链）：
  27| 
  28| ```text
  29| 标记集合变化：
  30|   初始: {1}       -> C 2 后: {1, 2}
  31| 
  32| Q 2 : 链1 [dfn1,dfn2] 最大已标记 dfn = dfn[2] -> 答案 2
  33| Q 5 : 先查链5 [dfn5,dfn5] 无标记 -> 跳到 parent[5]=2
  34|       再查链1 [dfn1,dfn2] 最大已标记 dfn = dfn[2] -> 答案 2
  35| Q 3 : 先查链3 [dfn3,dfn3] 无标记 -> 跳到 parent[3]=1
  36|       再查根链 [dfn1,dfn1] 最大已标记 dfn = dfn[1] -> 答案 1
  37| ```
  38| 
  39| 观察"Q 5"和"Q 3"的路径：它们都先查了自己的链段（没有标记），各跨一条轻边才到达根所在的重链，这正是"逐链向上"只走 $O(\log n)$ 段的原因；而"Q 2"因为目标就在自己链上，一次区间查询直接命中。
