## relations3-graph 视觉优化实施计划

状态：已实现（代码与构建已完成；真实浏览器截图验收需在部署环境运行）。日期：2026-10-02。代码基线：`0a3a1992`。

本文供 GPT 6.1 Sol 直接执行。目标是让 `/relations` 的三维关系图更清晰：使用接近黑色的画布，把注意力集中到题目节点、当前关系和可读的文字上，同时增加实际可用的画布面积。

用户已确认优化方向。本轮交付包括代码、必要测试、构建和真实浏览器验收；不需要重新进行产品决策访谈。本文自身只记录计划，不代表下述功能已经完成。

### 依据与适用范围

- 视觉参考：[react-force-graph large-graph 示例](https://vasturiano.github.io/react-force-graph/example/large-graph/)。重点借鉴黑色背景、彩色球体、弱化的连线和较少的常驻文字。
- 原始功能约束：[首次实现计划](./relations3-graph-implementation-plan.md)。其中三版并存的入口设计已被后续迁移替代。
- 当前路由和构建约束：[默认入口迁移记录](./relations-default-3d.md)。以当前代码为准，保留 `/relations` 默认入口和旧版下线结果。
- 当前界面参考：[桌面聚焦截图](./relations-default-3d-assets/desktop-focus.png)、[手机聚焦截图](./relations-default-3d-assets/mobile-focus.png)。这些是优化前记录。

规划时读取的实际数据是 2169 个题目节点、112 条关系，其中 120 个节点参与关系、2049 个孤立节点；关系包括 87 条前置关系和 25 条相似关系。忽略方向后，参与关系的节点分成 24 个连通分量，最大的分量有 22 个节点。数据会随内容维护变化，测试不能把这些数量写死。

参考示例当时包含 1238 个节点、2602 条边，其连线密度与本项目不同。黑色主题可以改善对比和层次，但不能把当前稀疏数据变成示例中的密集网络。禁止为了视觉效果添加不存在的关系。

## 一、本轮交付边界

### 必须完成

1. 关系图独立使用黑色画布和协调的深色控件，不随全站明暗主题切换。
2. 节点使用有柔和明暗变化的球体；保留类别颜色语义；选中状态使用简洁圆环。
3. 总览弱化边，聚焦后突出当前题目的直接关系，明确区分前置、后续和相似关系。
4. 用屏幕空间 HTML 标签替换当前 SpriteText 标签，解决文字模糊、背景块过重和重叠问题。
5. 压缩标题和工具区，总览收起详情面板，选中题目展开详情；改善手机上的画布空间。
6. 保留已有搜索、关系筛选、探索历史、镜头、拖动固定、缓存及故障降级能力。
7. 完成回归测试、构建、同条件截图对比和验收记录。

### 后续候选，本轮不实施

- 按连通分量组织初始布局。
- 仅在选中或悬停的前置边上显示方向粒子。

先完成本轮视觉改动并记录效果，再评估上述候选是否值得单独实现。首轮不修改布局算法，不增加粒子动画，不升级框架或图形依赖，不引入后处理、阴影、贴图或新的图形渲染框架。

### 必须保护的行为

- `/relations` 提供新版；`/relations3` 保持 308 重定向并保留参数；旧页面与旧静态资源继续 404；`npm run build` 只构建 relations3。
- `pre` 的箭头仍然指向后续题目；`common` 仍然无方向。颜色不能代替实线、虚线、箭头和清单文字。
- 聚焦只突出当前题目的直接关系，不把邻居之间的边也当作当前关系。
- 切换中心、悬停、搜索、主题和面板状态不重新生成坐标，也不重启力模拟。原本允许布局的初始化、拓扑更新和显式重新布局继续走已有流程。
- `GraphModel`、节点对象和边对象保持稳定身份。不要通过修改 React `key` 实现视觉刷新。
- 不改变 API 返回数据，不把图形库写入的对象回填原始 API 数据。
- 保留布局缓存格式、键名、用户固定位置和探索镜头记录。本轮不提高布局版本或清空缓存。
- 鼠标拖动固定节点、触屏点击、双指手势、键盘操作和 WebGL 不可用时的清单必须继续工作。

## 三、黑色主题与视觉角色

### 主题隔离

给 `.relations3-app` 设置自己的主题标记，例如 `data-r3-theme="dark"`，将所有 `--r3-*` 变量限定在该根元素下。画布背景统一读取 `graph-theme.ts`，CSS 面板变量保持同一套取值。

删除 `App.tsx` 中仅用于跟随全站主题的 `dark` 状态和 MutationObserver，并同步调整 `VisualState` 及使用者。保留测量全站导航高度的 ResizeObserver。不要修改 `document.documentElement.dataset.bsTheme`；站点其他页面和导航继续遵循全站主题。

这组颜色是初始实现值，可在浏览器验收中微调，并在验收文档记录最终值。

| 用途 | 初始值 | 说明 |
| --- | --- | --- |
| 画布 | `#000011` | 接近参考示例的黑色，保持均匀背景 |
| 工具栏、详情面板 | `#0b1020` | 与画布区分，但不抢占注意力 |
| 输入框、悬停面 | `#151d30` | 保留明确控件边界 |
| 分隔线 | `#263247` | 低亮度分隔，不画厚重卡片边框 |
| 正文 / 次要文字 | `#e6edf7` / `#a6b2c5` | 禁止对整块文字容器统一降低 opacity |
| 总览边 | `#94a3b8` | 配合较低透明度 |
| 前置 / 后续 / 相似 | `#fbbf24` / `#7db5ff` / `#5eead4` | 分别对应入边、出边和无向相似边 |
| 中心环 / 悬停环 | `#f8fafc` / `#fbbf24` | 中心与悬停同时存在时可区分 |

错误、加载、重试、空结果、搜索下拉、原生按钮和禁用状态也必须检查深色适配，不能只改正常状态。

### 节点颜色

以 API 的 `node.color` 为输入，保留原有类别色相，对过暗的颜色提高明度，必要时限制过高饱和度。将转换集中为 `getGraphCategoryColor(color)`，图例也必须使用同一个函数。

使用安装版本的 Three.js 颜色接口时显式处理颜色空间，避免把线性 RGB 当作 CSS RGB。不得修改 `node.color` 或 `tagStats`；相同输入必须得到相同输出；非法输入返回稳定的默认颜色。不要随机重新分配类别颜色。

### 节点与边状态优先级

节点按“中心 > 悬停 > 直接邻居或搜索命中 > 普通节点 > 弱化背景”处理。中心球半径初始保持原来的 `6 × 1.3`，普通球半径保持 6；本轮不按节点度数扩大球体。

下表给出边的基础规则，供纯函数统一解析，避免 JSX、材质和图例各写一套判断。

| 场景 | 边颜色与透明度初始值 | 结构语义 |
| --- | --- | --- |
| 无中心的总览 | 中性灰，opacity 0.22 | 前置实线带箭头，相似虚线无箭头 |
| 有中心，指向中心的前置边 | 橙色，opacity 0.9 | 表示中心题目的前置题目 |
| 有中心，从中心指出的前置边 | 蓝色，opacity 0.9 | 表示中心题目的后续题目 |
| 有中心，与中心相连的相似边 | 青绿色，opacity 0.85 | 保持虚线和无方向 |
| 有中心的其他边 | 中性灰，opacity 0.05 | 保留空间上下文 |
| 悬停直接边 | 对应关系颜色，opacity 1 | 箭头可略放大，不能反转方向 |

总览悬停节点时，可以临时按该节点解释相邻边的入/出方向，但不建立探索中心、不改 URL、不移动镜头。已有中心时，悬停邻居仍只强化它与中心之间的关系；不要把邻居的所有关系都点亮。

节点透明度初始使用：普通 0.9、中心/邻居/命中/悬停 1、背景 0.18。搜索命中影响节点和标签，不创建额外边。优先级冲突必须有测试，特别是“中心仍在、搜索另一个节点”的场景。

图例在总览解释灰色实线/虚线，在聚焦状态解释橙色前置、蓝色后续、绿色相似；类别色点始终与节点一致。

## 四、球体、圆环和边几何

### 球体材质与照明

把节点球体的 `MeshBasicMaterial` 改为 `MeshLambertMaterial`，先保持现有 `SphereGeometry(6, 12, 8)`。检查现有图形库灯光下的效果；安装版本公开提供 `lights()`，确有需要时通过此接口配置简单的环境光和方向光。

优先复用默认灯光，避免重复添加。验收时旋转镜头，确认球体仍有明暗层次，背面不会黑到不可见。不要增加阴影贴图、Bloom、环境贴图或高面数球体。淡化节点保持 `depthWrite=false`，正常前景节点保持合理深度写入，实际检查透明物体排序。

### 用圆环替换线框球

保留现有 `NodeObject.halo` 的职责，几何换成轻量 `RingGeometry`，材质使用透明的 `MeshBasicMaterial`。圆环只在中心或悬停节点上可见；中心优先，单个节点不叠两圈。

圆环内半径略大于球体实际半径，宽度约为普通球半径的 0.12～0.18。通过既有动画帧更新圆环自己的 quaternion，使其朝向相机；不要旋转整个节点 Group。禁止脉冲或持续闪烁。

圆环 `raycast` 为空操作，不能挡住球体拾取。保留球体上的 `userData.nodeId`，现有鼠标拖动和触屏候选拾取继续命中球体。采用每节点独立几何/材质以延续当前释放方式；若优化共享资源，必须先证明图形库删除单个节点时不会提前释放共享对象。

### 边端点与缓存

把“节点当前半径”抽成统一函数，球体缩放、圆环和边端点裁切都使用它。现在边端点固定按 `BASE_RADIUS + 2` 裁切，中心球变大后会产生不一致，应一并修正。

`updateEdge()` 的缓存键不能只包含两端坐标：中心切换后半径变化，即使坐标没变也需要重新计算端点。将端点半径加入缓存键，或在相关状态变化时准确失效相邻边缓存。

保留平行关系的曲线分离和箭头切线方向；距离不足、两端重合时不得产生反向裁切、NaN 或无限长几何。不要依赖 WebGL `LineBasicMaterial.linewidth` 实现粗线，本轮用颜色、透明度和箭头尺寸表达强调。

## 五、HTML 标签实现

### 组件边界与数据流

`Graph3D` 内增加绝对定位的 `GraphLabelOverlay`，覆盖画布且限制在 stage 内。标签层 `pointer-events: none`，不影响 OrbitControls、滚轮、节点点击和拖动。画布标签属于详情清单的视觉补充，可设 `aria-hidden="true"`；可访问操作继续由搜索与详情 DOM 提供。

React 只管理标签候选及文字内容；已有动画帧负责投影后更新 DOM 元素的 `transform` 和 `visibility`。不要每帧调用 `setState`，也不要为每个题目创建一个 HTML 标签。

建议拆成以下三个步骤，函数签名根据现有类型适配。

```typescript
// 纯计算：确定有限候选、排序及其文字展示方式。
selectLabelCandidates(visual, nodeMetadata, budget)

// 几何计算：使用相机、世界坐标和 stage 尺寸得到屏幕锚点。
projectLabelAnchors(candidates, positions, camera, viewport)

// 纯计算：使用实际测量尺寸和障碍矩形，返回可见标签位置。
placeLabels(anchors, measurements, reservedRects, previousPlacements)
```

候选计算与每帧投影分离；上例表达职责，不要求引入大型布局框架。`label-manager.ts` 不再依赖 `GraphObjects.label()`。

### 标签内容、预算与优先级

- 中心：题号加完整标题，字号 14～15 CSS px，允许换行，不使用省略号截掉正常长度标题。
- 邻居：题号加短标题，字号 12～13 CSS px，短标题按 Unicode 字符安全截断，默认约 14 字。
- 悬停：优先显示该节点标签，完整标题继续由现有 HTML tooltip 展示，避免同时出现两块完整标题。
- 总览远景：仅保留悬停标签；拉近后才显示有限数量的普通节点标签，保留现有“近处显示”的交互方向。
- 搜索：只为有限命中结果分配标签，搜索结果清单保持完整分页能力。

初始 DOM 候选预算为桌面最多 48 个、窄屏最多 24 个，包含中心与悬停，不是额外加在预算外。优先级为中心、悬停、直接邻居、搜索命中、近景普通节点；同优先级按稳定 ID 排序，避免随 Set 插入次序跳动。

候选截断前先排除不可见、相机背后和视锥外节点，让屏幕外邻居不占满可见标签名额。候选预算限制 DOM 数量，不限制关系清单中的邻居数量；100 个邻居仍全部可浏览。

### 投影、避让和稳定性

1. 读取画布实际宽高及相机矩阵，排除 near/far 裁剪范围外的节点。
2. 用 CSS 像素计算锚点，不能再乘 devicePixelRatio。标签字形由浏览器绘制，避免重新生成文字纹理。
3. 每个标签按固定顺序尝试上、下、左、右及对角位置；中心优先占位，其他标签避开它。
4. 使用实际文字尺寸计算矩形。尺寸由元素测量和 ResizeObserver 缓存，只有内容、字体或容器变化时更新；禁止每帧交替读写 DOM 布局。
5. 避开已放置标签、缩放按钮、状态提示和其他可见浮层。stage 外的工具栏和详情区不参与画布坐标计算。
6. 优先保留上帧仍合法的位置，使用小幅移动容差防止标签来回换边。相机缩放跨越近景阈值时采用滞回，避免闪烁。
7. 放不下的普通标签隐藏；中心必须优先保留。中心与悬停重叠时，尝试移动悬停标签，仍放不下则依靠 tooltip，不允许两个优先标签强行重叠。
8. 超长中心标题设置与 viewport 相关的最大宽高并换行；小屏实在无法完整展示时允许限定高度截断，完整标题必须可从详情读取，并在验收记录注明此规则。

标签背景使用轻量半透明深色底或文字阴影，中心可以有稍明显底色；禁止恢复成大片不透明白色卡片。不要让标签经过无关节点时整块遮住关系结构。

### 更新触发与清理

扩展现有相机/尺寸/visualRevision 签名，覆盖候选、文字测量结果与障碍矩形变化。力模拟运行、拖动节点和相机动画期间正常更新；静止时不反复测量和重新布局。

字体加载完成、窗口 resize、详情开合和屏幕旋转后重新测量。WebGL 重试、组件卸载和 StrictMode 重挂载时断开 observer、清除元素引用及异步回调。标签层随 Graph3D 生命周期退出，不能在错误清单上留下旧标签。

移除 `graph-objects.ts` 的 SpriteText 字段、创建函数及相应导入。检查全仓库引用后再决定是否移除 `three-spritetext` 直接依赖；不要因本轮顺带删除旧源码依赖或手工编辑 lockfile。

## 六、紧凑界面与镜头协调

### 桌面结构

把大标题“从一道题，找到下一步。”收成一行“题目关系图”，保留 3D 标记和可见节点/关系统计。去掉额外的宣传性标题高度，主要操作围绕搜索、筛选、返回、总览和适应视图组织。

重置视角、重新布局、刷新数据可以放进“更多操作”，保留完整文字和原有语义，不能删除功能。控件保留可见焦点状态、明确标签和禁用原因；不要只保留没有说明的图标。

总览状态取消空详情侧栏，画布占满工作区。选择中心后展开约 320 px 的详情栏；用户可以收起，并通过明显按钮重新打开。保留前置、后续、相似三个分组、数量、关系原因和打开题目链接。

### 手机结构

搜索始终可达，次要工具默认折叠，避免工具区与详情同时占满屏幕。详情采用现有底部抽屉方向，保留收起栏，展开高度通常控制在工作区的约三分之一，内部清单滚动。

在 390×844 的验收视口中，未唤起软键盘时，详情展开后争取保留至少 300 CSS px 高的画布；短横屏优先保证控件和抽屉可滚动，不机械坚持这一高度。触摸按钮目标尺寸按约 44 CSS px 设计。

搜索下拉可滚动，不能被 canvas 或详情遮住。手机点击节点后展开抽屉时，保留现有防止兼容 click 误触新位置按钮的处理。

### 详情状态转换

按下表处理状态，避免只改鼠标选中路径、漏掉 URL 和历史恢复。

| 操作 | 详情区行为 |
| --- | --- |
| 无中心进入总览 | 收起，不预留空侧栏 |
| 有效深链接直接进入中心 | 数据确认有效后自动展开 |
| 搜索、节点、关系清单选择题目 | 展开，包括再次选择同一题目 |
| 探索返回到某中心 / URL 历史恢复到某中心 | 展开并展示恢复的题目 |
| 返回总览 / 无效中心被移除 | 收起 |
| 用户手动收起 | 保留当前中心、筛选、坐标与历史；下一次显式选择再展开 |
| 悬停或全站主题切换 | 不改变详情开合 |

实现时可提取小型纯状态函数或 reducer，用事件表达开合规则，不要仅依赖 `selectedId` 变化，因为再次选择同一题目也需要展开。

### 镜头与 resize

面板宽度改变不重建图。初版不为 grid 列宽做持续动画，使 ResizeObserver 在稳定尺寸后触发一次必要的镜头处理，避免每帧重新聚焦。

选择中心时先确定最终 stage 尺寸，再执行一次聚焦。恢复探索历史时，优先恢复已有 camera checkpoint，不能紧接着被 resize effect 的自动 fit 覆盖。若视口尺寸改变导致中心不在可视区域，保留观察方向，只做必要的距离调整，并增加回归用例。

手动收起/展开详情时保持中心和观察方向，必要时执行一次适应；用户开始拖动 OrbitControls 时继续取消镜头动画。保留 `prefers-reduced-motion` 对镜头动画的影响。

## 七、按阶段推进

每阶段完成相关检查后继续下一阶段，无需逐阶段等待确认。以下是实现与评审的拆分顺序，不代表自动提交 Git。

### 阶段 0：建立可比较的基线

1. 检查工作区和 Node 版本；从仓库根目录执行命令，项目没有独立的 `relations3-graph/package.json`。
2. 运行现有类型检查与关系图测试，确认基线；用现有浏览器脚本保存当前截图和报告。
3. 保存真实 API 数据快照、布局缓存、镜头位置/目标、视口和 DPR；记录全站主题、选中题目和筛选。
4. 至少准备总览、同时包含三类关系的中心、关系最多的中心、孤立节点和 100 邻居压力数据。

比较颜色与材质时，使用相同数据、布局坐标、镜头和 stage 尺寸。比较整体界面时使用相同浏览器窗口，允许新界面提供更大的 stage，并在报告区分两种比较。

### 阶段 1：主题、球体和边

实现主题 token、类别色转换、纯视觉角色函数、Lambert 球体、圆环和边端点半径修正。同步修改图例，验证全站主题切换不改变画布配色、不重启布局。

完成条件：黑色主题全状态可用，三类关系含义正确，坐标稳定，旋转时球体与圆环正常，相关测试与类型检查通过。

### 阶段 2：标签替换

实现 HTML overlay、投影与避让算法，移除 SpriteText 标签路径，更新浏览器脚本对标签的采样方式。保留现有 tooltip，完成长标题、100 邻居、缩放和触摸检查。

完成条件：中心标题清晰，邻居标签有预算且不重叠，文字不会挡住输入，静止时没有持续 React 重渲染，错误重试不残留 DOM。

### 阶段 3：空间与面板

压缩标题和工具栏，实现桌面详情开合、手机工具折叠和详情状态转换；集中处理 resize 与历史镜头的优先级。

完成条件：总览拥有完整宽度，所有选择入口的详情状态一致，历史镜头不被自动 fit 覆盖，手机仍能旋转、缩放、选择与返回。

### 阶段 4：回归、构建与浏览器验收

完成下节检查，保存新截图和报告，更新验收文档。遇到失败先定位原因；不要通过删除断言、延长所有等待时间或固定真实数据数量让测试通过。

保留原有坐标、关系清单、镜头、触摸、错误恢复和资源检查。主题测试改为“全站主题可切换，关系图保持黑色”，并检查离开关系图后其他页面的主题仍正常。

现有几何数量检查允许因圆环替换发生一次性基线变化，但同一页面反复操作后不能持续增长。增加标签元素预算、重复挂载后的 observer/DOM 清理检查。用实际生命周期行为证明资源稳定，不把历史资源数量当作永久常量。

使用仓库要求的 Node.js 22 或更高版本及现有 lockfile。开发时按改动运行窄范围检查；最后运行完整验证。命令均从仓库根目录执行。

```bash
npm run test:relations3
```

`verify:push` 已包含完整测试和构建验证，前面的命令用于阶段检查，不需要无理由反复执行。真实浏览器验收记录 Chromium 版本、GPU、视口、DPR、数据规模和采样方法。如果没有硬件图形环境，可以补充软件渲染检查，但必须明确标注，不能作为真实 GPU 性能结论。

## 九、后续候选的评估方法

### 连通分量布局

首轮验收后，如果总览依然主要被分散的小分量和大块空白影响，可另开布局改进任务。记录分量大小、各分量屏幕占用和空白区域，不凭截图猜测数据密度。

后续实现方向：以真实边计算弱连通分量，稳定排序分量并分配三维中心，在分量内部保留力导向结构，限制分量之间过强的排斥。只在首次无缓存布局或用户显式重新布局时应用；不引入假边，不因切换中心重新组织全图。

届时单独设计缓存迁移与固定节点策略。已有 pins 不能因为布局版本变化被静默丢弃；有缓存的用户仍应能继续使用原位置。不要在本轮为候选方案提前修改缓存版本。

### 方向粒子

只有用户仍难以辨认箭头方向时再评估。候选方案只为当前中心的少量前置边或悬停边展示粒子，相似边没有粒子；数量设上限，遵循减少动态效果偏好。

当前使用自定义曲线边，后续必须先验证图形库粒子轨迹是否与这些曲线一致，不能直接设置全局 `linkDirectionalParticles` 后就视为完成。测试方向、路径、性能与离开悬停后的清理。
