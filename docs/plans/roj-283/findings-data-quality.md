## 零、为什么重要

`data/*.out` 是由 `std.cpp` 生成的。**`std.cpp` 自己有 bug，`.out` 就是错的** ——
而我们的验收标准是「真实数据 10/10」，于是会出现：

> 正确的实现跑不过错误的数据。

**处理原则（写进任务卡了）**：

> **不要为了让 `.out` 通过而写错算法。**
> 用正确读入实现；若逻辑对但 `.out` 不符，在 `index.md` 写明
> 「`.out` 由带 bug 的 std 生成，本点数值可能是垃圾」，把**正确实现作为主解**。

1762 的子代理就是这么做的：它用 BFS 暴力 + 手算证明了原实现语义正确，
**拒绝迎合错误数据**，转而推动修数据。

### 缺陷 #12 · 5012 `std.cpp` — `p == 1` 时漏算自身溅射

**症状**：`R = isqrt(p-1)`，`p == 1` 时 `R == 0`。滑动窗口的弹出条件
`if (R >= 1 && rem < n)` **把「加入」也一起挡住了** ⇒ 窗口恒空 ⇒
漏算自身的 `p` 点伤害 ⇒ 可行的 `p = 1` 被误判为不可行。

**最小复现**：
```bash
printf '3 6\n1 1 1\n' | ./main    # 错：2    对：1
```

**影响**：`new_ROJ/problems/5012/std.cpp` 同错（专家与 worker 的 `main.cpp`
初版也同错，已由 worker 修复）。数据未触发（`data.py` 生成的 10 个点无 `p = 1` 情形），
**故不影响判题**，但属参考实现的真实缺陷。

**类别**：参考实现缺陷 · 未被数据生成器覆盖（第 2 例，前例为 5011）

### 缺陷 #13 · 5011 `std.cpp` — 「min-over-j + 回溯」在段和并列时不精确

**症状**：素材 `std.cpp` 用「对 `j` 取 `min` + 回溯统计段数」的写法，

### 缺陷 #14 · 3161 数据整体损坏（**已修复**）

**症状**：
- `count1.in` 只有 `50` 一个数 —— 而题面说「输入共一行，包含两个整数 N 和 M」，**缺 M**
- `count1.out` 是 **18851 字节的表格**，每行 `n m 恰好m条桥的图数`，
  不是任何单次输入的答案

**真相的推理链**（本批方法学最完整的一次）：

1. 现象：`.in` 缺 M，`.out` 是表格
2. 表的 `(n,m)` 组合很怪：n 对应 `m ∈ {0,…,n−3} ∪ {n−1}`（共 `n−1` 个，合计 1226 行）
3. **独立暴力**（枚举全部图 + Tarjan 求桥）：真值 `(4,1)=22`，专家程序 22 ✅，表 12 ❌
4. 看出表的含义：n=4 的表值 `10,12,16` = 「**恰好** 0/1/3 条桥」的图数；
   而 `22 = 10+12` 是**前缀和**
5. **决定性验证**：表的**前缀和** vs 专家程序，全 n≤50 全 m ⇒ **20875/20875 吻合**
6. 结论：算法对、题面对（「**不超过** M 条」，样例 `3 3 → 4` 印证），
   **坏的是数据封装**（缺 M + 存了张分布表）

**为什么第 3 步不能省**：只做第 5 步会得到「完全吻合」然后**误判数据没问题**；
是第 3 步的独立暴力揭出「表 ≠ 真值」。
**为什么第 5 步也重要**：它把验证范围从「暴力能算的 n ≤ 6」扩展到「n ≤ 50 全定义域」。

**修复**：用已验证的参考程序重新生成 10 个点（`N M` → 单整数），
原数据备份在 `/tmp/3161-data-backup/`。新点覆盖样例、最小 n、饱和边界、
大 n 未饱和等形态，10 个答案互不相同（有区分度）。

**⚠ 新增流程风险（父会话自造）**：数据由被测程序生成 ⇒ **闸门通过成为循环论证**
（`专家程序 → 生成数据 → 闸门通过 → "证明"专家程序正确`）。
补丁：worker 的独立暴力验证在此场景下是**唯一非循环证据**，必须强制。
待办：`land.py`/`accept.py` 增加「数据来源」标记。

### 缺陷 #15 · 1378 `SHOPTH8.IN` 第 10 行少 1 个 token（**结构错，非算错**）

**症状**：专家的「整篇 split 成 token 连读」在真实数据第 8 点上**崩溃**
（C++ `stoll` 抛 `std::invalid_argument`、Python `IndexError`），修前 `PASS=9 FAIL=1`。

**不变量判定**：邻接矩阵每行必须恰好 `n` 个 token。逐行统计：
`SHOPTH8.IN` **第 10 行只有 19 个**（`n = 20`），其余 21 行都是 20 个；
全文件 **401** 个 token，应为 `2 + 20² = 402`。

**后果机制**：token 流连读时第 10 行少 1 个 ⇒ **其后所有行的元素整体左移一格**
⇒ 最后一轮读空 ⇒ 崩溃。这解释了为什么**恰好只有第 8 点**挂。

**证据链（四条，缺一不可）**：

1. 逐行 token 计数 → 定位到第 10 行
2. 改成**按行读**（短行只影响本行，缺列按「无边」）→ 输出与 `SHOPTH8.OUT` **逐字节一致**
3. 把缺失 token 补在 **col 10~20 任意位置**都能复现 `OUT`；补在 **col 9** 把 `0` 顶到
   对角线反而对不上 ⇒ 缺失发生在**行尾**
4. 判定：官方数据是**按行组织**的，该行行尾漏了 1 个 token

**处置**：采用按行读（对「某行短一个元素」这类脏数据**鲁棒**）。
数据本身**未修改**（按行读即可正确判题）。

**类别**：数据缺陷 · 结构完整性 · **鲁棒性错而非算法错**

### 缺陷 #16（新类别）· 5017 — 题面允许但数据未覆盖的**合法输入**

**这不是「数据错」，也不是「代码错」，而是「覆盖缺口」。**

**症状**：题面只写 $a[i] < p$，**未排除 $a[i] = 0$**；而 $0$ **没有模逆元**，
专家的 MITM（折半搜索 + 费马小定理求逆元）对它失效。
最小复现：`printf '2 5 0\n0 1\n'` → 输出 `0`，**正确应为 `2`**（子集 `{0}` 与 `{0,1}`）。

**为什么数据没暴露**：`data.py` 只产 $a[i] \ge 1$，10 个点全部扫描确认无 $0$。
**但 `data.py` 碰巧没产 0，不等于评测机不会。**

**修法**：设 $z$ = 0 的个数、$m$ = 非零元素个数。含至少一个 0 的非空子集积恒为 0，
共 $(2^z - 1)\cdot 2^m$ 个 ⇒ $c=0$ 时全部合法（`base`），$c \ne 0$ 时全部非法。
剩余非零元素走原 MITM。空集扣减只在 MITM 部分做一次（`base` 天然不含空集）。

**验证**：回归真实数据仍 10/10；新增含 0 对拍 **660 组**零分歧；
最小复现现在输出 `2`；反事实实验（关掉 `if (c == 0)`）证明 `base` 项承重。

**★ 重要的判据区分（本次确立）**：

| | 之前的 6 个例子（3058/5004/…） | **5017 这次** |
|---|---|---|
| 谁错 | **数据错**（`.out` 与题面无关） | **代码错**（输入合法但答错） |
| 该修什么 | 修**数据** | 修**代码** |
| 判据 | `.out` 与题面矛盾 | **题面允许该输入，且代码给出错误答案** |
| 纪律 | 「不要为了让错误数据通过而写错算法」 | 「不要因为数据没覆盖就放任合法输入答错」 |

**结论**：两条纪律**互补**，不矛盾。判据是「**输入是否合法**」——
合法就修代码，非法就修数据。

### 方法学 · 任务卡的「提示」应当写成**疑问式探针**，不是断言

本批父会话（我）给 worker 的提示错误率 **4/4**：

| # | 我写的（断言） | 实际 | 发现者 |
|---|---|---|---|
| 1 | 1374「否则要找奇度点配对（中国邮递员）」 | 双车道模型 | worker-6 |
| 2 | 5011「段和**严格**递增」 | 题面是「不下降」 | worker-5 |
| 3 | 「四位自幂数共 4 个」 | 只有 3 个 | worker-13 |
| 4 | 5018「按 $D_i$ 升序 / 退 $C$ 最大」 | 按 $d_i = M - C_i$ 升序 / 退 $p_i$ 最大 | worker-19 |

第 4 次尤其严重：若 worker 盲信，会把错误前提写进暴力，
两边**共享同一错误假设** ⇒ 穷举 325,440 组也「0 分歧」通过。
（实测：照提示①改代码，10 个真实点挂 8 个；照提示②改，挂 3 个。）
