# 无测试数据题的流水线（C2 / D 组）

## 适用范围

`new_ROJ` 里 `data/` 为空或无数据目录的题（全仓 15 道）：

| 组 | 题号 | 题面形式 | 有 `std.cpp`？ |
|---|---|---|---|
| **C2** | `20028` `20029` `20030` `3123` `3194` `8010` | `content.md` | ❌ 无 |
| **D** | `10005` `10012` `10013` `10014` `10015` `10016` `10017` `10018` `10019` | **`content.pdf`** | ✅ 有 |

## 为什么需要单独的工作流

**没有 `.in`/`.out`** ⇒ 既有的两道闸门（`check_new_analysis --realdata`、`check_bytes`）
**完全无法运行**，`accept.py` 也无法落账。

⇒ 必须用**跨源对拍合成数据**替代「与官方 `.out` 比对」。

## ★ 证据强度分层（**必须写进 `index.md`**）

```
最强  与官方 .out 逐字节一致
  ↑   ★ 本工作流能达到的上限：三方一致 + 反事实表 + UBSan + 对照组
  ↑   两方一致（main vs 自写 ref 或 main vs std.cpp）
  ↑   仅静态审查（**不作为证据**）
最弱  仅能编译通过
```

★ **`T27` 的延伸**：本工作流证明的是「**多个独立实现互相一致**」，
**不是**「与官方标准一致」。
⇒ 若官方题面/数据有隐藏约定（如特殊输入、特定 tie-breaker），**本工作流无法发现**。
⇒ **必须如实标注**。

## 工作流（四步）

### 第 0 步：题面获取
- **C2**：直接读 `content.md`
- **D**：用 `fetch_content` 等方式**从 `content.pdf` 提取题面**，
  并把提取结果**写入** `/tmp/roj-think/<pid>/statement.md`（便于复核）

### 第 1 步：专家出稿（R1）
产出 `/tmp/roj-think/<pid>/` 下的 `index.md` + `main.cpp` + `main.py`
（格式要求同常规题）
★ 若 D 组有 `std.cpp`，**也要读它** —— 它是官方参考实现，是重要的意图来源

### 第 2 步：worker 跨源验证（R2）★ 本工作流的核心
worker **必须**做：
1. **自写参考实现**（`ref.cpp`）——
   **与专家实现不同源**（不同算法思路 / 不同数据结构）
   ★ 若有 `std.cpp`：`ref` **也不能照抄 `std.cpp`**
2. **合成测试数据**，覆盖：
   - **最小规模**（`n = 0` / `1` / 空输入）
   - **最大规模**（按题面的边界）
   - **边界值**（上界 / 下界 / 相等 / 重复）
   - **极端结构**（全相同 / 严格递增 / 严格递减 / 随机）
   - ★ **反例倾向**（容易出错的输入，如溢出边缘、退化情形）
3. **三方对拍**：`main.cpp` × `main.py` × `ref.cpp`（× `std.cpp` 若存在）
   ⇒ 任一方不一致 ⇒ **至少一方有错，必须定位**
4. **`V1` 反事实**（删/改承重行 ⇒ 看看对拍能否发现）
   ★ 若「改坏后对拍仍一致」⇒ **说明合成数据的鉴别力不足**，需加强数据
5. **`V9` UBSan + 对照组**、**闸门对照组**（用合成数据跑一遍判据）
6. ★ **`T38` 空间与时间**：实测 peak RSS + 耗时，与 `config.json` 对比
7. ★ **`V6` 的最高形态**：对**小规模**做**穷举**（而非随机抽样）

### 第 3 步：专家定稿（R3）
据 worker 报告写最终 `index.md`，**必须包含**：
1. **算法**与复杂度
2. **★★★ 证据强度分层声明**（见上）：
   「本题**无官方测试数据**，验证基准是**自写参考实现**；
   证明的是『多个独立实现互相一致』，
   **不是**『与官方标准一致』」
3. **合成数据的覆盖清单**（哪些规模/边界/极端结构）
4. **三方对拍的规模与分歧数**
5. **`V1` 反事实表**
6. **`T9` 五项**

## 落地约定

- **落盘**：`index.md` + `main.cpp` + `main.py`（正常落盘，但**不跑数据闸门**）
- **`accept.py` 不适用**（它依赖数据闸门）⇒ 队列中标记为 `done` 时
  **附注 `no-data`**，并以**三方对拍报告**作为验收依据
- ★ **不要**为了「让闸门过」而伪造 `.in`/`.out`

## 纪律

1. ★ **不能声称「验证通过」** —— 只能说「**三方对拍一致**」
2. ★ **必须列出自写参考实现与专家实现的差异点**（否则「异源」无法审计）
3. ★ **合成数据必须含反例倾向的输入**（否则对拍可能空转）
4. ★ **`V1` 反事实是对拍本身的鉴别力检验**：
   改坏后对拍仍一致 ⇒ 数据不足
5. ★ 若 D 组有 `std.cpp`：**`ref` 不得照抄 `std.cpp`**，
   且**必须报告 `ref` 与 `std.cpp` 的分歧**（若有）


## ★★ 前置检查（T63）：先查题面里的**下载链接**！

**「本地无 `data/`」≠「官方无数据」。**

```bash
grep -o -iE 'https?://[^ )]*' content.md | grep -i 'down/'
```

- **有链接** ⇒ **先下载到 `new_ROJ/problems/<pid>/data/`**，然后走**常规闸门**
  （这才是最强证据层！本工作流只在**确实没有**官方数据时才用）
  ★ 注意：答案文件可能叫 **`.ans`** 而非 `.out` ⇒ 需 `cp xxx.ans xxx.out`
- **无链接** ⇒ 才进入本工作流（跨源对拍）
