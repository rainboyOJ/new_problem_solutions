# R2 任务卡模板（worker 用）

> **为什么要有模板**
> 2026-10-08 一天内，父会话在任务卡里给出的「提示」错了 **5 次**（命中率 0/5）：
>
> | 我写的 | 题面实际 |
> |---|---|
> | 1374「否则要找奇度点配对（中国邮递员）」 | **双车道模型**（每街道两车道都要铲 ⇒ 总路程 = 2×） |
> | 5011「段和**严格**递增」 | 「**不下降**」 |
> | 「四位自幂数共 4 个」 | **只有 3 个** |
> | 5018「按 $D_i$ 升序 / 退 $C$ 最大」 | 按 $d_i = M-C_i$ 升序 / 退 $p_i$ 最大（**两条都错**） |
> | 5016「追加 $v_i$ 个 $i+1$」「问第 $N$ 项的值」 | 追加 $v_i$ 个 $i$；求 $last(last(N))$（**描述成了另一道题**） |
>
> 为什么危险：worker 若**盲信**提示去写暴力，两边**共享同一错误前提** ⇒
> 穷举几十万组也「0 分歧」通过。5018 实测：照我的提示改代码，10 个真实点挂 8 个。
>
> **所以：任务卡里给的是「探针」而不是「答案」。**

## 一、必须直接给的事实（这些是**查得到**的，不是我的记忆）

- [ ] 题目 ID、标题
- [ ] **目标目录绝对路径**（产出侧 `pcs2-roj-py/problems/roj/<pid>/`）
- [ ] **素材源绝对路径**（`new_ROJ/problems/<pid>/`）
- [ ] **数据文件名**（⚠ 必须让 worker 先 `ls`，不要断言；已见过 `problem1.in` /
      `SNOW1.IN` / `BEAD0.IN` / `CITY1.IN` / `gwdml1.in` / `count1.in` 六种形态）
- [ ] 要求：**先读两个 SKILL.md**（`oj-cpp-competitive-style` / `python-oj-short`）
- [ ] 准入命令（可粘贴）
- [ ] ⛔ 硬纪律（单条 bash ≤ 30s、临时文件写 /tmp、不写 index.md、不 commit、
      题目目录只许 4 文件）

## 二、「待验证」区 —— **只写疑问，不写结论**

❌ **不要这样写**（断言）：
```
提示：这题应该按 D_i 升序排序
提示：追加 v_i 个 i+1
提示：图论模型是奇度点配对
```

✅ **要这样写**（疑问式探针）：
```
### 待验证 1：排序键该用哪个？
候选：D_i / D_i−C_i / C_i —— 三个都「看起来有理」。
请**从题面推导**，并**构造反例推翻其中两个**。

### 待验证 2：构造规则到底是什么？
题面写「第三个数是 2，所以我们在序列后面写 2 个 3」。
这说的是「追加 2 个 **3**」还是「追加 2 个 **4**」？
请以**题面原文 + 样例**为准，不要采信任何转述。

### 待验证 3：这题问的是什么？
候选：(a) 第 N 项的**值**  (b) last(last(N)) mod 1e9+7  (c) 其他。
**请直接读 `problem.md` 的「输出」节**，以原文为准。
```

**判据**：如果一句话我能写成「结论」，就必须改写成「在 A/B/C 中选，并构造反例」。

## 三、结构完整性检查（每张卡都加）

在任何算法验证之前，先做**不依赖实现**的输入格式检查：

- 每点 token/行数 是否恒定？（1378 就是靠「每行应有 n 个 token」发现第 10 行缺 1 个）
- 声明值与实际是否一致？（1388：题面称 1000 组/30 代，实测 20002 组/10000 代）
- 题面允许的**边界输入**数据是否覆盖？（5017：题面未排除 $a[i]=0$，但数据无 0）

## 四、验证手法选择（按题型挑 1–3 种，见 worker 定义 V1–V6）

| 题型特征 | 建议手法 |
|---|---|
| 有「看似可选」的防御性代码 | **V1 反事实**（删掉它，让测试失败） |
| 无输入 / 输出恒定 / 答案是小整数 | **V2 字面量集合**（枚举全部字面量并断言集合） |
| 题面含图 | **V3 像素测量**（纯 Python 解码 PNG，逐行测边界） |
| 矩阵 / 结构化输入 | **V4 结构不变量**（先验格式，再验算法） |
| 算法本身就是考点（贪心/MST/二分） | **V5 扰动 + 独立判定法**（如 MST 用「二分+并查集」验） |
| 任何情况 | **V6 异源暴力**（判据：能否一句话说出「我的暴力和正解其实是同一个思路」） |
| 参数空间小（900 组、100 组） | **穷举全部**，不要随机抽样 |

## 五、诚实性要求

- 若数据由被测程序生成（如 `data.py` 调 `std.cpp`）⇒ 必须在报告与 `index.md` 里
  说明「realdata PASS 只证明与 std 一致」，并指出**独立证据来自哪条异源路径**
- 若发现题面声明与数据不符 ⇒ 如实报告，**不要**替题面圆场
- 若发现缺口（题面允许但数据未覆盖）⇒ 报告并请求指示（**修代码 vs 修数据**的判据
  是「输入是否合法」）

## 附：修代码 vs 修数据的判据

| | 数据错 | 代码错（覆盖缺口） |
|---|---|---|
| 表现 | `.out` 与题面矛盾 | 题面允许的输入，代码给错答案 |
| 例子 | 3058 / 5004 / 1378 / 3161 | **5017**（$a[i]=0$） |
| 该修什么 | 修**数据** | 修**代码** |
| 纪律 | 「不要为了让错误数据通过而写错算法」 | 「不要因为数据没覆盖就放任合法输入答错」 |
