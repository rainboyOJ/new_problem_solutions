description: 独立推导并检索真正不同的候选解法，比较后给出是否值得收入题解的报告
---
题目目录：优先用用户消息里给出的路径；消息里没给就用当前工作目录。

目标：寻找当前题解之外真正不同的算法路线，完成去重、验证和教学价值评估。

硬约束：只输出候选解法报告，不修改 `index.md`、代码或过程文档。不要为了凑数量，把同一算法的容器替换、循环改写或常数优化包装成新解法。

步骤：

1. 第一阶段只读 `problem.md` 和题目约束，先独立推导候选路线，避免被现有实现锁定思路。
2. 第二阶段读取 `index.md`、`main.*`、`brute.cpp` 和 `problem-analysis-workspace/*.md`，识别已有解法的核心模型，并对候选路线去重。
3. 使用环境中提供的 `rbook-http` 能力检索项目内相似题、算法文章和代码模板，不凭记忆猜文章 ID 或模板内容。
4. 允许联网时，再查官方题解、原题来源或可信技术资料补漏和交叉验证。报告中为外部思路附来源链接；不要照搬原文，也不要把未经验证的说法当成结论。
5. 每个保留的候选解法都要验证核心转移或贪心选择，分析边界、时间和空间复杂度，并说明在题目约束下是否真的可行。必要时只在 `/tmp` 写原型或做小规模实验。

一种候选路线只有满足至少一项时，才算独立解法：

- 使用不同的核心模型或关键观察
- 采用不同的算法范式
- 具有不同的复杂度或适用约束
- 复杂度相同，但显著降低实现难度或具有明确教学价值

输出：

- 现有解法基线：概括当前正文和代码采用的核心路线
- 候选解法：逐个写核心观察、推导概要、正确性依据、复杂度、实现难点和适用约束
- 差异判断：说明它为什么不是现有解法的换皮版本
- 证据与来源：独立推导、仓库内资料或外部链接分别标明
- 推荐排序：必须收入 / 值得作为并列解法 / 适合延伸阅读 / 不建议收入，并说明教学收益和篇幅成本
- 未确认项：尚未证明、未实现或资料相互冲突的部分

没有找到可靠的新路线时直接说明，不要编造解法。
