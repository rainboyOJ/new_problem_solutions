description: 主动验证 main.*：样例、边界、随机对拍和极限压力测试，只报告不修改文件
---
题目目录：优先用用户消息里给出的路径；消息里没给就用当前工作目录。

目标：在尚未发现明确故障时，主动收集证据，判断 `main.*` 是否经得住样例、边界、随机对拍和极限压力测试。

硬约束：只报告，不修改仓库里的任何文件。临时编译产物、测试输入、对拍报告和失败数据全部放在用 `mktemp -d` 创建的 `/tmp` 目录中。

步骤：

1. 读 `problem.md`，列出输入格式、范围、多测、精度和特殊结构约束；再读 `main.*`、`brute.cpp`、`gen.py`、已有 `index.md` 和 `problem-analysis-workspace/*.md`。
2. 运行样例检查：

   ```bash
   python3 scripts/problem-analysis-tools/check_sample.py <题目目录>
   ```

3. 根据题意补充少量确定性的边界输入，包括最小规模、极值、重复值、退化结构和容易触发越界/溢出的情况。每个用例说明它在验证什么。
4. 只有 `brute.cpp` 和 `gen.py` 都可信时才进行随机对拍。显式使用 `--seed`，并把 `--report`、`--failed-dir` 指向 `/tmp`：

   ```bash
   ptool duipai --gen <题目目录>/gen.py --user <题目目录>/main.<ext> --brute <题目目录>/brute.cpp -n 200 --seed 1 --report <临时目录>/duipai-report.md --failed-dir <临时目录>/duipai-failed
   ```

5. 若生成器支持 `GEN_MODE=stress`，用接近上限的数据单独检查运行时间、内存、递归深度和溢出风险。不要把“跑完一次压力数据”当作正确性证明。
6. 缺少或不信任 `brute.cpp` / `gen.py` 时，不要临时把 `main.*` 当标准答案；标记对应验证为“未执行”，并建议先运行创建暴力或生成器的 prompt。命令中的 `main.<ext>` 要替换成目录内真实的主解文件名。

输出：

- 结论：验证通过 / 发现阻塞问题 / 证据不足，一句话说明证据强度
- 检查结果：样例、固定边界、随机对拍、压力测试逐项写“通过 / 失败 / 未执行”
- 失败证据：输入、实际输出、正确输出、seed、复现命令和相关代码位置
- 未验证项：缺少的工具、文件、约束或测试类型

即使全部测试通过，也只能写“在已覆盖范围内未发现问题”，不能声称程序已被证明正确。
