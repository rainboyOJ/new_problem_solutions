题目目录：优先用用户消息里给出的路径；消息里没给就用当前工作目录。

目标：以独立审稿人的身份判断题目目录里的 `index.md` 是否准确、讲得清楚，并达到可发布标准。

硬约束：只报告，不修改 `index.md`、代码、题面、frontmatter 或任何过程文档。

完整读取并遵循 `.agents/skills/oj-problem-analysis-reviewer/SKILL.md`。按该 skill 的顺序读取 `index.md`、`main.*`、`brute.cpp`、`problem.md`、过程文档和格式规范，并运行其中适用的确定性检查工具。

除 skill 的教学质量检查外，必须明确核对：

- 题意、约束、子任务和输入输出是否与 `problem.md` 一致
- 每种解法的关键观察、推导和正确性论证是否闭环，是否存在“显然”“容易得到”等跳步
- 正文描述、变量含义、边界处理是否与实际代码一致
- 时间和空间复杂度是否由真实循环、状态和数据结构推出
- 样例、表格和图示是否解释了关键过程，而非仅作装饰
- frontmatter、章节、`[[TOC]]`、公式和 `@include-code` 是否符合仓库规范
- 文中声称的样例通过、对拍通过、来源和难度是否有证据

输出：

- 总结论：可发布 / 修正后可发布 / 不可发布
- 必须修：事实错误、算法或证明错误、代码不一致、复杂度错误、格式阻塞
- 建议修：影响读者理解的跳步、样例不足、变量或边界解释不清
- 可选优化：表达、图示、元数据和延伸阅读建议
- 已通过：明确列出检查后确认无误的关键项目
- 未验证项：说明缺少的材料或无法确认的事实

每条问题都要给出章节或行号、影响和具体修改方向；不要用“可以再完善”这类空泛评价。
