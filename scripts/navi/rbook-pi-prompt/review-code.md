题目目录：优先用用户消息里给出的路径；消息里没给就用当前工作目录。

目标：对题目目录里的 `main.*` 做一次提交前审查，找出「这样交上去会挂」的点。

硬约束：只报告，不要修改仓库里的任何文件。可以跑样例命令、在 `/tmp` 里做临时实验。

步骤：

1. 读 `problem.md`，把约束逐条列出来：数据范围、子任务、多测、精度、输入输出格式。再读 `main.*`、`brute.cpp`、`gen.py`、`problem-analysis-workspace/*.md`。
2. 逐条核对，每条都给出「通过 / 有风险 / 未验证」和依据：
   - IO 格式：大小写、空格、换行、行尾、多测是否清空、是否多输出空行
   - 边界：最小值、最大值、空输入、单个元素、全部相同、特殊结构（链、星、二分图、稠密图）
   - 溢出与精度：`int` / `long long` 选择、中间量、取模、`eps`
   - 复杂度与常数：最坏情况真的能过吗、递归深度、反复扩容、`endl` 刷缓冲
   - 未定义行为：数组越界、迭代器失效、读入失败、未初始化变量
3. 每条风险用具体输入说明：给能触发它的最小输入，说清预期输出和可能输出。可以跑 `python3 scripts/problem-analysis-tools/check_sample.py <题目目录>` 验证样例。
4. 拿不准的标成「未验证」，不要用「看起来没问题」下结论。

输出：

- 结论：可以提交 / 有阻塞问题 / 有风险但可能过，一句话说清
- 问题清单：按严重度排序，每条含位置、触发输入、为什么错、修法方向
- 未验证项：明确列出没查的和原因
