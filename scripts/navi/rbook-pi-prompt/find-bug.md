题目目录：优先用用户消息里给出的路径；消息里没给就用当前工作目录。

目标：找出这份代码为什么错，并给出**可复现的具体证据**。

硬约束：不要修改仓库里的任何文件（`main.*`、`brute.cpp`、`index.md`、题面、样例数据都不许动）。需要临时文件时只写 `/tmp`。

步骤：

1. 读 `problem.md`（题面、约束、子任务、样例）和目录内的 `main.*`、`brute.cpp`、`gen.py`、`problem-analysis-workspace/*.md`。
2. 先确认失败形态：`python3 scripts/problem-analysis-tools/check_sample.py <题目目录>`。
3. 找反例，优先用对拍而不是盯着代码猜：

```bash
ptool duipai --gen <题目目录>/gen.py --user <题目目录>/main.cpp --brute <题目目录>/brute.cpp -n 200
```

没有 `gen.py` 或可信暴力时，在 `/tmp` 写一个只信得过的朴素暴力（直接按题面定义实现，不优化），再对拍。

4. 拿到反例后必须解释：哪一行代码被这个输入触发、为什么错、违反题面哪条约束。对拍跑不出反例时，说明试过什么、覆盖了哪些边界，不要硬猜一个「可能是这里」。

输出（只报告，不改文件）：

- 结论：错因一句话 + 置信度（高/中/低）
- 反例：最小输入、程序输出、正确输出、复现命令
- 根因：具体到文件与行号
- 修复方向：改什么、为什么，但不要替我改
