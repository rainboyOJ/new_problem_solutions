# 旧文章格式修正（显式启用）

本文件只在用户明确要求“格式修正/迁移旧题解”时读取。普通新题解和普通审稿不批量迁移旧文章；`oj-problem-analysis-reviewer` 继续负责旧文章内容审查。

允许的格式修正：

- 补齐或按规范顺序整理 frontmatter，保留所有已有有效值和日期。
- 补上 `[[TOC]]`、共同外层章节和所选布局缺失的结构。
- 当已有正文足以判断解法关系时，将章节整理为四种布局之一；正文内容和算法结论不改写。
- 只有对应代码文件存在时，才把完整代码块替换为 `@include-code(...)`；正式教学暴力应移动到独立 `## 暴力解法` 的 `### 代码`。
- 缺失部分用 HTML 注释占位。

禁止的格式修正：

- 不重写算法思路、正确性或复杂度，不删除可读正文，不强制套空模板。
- 不擅自修改具体 `tags`、`categories`、`pre`、`common`、`recommend`；除非用户明确要求，或只是整理数组格式。
- 不在不知道标题、来源、难度或代码时编造内容。
- 旧文章没有 `pre`/`common`/`recommend` 时不因迁移而强制添加；新建文章的字段要求不能倒推到旧文。

若已有文章使用旧的扁平结构，只有用户明确要求迁移时才移动到目录结构；迁移前核对引用路径和代码文件，保留原正文，并在交付中说明哪些内容仅做格式处理、哪些仍缺失。
