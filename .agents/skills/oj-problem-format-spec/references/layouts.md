# 正文布局与嵌入

## 共同结构

frontmatter 后固定写：

```markdown
[[TOC]]

## 形式化题目

<!-- 由题目解析 skill 填写 -->

<!-- 这里放一种正文布局 -->

## 总结
```

`## 形式化题目` 去掉故事背景，直接描述给定对象、约束关系和要求；不写输入输出格式或数据范围。正文不使用一级标题。非平凡题目可以在 `## 总结` 后追加 `## 图示解析`，具体图示由可视化 skill 决定。

## 四种布局

直接正解型：没有独立教学层，直接方法就是最终方法。

```markdown
## 正解

### 思路

### 代码

@include-code(./main.cpp, cpp)

### 复杂度
```

暴力到正解型：朴素方法能暴露最终优化所消除的瓶颈。

```markdown
## 暴力解法

### 思路

### 代码

@include-code(./brute.cpp, cpp)

### 复杂度

### 瓶颈

## 正解

### 思路

### 代码

@include-code(./main.cpp, cpp)

### 复杂度
```

并列多解法型：至少两个独立且值得教学的完整解法，是替代关系而非连续优化。

```markdown
## 解法总览

说明各解法差异，并指出正式主解及其 `main.<ext>`。

## 解法一：...
### 思路
### 代码
### 复杂度

## 解法二：...
### 思路
### 代码
### 复杂度

## 复杂度对比
```

子任务递进型：题面中的真实约束或子任务形成层层推进，每层复用前一层观察并移除新的瓶颈。

```markdown
## 解法路线

说明每层真实约束、上一层瓶颈、复用观察，并指出正式主解。

## 暴力解法
### 适用范围
### 思路
### 代码
### 复杂度与瓶颈

## 子任务解法：实际约束
### 适用范围
### 思路
### 代码
### 复杂度与瓶颈

## 正解
### 关键观察
### 思路
### 代码
### 复杂度
```

布局选择优先级：子任务递进型、并列多解法型、暴力到正解型、直接正解型。优先依据已核实的约束和解法关系，不按模糊的“简单/困难”决定；标题不要编造“60 分/80 分”，使用实际约束。

每个正式解法都拥有自己的 `### 思路`、`### 代码`、`### 复杂度`（递进层可用 `### 复杂度与瓶颈`）。如果解法共享代码，必须在该解法的 `### 代码` 明确写“同解法一/见上文/不单独给出”及原因。正式主解至少出现一次 `@include-code(./main.<ext>, <lang>)`，普通 C++ 为 `@include-code(./main.cpp, cpp)`；暴力代码只能放在暴力层自己的 `### 代码`。

## Markdown 细节

- 代码引用路径相对当前 Markdown 文件；不要在正文粘贴完整源代码。
- 缺少代码文件时保留 `### 代码`，用 `<!-- 缺少对应代码文件 -->` 占位；不要使用可见 TODO。
- 行内公式使用 `$...$`，展示公式使用 `$$...$$`；不等式写 `\leqslant`、`\geqslant`，不要混用 `<=` 或 `>=`。

## 可视化辅助格式

允许的形式：Markdown 表格（DP、背包、网格、样例推演）、Mermaid（流程/状态/简单树）、ASCII 文本图（小型流程和递归分支）、Graphviz dot（图、DAG、拓扑关系）、`tree_draw.py` 生成的 SVG（树、二叉树、线段树）以及确有必要的图片。具体渲染扩展以 `rbook-markdown` 为准，题目专用素材由 `oj-sample-visualizer` 生成。

放置规则：样例图放在 `## 形式化题目` 的样例附近；算法本质图放在对应解法的 `### 思路` 或 `### 关键观察`；非平凡题目的总路线图放在 `## 总结` 后的 `## 图示解析`。除该二级标题外，图示小节使用三级标题，不添加一级标题。直接输入输出、极短模拟和纯语法学习可以省略，但应在过程记录说明理由。

每个图或表必须有教学目标，图前用一句话说明展示内容，图后用 2--5 句说明观察重点；表格解释行、列和单元格含义。Mermaid/Graphviz 节点 ID 尽量使用 ASCII，中文放在 label 或正文。普通题解通常最多 1--2 个可视化块，难题最多 3 个；超过 30 个节点、`10 x 10` DP 表或搜索树 3 层时只展示关键局部，避免装饰性图片。

本地 SVG 用标准相对路径引用，例如 `![线段树结构图](./segment-tree.svg)`；推荐文件名为 `tree.svg`、`binary-tree.svg` 或 `segment-tree.svg`。DP 题的最终文章必须在对应解法思路中有小规模状态/转移表，并在表格前后解释观察内容。
