# 主 agent 监督、验收与回收协议

主 agent 开工前必读。Herdr 目标使用本批记录的 pane ID 或唯一 agent 名，不依赖 UI 焦点。示例尖括号需要替换，语法以本机帮助为准。

## 状态与巡检

用 `git rev-parse --git-path rbook-batches/<batch>` 定位本批本地状态目录，建立 `state.json` 保存任务队列和槽位。它用于主 agent 恢复监督，不作为题解提交；子 agent 只写自己题目下的交付报告。

最少记录：

- workspace、主 pane、每个 worker 的 tab/pane、agent 名、启动代次、当前 `oj/id` 和模型。
- 任务状态：待分配、执行中、待验收、返修中、恢复中、等待用户、通过、异常；槽位状态：空闲、占用、隔离。
- 分配时间、最近有效活动时间、未返回命令的开始时间、连续临时错误的首次时间、干预时间、自动重启次数。
- 最近输出对照、已处理 DONE 所属分配/返修轮次、交付报告路径、验收和恢复记录。

派题、返修、干预、验收和回收后保存。开始时记录原有工作区改动，不能把别人的变更误当作当前子 agent 产物。恢复监督先核对实时 agent、进程和文件，不能因旧状态而重复派题。

每 30 秒检查所有活动槽位：

```bash
herdr agent get <worker-name>
herdr agent read <worker-name> --source recent-unwrapped --lines 120
```

必要时读更多行并查看 `herdr pane process-info <pane-id>`；agent 消失后用 pane 读取现场。一个槽位的工具错误不得终止整轮巡检。派题不带 `--wait`；耗时测试异步启动后继续巡检，验收分段进行，每段后检查巡检是否到期，不能一直阻塞在某题上。

### 活动判定

- 新的有效正文、真正新增的工具调用、正常工具结果或可识别的命令进度计为活动。重绘、滚动、光标、动画、计时、token 计数变化不计；不能仅对整屏做 hash 就重置计时。
- 相同错误、重复请求重试、反复“等待中”不算有效进展；503 等错误结果不是正常工具完成。
- 派题时建立基线，连续 300 秒无有效活动就干预。单条命令一直等待返回且无有效进度也适用；能观察到真实进度则允许继续，不把所有超过 5 分钟的任务一律中断。
- 401 等明确认证错误立即介入；503 等临时错误允许重试，但从首次连续失败计时，300 秒后介入。确认请求恢复并继续工作才清除错误计时，重试日志不能延期。
- Herdr 的 idle、done、unknown 只是信号，不证明题目完成。blocked 时读内容：普通解题疑问由主 agent 指导；超出现有授权的审批转达用户，记录为等待用户，其他槽位继续。
- 5 分钟无进展判断只用于应当推进的执行中或返修中任务；已提交 DONE 等待验收、等待主 agent 指令或等待用户审批时暂停此判断，不能把遵守等待要求误判为卡死。主 agent 发出继续指令后重新建立活动基线。

## 打断、指导与恢复

1. 保存现场、当前任务和测试信息，发送 Esc：

   ```bash
   herdr agent send-keys <worker-name> esc
   ```

   下一轮巡检读取响应。仍陷于原操作且需要时再发 Esc；不要无差别连续按键，避免已回到空闲态时触发其他 UI 操作。

2. 恢复可交互后，用 `herdr agent prompt` 发送具体指导，例如取消挂起命令、给测试设超时、检查已有结果、拆分测试或修正算法。明确下一步，保留已有工作；记录干预并观察是否真的取得进展。
3. 认证失败时，重复请求或重启本身不能修好凭据。可在用户已允许的模型清单内调整模型并记录原因；无可用模型则标记异常，报告所需认证修复。不要打印或修改密钥，不换用清单外模型。503 干预后也先检查是否恢复。
4. 打断后最多观察两个巡检周期（60 秒）。无法恢复正常交互，或确认原操作无法继续，就结束旧 pi；确认进程清理后于同一 pane 启动新 `pi --no-session`。恢复 prompt 给出题面路径、已改文件、失败现场、测试证据和下一步；新 agent 自行核对文件，不假设上次已完成。
5. 每题从初次分配到最终结论最多自动重启 2 次（至多初始实例加 2 个替代实例）；换槽位或模型、返修都不清零。超过上限仍无法继续就标记异常、记录原因，安全清理后派其他题。重复无进展的指导不能无限重置计时：未出现真实进展就进入重启或异常流程。

## DONE 和验收

`DONE <pid>` 中 pid 是题号，不是进程 ID，例如 `DONE P11230`。内部用 `oj/id` 标识，同号跨 OJ 由当前槽位分配区分。

只接受当前 agent 在本轮分配或返修提交后新增的独立完成行，并核对 `batch-handoff.md` 的题号、批次、分配代次及实际文件。不能因历史中有 DONE、prompt 示例包含 DONE 或工具日志打印 DONE 就回收；输出截断无法确认时读更多历史或向子 agent 核实。同一完成行只处理一次。

主 agent 将题目标为待验收，要求子 agent 保持可交互且停止修改，读取实际题面、题解、全部引用代码和报告，使用 `oj-problem-analysis-reviewer` 独立审稿：

1. 题意、约束和分档与来源一致；推导、正确性、边界、复杂度清楚，引用文件和图示存在且相符。
2. 真实分档都有解释，合并有依据；各算法代码齐全，适用范围明确。独立主流满分多解法都有正文、代码与验证。
3. 复核所有交付算法的 C++17 `-Wall -Wextra` 编译，要求无编译错误和警告，重跑满分解法样例和关键边界；部分分程序只用符合对应限制的数据，不能把范围外失败误判为 bug。
4. 对拍依据 writer 的 verification reference：基线可靠、生成器规模适合、各算法有实际结果；适用时默认 300–500 组。检查日志，并用针对关键风险的小规模测试独立复核。不适用项说明替代验证方式，未运行不能伪称通过。
5. 运行以下检查；质量检查脚本存在时按 reviewer 要求执行，核对 frontmatter、updated 和引用：

   ```bash
   python3 scripts/problem-analysis-tools/check_problem.py problems/<oj>/<id>
   python3 scripts/problem-analysis-tools/check_relations.py problems/<oj>/<id>
   ```

不通过就发送可执行返修清单：文件/章节、问题、原因、通过条件；保持同一子 agent、题目和 tab。标为返修中，新的 DONE 后重新验收。材料缺失、凭据不可用等问题无法自行解决时记录异常，不能为了清空队列降低验收标准。

每题验收通过后才回收槽位。所有写手停止修改后，主 agent 统一运行 `npm run check:content`。发现本批问题则重新派该题返修并验收，然后重跑。原有无关错误单独汇报，不改其他题，也不声称全库检查通过。

## 退出旧 pi 与复用原 tab

回收和超时恢复都保留原 tab/pane：前者旧题已验收，后者仍接续同题并增加重启计数。

1. 保存交付或失败记录，确认目标是本批占用的 pi。优先在可交互状态使用 pi 支持的退出操作；可发送 `ctrl+c` 后读状态，按实际行为决定是否需再发一次。一次 Ctrl+C 可能只清空输入或中断，不能视为退出成功。
2. 用 pane 输出和 `process-info` 核实旧 pi 及其工具子进程已退出、shell 回到前台。长命令可能残留，不能只看 Herdr 标签变 idle 就启动新写手。
3. 正常退出无效时，只对核实属于本槽位旧任务的进程做定向终止，先 TERM、确认后必要时 KILL；保留 shell。核实 PID 和归属，不能用 `pkill pi` 或模糊命令行批量杀进程，不误杀主 agent、其他批次或 Herdr。
4. 无法确认旧写手和命令已停止就隔离槽位并报告；不得在那里启动新 pi，也不得把同题交给另一槽位造成双写。其他健康槽位继续。
5. 确认 shell 可用后，用新 agent 名和启动代次在原 pane 执行 `herdr agent start ... -- --no-session --model ...`，读取成功结果后再发下一题或恢复任务书。旧屏幕输出仅是历史，不属于新分配。

批次结束保留 workspace 和 tab 供用户查看，不自动关闭。最终报告区分逐题通过、异常、待用户处理及全库内容检查结果。

若所有槽位都已隔离或等待用户，剩余题目记为未执行并汇报阻塞原因，不新增 workspace/tab 绕开并发限制，不把队列等待误报为执行失败。
