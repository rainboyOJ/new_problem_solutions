# agy 外部评审委托

agy 是 Antigravity CLI，本机已登录（`~/.gemini/antigravity-cli/`）。它在这里的角色不是"另一个 pi"，而是**一支独立的外部意见**：pi 负责准备材料、给出验收标准、复核结论；agy 只负责给判断。

先看 `references/cli-contract.md` 里本机实测的 CLI 行为再动手，那份记录里有几个和官方文档式描述不一致的坑。

## 何时用、何时不用

用 agy：

- 需要**跨模型**的独立意见（agy 可跑 Gemini / Claude / GPT-OSS，见下），便于发现 pi 自己的盲点；
- 单点判断型任务：这段证明有没有跳步、这个贪心为什么不成立、这份题解的复杂度写错没有；
- 用户明确要求"让另一个模型看看"。

不用 agy，改用 pi 自己的 `subagent`：

- 需要**改文件**并保留可审查的 diff（pi 的 worktree 机制更可控）；
- 任务要跑本仓库的测试、评测、对拍（这些是 pi 的活，agy 拿不到这些能力，见权限一节）；
- 需要多轮工具链协作（读文件 → 改 → 测 → 再改）。

## 两个入口，按场景选

**在 herdr 里跑 pi（`HERDR_ENV=1`）且工具列表中有 `agy_tab` 时，优先用它**：agy 会在一个独立 tab 里跑，用户能实时看到它调了哪些工具、想了什么，结束后 pi 拿到结论，成功自动关 tab、失败保留现场。参数：`prompt`（必填）、`model`、`effort`、`write`、`cwd`、`label`、`timeoutSec`。

**没有 herdr，或要批量跑**时用 `scripts/agy-ask.sh`，不要手写 `agy` 命令行。下面命令里的路径相对仓库根（`.agents/skills/agy-delegate/`）。它兜住了三个实测坑：`status=SUCCESS` 但回复为空的假成功、stderr 污染 JSON、缺超时导致偶发上百秒挂住。

```bash
.agents/skills/agy-delegate/scripts/agy-ask.sh "提示词"
```

常用参数：

| 参数 | 作用 |
| --- | --- |
| `-m <id>` | 指定模型，见 `agy models` |
| `-e <level>` | `low`/`medium`/`high`/`xhigh`/`max`，只对部分模型有效，无效时直接报错 |
| `-P <time>` | 传给 agy 的 `--print-timeout`，默认 `180s` |
| `-T <sec>` | 外层 `timeout`，默认 240 |
| `-c <cid>` | 续接上一次会话，用于多轮追问 |
| `-w` | 允许 agy 自己跑命令、改文件（见下面权限一节） |

退出码：`0` 成功、`3` 工具被权限拒绝、`4` 空回复、`5` agy 报错、`124` 超时。**只有 0 才代表拿到了可用的回复。**

## 权限：默认只读，写操作要显式开口

本机实测的权限边界（`agy` 1.4.7）：

- 不带 `-w` 时，agy 能用 `view_file`、`grep_search`、`list_dir` 这类只读工具，**不能** `run_command`；
- 想让它跑 `git diff`、`sed` 切片、跑脚本，必须 `-w`（内部是 `--dangerously-skip-permissions`，会批准**全部**工具，包括写文件）；
- 官方文档常说的 `settings.json` 里 `permissions.allow` 白名单，**在这个版本不起作用**：agy 退出时会重写 `settings.json` 并把该键丢掉。别在这上面浪费时间。

因此：

1. 默认走只读，并且在提示词里明确写"不要读文件、不要运行命令，只基于我给的内容判断"，然后把**要审的片段内联进提示词**。实测只读模式让它自己去看一个 200 行文件，它会试图 `sed`/`head` 切片然后被拒（退出码 3）。
2. 只有任务确实需要它自己探索（多文件、要跑只读命令）时才加 `-w`，并且：先确认 `git status` 干净或改动可辨；任务里写明"只读分析，禁止修改文件"；结束立刻 `git status --short` + `git diff` 复核。它对"禁止修改"的遵守**不能当作保证**。

## 三种委托角色

### 一、思考与反驳

给它一段结论和它依赖的前提，要求它只找漏洞，不许重写：

```bash
S=.agents/skills/agy-delegate/scripts/agy-ask.sh
timeout 400 $S -m gemini-3.8-flash-high "只读任务, 不读文件, 不运行命令。下面是某题解的推理链, 请只指出其中不成立的步骤, 不要重写。
输出格式:
结论: 成立/不成立
问题步骤: <引用原文片段> 或 无
为什么: <一句话>
反例: <最小反例或无>

<把推理链贴进来>"
```

### 二、评审（reviewer）

把验收标准交给它，别让它自己猜标准：

```bash
timeout 500 $S -m gemini-3.8-flash-high "只读任务。按下面清单审查这段题解, 每条给 通过/不通过 + 一句理由。
清单: 1 结论是否正确 2 关键步骤有无跳步 3 复杂度是否与代码一致 4 是否解释了公式作用
输出: 逐条要点 + 最后一行 '总评: 通过/不通过'

<材料>"
```

### 三、交叉验证

已经有一版结论，要独立复算：

```bash
timeout 400 $S -m claude-opus-4-6-thinking "只读任务。独立推导下面的问题, 不要参考我给的答案; 最后再和我的答案对比并指出差异。

<问题>"
```

模型选择：机械核对用 `gemini-3.8-flash-low`（快）；需要真推理用 `gemini-3.8-flash-high` 或 `claude-opus-4-6-thinking`；`--effort` 只对支持它的模型有效，`claude-opus-4-6-thinking` 会直接拒绝 `--effort`。`agy models` 是权威列表。

## 延迟与预算

实测（本机、网络正常时）：

| 场景 | 耗时 |
| --- | --- |
| 一句话问答 | 3–6 s |
| 带一小段材料的判断题 | 19–75 s |
| `-w` 下按路径自行读文件 | 8–60 s |
| 续接会话的追问 | 曾出现 150 s |

结论：**每次委托都当它可能是分钟级**。提示词里把范围收窄（只审一节、只判一句），别一次让它审整篇文章。需要多轮时用 `-c <cid>` 复用会话，别重复灌同样的材料。

## 硬规则

1. **不采信 agy 的结论本身**。它说"通过"就自己再核一遍关键点；它说"这里错了"就去找反例确认。实测它能发现真问题（例如把 `f \le D + 2\max h` 直接改写成 `f \le D + \max h` 的系数丢失），也会给出瞎猜的理由，两者外表一样自信。
2. **`structured_output` 不可信**。用 `--json-schema` 时它可能把字段填成"任务复述"而不是答案（实测 `ok: true` 而正文结论是 false）。判定以 `response` 正文为准，结构化字段只当辅助。
3. **不要让 pi 和 agy 同时改同一份文件**。agy 的写入没有 diff 审查环节。
4. **不要把密钥、token、私有 URL 贴进提示词**。提示词会进 agy 的会话记录（`~/.gemini/antigravity-cli/conversations/`）。
5. **每次委托都留证据**：把调用命令、模型、会话 id（脚本打印在 stderr 的 `cid=`）、agy 原始结论、pi 的复核结果一起写进回复。凡是要落实到文件或提交，只写 pi 自己验证过的结论。

## 报告格式

委托结束后按这个结构回复用户：

```text
委托: agy <模型> — <一句话任务>
耗时: <s>, 会话: <cid>
agy 结论: <要点>
pi 复核: 成立 / 不成立 / 部分成立 + 依据(反例、验算、命令输出)
已落实: <改了哪些文件, 或"未改文件">
```
