# 暴力解与 `brute.cpp`

## 何时需要

算法题通常要有完整的同输入输出格式 `brute.cpp`，用于展示最直接的模型、暴露瓶颈和作为小数据对拍基线。以下情况可以跳过正式暴力层：

- 最终方法就是直接输入输出、固定规则模拟、固定子串检查或一次公式计算；
- 不存在有教学价值的优化步骤，单独暴力只会复制 `main.cpp`；
- 题目是明确的语言/语法学习文章。

跳过时不创建或强制要求 `brute.cpp`、`gen.py`，不写 `## 暴力解法`，并在 `02-observation-and-model.md` 或 `03-solution-derivation.md` 说明原因，在 `04-correctness-and-edge-cases.md` 说明样例/手工验证。脚手架已经生成的空 `brute.cpp` 可保留为本地材料，但不在正文冒充教学层。

## 实现规则

- 新建或需要改进时，代码必须是可编译的 C++17 程序，输入输出与正解一致，遵守 `oj-cpp-competitive-style`。
- 复杂度允许很高，但要明确是小数据/验证代码；正确性不确定时记录不确定性，不宣称可可靠对拍。
- `brute.cpp` 不替代 `main.cpp`，正式正文应在独立 `## 暴力解法` 的 `### 代码` 引用它。
- 新题默认不额外创建 `brute_01_style.cpp`。已有稳定暴力不因风格偏好重写；若旧文确实需要教学补充，可添加 `brute_01_style.cpp`，放在原暴力 include 后的折叠 `<details>` 中，不能替代默认基线。

## 01 序列 / 选择序列优先

当问题可理解为每个元素“选/不选”、每个位置选择一个值/方向/操作、搜索每层选择下一步，或从左到右决定跳过/使用时，优先用普通递归枚举选择序列：

```text
choose[i] 表示第 i 个对象的选择
dfs(dep) 枚举 choose[dep] 的所有合法取值
生成完整 choose[1..n] 后在叶子 check()
合法时 calc_answer() 或统计方案并更新答案
```

01 序列的教学重点是“先生成、后检查”：`dfs(dep)` 只填写当前选择并递归到下一层，`dep == n + 1` 才检查完整序列。不要用携带 `last_end`、`cnt` 等剪枝状态替代完整选择序列，除非题目本身更适合另一种直接模拟、BFS、公式或小数据 DP。多分支选择仍保持“每层一个决策点、枚举该点全部合法选择”的结构。

若重复状态使小数据也无法测试，可以保留选择递归并增加简单 `memo`/`vis`；不要把暴力伪装成高度优化的正解。文件头应注明“小数据暴力”和选择序列含义。

正文解释 01 序列时，说明递归层含义、每层选择、`choose[]` 如何记录、叶子 `check()` 检查什么、如何统计答案、为何覆盖所有小数据方案以及最终解法移除了哪个瓶颈。
