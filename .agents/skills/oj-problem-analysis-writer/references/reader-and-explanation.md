# 读者与讲解规范

本文件是 writer 与 reviewer 共用的内容标准。writer 在组织正文前读取，reviewer 在评价可读性和推导链条前读取；两者不另维护一份风格规则。题解的章节、元数据和渲染语法仍由格式与 Markdown skill 负责。

## 读者与目标

默认读者已经学会题目涉及的基础算法，但不会从这道题的条件出发找到解题思路。文章的目标是让他**复现思路的发现过程**，并且易读、易懂、心智压力低。用户明确指定其他基础或学习目标时，以用户要求为准。

把篇幅用在本题的观察、选择和建模上。可以简短提醒必要的算法性质，不重讲整套 DFS、背包或最短路教程；与当前难点无关的排序读法、语法细节也不展开。算法正确、代码齐全并不代表文章已经达到教学目标。

## 组织讲解的两条路线

“复现发现过程”是共同目标，不是与下面两条并列的第三种风格。根据题目的真正难点选择路线，必要时局部结合；它们描述思路内部的讲法，不替代格式 skill 的四种正文布局。

| 路线 | 适用情况 | 讲解重点 |
| --- | --- | --- |
| 逐步建模 | 核心难点是把题目转成背包、最短路等通用模型 | 从题目条件和直接做法的困难出发，解释哪个观察提示了模型，再对应状态、点边或决策，并核对转换前后的合法性与目标。 |
| 骨架展开 | 没有贴切的通用模型，或先看全貌更容易理解一串操作 | 先用几步给出可理解的算法骨架，再逐步补上每个选择的来源、直觉和正确性；骨架里的术语当场解释，不能留下一串陌生名称。 |

两条路线都要交代“为什么想到这一步”。仅仅验证一个已经给出的算法正确，不算完成发现过程。先给骨架也不等于把未经解释的答案当成读者已知条件。

优先走通一条主线。其他方案只有独立教学价值时才展开，不按代码文件数量堆解法。朴素做法、失败尝试和特例只在能暴露下一步的需要时保留，不强制每篇都从暴力开始，也不虚构灵光一现或机械套用问答格式。

## 控制读者需要同时记住的信息

- **先有需要，再有定义。** 先指出当前要解决什么困难，再引入所需对象；先用普通语言解释用途，再给名称、符号和公式。不要在开头列出后文尚无用途的整套记号。
- **每段推进一个关键点。** 给出足以支撑它的理由，再承接下一步；需要同时引入多个对象、转换视角或处理多个分支时拆段。拆段必须降低依赖负担，不能只是把同一段形式证明换行。
- **沿用例子和记号。** 优先让同一个小例子贯穿推导，图、正文、公式中的点名或状态名一致。需要反例或新例子时，先说明旧例子无法说明什么。
- **公式用于压缩已经讲清的意思。** 不连续抛出多个集合、函数和不等式，让读者自行拼出它们与题目的关系。
- **解释一次就够。** 同一结论不要依次在直觉框、定理、证明、样例和总结中完整复述。重点放在关键选择，常识性操作简述即可。

## 直觉与证明的安排

正文先给例子与直觉，再给推动下一步所需的简短理由。允许读者先接受部分结论，再到后文、折叠块或选读中展开证明；在使用处说明这是待解释的结论，并给出可定位的证明入口，不把“后面再证”当作省略证明的借口。

决定正确性的结论必须已经核验。例子说明现象，图示帮助理解，二者都不能代替一般性论证；不能把尚未证明的猜想润色成确定结论。读者已掌握的标准算法性质可以明确引用，不必重新证明。

禁止把多个证明目标塞进一个超长段落。复杂证明按实际依赖拆成连续的小步：每步先说明当前要解释什么，用直觉或具体情形帮助定位，再给出短理由；新结论成立后再进入下一步。优先复用同一张图逐步说明，完整的形式化细节可以后置。必要性、充分性和边界分别交代，不用一个样例同时充当三者的证明。

例如，“核心连通，所以自然想到逐轮剥叶”跳过了删除顺序为何最优。应先解释某个点不选会造成什么距离问题，再说明这个条件如何引出剥叶。发现过程必须建立在可核验的理由上，不能只增加几个引导问句。

## 图论结论的图解

正文中讲解的图论定理，以及决定解法的路径、连通性、割、树结构等关键结论，**必须有对应图解**，使用 SVG、Mermaid 或 Graphviz。仅调用读者已掌握的标准图算法、不展开其定理时，不要求重画整套算法教程。

图要展示结论成立的关键结构：例如被删点分开的两侧、必须经过的路径、交换前后的边。只画一张完整样例树而不对应所讲结论，不算完成图解。

图前交代看什么，图后指出哪条路径或关系支持当前推理；颜色、标记和长度要有明确含义。多个证明小步可以引用同一张图，必要时用同图的分步标记或少量局部图。**不强制每个证明段落各生成一张新图**，避免读者反复适应新编号和新布局。素材制作与规模控制见 [visualization.md](visualization.md)。

## 语气

像老师与学生一起分析当前困难：平实、具体，承认哪里需要新观察。可以提出读者此时真正会有的疑问，但不把每句话都改成自问自答。

不用“显然”“自然想到”“不难发现”替代关键理由，不以“很简单”“只需套模板”评价读者的困难。不堆叠“本质”“核心”“优雅”等评价性词语；直接说题目哪个条件允许了哪个动作。

写完后，沿正文主线检查：读者能否在每个关键转折说明当前困难、选择这一步的理由，以及它解决了什么；是否存在只靠回翻记号表或连续阅读长证明才能接上的部分。若存在，优先重排依赖关系，再考虑补解释，不能一律靠加长文章解决。
