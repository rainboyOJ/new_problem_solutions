# 前置知识访谈

## 先定位卡点，再确认必要基础

先读用户的解释，找出他已经能推演的部分和第一个无法解释的动作。用户已经说清“会普通 Trie，不懂两棵树怎样配合计数”时，直接把配合计数作为教学入口；不要重新询问是否学过 Trie。

卡点不明时，一次只问一个能定位断点的问题，例如“你能理解更新了哪个位置，还是不清楚为什么此时更新？”随后形成内部依赖图，只确认解决这个断点必需且尚不明确的知识。内部依赖图不是页面必须依次展示的课程目录。

例如同一道题的 AC 解法与普通 Trie 解法，可能需要不同前置知识。用户指定普通 Trie 解法时，不要沿用另一份代码的 AC、fail 树、树状数组问卷。

知识自评通常采用下列层级，但每次只询问一项：

- 没学过：需要从本题所需的最小定义和例子开始。
- 听过：需要重新建立含义，再用一次小过程确认。
- 会模板：需要补状态含义、条件来源、不变量，以及模板如何映射到本题。
- 理解原理且能推演：简短复盘，重点讲本题新增的关系。

避免把“会树状数组”当成“会所有树状数组用法”。若目标使用差分区间加、单点查，就询问这个具体能力。若用户已经明确掌握，不再逐个追问 lowbit 等无关细节。

## 一次一个问题

每轮先承接上一答，再问当前最关键的一个问题，给出易区分的选项或允许自由描述。知识自评无需推荐用户选择“理解”；推荐的是后续教学安排。

示例：

> 你对“DFS 序把子树映射到连续区间”熟悉到哪一步？
>
> A. 能解释并自己求出区间。
> B. 听过，但希望看图走一遍。
> C. 没学过。
>
> 我建议教程保留一个短编号演示，用它接上后面的子树操作；你的回答决定需要讲多细。

这是一次问题。不要在同一轮再顺带询问离线排序、语言水平和网页风格。

## 必要时用小预测题确认

用户对已有知识的描述含糊、只会照抄模板，或某个前置概念决定后续能否理解时，可用一道低负担题代替继续问术语。陌生过程不先考：先展示对象与操作，完整演示一次，再预测后续动作或相似小例。

- 提供小规模、足够作答的状态，询问下一步或某个条件是否成立。
- 只考已经声称掌握的知识，不拿本题尚未讲解的关键观察作入门考试。
- 要求必要的简短理由，以区分猜中与理解；用户不想测试时保留其自评，注明尚未验证，继续教学。
- 答错时定位具体缺口，调整教学粒度，不批评、不无限追问同一知识。

例如用户声称理解 fail 链，可给出模式串 `abc、bc、c` 和文本 `abc`，问最后一位结束了哪些模式。用户只会 AC 模板时，这比问“是否精通 AC”更有意义。

## 何时停止访谈

当关键依赖的掌握程度已经足够决定讲解粒度，就结束。不要等到“所有知识都验证通过”才允许制作教程。

汇总路线时，清楚指出：

- 指定的题目与源码文件；
- 当前卡点、首屏核心图，以及学生第一次要看懂的动作；
- 用户已掌握的部分如何简讲、连接到本题；
- 哪些前提必须先简短说明，哪些基础与完整推导按需展开；
- 是否需要先演示单个对象，再过渡到目标实现，以及两者如何对应；
- 本题真正新增的推理与关键代码如何一一对应；
- 三类验收要用户独立做什么。

只进行一次必要的路线确认。若用户已确认这些内容或明确要求按现有方案开始，不重问。不要把发布、配色、动画速度等问题捆成额外审批；根据用户偏好和常规设计判断实现即可。

## 参考案例的正确用法

P14363 的一次实际访谈中，用户理解 AC、树状数组区间加单点查和离线排序，但对 DFS 序只“听过”。适合压缩 AC 通用构建、BIT 模板和排序基础，重点演示子树连续区间，并详细推导本题的字符对、覆盖条件、fail 祖先与子树关系。

同题的双 Trie 解法中，若学生会普通 Trie，却混淆“规则还是询问在走”，入口应是两棵可操作的 Trie 和一条询问的完整计数过程，再解释 DFS 怎样共享行走路径。无需先复习所有字符串算法。

这些是定位卡点的示例，不是对所有用户的默认画像。不要固定询问这些算法，也不要固定八关。双 Trie、激活与撤销不适用于所有题目。
