# OJ 纯 SVG 题解配图

直接创作可独立打开的 `.svg`。图的作用是让读者看见决定解法的关系；采用论文插图的克制表达，同时保持中文题解的可读性。用户指定的风格、位置与范围优先。

## 先确定要画什么

读取当前题解、相关代码和必要的题面或样例，沿用正文符号。先用一句话确定这张图要解释的结论，再选择能展示它的最少对象。

- 区间与前缀和：用边界、切点和覆盖范围表达关系，明确元素位置与切点位置的区别。
- 图与树：画决定结论的路径、边或局部结构，保留必要的上下文，不为美观改变连通关系。
- DP 与状态转移：突出目标状态及其依赖，说明箭头方向，避免把整个大表缩成不可读的图。
- 操作前后：用相同尺度、方向和符号并列呈现，必要时用（a）（b）区分。

图示例子不能代替一般证明。不要将仅在样例成立的关系画成一般规律，不凭空添加节点、边、数值或不变量。

## 视觉约定

默认样式如下，数值是起点，可按最终展示尺寸调整：

| 元素 | 默认处理 |
| --- | --- |
| 背景 | 白色，不加装饰性外框 |
| 正文与主结构 | 深灰 `#222222`，线宽约 1.2–1.6 |
| 辅助线与次要标记 | 中灰 `#777777`，保持可读对比度 |
| 区域填充 | 白色或很浅的灰色 `#f4f4f4` |
| 强调 | 优先线宽、虚实和局部标注；需要颜色时默认只加一种低饱和强调色 |
| 字体 | 中文使用可用的 CJK 字体，数学字母可用衬线斜体 |
| 字号 | 以正文最终显示宽度为准，常用标签约 16–20 SVG 单位，避免缩放后变成小字 |

- 默认不使用渐变、阴影、发光、立体效果、表情、装饰图标、大面积饱和色或卡片式包装。
- 不放宣传式大标题、横幅、重复结论框。解释通常放在正文图注里；图内只保留理解结构所需的短标签和公式。
- 矩形默认直角，圆角仅在表达对象性质或用户要求时使用。不要把所有数学对象套进文本框。
- 强调色必须有明确语义，且不用颜色作为唯一辨别方式；灰度打印后仍能理解。
- 空间关系应诚实：等和不意味着等长；示意长度不按比例时要说明。数字坐标轴与数值图形不得随意改变比例。
- 留白用于隔开语义层次，不为了填满画布加入无关内容，也不为了左右对称增删信息。

## 直接编写 SVG

使用 `svg`、`g`、`rect`、`line`、`path`、`circle`、`text`、`tspan`、`marker` 等原生元素。简单图直接写文件；重复结构可用短 Python 脚本计算坐标并输出原生 SVG，但不引入其他绘图 DSL 或渲染框架。

1. 先安排对象与标签的位置，再连接线条。共享基线和间距，优先短直线；折线、曲线按拓扑和避让需要选择，不把某种连线风格当成数学要求。
2. 箭头只用于方向、依赖或操作；区间覆盖通常用端点刻度和横线，不用箭头暗示流程。连线不得穿过无关节点或文字。
3. 按文字实际宽度安排空间。标签过长先缩短、分行或扩展布局，不反复缩小字体迁就画布。
4. 下标、上标用 `<tspan>` 的字号和基线控制；不要用形似字符代替数学字母，例如用希腊字母充当下标 q。SVG 文本不会自动排版 LaTeX。
5. 保持文件自包含：给出 `xmlns`、`viewBox`、合理的 `width` / `height`，用白色背景保证嵌入深色页面时可读。禁止内嵌位图伪装成 SVG，不依赖外部图片、字体请求、脚本或 `foreignObject`。
6. 添加简短的 `<title>` 和 `<desc>`，描述图意；正文用有意义的替代文本引用。转义文本里的 `&`、`<` 等 XML 特殊字符。

可参考 [三段等和示例](assets/prefix-sums.svg)：三段采用不同示意长度，覆盖线从同一起点延伸到各切点，表达累计范围；仅供样式与标注参考，不作为所有题目的固定模板。

## 输出与嵌入

- 默认保存到当前题目目录的 `assets/<meaningful-name>.svg`，沿用已有合理命名。SVG 本身就是可维护的源文件，不额外生成无用的中间格式。
- 用户要求加入题解时，在相关推导附近引用 `![具体图意](./assets/<name>.svg)`。图前交代看什么，图后用一两句指出关键关系；不要在图内与正文重复整段解释。
- 修改项目 Markdown 时遵守项目已有语法与格式规范。仅要求绘图时不擅自重写正文。
- 修改已有图时尽量保留文件名和有效引用；用户没有要求替换时，不删除其他图。

## 交付前检查

先核对语义，再检查外观：

- 区间端点、开闭范围、切点、箭头方向、公式、样例值是否与正文一致？
- 读者能否区分一个对象的值与多个对象累计的值？颜色、长度或位置是否暗示了不存在的性质？
- 用 XML 解析器检查文件有效，检查所有本地资源与 Markdown 引用确实存在。
- 用可用的浏览器或 SVG 渲染器生成预览并实际查看；检查文字溢出、遮挡、线条压字、箭头端点、下标和画布裁切。至少按正文预计展示宽度看一次，不能只看放大后的图。
- 修复后重新生成预览，确认最终版本。没有可用预览工具时如实说明，不宣称已完成视觉验收。

本机可以用以下命令进行基础检查和预览，替换实际路径；临时截图放 `/tmp`，不加入题目资源：

```bash
timeout 10 python3 -c 'import sys, xml.etree.ElementTree as E; E.parse(sys.argv[1]); print("XML OK")' path/to/figure.svg
timeout 20 chromium --headless --disable-gpu --no-sandbox --hide-scrollbars --window-size=1000,600 --screenshot=/tmp/figure-preview.png file:///absolute/path/to/figure.svg
```

交付时简述图解释了什么、文件位置、是否已嵌入正文，以及实际完成的验证。不要把 XML 合法等同于数学正确或排版正确。
