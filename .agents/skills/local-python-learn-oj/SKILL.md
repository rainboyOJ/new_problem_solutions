# Python OJ 学习入口

将 Python 学习目标交给 [`oj-problem-workflow`](../oj-problem-workflow/SKILL.md) 统一编排。本 skill 只补充语言与教学适配，不覆盖算法布局、评测方式和阶段完成标准。

## 进入方式

1. 从用户请求确定题目目录、目标语言和交付范围。完整 Python 学习题解包括实现、Python 知识映射和文章；只要代码或解释时不自动扩大。
2. 把“Python 实现＋Python 学习内容”作为当前任务目标，读取 workflow 并一次性进入。已有规划、代码和笔记照其恢复规则复用。
3. workflow 在实现与教学材料阶段使用已安装的 `python-oj-learn`，在写作阶段使用 writer。本入口不再单独执行一轮“先写程序、再重新规划写文章”。若当前已在 workflow 内，只应用下文适配后返回当前阶段，不再次进入总入口。

## Python 实现与教学

`python-oj-learn` 位于已安装技能目录，当前常用位置为 `~/.agents/skills/python-oj-learn/SKILL.md`；先确认实际位置再读，不假设必然存在。缺失时报告，并按可用材料继续能完成的工作，不编造本地笔记来源。

- planner 决定算法与分层关系；`python-oj-learn` 负责相关笔记检索、Python 表达和教学映射。不要因为换语言重复推导已可靠的算法。
- 知识库查找与引用遵循 `python-oj-learn`。只使用实际读取的文章，缺少笔记时如实说明，不能伪造链接。
- 代码文件使用 `main.py`；确有教学或验证价值时才添加 `brute.py`，额外算法按规划独立命名。仅 Python 任务不自动创建 C++ 文件，也不删除已有 C++ 实现。
- 用户要求教学短变体时使用 [`oj-python-style`](../oj-python-style/SKILL.md)；外部旧资料中的 `python-oj-short` 对应这个现有 skill。展开式讲解不强制压行。
- 保持算法正确性和渐近复杂度，核对 Python 的递归、对象内存和运行开销。短变体的 TLE/MLE 如实记录，不能作为正式可提交解法通过的证据。
- 学习笔记的新文章建议不属于当前题目的交付，不自动创建或修改用户的博客。

## 验证交接

本仓库实际评测统一使用 [`oj-judge-and-stress`](../oj-judge-and-stress/SKILL.md)，由 workflow 的验证阶段执行。样例、边界及必要对拍分别留下证据；基线只在共同适用范围比较。不要沿用旧的 `duipai.py` 调用或自写评测器，也不要把风格检查当作正确性验证。

是否实现暴力由算法价值和验证需求决定，不按语言强制生成。没有暴力时说明替代验证方式；未执行测试时明确状态，不声称通过。

## 文章适配

writer 消费算法规划、实际实现、验证证据和 Python 教学材料，正文骨架仍以 [`oj-problem-format-spec`](../oj-problem-format-spec/SKILL.md) 为准：

- 根据算法关系采用直接、暴力到正解、并列或递进布局；不强制退回“思路／代码／复杂度”的全局旧骨架。
- 每份代码放在所属解法的 `### 代码` 中，使用 `@include-code(./main.py, python)` 等真实路径。暴力归自己的解法层；同算法多语言实现可以放一起，不同算法分开讲。
- 在所选布局中、总结之前加入有价值的 `## Python 知识`，或者在相应实现附近解释。包含实际使用的语言模式、必要的 C++ 对照和简洁模仿清单，避免与算法推导重复。
- 文章 tags 包含 `python` 和准确算法标签，其他 frontmatter、更新时间、公式、图示与引用遵守现有格式规则，不另造 Python 专用元数据。
- 本地笔记绝对路径及用途记录在过程文档和交付报告。正式文章只放适合读者访问的真实来源，不把本机路径当作公开站点链接。

过程文档继续使用统一的 `01` 至 `06` 文件；Python 性能分析写入 `05`，语言教学素材可合并到 `03` 或草稿，不要求额外创建固定编号的图片评估文档。

## 完成报告

由 workflow 汇总，补充 Python 文件、知识映射、真正使用的笔记路径及用途、是否存在暴力与原因、实际验证结果和 Python 性能限制。仅完成代码或学习解释时按用户范围交付，不声称整篇题解已完成。
