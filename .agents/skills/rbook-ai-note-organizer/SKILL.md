# RBook AI 对话整理

本 skill 只整理用户指定的 `problems/<oj>/<problem_id>/talking_with_ai/`，不写新对话、不审查算法结论、不套用 `index.md` 的题解格式。目录名是 `talking_with_ai`，不是 `talk_with_ai`。站点接受的字段与校验规则以 `lib/ai-notes.js` 为准；涉及 Markdown 链接语法时同时遵守 `rbook-markdown`。

## 定位与扫描

优先使用用户明确给出的目录。未给路径时，仅当当前工作目录就是 `talking_with_ai/`，或当前题目目录下有唯一的 `talking_with_ai/`，才自动定位；否则请用户给出路径。不要扫描整个仓库，也不要处理其他题目目录。

扫描目标目录第一层全部非隐藏的普通 `.md` 文件（扩展名大小写不敏感），包括已有完整元数据的文档和 `draft: true` 文档。逐份读取全文；不递归子目录，不碰 `assets/`。隐藏 `.md` 和符号链接只在结果中列出，不修改。目录不存在、不是普通目录或路径有歧义时停止，不猜测目标。

## 元数据与文件名

每份文档都应在正文前有 YAML frontmatter。只维护以下五个字段；已有其他字段和值原样保留，尽量保留原有顺序和注释：

```yaml
---
title: 对话主题
description: 一句话概括这份对话实际讨论的内容
date: 2026-09-15
slug: concise-english-topic
draft: false
---
```

- 已有合法的 `title`、`description`、`date`、`slug`、`draft` 保持不变；只补缺失项或修正不合规项。`title` 和 `description` 必须是非空字符串，概括真实讨论，不能把未经验证的 AI 推测写成定论。正文不足以判断主题时跳过该文件并说明原因。
- `date` 表示对话发生日期，不是整理日期。优先保留已有合法的 `YYYY-MM-DD`；缺失或无效时，从正文里的对话时间或导出时间提取，并校验日历日期。旧文件名只能作为查找线索，不能单独作为日期证据；无法确定时跳过，不用今天、文件修改时间或 Git 提交时间代替。
- `slug` 只允许小写英文字母、数字和单连字符分隔的词，且在同一道题的全部对话中唯一，包括草稿。已有合法且唯一的 slug 保留；否则根据讨论主题生成简短、可读的英文 `kebab-case`，不使用整标题拼音，也不重复题号。冲突时先添加有意义的主题限定词；仍不能安全区分就跳过冲突文件，不覆盖。
- 缺少 `draft` 时补 `draft: false`，整理后会公开。已有合法布尔值保持不变；无效值只有在含义明确时才转换为布尔值，否则跳过并报告。
- 若已有 frontmatter 无法安全解析或保留其中未知字段，跳过并报告，不用重建整个文档的方式覆盖它。

每份成功处理的文件名统一为 `YYYY-MM-DD--slug.md`，与最终 `date`、`slug` 完全一致。即使元数据已经合法，也要检查并修正文件名。这个命名约定由本 skill 维护；当前站点只校验元数据，不强制文件名。

## 安全执行

1. 先读完所有候选文件并形成完整计划：逐项列出旧名、新名、元数据变更、同目录链接变更及跳过原因。检查所有目标文件名和 slug，不能覆盖现有文件；如多个改名互相占用路径，采用可回退的安全步骤。
2. 用户请求整理且目标明确时，预检后直接执行可安全处理的文件，不逐文件等待确认。单个文件无法处理不应中断其他文件。只修改目标目录内的文件名、frontmatter 和明确指向旧文件名的相对 Markdown 链接；不要润色、删减或重排对话正文，也不要调整正文的 `#` 标题。
3. 在仓库其他位置搜索对旧文件名的引用。只报告这些位置，不自动修改目标目录之外的文件；不盲目替换代码块、普通文字或无法确定目标的链接。保留目标目录内的图片和其他资源路径。
4. 完成后核对新旧文件清单、元数据、slug 唯一性、同目录链接和正文差异。运行 `npm run check:content` 与 `git diff --check`；若失败，区分本次引入的问题与原有问题，修复本次问题。不要自动提交或 push。

报告已处理、未变化、跳过和忽略的文件数量；逐一列出旧名到新名、补改的字段、跳过原因、目录外引用和实际验证结果。仅在用户要求时另行修改站点校验或其他目录。
