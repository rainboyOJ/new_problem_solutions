# 更新记录

## 2026-10-28

这次只补编辑流程，31 条模式与示例不动。

- 工作流程改成两阶段：先列出缺陷清单（位置、命中哪类、为什么是问题），再逐条改。不带清单直接改写，容易把原文抹成另一种模板。
- 增加句长节奏检查：连续三句以上长度接近才算线索，改法是拆、合、删，不靠加字；列表、表格和单句无节奏可量。
- 增加删除与回退双测：新增的词删掉后句子仍成立即为填充；替换词换回原词更短且不差就退回原文。修复性新增（拆句所需的连接词、去名词化还原的动词、词序）不受影响。
- 明确选点上限：一次只改真正有问题的 3–5 处，避免把全篇扫平成新指纹；命中数量不是验收指标。澄清缺陷清单是过程记录，默认不随成稿交付。

参考并致谢：[Nanako0129/sepia](https://github.com/Nanako0129/sepia) 的编辑流程。中文模式层、语体判断和“不编造具体信息”的约束仍以本文件为准，未引入其英文规则表、技术文章基线和台湾标点规范。

## 2026-09-23

这次更新重点处理一个问题：文章改顺了，意思却变了。

- 明确要求保留事实、数字、否定、条件、时间、归因和作者态度。“可能”不能改成“确定”，“大家觉得”不能改成“我以前觉得”。
- 基于上游 v3.0.0 与 PR #39 整理 31 个检查点，重写示例，并给每条规则补充适用条件和应该保留的表达。
- 修正原有示例中凭空添加产品功能、研究数据、人物经历等问题。原文没有的信息，不用润色补出来。
- 不再根据词语、标点或列举数量机械修改。真实的三项功能、必要的破折号、中文排比和连接词可以保留。
- 匹配作者样本和文体。技术说明、商务报告和个人随笔分别处理，不统一改成聊天语气。
- 文件模式明确保护代码、命令、路径、链接、YAML、标题和锚点；默认只返回最终稿，取消自评分要求。
- 增加 18 个短文本案例、Markdown 文件样例和只读结构检查脚本。完成两篇长文的单次版本对照，仍需在更多模型和文体中观察效果。
