## 形式化题目

给定一个大小为 $n \times m$ 的正整数矩阵 $a$（$1 \le n, m \le 16$），以及目标子矩阵尺寸 $r, c$（$1 \le r \le n, 1 \le c \le m$）。

从原矩阵中选择 $r$ 行 $i_1 < i_2 < \dots < i_r$ 与 $c$ 列 $j_1 < j_2 < \dots < j_c$，构成一个 $r \times c$ 的子矩阵 $b_{u, v} = a_{i_u, j_v}$。

子矩阵的分值定义为所有四连通相邻元素之差的绝对值之和：

$$\text{Score} = \sum_{u=1}^{r-1} \sum_{v=1}^c |b_{u, v} - b_{u+1, v}| + \sum_{u=1}^r \sum_{v=1}^{c-1} |b_{u, v} - b_{u, v+1}|$$

求所有可选子矩阵中的最小分值。

## 题目解析

!!! info 拆分行列自由度：搜索枚举行子集，动态规划多阶段选取最优列。
行列如果同时暴力枚举，组合数 $\binom{16}{8}^2 \approx 1.6 \times 10^8$ 必定超时。但由于分值公式中“相邻行之差”与“相邻列之差”关于列具有一阶马尔可夫性：固定所选的 $r$ 行后，每个单独一列的纵向差固定，相邻两选列之间的横向差仅取决于该两列。将列的选择建模为类似序列选 $c$ 个元素的动态规划，在 $O(c \cdot m^2)$ 内求解，整体即可在 0.1 秒内快速完成。
!!!

### 思路

**1. 打破对称双重搜索的瓶颈**

矩阵规模 $n, m \le 16$。
若同时枚举行和列，最坏情况下 $n=16, r=8$ 时，$\binom{16}{8} = 12870$。
行列双重枚举的方案数为 $12870 \times 12870 \approx 1.65 \times 10^8$。每次计算矩阵分值还需要 $O(r \cdot c)$，总运算量达数十亿，必定 TLE。

但观察分值的构成：
$$\text{Score} = \sum_{v=1}^c \underbrace{\sum_{u=1}^{r-1} |b_{u, v} - b_{u+1, v}|}_{\text{第 } v \text{ 列的纵向分值}} + \sum_{v=1}^{c-1} \underbrace{\sum_{u=1}^r |b_{u, v} - b_{u, v+1}|}_{\text{相邻列 } v \text{ 与 } v+1 \text{ 之间的横向分值}}$$
可以发现：
- 只要我们**固定选定的 $r$ 行**，那么对于任意一列 $j$，其内部上下相邻元素的差值和便已经完全确定；
- 对于任意两列 $i$ 和 $j$，若它们在子矩阵中成为相邻的左右两列，它们所产生的横向分值也只取决于 $i$ 和 $j$ 两列对应行的绝对差之和，与其它列完全无关！

这就具备了典型的**动态规划无后效性**结构。因此，只需“搜索枚举所选的行”，对于每一种确定的行选择，“通过动态规划高效选出最优的 $c$ 列”。

**2. 行子集的组合枚举与剪枝**

通过深度优先搜索从 $n$ 行中选出 $r$ 行：
- 设递归状态 `dfs_rows(cur_row, chosen_cnt)`；
- **可行性剪枝**：如果剩余未决定的行数不足以凑齐 $r$ 行（即 $n - cur\_row + 1 < r - chosen\_cnt$），立即回溯。
- 组合数最多为 $\binom{16}{8} = 12870$。

**3. 固定行后的列动态规划**

假设当前选中的 $r$ 行下标为 $row_1 < row_2 < \dots < row_r$。
预处理两张代价表：
1. **单列自身纵向代价** $col\_cost[j]$：第 $j$ 列被选中时，内部 $r-1$ 对相邻元素的差值绝对值之和：
   $$col\_cost[j] = \sum_{k=1}^{r-1} |a_{row_k, j} - a_{row_{k+1}, j}|$$
2. **两列相邻横向代价** $pair\_cost[i][j]$（$i < j$）：第 $i$ 列和第 $j$ 列作为相邻列时产生的横向差值之和：
   $$pair\_cost[i][j] = \sum_{k=1}^r |a_{row_k, i} - a_{row_k, j}|$$

定义 DP 状态：
设 $dp[j][k]$ 表示**在原矩阵前 $j$ 列中已经选出了 $k$ 列，且第 $k$ 列恰好为原矩阵第 $j$ 列时的最小分值**。

状态转移：
枚举上一列选取的原列号 $i$（满足 $k-1 \le i < j$）：

$$dp[j][k] = \min_{k-1 \le i < j} \Big( dp[i][k-1] + pair\_cost[i][j] \Big) + col\_cost[j]$$

初始状态：
当 $k = 1$（选择第一列）时，没有前驱横向代价：
$$dp[j][1] = col\_cost[j] \quad (1 \le j \le m)$$

最终在该行选择下的最优列得分即为：
$$\min_{c \le j \le m} dp[j][c]$$

遍历所有合法的行子集，取所有 DP 结果的最小值即可得到全局答案。

### 正确性与边界

- **相对顺序不变性**：
  搜索行和递推列时，下标均保持单调递增，严格保证选出的子矩阵行与列的相对空间顺序不变。
- **边界初始值**：
  DP 数组初始全填充极大值 $\text{INF}$，第一列合法初始化后，未被到达的状态无法参与后续转移，杜绝非法状态渗透。
- **极小矩阵尺寸**：
  若 $r = 1$，则纵向代价项自然为 0（因求和上限 $r-1 = 0$）；若 $c = 1$，则横向代价项自然为 0。所有极端边界在算法框架下完全平滑自洽。

### 复杂度

- **时间复杂度**：
  - 行枚举次数至多 $\binom{16}{8} = 12870$ 次；
  - 每次枚举后，预处理代价耗时 $O(m \cdot r + m^2 \cdot r)$；
  - 列 DP 状态转移耗时 $O(c \cdot m^2)$；
  - 当 $n = 16, m = 16, r = 8, c = 8$ 时，单次 DP 与预处理操作约为 $16^2 \times 8 + 8 \times \frac{16^2}{2} \approx 3000$ 次基本运算；
  - 尽管理论上限约 $12870 \times 3000 \approx 3.8 \times 10^7$，但实际在 $n=16, r=8$ 时指令常数极小，且当 $r$ 较小时组合数更少，总运行耗时在 0.1 秒左右，远低于 1.0 秒限制。
- **空间复杂度**：
  - 代价表与 DP 数组规模均为 $20 \times 20$，递归栈深度不超过 16，内存占用不足 1 MB。

## 总结

对于二维矩阵的子集选择问题，同时在两维上进行组合暴力搜索往往会导致复杂度灾难。**利用问题的结构解耦（一维具备无后效相邻依赖）**，采用“一维搜索固定 + 另一维动态规划”的混合策略（Search + DP），是打破组合爆炸、化简问题维度的经典武器。
