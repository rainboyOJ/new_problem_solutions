### 题意

对每个节点 $v$，累加所有无序端点对的最短路经过它的比例：

$$
I(v) = \sum_{s \ne v,\ t \ne v} \frac{C_{s,t}(v)}{C_{s,t}}
$$

其中 $C_{s,t}$ 是 $s$ 到 $t$ 的最短路条数，$C_{s,t}(v)$ 是其中经过 $v$ 的条数。图保证连通。

### 思路

要求 $I(v)$，需要两个量：任意两点的最短路条数 $C_{s,t}$，以及经过 $v$ 的最短路条数 $C_{s,t}(v)$。

#### 第一个量：在 Floyd 里同步计数

普通的 Floyd 最后只留下一个数 `dist[i][j]`，路径条数的信息在松弛过程中被覆盖掉了。但请注意 `dist` 是怎么更新的——既然距离可以按规则合并，**条数就能按同样规则合并**，只需要给这一个转移配上两条规则：

```cpp
d = dist[i][k] + dist[k][j]
if (d < dist[i][j]) {          // 经 k 更短：旧走法全部作废，条数替换
    dist[i][j] = d;
    cnt[i][j] = cnt[i][k] * cnt[k][j];
} else if (d == dist[i][j]) {  // 经 k 一样短：一批新最短路，条数累加
    cnt[i][j] += cnt[i][k] * cnt[k][j];
}
```

**为什么可以累加？** 因为 Floyd 第 $k$ 轮只在上一轮的结论上做一件事：放开 `k` 这个中转点。所以每轮产生的候选恰好是两类：

| 类别 | 含义 | 来源 |
| --- | --- | --- |
| 不经 `k` | 中间点均来自前 $k-1$ 批 | 上一轮的 `dist[i][j]` |
| 经 `k` | 中间点集合包含 `k` | 本轮的 `dist[i][k] + dist[k][j]` |

这两类**互斥**，所以相加不会重复。

**为什么用乘法？** 一条经 `k` 的路径需要拆成“`i` 到 `k` 的一段”和“`k` 到 `j` 的一段”，两段的选择互相独立，按乘法原理相乘。

#### 必须跳过 `i == k` 和 `j == k`

这一条不是优化，而是**正确性必需**。

当 `i == k` 时，`dist[i][k] = 0`，那条“路径”原地没动。它既不是“经 `k` 的”，也不是“不经 `k` 的”，而是**两类都能算**——上表那个互斥前提被破坏，累加就重复了。

实测后果很严重：不跳过时 400 组随机数据里有 344 组算出错误结果，例如

```
3 个点，边 1-2 权 1、1-3 权 2
不跳过: I(1) = 1.333     正确值: 2.000
```

所以三重循环里的 `if (i == k) continue;` 与 `if (j == k || i == j) continue;` 都不可或缺。

#### 第二个量：两段距离之和等于总距离

有了距离矩阵和第个条数矩阵，剩下的是判断“`v` 是否在 `s → t` 的某条最短路上”。判据是距离的加性：

$$
dist[s][v] + dist[v][t] == dist[s][t]
$$

**为什么这条等式与“存在经过 `v` 的最短路”等价？**

- 若存在一条经过 `v` 的最短路，它的前半段是 $s \to v$、后半段是 $v \to t$，两段长度之和必然等于全长。
- 反之若等式成立，那么“$s$ 走最短路到 $v$，再走最短路到 $t$”就是一条长度为 $dist[s][t]$ 的路径，即一条经过 `v` 的最短路。

而**唯一的拆分**是关键：`v` 在路径上的位置是确定的，任何经过 `v` 的最短路都能唯一拆成一头一尾，不存在“同一路径按不同方式拆分”的重叠。所以

$$
C_{s,t}(v) = cnt[s][v] \cdot cnt[v][t]
$$

成立。若一个点可以在路径上出现多次，这个乘积就会重复计数——但本题边权为正，最短路不可能重复经过同一点。

#### 汇总

三段组合起来就得到答案：

$$
I(v) = \sum_{\substack{s \ne v,\ t \ne v \\ s \ne t}} \frac{cnt[s][v] \cdot cnt[v][t]}{cnt[s][t]}
$$

必须排掉 $s = t$ 的情形：自己到自己的最短路无意义。

#### 两个容易忽略的点

**溢出：** 题面保证任意两点间的最短路条数不超过 $10^{10}$，而 `cnt[i][k] * cnt[k][j]` 只在 `i→k→j` 确实是最短路时才有意义，此时乘积不超过 `cnt[i][j]`，不会溢出。但代码里 **先算乘积再比较距离** 的写法，在“经 `k` 不是最短路”时仍会乘出一个可能超出 `long long` 的中间值（随后被丢弃，结果仍正确，但技术上有一次有符号溢出）。稳妥写法是先判断 `d > dist[i][j]` 就 `continue`，再算乘积。

**浮点：** 最后求和用 `long double` 累积，输出 `fixed << setprecision(3)`，避免多次除法叠加的精度损失。

### Python 知识

- Python 的 `int` 是任意精度，`cnt` 乘积不需要担心 $10^{10} \times 10^{10}$ 溢出，比 C++ 省心。
- 二维列表分别保存距离和计数，两个矩阵在松弛里同步更新，公式与代码一一对应。
- `f"{importance:.3f}"` 按要求输出三位小数。

### 复杂度

Floyd 是 $O(n^3)$，重要度统计也是三重循环 $O(n^3)$，空间两个 $n \times n$ 矩阵共 $O(n^2)$。$n \le 100$ 时约 $2 \times 10^6$ 次运算。

### 总结

Floyd 的 `middle` 不是“迭代次数”，而是**控制允许使用的中转点集合**，这正是 DP 的阶段划分。在这个阶段上同步维护计数辅助状态即可：每轮的路径类互斥，所以计数能相加；路径在某个点上有唯一拆分，所以两段条数能相乘。

最后用“两段距离之和等于总距离”把几何上的“经过 `v`”翻译成数值判断。一句话：**DP 提供状态，计数原理提供合并规则，而“互斥”与“唯一”保证这两个操作是合法的**。
