## 形式化题目

给定一棵 $n$ 个点的树，每个点 $v$ 带两个整数属性：颜色 $c_v$ 与权值 $w_v$（$w_v$ 为正整数）。记树上 $u$ 到 $v$ 的唯一简单路径上的点集为 $P(u, v)$。依次处理 $m$ 条操作：

1. `CC x c`：把点 $x$ 的颜色改成 $c$，即 $c_x \leftarrow c$；
2. `CW x w`：把点 $x$ 的权值改成 $w$，即 $w_x \leftarrow w$；
3. `QS x y`：在路径 $x \to y$ 上，把所有颜色等于 $c_x$ 的点的权值相加并输出，即求 $\sum_{v \in P(x, y),\ c_v = c_x} w_v$；
4. `QM x y`：在路径 $x \to y$ 上，取所有颜色等于 $c_x$ 的点的权值最大值并输出，即求 $\max\{\, w_v \mid v \in P(x, y),\ c_v = c_x \,\}$。

数据保证每次查询满足 $c_x = c_y$。原题把颜色称为「宗教」、把权值称为「评级」，下文遇到时按这两个叫法理解，指的是同一组属性。

## 解法总览

三个解法共享前一半：**树链剖分把路径变成 $O(\log n)$ 段 dfn 连续区间**。它们在「怎么按宗教过滤」上分成三条路。

树链剖分部分：两次 DFS 求每个点的重儿子与链头，再按「先重儿子」的顺序重新编号（dfn），让每条重链在 dfn 上连续。样例的树很小，剖分结果可以直接摊开看。点 $1$ 有两个儿子 $2$、$3$，而 $3$ 的子树有 $3$ 个点、$2$ 的子树只有 $1$ 个，所以重儿子是 $3$；$3$ 的重儿子是 $4$。

```text
      1                 重儿子：1 -> 3 -> 4
     / \                dfn：dfn[1]=1, dfn[3]=2, dfn[4]=3, dfn[5]=4, dfn[2]=5
    2   3
       / \              重链 1->3->4 占 dfn 1..3（连续）
      4   5              单点链 5 占 dfn 4，单点链 2 占 dfn 5
```

`QS 5 1` 这条路径（$5 \to 3 \to 1$）被拆成两段：先取 $5$ 所在的单点链，得到 dfn 区间 $[4,4]$；再取剩下的 $3 \to 1$，得到 dfn 区间 $[1,2]$。两段都是连续区间，可以交给线段树。

三条分支的差别只在下一层：

| 解法 | 过滤宗教的手段 | 时间（预处理 / 单点 / 查询） | 空间 | 实测（$n = m = 10^5$） | 对应代码 |
| --- | --- | --- | --- | --- | --- |
| 一（推荐提交） | 每种宗教一棵线段树，共享节点池、动态开点 | $O(n\log n)$ / $O(\log n)$ / $O(\log^2 n)$ | $O((n+m)\log n)$ | 169–293 ms，33–61 MiB | `main.cpp` |
| 二 | 每种宗教一棵**普通**线段树，坐标先离线离散化成「该宗教历史上出现过的 dfn」 | $O((n+m)\log n)$ / $O(\log n)$ / $O(\log^2 n)$ | $O(n+m)$ | 162–276 ms，20–28 MiB | `main2.cpp` |
| 三 | 只开一棵 dfn 线段树，每个节点挂一张「宗教 → 摘要」的 `map` | $O(n\log n\log C)$ / $O(\log n\log C)$ / $O(\log^2 n\log C)$ | $O(n\log n)$ 个表项 | 1.8–6.3 s（换哈希表 1.2–3.6 s），95–119 MiB | `main3.cpp` |

三者的关系：解法一和解法二是同一个「按宗教拆树」模型，差别只在坐标空间怎么来（在线开点 vs 离线压缩）；解法三完全不拆树，把宗教当成线段树节点里的一维映射，写法最短、最慢。解法一不需要离线、常数和空间都适中，所以作为推荐提交的主解。

## 暴力解法

### 适用范围

$n \leqslant 100$，即 `brute.cpp` 里 `MAXN = 105` 的上界。它的用途有两个：把题意写成可执行的说明书，以及作为三个解法的对拍基准。

### 思路

先用一次 BFS 把树定根（根取 $1$），得到每个点的父亲 `parent` 与深度 `depth`。查询时只做一件事：把两个端点沿父亲往上爬，逐点判断宗教。

具体是三步：先让较深的一端单独往上爬，直到两端深度相同；然后两端一起往上爬，直到相遇；路径上的每个点（包括起点和终点）都检查一次宗教是否等于 $c_x$，符合就累加评级、更新最大值。`CC` 与 `CW` 直接改数组，$O(1)$。

### 复杂度与瓶颈

- 时间：预处理 $O(n)$；单次查询走的点数等于路径长度，最坏 $O(n)$，$m$ 次查询合计 $O(nm)$。$n = m = 10^5$ 时是 $10^{10}$ 量级，不可行。
- 空间：$O(n)$。

瓶颈是查询本身：**路径上的每一个点都要亲自走一遍、亲自判一次宗教**。链状树上路径长度就是 $n$，这条代价躲不掉。要让查询变快，就得同时解决两件事：把「路径」换成擅长区间查询的结构，把「只统计同宗教」这个过滤条件也交给数据结构去扛。

## 解法一：树链剖分 + 按宗教拆分的动态开点线段树

### 思路

`QS/QM x y` 全程只关心 $c_x$，别的宗教的点全部视而不见。既然查询是「在一段区间里只看某一类点」，那就干脆按宗教把点分家：**每种宗教一棵线段树**，只存当前属于该宗教的点，叶子下标仍然用 dfn。

样例初始状态按宗教拆开是这样的（$5$ 个点的评级依次是 $3,2,1,3,5$，宗教依次是 $1,3,2,3,1$）：

```text
城市：         1   3   4   5   2
dfn 位置：     1   2   3   4   5
评级：         3   1   3   5   2
宗教：         1   2   3   1   3

按宗教拆成三棵独立的线段树（下标仍是 dfn 位置）：
  宗教 1 的树：  [3] [ ] [ ] [5] [ ]
  宗教 2 的树：  [ ] [1] [ ] [ ] [ ]
  宗教 3 的树：  [ ] [ ] [3] [ ] [2]
```

同一个 dfn 位置只在一棵树上取得到值——它在哪棵树的哪片叶子上，就代表那个城市当前属于哪个宗教。于是「查路径上宗教 $1$ 的评级和」就变成了「在宗教 $1$ 的树上查两段区间」，城市 $1$ 与 $5$ 命中，$3 + 5 = 8$。`CC 3 1` 之后，评级 $1$ 从宗教 $2$ 的树搬到宗教 $1$ 的树，同样两段查询就得到 $3 + 1 + 5 = 9$，与样例一致。

第一个障碍是空间：宗教数 $C$ 可达 $10^5$，如果每种宗教都开一棵 $4n$ 的线段树，需要 $4nC = 4\times10^{10}$ 个节点，按每个节点一个 `int` 也有 160 GB，而限制是 512 MiB。可是任意时刻只有 $n$ 个点有值，分布在所有宗教树上，其余位置全是空的。所以让所有宗教树共享一个节点池、按需开点：一次单点写入只新建它经过的 $O(\log n)$ 个节点，总量 $O((n + m)\log n)$。

四个操作因此各自落在很明确的位置上：

| 操作 | 做法 |
| --- | --- |
| `CC x c` | 在旧宗教树上把 dfn[x] 一叶清 $0$，改 `col[x]`，在新宗教树上把 dfn[x] 写成 $w_x$ |
| `CW x w` | 改 $w_x$，在当前宗教树上把 dfn[x] 一叶覆盖成 $w$ |
| `QS x y` | HLD 拆成 $O(\log n)$ 段，每段在 `roots[col[x]]` 上查区间和，累加 |
| `QM x y` | 同上，查区间最大值，取最大 |

实现上有两个必须写对的地方：

- **空节点 $0$ 全局共享。** `range_query` 一进来遇到 `node == 0` 就直接返回，表示这棵宗教树在这段区间里没有任何城市。评级是正整数，所以「空」既可以当成和 $0$、也可以当成最大值 $0$，两个都是安全的中性元。
- **`point_set` 的根要传引用。** 一个宗教第一次出现时 `roots[c] == 0`，函数里边必须新建根节点并把编号写回 `roots[c]`，否则后续所有操作都找不到这棵树。

### 复杂度

- 预处理：两次 DFS $O(n)$；$n$ 次初始插入，每次 $O(\log n)$，合计 $O(n \log n)$。
- `CC`：两次单点写入 $O(\log n)$；`CW`：一次单点写入 $O(\log n)$。
- `QS` / `QM`：路径拆成 $O(\log n)$ 段，每段在宗教树上做一次区间查询 $O(\log n)$，合计 $O(\log^2 n)$。
- 空间：树剖数组 $O(n)$；节点池 $O((n + m)\log n)$，$n = m = 10^5$ 时约 $3.6\times10^6$ 个节点，四个 `int` 数组约 58 MiB。

$n = m = 10^5$ 的实测（`-O2`、`cin` 关闭同步、含读入，限制 1000 ms / 512 MiB）：随机树、链、菊花、完全二叉树、全 `CC`、全查询六组数据在 169–293 ms 之间；最坏的一组是「全同宗教 + 完全二叉树 + 叶子互查」，350 ms、21 MiB。峰值内存 61 MiB 出现在全 `CC` 那组，与节点池只增不减相符。

## 解法二：离线离散化 + 每个宗教一棵普通线段树

### 思路

解法一的空间浪费来自「为还没出现的位置预留节点」。如果能把每种宗教的坐标空间压到它**真正可能出现**的那些 dfn 上，普通线段树就够了，连动态开点都不需要。

未来是已知的：题目把所有操作一次性给出，没有加密、没有交互。于是先读入全部操作，模拟一遍宗教变更，就能收集到「宗教 $c$ 历史上出现过的所有 dfn」。把这些位置排序去重，得到大小 $k_c$ 的坐标表，第 $c$ 棵普通线段树只需要 $4k_c$ 个节点。因为每个城市初始占一个位置、每次 `CC` 最多给新宗教增加一个位置，所以

$$\sum_c k_c \leqslant n + m,$$

也就是所有宗教树的节点总数不超过 $4(n + m) + 4C$，约 $1.2\times10^6$ 个，不到解法一的三分之一。

剩下的问题是「dfn 值 → 该宗教内部的下标」。这个映射用一次二分就能完成：在 `pos[c]` 上 `lower_bound`。

路径查询也照旧拆段，只是每段多一步转换：dfn 区间 $[L, R]$ 先变成内部下标区间 $[\,\text{lower\_bound}(L),\ \text{upper\_bound}(R)-1\,]$，再到第 $c$ 棵树上查。若某段里没有该宗教的点，下标区间会落空，直接跳过。

代价有两个，都很实际：

- **必须离线**。要先把全部操作读进来才能知道每棵树的坐标表。如果题目改成强制在线（比如操作依赖上一次答案），这条路直接失效，只能回到解法一。
- **每次操作多一次二分**。dfn 换成内部下标是 $O(\log k_c)$，与线段树的 $O(\log n)$ 同阶，实测差别不大。初始化也多了一步：排序去重所有宗教的坐标表，合计 $O((n + m)\log(n + m))$。

`CC` 与 `CW` 的语义和边界（空位置、成对清除）与解法一相同，只是「清 0」变成了「往坐标表里定位再覆盖」。

### 复杂度

- 预处理：两次 DFS $O(n)$；离线模拟收集坐标 $O(n + m)$；排序去重 $O((n + m)\log(n + m))$；$n$ 次初始插入 $O(n\log n)$。

实测同样是六组 $n = m = 10^5$ 的数据：162–276 ms，峰值内存 20–28 MiB。**时间与解法一同级，内存只有解法一的一半左右**——省下来的正是动态开点为「将来可能用到」预留的那部分节点。

## 解法三：一棵 dfn 线段树 + 每个节点挂宗教映射

### 思路

前两个解法都在「按宗教拆树」。换个方向想：树不拆，只在每个线段树节点上额外记一维「宗教 → 摘要」，也就是给每个节点挂一张 `map`。

```text
dfn 线段树的每个节点各自持有一张「宗教 -> (和, 最大值)」的表：

                  [1,5]
        ┌──────────┴──────────┐
      [1,3]                 [4,5]
     ┌───┴───┐            ┌───┴───┐
   [1,2]   [3,3]        [4,4]   [5,5]

  节点 [1,2] 的表：{ 宗教1: (3, 3) }      节点 [4,5] 的表：{ 宗教1: (5, 5), 宗教3: (2, 2) }
  节点 [1,5] 的表：{ 宗教1: (8, 5), 宗教2: (1, 1), 宗教3: (2, 2) }
```

这样一来：

- **单点写**：叶子节点上把宗教 $c$ 的项设成 $(w, w)$（清 0 就是删掉这一项），回溯时**只需要重算宗教 $c$ 这一项**——别的宗教没被改过，不必动。
- **区间查询**：区间拆成 $O(\log n)$ 个整节点，每个节点查一次 `map` 取该宗教的摘要，把和相加、最大值取 $\max$。某个节点上没有该宗教的项，就等价于空，贡献 $0$。

写法确实最短：没有节点池，没有坐标映射，也没有「空节点」这种特殊情况——`map` 里没有这一项就是空。

但代价很直接。一次查询要访问 $O(\log n)$ 段（HLD）× $O(\log n)$ 个节点，每个节点再做一次 $O(\log C)$ 的红黑树查找，合计 $O(\log^2 n \log C)$；$n = m = 10^5$ 时是 $10^5 \times 17 \times 17 $ 量级的节点访问，每次又带一层 `map` 查找。而每个节点各持一张 `map`，$4n$ 个 `map` 对象加 $O(n\log n)$ 个表项，也把内存推到 100 MiB 以上。

### 复杂度

- 预处理：$n$ 次单点写入，每次 $O(\log n\log C)$，合计 $O(n\log n\log C)$。
- `CC`：两次单点写入 $O(\log n\log C)$；`CW`：一次 $O(\log n\log C)$。

所以这个解法适合当「同一个模型的编码对照」：它说明动态开点 / 离线离散化省下来的到底是什么（不是算法复杂度，而是每次操作要碰的节点数和内存），但不宜作为正式提交。

## 总结

这道题的骨架是「**一维路径区间化 + 第二维按宗教过滤**」，前半段三种解法完全一样，差别全在第二维怎么落地：

- 树链剖分把路径变成 $O(\log n)$ 段 dfn 连续区间，解决「路径不是区间」这个障碍；
- 解法一把第二维拆成很多棵树，用动态开点把空间压到 $O((n + m)\log n)$；
- 解法二同样拆树，但用离线已知的操作把坐标空间压缩成 $O(n + m)$，于是普通线段树就够，内存还更省；
- 解法三不拆树，把第二维放进每个节点的 `map`，写法最短，代价是每次操作要碰 $O(\log^2 n)$ 个节点、每个节点再查一次 `map`。

两个操作语义值得单独记住：`CC` 是「一清一写」，相当于在两个集合之间搬家；`CW` 是单点覆盖。它们都只碰 $O(\log n)$ 个节点，这正是这几个结构最省的地方。

```text
  两次 DFS 求重儿子与链头，按 dfn 重编号
  任意路径 = O(log n) 段 dfn 连续区间
        |
        | 剩下的事：区间里混着各种宗教，怎么只统计其中一种

解法一：按宗教拆树            解法二：拆树 + 离线压缩      解法三：不拆树
  每宗教一棵树，共享节点池      每宗教一棵普通树            单棵 dfn 线段树

  QS/QM  O(log^2 n)            QS/QM  O(log^2 n)           QS/QM  O(log^2 n log C)
  169-293 ms, 33-61 MiB        162-276 ms, 20-28 MiB       1.8-6.3 s, 95-119 MiB
```

图中三处分支比较的是同一件事的三种落地方式。解法一和解法二的差别只有「坐标空间从哪来」（在线开点 vs 离线压缩），所以时间同级、内存差一倍；解法三把过滤搬进节点内部，省掉了拆树，却让每次操作多乘一个 $\log C$，于是从 300 ms 掉到秒级。
