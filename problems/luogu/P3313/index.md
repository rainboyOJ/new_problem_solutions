## 形式化题目

树上有 $n$ 个点，点 $i$ 带两个属性：宗教 $c_i$ 与评级 $w_i$（评级是正整数）。按顺序处理 $m$ 条操作：

1. `CC x c`：把 $c_x$ 改成 $c$；
2. `CW x w`：把 $w_x$ 改成 $w$；
3. `QS x y`：在路径 $x \to y$ 上取出所有宗教等于 $c_x$ 的点，输出它们的评级之和；
4. `QM x y`：同 `QS`，输出评级最大值。

题面保证每次 `QS` / `QM` 的两端宗教相同，所以「取哪一类宗教」总是明确的。

## 暴力解法

### 适用范围

$n \leqslant 100$，即 `brute.cpp` 里 `MAXN = 105` 的上界。它的用途有两个：把题意写成可执行的说明书，以及作为对拍的基准。

### 思路

先用一次 BFS 把树定根（根取 $1$），得到每个点的父亲 `parent` 与深度 `depth`。查询时只做一件事：把两个端点沿父亲往上爬，逐点判断宗教。

具体是三步：先让较深的一端单独往上爬，直到两端深度相同；然后两端一起往上爬，直到相遇；路径上的每个点（包括起点和终点）都检查一次宗教是否等于 $c_x$，符合就累加评级、更新最大值。`CC` 与 `CW` 直接改数组，$O(1)$。

### 复杂度与瓶颈

- 时间：预处理 $O(n)$；单次查询走的点数等于路径长度，最坏 $O(n)$，$m$ 次查询合计 $O(nm)$。$n = m = 10^5$ 时是 $10^{10}$ 量级，不可行。
- 空间：$O(n)$。

瓶颈是查询本身：**路径上的每一个点都要亲自走一遍、亲自判一次宗教**。链状树上路径长度就是 $n$，这条代价躲不掉。要让查询变快，就得同时解决两件事：把「路径」换成擅长区间查询的结构，把「只统计同宗教」这个过滤条件也交给数据结构去扛。

## 正解：树链剖分 + 按宗教拆分的动态开点线段树

### 关键观察

**观察一：路径可以拆成 $O(\log n)$ 段连续区间。** 树链剖分（HLD）用两次 DFS 求每个点的重儿子与链头，再按「先重儿子」的顺序重新编号（dfn）。这样每条重链在 dfn 上是连续的一段，任意路径都被拆成不超过 $O(\log n)$ 段这样的区间。

样例的树很小，剖分结果可以直接摊开看。点 $1$ 有两个儿子 $2$、$3$，而 $3$ 的子树有 $3$ 个点、$2$ 的子树只有 $1$ 个，所以重儿子是 $3$；$3$ 的重儿子是 $4$。

```text
      1                 重儿子：1 -> 3 -> 4
     / \                dfn：dfn[1]=1, dfn[3]=2, dfn[4]=3, dfn[5]=4, dfn[2]=5
    2   3
       / \              重链 1->3->4 占 dfn 1..3（连续）
      4   5              单点链 5 占 dfn 4，单点链 2 占 dfn 5
```

`QS 5 1` 这条路径（$5 \to 3 \to 1$）被拆成两段：先取 $5$ 所在的单点链，得到 dfn 区间 $[4,4]$；再取剩下的 $3 \to 1$，得到 dfn 区间 $[1,2]$。两段都是连续区间，可以交给线段树。

**观察二：查询只统计一种宗教，而改宗教只动一个点。** `QS/QM x y` 全程只关心 $c_x$，别的宗教的点全部视而不见。既然查询是「在一段区间里只看某一类点」，那就干脆按宗教把点分家：**每种宗教一棵线段树**，只存当前属于该宗教的点，叶子下标仍然用 dfn。

样例初始状态按宗教拆开是这样的（$5$ 个点的评级依次是 $3,2,1,3,5$，宗教依次是 $1,3,2,3,1$）：

```text
城市：         1   3   4   5   2
dfn 位置：     1   2   3   4   5
评级：         3   1   3   5   2
宗教：         1   2   3   1   3

按宗教拆成三棵独立的线段树（下标仍是 dfn 位置）：
  宗教 1 的树：  [3] [ ] [ ] [5] [ ]
  宗教 2 的树：  [ ] [1] [ ] [ ] [ ]
  宗教 3 的树：  [ ] [ ] [3] [ ] [2]
```

同一个 dfn 位置只在一棵树上取得到值——它在哪棵树的哪片叶子上，就代表那个城市当前属于哪个宗教。于是「查路径上宗教 $1$ 的评级和」就变成了「在宗教 $1$ 的树上查两段区间」，城市 $1$ 与 $5$ 命中，$3 + 5 = 8$。`CC 3 1` 之后，评级 $1$ 从宗教 $2$ 的树搬到宗教 $1$ 的树，同样两段查询就得到 $3 + 1 + 5 = 9$，与样例一致。

**观察三：宗教数有 $10^5$，但同时在册的点只有 $n$ 个。** 如果每种宗教都开一棵 $4n$ 的线段树，空间是 $4nC$，直接爆炸。可是任意时刻只有 $n$ 个点有值，分布在所有宗教树上。所以让所有宗教树共享一个节点池、按需开点：一次单点写入只新建它经过的 $O(\log n)$ 个节点，总量 $O((n + m)\log n)$。

四个操作因此各自落在很明确的位置上：

| 操作 | 做法 |
| --- | --- |
| `CC x c` | 在旧宗教树上把 dfn[x] 一叶清 $0$，改 `col[x]`，在新宗教树上把 dfn[x] 写成 $w_x$ |
| `CW x w` | 改 $w_x$，在当前宗教树上把 dfn[x] 一叶覆盖成 $w$ |
| `QS x y` | HLD 拆成 $O(\log n)$ 段，每段在 `roots[col[x]]` 上查区间和，累加 |
| `QM x y` | 同上，查区间最大值，取最大 |

实现上有两个必须写对的地方：

- **空节点 $0$ 全局共享。** `range_query` 一进来遇到 `node == 0` 就直接返回，表示这棵宗教树在这段区间里没有任何城市。评级是正整数，所以「空」既可以当成和 $0$、也可以当成最大值 $0$，两个都是安全的中性元。
- **`point_set` 的根要传引用。** 一个宗教第一次出现时 `roots[c] == 0`，函数里边必须新建根节点并把编号写回 `roots[c]`，否则后续所有操作都找不到这棵树。

### 思路

把三点观察按顺序接起来：

1. **预处理**：`dfs1` 求 `parent`、`depth`、`sz`、`heavy`；`dfs2` 先走重儿子再走轻儿子，得到 `top` 与 `dfn`。
2. **初始建树**：对每个城市 $i$，把 $w_i$ 写进 `roots[col[i]]` 的 dfn[i] 位置。
3. **处理操作**：
   - `CC`：旧树清 $0$ → 改 `col` → 新树写 $w$（两次单点写入）；
   - `CW`：改 $w$ → 当前树单点覆盖；
   - `QS/QM`：`while (top[x] != top[y])`，谁链头更深就先取谁的 `dfn[top[x]]..dfn[x]` 这一段，然后跳到链头的父亲；最后同一链上再取一段，把各段结果合并。
4. **合并方式**：和直接相加，最大值取 $\max$，与暴力里逐点累加的结果完全一致。

查询里那一段区间拆分是全文最容易写错的地方：跳链时只能取 `dfn[top[x]]..dfn[x]`，不能取到 $y$ 所在的位置；跳完必须把 $x$ 移到 `parent[top[x]]`，否则会死循环；最后的同一链区间要按深度定左右端点。

### 复杂度

- 预处理：两次 DFS $O(n)$；$n$ 次初始插入，每次 $O(\log n)$，合计 $O(n \log n)$。
- `CC`：两次单点写入 $O(\log n)$；`CW`：一次单点写入 $O(\log n)$。
- `QS` / `QM`：路径拆成 $O(\log n)$ 段，每段在宗教树上做一次区间查询 $O(\log n)$，合计 $O(\log^2 n)$。
- 空间：树剖数组 $O(n)$；节点池 $O((n + m)\log n)$，$n = m = 10^5$ 时约 $3.6\times10^6$ 个节点，四个 `int` 数组约 58 MiB。

$n = m = 10^5$ 的实测（`-O2`、`cin` 关闭同步、含读入，限制 1000 ms / 512 MiB）：随机树、链、菊花、完全二叉树、全 `CC`、全查询六组数据在 170–290 ms 之间；最坏的一组是「全同宗教 + 完全二叉树 + 叶子互查」，350 ms、21 MiB。峰值内存 61 MiB 出现在全 `CC` 那组，与节点池只增不减相符。时间与空间都还有明显余量。

## 总结

这道题的骨架是「**一维路径区间化 + 第二维按宗教拆分**」：

- 树链剖分负责把路径变成 $O(\log n)$ 段 dfn 连续区间，解决「路径不是区间」这个障碍；
- 按宗教拆成多棵线段树，把「只统计同宗教的点」这个过滤条件直接编码进数据结构，查询不需要任何额外判断；
- 动态开点让 $10^5$ 棵树共用一份节点池，空间从 $O(nC)$ 降到 $O((n + m)\log n)$。

两个操作语义值得单独记住：`CC` 是「一清一写」，相当于在两个集合之间搬家；`CW` 是单点覆盖。它们都只碰 $O(\log n)$ 个节点，正是这个结构最省的地方。

把本题与同类题对照：树剖 + 线段树的题（如 P3976 的路径最大买卖差）只有一维，摘要要处理的是方向；本题多出「宗教」这一维，代价是把一棵树变成很多棵、并且必须动态开点才能装得下。反过来，如果只需要区间和，还可以用「每种宗教一个树状数组 + 修改时维护」，但最大值不支持删除，所以本题只能走上线段树这条路。
