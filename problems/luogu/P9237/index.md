## 形式化题目

给定 $n \times m$ 的 $01$ 网格，其中若干格子附带一个数字 $x$（$0 \leqslant x \leqslant 9$）。数字位于 $(i,j)$ 时，要求 $(i,j)$ 及其八个相邻格（越界的格子不计数）中黑色格子的个数恰好为 $x$。求满足全部数字约束的 $01$ 网格。数据保证有解且解唯一。

## 暴力解法

### 思路

最直接的做法是把每个格子的颜色当成一个未知量，用一个 $01$ 序列表示整张棋盘，枚举全部 $2^{nm}$ 种染色。

按行优先的顺序递归：第 $dep$ 层决定第 $dep$ 个格子的颜色（$dep$ 从 $0$ 开始，对应格子为 $(dep/m+1,\ dep\%m+1)$）。每层先试 $0$（白）再试 $1$（黑），递归到 $dep = nm$ 时再回头检查每个数字约束是否恰好被满足，第一个满足全部约束的方案就是字典序最小的解。

**为什么必须等到最后才检查？** 因为按行优先枚举时，一个数字约束的 $3\times 3$ 窗口里总有一部分格子还没被枚举到。此时窗口内的黑格数只是一个下界，无法判断它最终是否等于 $x$；只有整张棋盘都确定之后，约束才变成可判定的。

这也是 `brute.cpp` 的写法。它穷举了所有染色方案，因此只要题目有解，输出必然正确。

### 复杂度

一共枚举 $2^{nm}$ 个完整染色，每个染色检查全部约束需要 $O(nm)$，总时间复杂度 $O(2^{nm} \cdot nm)$，空间复杂度 $O(nm)$（棋盘数组和递归栈）。

### 瓶颈

瓶颈就是 $2^{nm}$ 这个枚举量：$nm=20$ 已经是 $10^6$ 级别，而题目允许 $nm = 100$。暴力的第二个浪费在于——**它把判断推迟到了最后**，前面的 $nm-1$ 层递归完全不产生任何信息，即使某个数字约束早就被填爆了，也要等整棵树走完才发现。

## 正解

### 思路

既然暴力的浪费在于“判断太晚”，就让判断尽可能早：**按行优先顺序填格子，每填完一格，立刻检查那些已经能被完全确定的数字约束。**

关键观察：按行优先填到 $(i,j)$ 时，哪些数字约束的窗口已经全部见过？

- 窗口覆盖行 $[r-1, r+1]$、列 $[c-1, c+1]$，最后被访问的格子是 $(r+1, c+1)$。所以数字 $(r,c)$ 在格子 $(r+1,c+1)$ 填完的瞬间被完全确定。
- 反过来，刚填完 $(i,j)$ 时，新被确定的约束就是 $(r,c) = (i-1, j-1)$——恰好一个（越界时没有）。

为了让这个检查随时可做，维护两个数组：

| 数组 | 含义 |
| --- | --- |
| `part[r][c]` | 数字 $(r,c)$ 的窗口中，**已确定颜色**的格子里的黑格数 |
| `known[r][c]` | 数字 $(r,c)$ 的窗口中，**已确定颜色**的格子数 |
| `tot[r][c]` | 数字 $(r,c)$ 的窗口落在棋盘内的格子总数（预处理，越界格不计） |

填完 $(i,j)$ 后，只有与它相邻（切比雪夫距离不超过 $1$）的数字窗口会变化，最多 $9$ 个，逐个检查：

- **下界剪枝**：若 `part[r][c] > need[r][c]`，黑格已经超标，这个约束再也不可能被满足，回溯。
- **上界剪枝**：若 `part[r][c] + (tot[r][c] - known[r][c]) < need[r][c]`，即窗口内剩下未确定的格子**全部填黑也不够**，同样回溯。

这两条剪枝合起来，等价于对每个已确定约束做一次区间判定：`part[r][c] <= need[r][c] <= part[r][c] + (tot[r][c] - known[r][c])`。只要某一步破坏了这个不等式，当前分支直接死亡。

以样例的数字 $(1,2)=1$ 为例，它的窗口是第 $1\sim 2$ 行、第 $1\sim 3$ 列共 $6$ 格，最后被访问的格子是 $(2,3)$。当按顺序填入 $(1,1)=0$、$(1,2)=0$、$(1,3)=0$、$(2,1)=0$、$(2,2)=0$ 后，`part = 0`、`known = 5`，只剩 $(2,3)$ 一格；此时 `0 <= 1 <= 0 + (6-5)`，约束要求剩下的这一格必须是黑格。如果前面任何一格填了黑格，`part` 会立即超过 $1$，分支当场被剪掉。

因为数据保证解唯一，搜索找到的第一个解就是答案；即使解不唯一，由于我们始终先试 $0$ 再试 $1$，输出的也是字典序最小的解。

### 复杂度

每个格子只有 $0/1$ 两种取值，搜索树规模上界仍是 $O(2^{nm})$，但每落一子只做常数次（$\leqslant 9$ 个窗口）的剪枝判断，单步代价 $O(1)$；预处理 $tot$ 需要 $O(nm)$。空间复杂度 $O(nm)$（`need`、`part`、`known`、`tot`、`ans` 各为 $n \times m$）。在 $n,m \leqslant 10$ 且解唯一的数据上，剪枝会把搜索树压到实际可接受的规模。

## 总结

1. **暴力的问题在于判断太晚**：按行优先枚举时，只有整张棋盘填完才能检查约束，前面所有递归都不产生剪枝信息。
2. **正解的改进是让约束“何时可判定”变得精确**：数字 $(r,c)$ 的窗口在格子 $(r+1,c+1)$ 填完时被完全确定，所以每落一子只需检查最多 $9$ 个窗口。
3. **剪枝的本质是区间判定**：维护窗口内「已确定黑格数 `part`」和「已确定格子数 `known`」，一旦 `part > need` 或 `part + (tot - known) < need` 就回溯。
4. 这类「枚举 + 提前检查局部约束」的搜索题，通法是先想清楚**每做出一个决策后，哪些约束的取值区间会被更新**，再把约束的可行区间作为剪枝条件；本题的约束只有 $3\times 3$ 一小块，因此每次决策的影响面是常数级，剪枝既便宜又有效。
