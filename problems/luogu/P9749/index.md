### 题意

一共有 `n` 个站点，站点 `i` 到 `i+1` 的距离是 `v_i` 公里。

每个站点都能加油，站点 `i` 的油价是 `a_i` 元/升。油箱容量无限大，但每个站点只能购买整数升油。

每升油能跑 `d` 公里。开始时车在 `1` 号站点，油箱为空，要求最少花多少钱从 `1` 号站点开到 `n` 号站点。

### 思路

先看一个可以直接验证想法的朴素解：

把“当前位置 + 还剩多少公里油量”当成状态，跑一遍最短路：

- 在当前站点买一升油，花 `a_i` 元，油量增加 `d`
- 如果油量够，就开到下一站

这个做法在小数据上完全正确，也适合拿来对拍：

@include-code(./brute.cpp, cpp)

但它的状态很多，不适合本题 $10^5$ 的数据范围。

关键观察是：油箱无限大，所以只要前面出现过更便宜的站点，我们就完全可以提前在那个站多买一些油带着走。

于是走到第 `i` 段路之后，我们真正关心的不是“油箱里此刻还剩几升”，而是：

- 到目前为止一共走了多少公里
- 这些路程总共至少需要买多少整数升油

设前 `i` 段路的总长度是 `dist_sum`，那么要覆盖这些路程，至少需要：

$ceil(dist_sum / d)$

升油。

如果这个值比前面已经买过的总升数更多，就说明现在必须再补一些油。
而这些新增的升数，最优一定是在前 `i` 个站点里油价最低的那个站买。

所以从左到右扫描每一段路时：

1. 维护到当前为止的最小油价
2. 维护累计路程 `dist_sum`
3. 算出当前至少需要的总升数 $need = ceil(dist_sum / d)$
4. 如果 `need` 比已经买过的升数更多，就把新增部分按当前最小油价计入答案

这样只要线性扫一遍就够了。

### 另一种写法：新低站点分段

主解边扫边补油，还有一种等价的组织方式：先把油价序列里“从 1 号站开始依次出现的新低站点”挑出来（严格下降子序列，允许跳过中间站点），再按相邻两个新低站之间的距离分段结算。

贪心仍然成立：比新低站贵的站点，油都能用更便宜的价格提前买在前面。每段的起点就是这段里最便宜的站，缺口都在起点买；只能整升买，向上取整后多出来的油结转下一段。

Python 版本做法相同，用 `itertools.accumulate` 算前缀和与前缀最低价，用 `filter` 取新低位置：必须是 `filter` 而不是 `takewhile`，谓词失败后 `filter` 还会继续看后面的元素，价格回升不中断这个子序列，后面再创新低仍然会记进来。

两种写法时间复杂度都是 $O(n)$，区别只是“边扫边结算”和“先记新低再分段”。

### 复杂度

时间复杂度是 $O(n)$，空间复杂度是 $O(1)$（不计输入数组）。

### 总结

这题最容易卡住的点是“每次只能买整数升”。

一旦把问题改写成“累计路程至少需要多少总升数”，整数限制就被自然吸收到 $ceil(dist_sum / d)$ 里，剩下就是经典的“新增需求在此前最便宜处购买”的贪心。
