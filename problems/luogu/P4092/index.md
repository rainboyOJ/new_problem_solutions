## 形式化题目

给定一棵以 1 为根的有根树，维护一个标记集合 $M$，初始 $M = \{1\}$。支持两类操作：

1. 把节点 $u$ 加入 $M$（重复加入无效果）；
2. 询问 $u$ 到根路径上深度最大的已标记节点（$u$ 本身也算自己的祖先）。

要求按顺序处理全部操作，输出每次询问的答案。

## 思路

先看一个可以直接验证想法的朴素解：

@include-code(./brute.cpp, cpp)

`brute.cpp` 每次询问从 $u$ 沿父亲链向上爬，遇到第一个标记就输出，单次询问最坏 $O(n)$（链形树），总复杂度 $O(nq)$，无法通过 $10^5$ 的数据。

关键观察有两点：

1. **重链剖分把路径拆成 $O(\log n)$ 段**：从任意节点到根的路径，按"链头跳链头"的方式只跨 $O(\log n)$ 条轻边，每段是一条重链上的连续 dfn 区间。
2. **同一重链上"最近"就是"dfn 最大"**：链上深度随 dfn 严格递增，所以一段链内离 $u$ 最近的已标记节点就是区间内已标记 dfn 最大的那个。

于是用重链剖分 + 线段树：线段树维护每个 dfn 位置的最大已标记 dfn（0 表示无标记）。标记操作是幂等的点更新；询问从 $u$ 出发逐链向上——查 `[dfn[top[u]], dfn[u]]` 的区间最大值，非 0 就还原成节点输出，否则跳过整段跳到链头的父亲，直到进入包含根的重链（根 1 永远有标记，答案必然存在）。

下面这张 ASCII 图展示样例的查找过程（树形：`1-(2,3)`、`2-(4,5)`，重链为 `1 -> 2 -> 4`，`3`、`5` 是轻链）：

```text
标记集合变化：
  初始: {1}       -> C 2 后: {1, 2}

Q 2 : 链1 [dfn1,dfn2] 最大已标记 dfn = dfn[2] -> 答案 2
Q 5 : 先查链5 [dfn5,dfn5] 无标记 -> 跳到 parent[5]=2
      再查链1 [dfn1,dfn2] 最大已标记 dfn = dfn[2] -> 答案 2
Q 3 : 先查链3 [dfn3,dfn3] 无标记 -> 跳到 parent[3]=1
      再查根链 [dfn1,dfn1] 最大已标记 dfn = dfn[1] -> 答案 1
```

观察"Q 5"和"Q 3"的路径：它们都先查了自己的链段（没有标记），各跨一条轻边才到达根所在的重链，这正是"逐链向上"只走 $O(\log n)$ 段的原因；而"Q 2"因为目标就在自己链上，一次区间查询直接命中。

## 复杂度

- 预处理：BFS + 子树统计 + 重链编号，$O(n)$。
- 标记 `C u`：线段树点更新 $O(\log n)$。
- 询问 `Q u`：最多跨 $O(\log n)$ 条轻边，每段区间 max $O(\log n)$，总 $O(\log^2 n)$。
- 空间：$O(n)$。

## 总结

"向上找最近标记祖先"的通用套路：用重链剖分把祖先路径拆成 $O(\log n)$ 段连续区间，把"最近"翻译成"段内最大已标记 dfn"，交给线段树维护。本题标记是单点幂等更新，比常规路径修改题更简单，但"逐链向上 + 链段内贪心"的框架与 rbook 的《[树链剖分](https://rbook2.roj.ac.cn/tree-algo/hld/index.html)》文章中的路径操作（`hld` 模板）完全一致。
