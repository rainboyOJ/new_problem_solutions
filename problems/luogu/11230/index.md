### 题意

有 `n` 个人，每个人有一个整数序列 `S_i`。每一轮选择一个人 `p`，从他的序列中选择一个长度在 `[2,k]` 的连续子序列作为接龙序列。

规则是：

- 第一轮的接龙序列必须以 `1` 开头；
- 之后每轮的接龙序列必须以上一轮的最后一个数开头；
- 相邻两轮不能由同一个人接龙。

每个询问给出 `r` 和 `c`，问是否能进行恰好 `r` 轮，并让最后一轮的最后一个数为 `c`。

### 思路

先看一个可以直接验证想法的朴素解：

@include-code(./brute.cpp, cpp)

`brute.cpp` 对小数据显式枚举每个人序列中所有合法连续子序列，把它看成一条有颜色的边：

```text
起点数值 -> 终点数值，颜色 = 接龙人编号
```

然后做恰好 `r` 步的 DP，并检查相邻边颜色不同。

正解也沿用这个模型，但不能显式枚举所有边。因为当 `k` 很大时，一个位置后面很多位置都可以作为结尾，边数可能接近平方。

#### 状态压缩

第 `round` 轮结束后，我们关心：

```text
某个数值 value 是否能作为当前结尾，以及上一轮是哪个人接龙
```

下一轮如果要使用人 `p`，只需要知道：当前 `value` 是否存在一种到达方式，使得上一轮接龙人不是 `p`。

因此对每个 `value`，不需要保存所有可能的上一轮接龙人，只需要保存最多两个不同的人：

- 如果保存的人中有一个不是 `p`，就能接着用 `p`；
- 如果只保存了一个人且正好是 `p`，就不能连续用 `p`；
- 如果保存了两个人，那么对任意 `p`，至少有一种情况可以避开 `p`。

第一轮之前，认为结尾值是 `1`，上一轮接龙人为特殊编号 `0`，表示还没有人接龙，因此第一轮可以使用任何人。

#### 如何避免枚举所有边

固定某个人 `p`，扫描他的序列。

如果某个位置 `i` 的值可以作为本轮接龙序列的开头，那么它可以到达后面的：

```text
i+1, i+2, ..., i+k-1
```

这些位置都可以作为结尾。扫描时维护一个 `reach_until`，表示当前最远能覆盖到哪个结尾位置：

1. 扫到位置 `pos` 时，如果 `reach_until >= pos`，说明当前位置可以作为结尾；
2. 再判断当前位置的值能否作为开头，如果能，就用 `pos + k - 1` 更新 `reach_until`。

注意要先判断“当前位置能否作为结尾”，再把当前位置作为开头加入覆盖范围，这样才能保证接龙序列长度至少为 `2`。

#### 转移过程

每一轮做一次：

1. 清空下一轮状态；
2. 对每个人扫描他的序列；
3. 用上一轮状态判断某个位置能不能作为开头；
4. 用 `reach_until` 找出这一轮能到达的结尾；
5. 把“结尾值 + 当前接龙人”加入下一轮状态。

所有询问的 `r <= 100`，所以可以预处理每一轮哪些结尾值可达，然后直接回答询问。

### 复杂度

设单组数据所有序列长度之和为 `sum_l`，询问中的最大轮数为 `R`，值域上限为 `V = 200000`。

- 时间复杂度：`O(R × (sum_l + V))`
- 空间复杂度：`O(RV + V + sum_l)`

题目中 `R <= 100`，`sum_l <= 2 × 10^5`，可以通过。

### 总结

本题的关键是把连续子序列看成“有颜色的转移”，颜色就是接龙人。相邻不能同人这个限制看似需要保存很多历史，但实际上每个结尾值只保留两个可能的上一轮接龙人，就足够判断下一轮能不能使用某个人。
