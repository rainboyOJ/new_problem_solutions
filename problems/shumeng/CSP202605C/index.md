## 形式化题目

$n$ 个进程、$m$ 种资源，每个进程从第 $st_i$ 段首开始活动，按任务列表依次申请资源并运行，任务长度 $t_{i,j}$ 段。每段分为段首（申请）、段中（收益）、段末（推进/释放）。

- 同一资源同一段首被多进程申请时：资源空闲则编号最小者成功，否则全部失败；
- A 类：连续 $w$ 次申请失败后，在段末释放自己占有的全部资源，继续等待；
- B 类：连续 $w$ 次申请失败后，直接放弃该资源并进入运行；
- C 类：连续 $w$ 次申请失败后在段首强行抢夺，多个 C 同时抢夺时编号最大者成功。

运行中的进程每段获得等于其当前持有资源数的收益。输出每个进程的总收益与运行段数；若系统因死锁被强制结束，输出 `-1`。

## 思路

### 三个阶段逐一模拟

每段严格按“段首申请 → 段中收益 → 段末推进和释放”推进。进程维护状态、当前任务、等待开始时间、剩余段数与收益；资源维护当前占有者。

### 段首的统一处理

同一资源的申请必须收集到一起后一次性处理，不能按进程编号顺序修改资源状态，否则后面的进程会看到前面进程刚改过的状态：

1. 若本段有到期的 C 类进程（等待已达 $w$），编号最大者抢占资源，其余 C 类申请失败但仍进入运行；
2. 否则若资源空闲，编号最小的申请者成功；
3. B 类第 $w$ 次失败直接进入运行；A 类第 $w$ 次失败打上“段末释放”标记。

```text
段首申请:  收集 requests -> 优先 C 抢夺 -> 空闲则最小号成功 -> 记录 B 放弃 / A 待释放
段中收益:  运行进程 gain += 当前持有资源数, remain--
段末推进:  A 释放全部资源 -> 任务结束则释放并完成 / 否则进入下一任务
```

### 死锁检测

没有 C 类进程时系统可能陷入死锁。所有进程开始后，若某个完整系统状态（各进程的阶段、任务、等待时长与资源归属）再次出现，则之后必然无限循环，直接终止并把未完成的进程标为 `-1`。用哈希集合记录状态即可。

## 复杂度

- 时间：每段需要 $O(nm)$ 处理请求与统计收益，本题 $n\le 10,\ m\le 40$，模拟段数有界。
- 空间：$O(nm)$，加上死锁检测使用的哈希集合。

## 总结

资源申请必须按段首的同时性统一处理，不能按进程编号依次修改资源状态；把每一段拆成“申请、收益、推进”三个阶段即可准确模拟特殊规则。死锁检测的关键是识别出完整系统状态的循环。
