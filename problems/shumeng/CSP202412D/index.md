### 题意

站在格子 `i` 时，可以跳到区间 `[i+1, min(n,i+k_i)]` 中的任意落点 `j`；落到 `j` 后会后退 `a_j` 格，下一次实际站在 `j-a_j`。求从格子 `1` 到格子 `n` 的最少跳跃次数，无法到达时输出 `-1`。

### 思路

先看直接 BFS：

@include-code(./brute.cpp, cpp)

如果当前站在 `i`，直接枚举所有落点 `j`，就能得到转移 `i -> j-a[j]`。但同一个落点 `j` 可能被许多状态的跳跃区间重复扫描，最坏会达到 $O(n^2)$。

优化时观察 BFS 的出队顺序：状态按距离从小到大出队。对于某个落点 `j`，第一次有状态的跳跃区间覆盖它时，已经使用了能够到达该状态的最小跳数；以后再从更晚出队的状态使用 `j`，不会得到更短的路径。因此可以让每个落点只处理一次。

用并查集维护“下一个还没有处理的落点”：

- `find(x)` 返回不小于 `x` 的最小未删除下标；
- 处理落点 `j` 后，把它删除并令它指向 `find(j+1)`；
- 扫描状态 `i` 时，从 `find(i+1)` 开始，处理所有不超过 `min(n,i+k_i)` 的落点。

处理落点 `j` 时令 `v=j-a_j`。若 `v` 尚未访问，就把 `distance[v]` 设为 `distance[i]+1` 并加入 BFS 队列。并查集删除的是落点下标，不是状态下标，所以即使多个落点后退到同一个状态也不会影响正确性。

样例一中，从 `1` 可以处理落点 `2,3`，其中落点 `3` 让状态 `2` 入队；后续状态继续处理还未删除的落点，最终通过落点 `10` 到达终点。

样例一的 BFS 过程可以压缩成下面的表格。落点只在第一次被扫描时出现：

| 出队状态 | 跳数 | 本次处理的落点及转移 | 新入队状态 |
| ---: | ---: | --- | --- |
| 1 | 0 | `2 -> 1`，`3 -> 2` | `2` |
| 2 | 1 | `4 -> 3`，`5 -> 4`，`6 -> 3` | `3, 4` |
| 3 | 2 | `7 -> 6`，`8 -> 8` | `6, 8` |
| 4 | 2 | 无（落点已删除） | 无 |
| 6 | 3 | `9 -> 6`，`10 -> 10` | `10` |

状态 `10` 首次以距离 `4` 入队，因此答案为 `4`。状态 `8` 后续即使还能覆盖部分落点，也不会改变已经得到的更短答案。

### 复杂度

每个落点只被并查集删除一次，`find` 的均摊复杂度为近似常数，因此时间复杂度为 $O(n\alpha(n))$，空间复杂度为 $O(n)$。

### 总结

区间转移的难点不是 BFS 本身，而是避免重复扫描区间中的落点。BFS 提供了“第一次覆盖落点时距离最优”的顺序保证，并查集则把所有已处理落点跳过，从而把大量区间枚举压缩为一次线性删除过程。

## 图示解析

这张流程图概括每个 BFS 状态的处理方式：

```text
出队状态 i
|- 确定落点区间 [i+1, min(n, i+k_i)]
   `- 并查集找到区间内尚未处理的 j
      |- 删除 j，转移到 j-a[j]
      `- 未访问状态入队
```

落点 `j` 被处理后不会再次参与后续区间扫描。因为 BFS 出队距离单调不减，后面状态通过同一落点得到的路径不可能更短。
