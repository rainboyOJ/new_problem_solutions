## 形式化题目

给定十进制数字串 $s = d_1 d_2 \cdots d_n$（只含数字字符）。要求输出把数位顺序整体颠倒后得到的整数的十进制表示，且结果不能有前导 0（结果本身就是 0 时输出 `0`）。

题面样例和边界情形正好展示"反转"与"去前导 0"这两步各自处理什么：

| 输入 | 反转字符后 | 删前导 0 后 | 观察点 |
| --- | --- | --- | --- |
| `10` | `01` | `1` | 题面样例：末位 0 倒序后跑到开头 |
| `100000` | `000001` | `1` | 连续多个尾部 0 一次删净 |
| `1010` | `0101` | `101` | 只删开头，中间和末尾的 0 原样保留 |

三行分别是"单个尾部 0"、"整段尾部 0"、"中间 0 不受影响"三个典型情况：**前导 0 恰好一一对应原串的尾部 0**，这正是后面"反转 + `lstrip`"两步解法的依据。

## 正解

### 思路

**朴素做法：数值意义下取模倒序。** 想把数字倒过来，最直觉的算法是不断 $x \bmod 10$ 取出末位、再 $x \leftarrow \lfloor x/10 \rfloor$，从后往前输出每一位。但题面的数字串长度可达 250 位，64 位整数最多存约 19 位，输入根本装不进机器整数——$x$ 必须用高精度表示：每取一位都要做一次"大数除以 10"并扫过整个剩余串，总代价 $O(n^2)$，还得处理商的前导 0、末位取走后剩余全 0 等一堆细节。

**关键观察：这个"倒序"根本不是算术。** 十进制表示的数字倒过来，每一位的值不变、只换位置，中间不产生任何进位或借位：

$$d_1 d_2 \cdots d_n \;\longrightarrow\; d_n \cdots d_2 d_1$$

也就是说，把字符串反转后直接读出来就是答案，数值运算——连同那套高精度除法——完全不需要参与。问题降维成两步纯字符串操作：

1. `s[::-1]` 反转：$O(n)$ 的切片拷贝；
2. `lstrip('0')` 删前导 0：反转后开头的 0 恰好一一对应原串末尾的 0，删掉即满足"开头不能为 0"；`lstrip` 只删前缀，中间的 0 不受影响（`1010` → `0101` → `101`）。

两步顺序可以交换（先把原串尾部的 0 删掉再反转完全等价），代码选"先反转再删"，一个链式表达式就写完了。全 0 输入会被删成空串，用 `or '0'` 兜底，输出永不为空。样例 `100000` 走这条链：反转得 `000001`，`lstrip('0')` 一次删净得 `1`。

### 复杂度

- 时间复杂度：$O(n)$，$n$ 为数字串长度（$\leqslant 250$，真实数据最长 294）。读入、切片反转、前缀删除各只扫常数遍；朴素取模需要 $O(n^2)$ 的高精度除法，正解在量级上严格更优，1000ms 时限毫无压力（本地实测单组约 0.02s）。
- 空间复杂度：$O(n)$，输入串与反转副本共常数份长度 $n$ 的字符串，无递归、无辅助数组。

## 总结

- 同一个"把数字倒过来"，按数值理解要写高精度除法 $O(n^2)$，按字符串理解只是一次切片 $O(n)$；拿到高精度题先问一句"这个操作真的需要算术吗"。
- 前导 0 约束在字符串层面天然成立：反转后的前缀 0 就是原串的后缀 0，`lstrip('0')` 一次删净，全 0 输入用 `or '0'` 兜底。
- 长度 250 的真正作用是排除"读成 64 位整数再取模"的偷懒写法，它不暗示任何算法优化——这题本来就只有一个 $O(n)$ 的做法。
