## 形式化题目

给定两个双精度浮点数 $a$、$b$（$b \neq 0$），求余数 $r$，满足题面定义：

$$a = k \times b + r,\quad k \in \mathbb{Z},\ 0 \leqslant r < b$$

也就是整数取模 `%` 的浮点版本：$k$ 是 $a$ 里能塞下的整数个 $b$，$r$ 是剩下的那一小段。当 $a, b > 0$ 时 $k = \lfloor a / b \rfloor$，于是 $r = a - \lfloor a/b \rfloor \cdot b$。

输入样例：

```
73.263 0.9973
```

输出样例：

```
0.4601
```

样例推演如下表，展示从"读入两个数"到"输出字符串"的每一步：

| 步骤 | 操作 | 结果 |
| --- | --- | --- |
| 读入 | `a, b = map(float, input().split())` | `a = 73.263`，`b = 0.9973` |
| 求整数商 | $\lfloor a/b \rfloor = \lfloor 73.4613\ldots \rfloor$ | $k = 73$ |
| 相减 | $73.263 - 73 \times 0.9973 = 73.263 - 72.8029$ | $r = 0.4601$ |
| 格式化 | `f"{r:.6g}"`（6 位有效数字） | `0.4601` |

观察重点：$k$ 必须**向下取整**而不是四舍五入（$73.461$ 取 $73$ 才能保证 $0 \leqslant r < b$）；而期望输出 `0.4601` 只有 4 位有效数字，说明输出按有效数字定长——这与真实评测数据 `problem0.out` 的 `5024.45`（原值 $5024.44752057$）是同一条规则：**6 位有效数字**，与 C++ `cout` 的默认精度一致。

## 正解

### 思路

这道题的计算只有一条链路："读入 → 取余 → 格式化输出"。按定义展开的朴素写法 $r = a - \operatorname{int}(a/b) \cdot b$（评测仓库附带的 C++ 参考解 `std.cpp` 就是这一行）与最终做法是同一件事的两种写法，不存在能暴露瓶颈、值得单独成层的独立暴力版本，再写一层只会得到几乎相同的代码。所以本文不设暴力层，按直接正解型组织；真正要学的是**取余与格式化各自的精度语义**。

1. **取余用 `math.fmod`**：`fmod(a, b)` 的数学定义与题面逐字相同——存在整数 $n$ 使 $a = n \cdot b + \operatorname{fmod}(a,b)$，且 $b > 0$ 时结果落在 $[0, b)$。IEEE-754 规定 `fmod` 返回**精确**余数，不做乘除回代，因此既没有累计舍入，也不会出现 $r$ 微小越界（例如 $-1.4 \times 10^{-14}$ 或略大于 $b$）这类回代误差。
2. **输出用 `:.6g`**：期望输出是 6 位有效数字的 `%g` 语义（去尾随零、必要时切科学计数法），与 C++ `cout` 默认精度对同一个 double 生成相同字符串。`print(r)` 打印"最短可还原"的变长串，`problem0` 会输出 `5024.44752057` 而期望是 `5024.45`，逐字比对必然失败。

排除的备选写法：

| 写法 | 为什么不行 |
| --- | --- |
| `print(a - int(a/b) * b)` | 算法正确，但除、乘、减三次舍入可能让 $r$ 越界若干 ulp；且 `print` 输出完整 repr，格式不符 |
| `print(r)`（`r` 用 `fmod`） | 数值精确，但输出 `5024.44752057` 而非 `5024.45` |
| `a % b`（Python 运算符） | 对正数与 `fmod` 一致，但语义是"取模"（结果符号随除数），题面讲的是 `fmod` 的截断余数；负数输入时两者符号不同 |
| `round(r, 4)` / 手工截位 | 按固定小数位而非有效数字舍入，位数对不上：`1288.8119…` 得 `1288.8119`（期望 `1288.81`），`5024.44752057` 得 `5024.4475`（期望 `5024.45`） |

`a - int(a/b)*b` 与 `fmod` 在全部 10 组真实数据上输出完全相同（该数据集没有踩到回代误差），但 `fmod` 在任意输入上都严格落在 $[0, b)$，是更稳的同阶写法——复杂度同样是 $O(1)$，这里优化的不是规模而是精度。

### 复杂度

- 时间复杂度：$O(1)$，一次解析、一次取余、一次格式化，与数值大小无关；实测单例约 0.016 s，远低于 1000 ms 限制。

## 总结

- 浮点取余题，直接正解型：`float` 读入 → `math.fmod(a, b)` → `f"{r:.6g}"` 输出，三步到位。
- `fmod` 的定义就是题面的 $a = k \times b + r$（$k$ 取截断整数），且 IEEE-754 保证它是**精确**余数，天然满足 $0 \leqslant r < b$；`a - int(a/b)*b` 是同一定义的近似回代，可能越界若干 ulp。
- 这道题的"隐含一半"是输出格式：6 位有效数字、`%g` 语义，与 C++ `cout` 默认精度对齐——数值算对但格式写成 `print(r)` 同样过不了。
- 题面要求 $0 \leqslant r < b$ 隐含 $b > 0$，真实评测数据 10 组也均为正数：实测真实评测数据 10/10 PASS（约 0.016 s / 14.6 MB），题面样例逐字一致。
