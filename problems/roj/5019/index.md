## 形式化题目

给定一个正整数 $n$（$1 \le n \le 100$）。
要求将区间 $[1, n]$ 内所有的偶数按照由小到大的顺序，在同一行内依次输出。
如果有多项，两项之间以一个空格隔开，且行末不需要多余的空格。
如果区间内不存在偶数（例如 $n=1$ 时），则不输出任何内容（0 字节）。

## 正解

### 思路

对于偶数遍历，我们可以直接从最小的正偶数 $2$ 开始，每次递增 $2$，即可保证遇到的每一个数都是偶数。这种**步长为 2** 的方法（`for (ll i = 2; i <= n; i += 2)` 或 Python 中的 `range(2, n + 1, 2)`）比遍历每一个数再通过 `i % 2 == 0` 来判断更加直接、高效，也使得代码逻辑更简洁。

本题的重点在于**输出格式和边界特判**：
1. **多项输出格式**：要求相邻偶数间只有一个空格，且行首尾无多余空格。在 C++ 中，我们可以引入一个 `bool printed` 标志变量，第一次输出不带空格，之后的每一次在输出数字前先输出一个空格。Python 中则可以直接使用 `" ".join(map(str, evens))` 优雅完成。
2. **空答案边界（极大坑点）**：当 $n = 1$ 时，区间 $[1, 1]$ 内不存在任何偶数。题目的数据和逻辑均要求此时**什么也不输出**，即程序执行结束后应产生一个 **0 字节**的文件，而不是输出一个空行（`\n`）。因此在 C++ 实现中，只有当 `printed` 为 `true`（至少输出了一个数字）时，才在末尾补上换行符。

### 复杂度

- **时间复杂度**：循环步长为 2，共执行 $\approx n/2$ 次。因此时间复杂度为 $\mathcal{O}(n)$。在 $n \le 100$ 的数据规模下耗时可以忽略不计。
- **空间复杂度**：除读入和少量的控制变量外不需额外空间。Python 里的生成器对象/临时序列也消耗极少内存。空间复杂度为 $\mathcal{O}(1)$。

## 总结

本题虽然是一道极其基础的循环入门题，但其实暗含了几个值得注意的点：
1. **算法优化视角**：与其「逐个遍历并做 $i \pmod 2 = 0$ 的判断」，不如「从 $2$ 开始，以步长 $2$ 直接生成目标元素」，这不仅节省了运算开销，也是将数学规律直接转化为算法逻辑的优良习惯。
2. **末尾无多余空格技巧**：使用布尔型标志变量（C++ 的 `printed`）或字符串拼接工具（Python 的 `join`），这是格式化输出的经典套路。
3. **空答案（0 字节 vs 1 字节空行）**：本题最容易踩坑的是 $n=1$ 这个边界点。区间内没有偶数，答案为**空集**，此时的正确输出是**什么都不输出**（0 字节），而**不是输出一个空行**。在很多 OJ 上，严格判题器是能区分这两种形态的（0 字节对应文件为空，而 1 字节空行对应输出了 `\n`）。本题的数据集也确实通过人工字节级检查确认了 $n=1$ 的答案文件 `problem1.out` 是 `0` 字节长度，需在代码中进行精准控制。
