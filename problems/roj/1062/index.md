## 形式化题目

给定整数 $n$（$0 \leqslant n < 100$）和 $n$ 个 $[0,100]$ 内的整数成绩 $a_1, a_2, \dots, a_n$，求其中的最大值；$n=0$ 时序列为空，输出 $0$。

### 样例

输入：

```
5
85 78 90 99 60
```

输出：

```
99
```

5 个成绩中第 4 个 $99$ 最大，所以输出 $99$。

## 正解

### 思路

**朴素做法**：打擂台。用一个变量 `cur` 记录"当前看到的最高分"，从左到右扫一遍，每个成绩比 `cur` 大就更新它。一遍扫描 $O(n)$，每个成绩至少要看一次，所以这已经是复杂度下界——朴素做法没有可消除的瓶颈，问题只在于表达：读入、循环、比较、更新四行样板，承载的信息其实只有一句"取最大值"。

**推导**：观察擂台过程会发现，整个扫描只需要携带**一个标量**状态——当前最大值，历史成绩看过就丢。下表展示样例成绩被逐个比较时这个唯一状态的变化（行 = 第几次比较，两列分别是当前读到的成绩和状态值）：

| 步骤 | 当前成绩 | 当前最高分 |
| --- | --- | --- |
| 1 | 85 | 85 |
| 2 | 78 | 85 |
| 3 | 90 | 90 |
| 4 | 99 | 99 |
| 5 | 60 | 99 |

读这张表要抓住两点：状态里始终只有一个数；它只在遇到更大成绩时更新（第 2、5 步没变）。"单标量状态 + 单遍扫描"正是一次**归约**，而 Python 内置 `max()` 就是这个归约的 C 实现，于是整段循环可以塌缩成一个调用：复杂度不变、常数更小、代码更短。

**边界**：题面规定成绩都是 $[0,100]$ 的非负整数，所以擂台初值取 $0$ 是安全的——不会盖过任何真实成绩。$n=0$ 时成绩序列为空，`max(..., default=0)` 直接返回 $0$，与"没有成绩按 0 计"的语义一致，也避免了对空序列取最大值的 `ValueError`。

## 总结

求 $n$ 个数的最大值是典型的单标量归约：先想到逐个比较的擂台扫描，再注意到状态只需一个数，就能把循环塌缩为内置 `max()`；$n=0$ 的空序列用 `default=0` 兜住，正确性依赖"成绩非负"这一题面事实。
