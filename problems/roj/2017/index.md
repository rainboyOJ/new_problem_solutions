## 形式化题目

给定一个 $R$ 层的数字金字塔：第 $i$ 层（$1 \leqslant i \leqslant R$）有 $i$ 个数
$a_{i,1}, a_{i,2}, \ldots, a_{i,i}$，所有数都是非负整数。

一条从顶部到底部的路径是一个下标序列 $j_1 = 1, j_2, \ldots, j_R$，满足
$j_{i+1} \in \{j_i,\ j_i + 1\}$，即每一步只能走向下一层的正下方或右下方；
路径和为 $\sum_{i=1}^{R} a_{i,j_i}$。求所有路径中路径和的最大值。

样例金字塔如下，路径 $7 \to 3 \to 8 \to 7 \to 5$ 的和为 $7 + 3 + 8 + 7 + 5 = 30$：

```text
    7
   3 8
  8 1 0
 2 7 4 4
4 5 2 6 5
```

把这张图竖着看：第 $i$ 层的第 $j$ 个数，在下一层能被走到它的只有两个位置——
第 $j$ 个与第 $j+1$ 个。反过来同样成立：任何一个格子，只有上一层的两个格子能走到它。
这是后面所有推导的唯一依据。

## 正解

### 思路

**朴素做法与它的瓶颈。** 最直接的想法是 DFS 枚举所有路径，每条路径累加求和取最大。
路径条数是 $2^{R-1}$：$R = 5$ 时 16 条还能接受，$R = 1000$ 时约 $3 \times 10^{300}$ 条，
连枚举这个动作本身都写不完，必然不可行。

枚举慢的根源不是"路径太长"，而是**同一段后缀被重复展开**：
从顶部走到 $(i,j)$ 的路径各不相同，但它们到达 $(i,j)$ 之后的走法完全一样。
只要记住"走到 $(i,j)$ 时能取得的最大和"，重复计算就消失了。

**状态定义。** 令

$$dp_{i,j} = \text{所有从 } (1,1) \text{ 走到 } (i,j) \text{ 的合法路径中，路径和的最大值}.$$

这个定义合法的关键是**无后效性**：走到 $(i,j)$ 之后还能取到什么，只取决于 $(i,j)$
本身，与"是怎么走到这里的"无关。所以"前缀最优 + 同一段后缀"一定不劣于"前缀较差 + 同一段后缀",
丢掉较差的前缀不会有任何损失。

**转移方程。** 能一步走到 $(i,j)$ 的位置只有两个：$(i-1,j-1)$（右下方）与
$(i-1,j)$（正下方）。于是

$$dp_{i,j} = a_{i,j} + \max(dp_{i-1,j-1},\ dp_{i-1,j}), \qquad dp_{1,1} = a_{1,1}.$$

第 $i-1$ 行只有 $i-1$ 个数，所以 $j = 1$ 时不存在 $dp_{i-1,0}$、
$j = i$ 时不存在 $dp_{i-1,i}$，这些越界项按 $-\infty$ 处理。

**为什么这样取就对。** 对层号归纳：第 1 层只有一条路径，结论成立；假设第 $i-1$ 层的 $dp$ 值都已正确，
则任何走到 $(i,j)$ 的路径最后一步必然来自 $(i-1,j-1)$ 或 $(i-1,j)$，其和
$\leqslant a_{i,j} + \max(dp_{i-1,j-1},\ dp_{i-1,j})$；另一方面，把取到最大值那个来源的最优路径再接一步到
$(i,j)$，就能取到这个上界。两边夹住，转移式恰好等于 $dp_{i,j}$。

**答案。** 终点可以停在底部任意位置，因此

$$\text{answer} = \max_{1 \leqslant j \leqslant R} dp_{R,j}.$$

注意不是 $dp_{R,R}$：下面样例的末行是 `24 30 27 26 24`，最大值出现在第 2 个位置。

**小规模推演。** 用题面样例把每一层的 $dp$ 值算出来（空单元格表示该行没有这一列）：

| $i \backslash j$ | $j=1$ | $j=2$ | $j=3$ | $j=4$ | $j=5$ |
| --- | --- | --- | --- | --- | --- |
| **1** | 7 | | | | |
| **2** | 10 | 15 | | | |
| **3** | 18 | 16 | 15 | | |
| **4** | 20 | 25 | 20 | 19 | |
| **5** | 24 | **30** | 27 | 26 | 24 |

表格每一行是一个 $dp$ 层，单元格 `dp[i][j]` 表示走到该位置的最大路径和。挑几个格子核对
转移：$dp_{2,2} = a_{2,2} + dp_{1,1} = 8 + 7 = 15$；
$dp_{5,2} = a_{5,2} + \max(dp_{4,1}, dp_{4,2}) = 5 + \max(20, 25) = 30$。
末行最大值 30 就是答案，对应的路径正是 $7 \to 3 \to 8 \to 7 \to 5$。

**空间压缩。** 转移只读第 $i-1$ 行，所以算完第 $i$ 行就可以丢掉第 $i-1$ 行，
二维表压成一行（即滚动数组）。剩下的麻烦是行首、行尾"只有一个来源"的边界分支。

**消掉边界分支。** 与其在每格判断是否越界，不如把上一行**首尾各复制一份**：

```text
sources = [dp[0]] + dp + [dp[-1]]
```

补长后，第 $j$ 格的两个来源就固定是 `sources[j]` 与 `sources[j+1]`。
下表用 `dp` 表示上一行那个长度为 $i-1$ 的数组（`dp[k]` 就是 $dp_{i-1,k+1}$），
$j$ 是本行下标（$0 \leqslant j \leqslant i-1$）：

| 本格位置 | `sources[j]` | `sources[j+1]` | 等效来源 | 说明 |
| --- | --- | --- | --- | --- |
| $j = 0$（行首） | `dp[0]`，复制的行首自身 | `dp[0]` | 只有 `dp[0]` | 左上方不存在，`max` 自行退化 |
| $0 < j < i-1$（中间） | `dp[j-1]` | `dp[j]` | 左上方 `dp[j-1]`、正上方 `dp[j]` | 两来源齐全 |
| $j = i-1$（行尾） | `dp[i-2]` | `dp[i-2]`，复制的行尾自身 | 只有 `dp[i-2]` | 正上方不存在，同样退化 |

真正关键的只有第一行与第三行：它们把"越界时只有一个来源"编码成了"两个候选恰好相等"，
所以整段转移不需要任何 `if`。下面用 $i = 5$ 的最后一层验证（`dp = [20, 25, 20, 19]`）：
`sources = [20, 20, 25, 20, 19, 19]`，第 $j = 1$ 格取
`max(sources[1], sources[2]) = max(20, 25) = 25`，加上 $a_{5,2} = 5$ 得到 30，与 dp 表一致。

之所以能用"复制自身"代替 $-\infty$，是因为题面保证所有数非负，自身总是 $\geqslant -\infty$；
退一步说，即使允许负数，两个候选里有一个是自身，`max` 也绝不会取到比自身更小的值
（已用 2000 组随机负数对照朴素转移验证一致）。

**串起来。** 把"延伸一层"抽成函数 `extend(above, row)`：输入上一行的 $dp$ 值与本层原始数字，
输出本行的 $dp$ 值。整座金字塔就是把这个函数从左到右折叠一遍，最后对结果行取最大值：

```text
dp ← [a[0][0]]
for row in 第 2 层 … 第 R 层:
    dp ← extend(dp, row)
answer ← max(dp)
```

**读入的一个坑。** 题面给的是金字塔形排版（第 $i$ 行有 $i$ 个数），但"一行"并不总是等于"一层"。
如果实现成"按行切分、第二行就是一层的全部数字"，那么当所有数被摊在一行里时，
第 2 层会把后面每一层的数字全部吞掉，层结构直接崩掉（实测这种输入下会输出 8 而不是 30，
而且后面几层根本读不到）。稳妥的读法是只利用数学事实——**第 $i$ 层恰好有 $i$ 个数**——
按 $1, 2, \ldots, R$ 的长度依次切分 token，这样每层一行的标准排版和全部数字挤在一行的排版都能正确解析。

### 复杂度

- 时间复杂度：$O(R^2)$。第 $i$ 层做 $i$ 次 $O(1)$ 转移，总计 $\frac{R(R+1)}{2}$ 次；
  $R = 1000$ 时约 $5 \times 10^5$ 次，与输入规模同阶（每个输入数字至少要读一次，
  每个格子都要算出 $dp$），已是本题的最优复杂度，与标准 C++ 二维 DP 同阶。
- 空间复杂度：算法本身 $O(R)$（只保留上一行 $dp$ 与当前行）；实现把整份输入读进内存，
  额外的输入缓冲是 $O(R^2)$ 字节。$R = 1000$ 时实测峰值约 44 MB，低于 128 MB 限制。

## 总结

这道题是动态规划的入门模型：**路径计数与最优路径的核心不是枚举路径，而是给"位置"定义状态**。
本题的状态 $dp_{i,j}$ 只回答一个问题——走到这个格子的最大路径和是多少；它能成立，
是因为后续走法与"怎么走来的"无关（无后效性），于是转移只需上一层相邻两格的较大值：

$$dp_{i,j} = a_{i,j} + \max(dp_{i-1,j-1},\ dp_{i-1,j}), \qquad \text{answer} = \max_j dp_{R,j}.$$

实现上有两个值得带走的技巧：转移只依赖上一层，所以二维表可以压成一行滚动；
把上一行首尾各复制一份，行首行尾的越界分支就自然消失，转移退化成一句列表推导。
读入时按"第 $i$ 层有 $i$ 个数"切分 token，而不是按行切分，能同时兼容紧排版与松散排版。
实测 9 组真实数据全部一致，最大规模 $R = 1000$ 单点约 0.075 s、峰值内存 44.5 MB，
相对 1000 ms / 128 MB 的限制余量充足。
