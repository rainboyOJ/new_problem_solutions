## 形式化题目

给定一个长度 $n \geqslant 1$ 的非负整数序列 $A = (a_1, a_2, \dots, a_n)$，求它的**最大跨度值**

$$D = \max_{1 \leqslant i \leqslant n} a_i \;-\; \min_{1 \leqslant i \leqslant n} a_i$$

也就是统计学里的极差。样例 $n = 6$、序列 $3, 0, 8, 7, 5, 9$ 中最大值为 $9$、最小值为 $0$，故 $D = 9$。

只有两个元素真正决定答案，把它们挑出来即可：

| 元素 | 在序列中的角色 | 是否影响答案 |
| --- | --- | --- |
| $3$ | 普通元素，既非最大也非最小 | 否 |
| $0$ | 最小值 $\min A$ | 是（从 $\max A$ 中减去它） |
| $8$ | 普通元素 | 否 |
| $7$ | 普通元素 | 否 |
| $5$ | 普通元素 | 否 |
| $9$ | 最大值 $\max A$ | 是（作为被减数） |

也就是说，答案 $D = \max A - \min A$ 只由"最大值"与"最小值"两个下标决定，序列中其余元素无论取什么值都不改变结果——这是下面省掉排序的依据。

## 正解

### 思路

**朴素想法**是排完序再看两端：

```python
ordered = sorted(values)
print(ordered[-1] - ordered[0])
```

语义上无懈可击，代价却是 $O(n \log n)$ 时间外加 $O(n)$ 空间：为了得到两个极值，它把 $n$ 个元素全部排好，而中间 $n - 2$ 个元素的相对次序**对答案毫无影响**，等于白做。这正是可以砍掉的瓶颈——题目要的不是有序序列，而是两个极值。

于是把"整段排序"换成"只维护两个数"：每读入一个 $a_i$，做两次比较更新当前最大值 `mx` 与当前最小值 `mn`，读完输出 `mx - mn`。每个元素至少要被查看一次（否则无法判断它是否更大或更小），所以 $\Theta(n)$ 就是这道题的**下界**，这个做法正好达到下界；本题因此没有"暴力 → 正解"的优化阶梯，朴素与最优之间只差"放弃排序、改用常数状态"这一个选择。

这里有一个**必须避开的坑**：题面说"非负整数"，很容易顺手写成

```python
mx, mn = 0, 0
```

`mx = 0` 没问题（非负数的最大值至少是 $0$），但 `mn = 0` 只在序列里真的出现过 $0$ 时才对。若输入是 `3 / 3 5 5`，正确的最小值是 $3$、跨度是 $2$，而这个初始化会把 $0$ 当成最小值，输出 $5$。**写对的关键是让最小值以一个真实元素（或值域之外的正无穷）为初始值**，而不是拿 $0$ 当"非负数的下界"。

Python 的 `max()` / `min()` 内建恰好绕开了整个问题：它们都以**第一个元素**为初始值再逐个比较，不需要任何哨兵常量，也就不存在"哨兵没落在值域外"的风险。同时，这两个函数是与"边读边更新"完全同一模型的实现（归约可结合、可交换，任意切分后合并结果不变），只是把逐元素循环下沉到了 C 层。最后一个格式细节：第二行有多少个数由第一行的 $n$ 决定，用切片 `data[1:1 + n]` 按 $n$ 取出序列，比"把所有 token 都算进来"更忠实于题面。

### 复杂度

- 时间复杂度：$O(n)$。一次 `split()`、$n$ 次整数转换、两遍极值扫描（`max` 与 `min`）都是线性的；比排序写法的 $O(n \log n)$ 少一个 $\log n$。由于每个元素至少要被读一次，$O(n)$ 是下界，无法再快。
- 空间复杂度：$O(n)$。`data` 存 $n + 1$ 个字节串 token，`values` 存 $n$ 个整数；归约本身只用常数个游标状态。本题 $n \leqslant 1000$，实测峰值内存约 14.5 MB，远低于 128 MB。

## 总结

这道题要的量只有一个，而且由两个"可结合的归约"完全决定，所以**一次线性扫描既是正解也是下界**：维护最大值与最小值两个状态，读完相减即可，不需要排序，也不需要保存元素之间的任何相对次序。

两个容易踩的点：一是别写 `mn = 0`——"非负"说的是取值范围，不代表最小值是 $0$，$n = 1$ 或所有元素都大于 $0$ 时它会直接算错；二是按第一行的 $n$ 截取第二行的数，让"序列长度"这件事在代码里有名字。用 `max()` / `min()` 内建可以一次性避开第一个坑，因为它们以第一个元素为初始值。

实测 10 组评测数据全部一致，单组约 0.015 s、峰值内存 14.5 MB，相对 1000 ms / 128 MB 的限制十分宽裕。
