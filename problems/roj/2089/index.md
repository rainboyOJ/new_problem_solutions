## 形式化题目

$N \times N$ 网格（$1 \le N \le 7$），起点在左上角、终点在左下角。求从起点出发**恰好经过每个格子一次**并到达终点的路径条数。

## 正解

### 思路

#### 1. 朴素搜索与规模

这是**哈密顿路径计数**（NP-hard），$N = 7$ 时 49 个格子的全排列搜索空间高达 $48!$ 量级，纯 DFS 必然爆炸。出路是**强剪枝**：每走一步都判断剩余局面是否还有解，尽早砍掉死枝。

#### 2. 状态与增量维护

- **访问状态**：每个格子一个 bit，49 格用一个 Python 整数 `vis` 表示，测试/更新都是 $O(1)$ 位运算；
- **度数表** `deg[i]`：格子 $i$ 的**未访问邻居数**，随访问增量维护；
- **度 0/1 集合**：`zeros`（度 0）、`ones`（度 1）位掩码——这两个量是剪枝的核心信号。

#### 3. 三大剪枝

1. **区域切割**：若当前格的左右均已封死（访问/越界）而上下都未访问（或反之），走出当前格后未访问区域被切成两半，永远走不遍 → 剪枝。
2. **死胡同（度 1）**：度 1 的内部格只能"一进一出"，若它不与当前格相邻，它将成为永远进不去/出不来的死角 → 剪枝；若恰有一个度 1 邻居，它就是**唯一合法的下一步**（强制步）。
3. **度 0 / 集市隔绝**：出现度 0 的内部格立即剪；终点集市若被未访问格隔离（与所有可走邻居不通）也剪。

加上「按度数小的邻居优先试」（尽早撞墙暴露死局），这套剪枝让 $N = 7$ 的搜索在时限内完成。

### 复杂度

- **时间复杂度**：最坏仍是指数级（哈密顿计数固有的 NP 难度），但三大剪枝把实际搜索量压到可接受范围，$N = 7$ 实测秒级。
- **空间复杂度**：$O(N^2)$ 的位掩码与度数表，递归栈 $O(N^2)$。

## 总结

- 哈密顿路径计数的标准姿势：DFS + 位掩码状态 + **可行性剪枝**（切割/度 1 强制度 0 判死）。
- 度数增量维护是剪枝效率的关键：每次只更新当前格邻居的度，均摊 $O(1)$。
- 「强制步」剪枝（度 1 邻居必走）往往一次砍掉整棵分支，是本题最大的加速来源。
