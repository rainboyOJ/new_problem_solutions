## 形式化题目

给定一个 $r \times c$ 的字符矩阵作为虚拟键盘，以及一个长度为 $|S|$ 的目标文本串 $S$。初始光标位于左上角 $(0,0)$。
每次可以进行如下两种操作之一（每种操作的代价均为 1）：
1. **方向键（上/下/左/右）**：向该方向移动，直到遇到第一个与当前位置字符**不同**的格子并停下；若该方向上直到出界都没有不同的字符，则光标不移动（视为无动作）。
2. **选择键（Select）**：打印光标当前所在的字符。

目标是依次打印给定文本串 $S$ 中的字符，并在最后打印一个换行符（对应键盘上的 `*` 字符）。求最少的总按键次数。保证一定有解。

数据范围：$1 \le r, c \le 50$， $|S| \le 10000$。

## 正解

### 思路

因为每种按键代价均为 1，且要求最短操作次数，显然是一个最短路问题，通过 BFS 求解。
状态可设计为：`(当前行 r, 当前列 c, 已匹配的字符数 k)`，代价为经过的步数。

**瓶颈在哪里？**
1. 状态数庞大：整个搜索空间上界为 $50 \times 50 \times 10000 = 2.5 \times 10^7$。
2. 空间分配（MLE 隐患）：如果在 C++ 中开三维全量静态数组，会占据约 480MB 的内存。题目限制一般在 128MB，会导致必然 MLE。所以需要动态分配内存，例如使用 `std::queue` 保存状态即可，极大降低峰值内存。
3. 如果在每次 BFS 转移时动态顺延寻找“下一个不同字符”，开销过大。

**优化与正解**：
1. **预处理跳跃点**：先对每个格子向 4 个方向寻找不同字符的位置，提前把结果存在 `next[p][dir]` 中，在 BFS 时就能 $O(1)$ 获知落点。
2. **利用 `max_k` 剪枝**：记录 `max_k[i][j]`，代表走到坐标 $(i, j)$ 时匹配到的最长文本长度。若走到某个状态对应的 $k \le \text{max\_k}[i][j]$ 时，可以直接将其丢弃，这样能避免无用的冗余状态膨胀。结合上述优化，最终将状态队列精简到极小的量级。

### 复杂度

- **时间复杂度**：状态总数上界为 $O(rc(|S|+1))$，每个状态有 5 条边进行转移。时间复杂度 $O(rc(|S|+1))$。
- **空间复杂度**：最核心的是 `max_k` 数组与预处理跳跃落点的 `next` 数组，占用 $O(rc)$ 空间；BFS 的使用按需入队（`std::queue`），空间复杂度为 $O(rc(|S|+1))$，峰值常数大幅减小（相较于静态数组占用极小）。

## 总结

1. **算法**：BFS over `(位置, 已打印字符数)`。状态数 $O(rc(|S|+1))$；关键预计算 `next[p][dir]` 得到落点位置；终点为 $k = |S|+1$。总时间与空间理论复杂度 $O(rc(|S|+1))$。
2. **★★★ MLE 教训**：由于状态数 $2500 \times 10001 \approx 2.5 \times 10^7$，**绝对不能用静态数组存状态队列**。如果写成 `State q[55][55][10005]`，静态段内存直接爆到 480 MB，而题目限额 128 MB，在 `data10` 及以后将必然导致 MLE。改为使用标准库 `std::queue<State>` 后，静态段骤降至一百多 KB，且真实数据的峰值 RSS 仅为 8.3 MB。
3. **★★ `*` 未被转义**：题面里看到的字符 `X\*\*\*...Y` 是 Markdown 转义的结果，**不等于数据里的真实字节**。所有 `.in` 文件的实测 `\` 计数均为 0，完全没有转义字符，所以代码按纯 `*` 解析是完全正确的，若尝试兼容 `\*` 反而会报错。
4. **★★ `S` 不含 `*`**：题目数据中全部 19 个点的原字符串 $S$ 内本身全都不包含 `*`（0 个），“结尾的换行符”无法从原字符串里读取，所以这证明代码中的 `s += '*'` 主动拼接动作是必须的。
5. **★★ `data1` 手推 + 最短解唯一**：
   键盘 `XYZ`/`AAA`/`CAD`/`B**`，目标文本为 `A`，即要打印 `A*`。
   - 起点 (0,0) `'X'`
   - Right → (0,1) `'Y'` （`(0,1)` 与起点字符不同，落点）
   - Down → (1,1) `'A'` （`(1,1)='A'`，与 `'Y'` 不同，落点；而 `(2,1)` 起才是同字符）
   - Select → 打印 `'A'`
   - Down → 从 `(1,1)` 向下寻找：`(2,1)='A'` 与当前位置同字符被跳过 → 落点为 `(3,1)='*'`
   - Select → 打印 `'*'`
   - 共 5 次按键。经程序穷举，所有到达终点的序列中最短长度就是 5，并且最短解唯一（若走其他按键序列要 7 步）。

7. **★★ `(f)` 剪枝是离数据承重**：通过对比可以发现，删掉 `max_k` 剪枝，只用三维数组记录 `vis`，在 19 个实际点上同样 0 失败（仅时间常数增大），**说明剪枝不影响正确性，且在真实数据上零收益（没有引发 TLE 或 MLE 的质变）**。不过其正确性论证是绝对严谨的：BFS 按 `dist` 分层，到达 `(i,j)` 且 `k' ≤ max_k[i][j]` 时，旧状态已用不长于当前的 `dist` 匹配了更多（或相等）的字符；且由于打印过程逐字符前缀匹配，无分支可言，“已打印前缀更长”绝对包容“前缀更短”的状态，因此旧状态对新状态形成绝对支配。
