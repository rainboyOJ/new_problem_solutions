## 形式化题目

有 $N$ 盏灯排成一排，初始**全部关闭**。把灯的状态写成长度 $N$ 的 01 序列
$a_1 a_2 \cdots a_N$（$a_i = 1$ 表示第 $i$ 盏灯亮着）。依次执行 $M$ 个操作，
每个操作用三元组 $(c, l, r)$ 描述，其中 $1 \leqslant l \leqslant r \leqslant N$：

- $c = 0$：**区间取反**，即对每个 $l \leqslant i \leqslant r$ 执行 $a_i \leftarrow 1 - a_i$；
- $c = 1$：**区间查询**，输出 $\sum_{i=l}^{r} a_i$，即区间内亮灯的数量。

每个 $c = 1$ 的操作都要立刻输出一行答案。数据范围 $2 \leqslant N \leqslant 10^5$、
$1 \leqslant M \leqslant 10^5$，限时 1000 ms、内存 131072 KB。

样例 $N = 4$，操作依次为「取反 $[1,2]$」「取反 $[2,4]$」「查询 $[2,3]$」
「取反 $[2,4]$」「查询 $[1,4]$」。序列的变化是
$0000 \to 1100 \to 1011 \to 1100$，其中第三、第五个操作各输出一次查询结果：
查询 $[2,3]$ 时序列为 $1011$，第 2、3 位是 $0$ 与 $1$，和为 $1$；
查询 $[1,4]$ 时序列为 $1100$，和为 $2$。对应样例输出两行 `1`、`2`。

## 正解

### 思路

**朴素做法与瓶颈。** 直接用布尔数组存每盏灯的状态：操作 $c=0$ 就循环把 $[l,r]$ 里每个
元素取反，$c=1$ 就循环累加 $[l,r]$。单次操作 $O(N)$，最坏（每次都是 $[1,N]$）
总代价 $O(NM) = 10^{10}$ 次基本运算，1 秒内绝无可能跑完。

瓶颈在于：**每次操作都落到单盏灯上**。而"区间取反"这个动作，其实并不需要知道区间内部
每一盏灯分别是什么状态。

**关键观察：取反对区间和的封闭性。** 固定一段长度为 $L$ 的区间，设其中亮灯数为 $k$。
取反后：原来亮的 $k$ 盏全灭，原来灭的 $L-k$ 盏全亮，所以

$$\text{取反后亮灯数} = L - k.$$

也就是说，只要知道"这段多长"和"这段亮几盏"，就能 $O(1)$ 算出整段取反后的亮灯数，
**内部的具体排列完全不需要暴露出来**。这正是把区间整体变换压成一个标量的典型信号。

**关键观察：取反是自逆的。** 同一段取反两次等于没动，三次等于一次。所以"这段还需要
整体取反"这件事只需要一个布尔量（或者按取反次数的奇偶看成一个 bit），
两次标记叠在一起会互相抵消：

$$\text{tag} \leftarrow \text{tag} \oplus 1.$$

注意这里是**异或累加**而不是赋值 `tag = 1`——如果对同一段连续取反两次，
标记必须归零，写成赋值就会多算一次。

这两条观察合起来，正好对上线段树的懒标记模板：每个节点维护
`sum`（本段亮灯数）与 `len`（本段长度），区间被完全覆盖时
`sum = len - sum; tag ^= 1`，否则把标记下传给两个儿子再递归。

**为什么不用树状数组 / 分块。** 树状数组擅长的是"单点加、区间和"这类**线性**变换，
而这里的整段变换 $k \mapsto L - k$ 依赖段长 $L$，不是加法，套不进树状数组的差分结构。
分块是 $O(M\sqrt{N}) \approx 3 \times 10^7$，能过但不优，而且"整块取反 + 零散块暴力"
要额外维护每个块内的亮灯数。线段树天然按区间二分，配合懒标记正好做到 $O(\log N)$，
实现也不比分块长，是这道题的标准选择。

**下传（push_down）的时机是唯一的易错点。** 只要准备往儿子递归——不论是修改还是查询——
就必须先把当前节点的标记落地：两个儿子的 `sum` 各自按**自己的长度**取反，
标记各自异或，然后把当前标记清零。查询时也一样要下传，否则儿子手里还是旧数据，
答案会偏小。下传时段的长度务必取**子节点自身**的长度（`mid - l + 1` 与 `r - mid`），
取成父节点长度是这道题最常见的错。

由于灯初始全关，所有节点的 `sum` 一开始都是 0，所以建树只是把长度填好、再写一遍
$O(N)$ 的递归，也可以直接省掉：

- 节点 $u$ 代表 $[l, r]$，儿子是 $2u$ 与 $2u+1$，根是 $1$ 号、代表 $[1, N]$；
- `len` 不必存成数组——需要它的地方（整段取反）都可以现算 $r - l + 1$，
  下传给儿子时则要现算儿子自己的段长。

两版代码都保留了 `build`（C++）与等价的"数组默认全 0"（Python）两种起步方式，
因为 `sum` 初值为 0 时 $k \mapsto L - k$ 退化成了 $k \mapsto L$，两种写法等价。

**正确性。** 对树高归纳：任何时刻，「节点 $u$ 的 `sum` 等于它负责的区间内的真实亮灯数」
与「$u$ 的 `tag` 表示 $u$ 的整段相对儿子多做了奇数次取反」两条不变式同时成立。
完全覆盖时只改 `sum` 与 `tag`，第一式对 $u$ 成立；下传时把标记那一次取反
按 $k \mapsto L-k$ 精确地补给两个儿子，两式都不破；回溯时用儿子之和刷新 `sum`。
查询只在完全覆盖处取值，取值处的 `sum` 已在所有祖先标记的作用下被修正过，故答案正确。

### 复杂度

- **时间**：每次操作只会访问 $O(\log N)$ 个节点，总时间 $O((N + M) \log N)$。
  $N = M = 10^5$ 时约 $1.7 \times 10^6$ 次节点访问，实测 C++ 约 30 ms（限时 1000 ms）。
  Python 版每次操作走的是同样的 $O(\log N)$ 条递归路径，只是常数大得多
  （递归调用 + 列表下标 + `int` 装箱），10 个真实测试点里最慢的点 8 实测 0.68 s，
  贴 1 s 限时但能过；若换成常数更大的 Python 实现仍有 TLE 可能，
  但**算法与 C++ 同阶**，没有做任何降级（未改成 $O(NM)$ 暴力、也未用 numpy）。
- **空间**：线段树开 $4N$ 个节点，每个节点两个计数与一个标记，
  对应分析中 $4 \times 10^5$ 个整数的量级，实测峰值内存 20 MB 以内（限于 131072 KB）。
- **实现对应**：`main.cpp` 与 `main.py` 是同一个算法的两版，函数一一对应
  （`push_down` / `update` 对 `modify` / `query`），C++ 用 `scanf` 读入避免 I/O 成为瓶颈，
  Python 用 `sys.stdin.buffer.read().split()` 一次读完再顺序消费。

## 总结

- **先看变换是不是封闭在一个标量里**：长度为 $L$ 的段取反后亮灯数恰为 $L - k$，
  这是"信息可以只留 `sum` 与 `len`"的根据；找不到这种封闭性，就必须维护更多字段
  （例如同时维护"连续 1 的段长"那类题目）。
- **自逆变换的标记用异或累加**：`tag ^= 1` 而不是 `tag = 1`，
  两次同段取反必须抵消，这是懒标记类题目最常见的错点。
- **下传与递归必须成对出现**：修改和查询在进入儿子之前都要 `push_down`，
  而且儿子按**自己的段长**取反。
- **本题数据是自造的**：素材目录带有 `data.py` 分层生成脚本（按 $N$、$M$ 递增、
  覆盖最小 $N=2$、全区间 `[1,n]`、单点区间等边界），题面则是从网络来源完整转录的
  一本通《1993 开关switch》。因此数据只能保证与题面一致，出题意图可能与官方原始
  测试数据存在偏差；真实数据 10 个点全部通过，与题面描述一致。
