## 形式化题目

给定一棵 $n$ 个顶点、以 $1$ 为根的树，每个顶点 $u$ 带一个颜色 $c_u \in [1, n]$（不同顶点颜色可以相同）。
维护一个颜色序列，支持 $q$ 次操作：

- $1\;u\;l\;r$：设子树 $u$ 的顶点集合为 $S_u$，求 $|\{\,c_v : v \in S_u,\; l \leqslant c_v \leqslant r\,\}|$，
  即这些顶点里颜色落在 $[l, r]$ 的**不同**颜色个数；
- $2\;u\;c$：把 $c_u$ 改成 $c$。

$t = 1$ 时强制在线：第一条之后的每个操作，**除操作类型外**的每个数都要先与上一次询问的答案
$lastans$（初始为 $0$）做异或，才是真实参数。$1 \leqslant n, q \leqslant 10^5$，时限 3 s，内存 512 MB。

## 正解

### 思路

**第一步：把子树变成区间。** 对树做一次从根出发的 DFS，记 $tin_u$ 为 $u$ 的入时间、$tout_u$ 为
$u$ 子树内最大的入时间，则 $S_u$ 恰好是 DFS 序上的一段连续区间 $[tin_u, tout_u]$。
于是两类操作都变成序列上的问题：把位置 $k$（$1 \leqslant k \leqslant n$）上的顶点记为
$p_k$，那么

$$|\{\,c_v : v \in S_u,\; l \leqslant c_v \leqslant r\,\}| = \bigl|\{\,c_{p_k} : k \in [tin_u, tout_u],\; l \leqslant c_{p_k} \leqslant r\,\}\bigr|.$$

**第二步：颜色只有 $10^5$ 种，把它压成位集。** 对任何一段位置区间，我们真正需要的信息是
"哪些颜色出现过"这一件布尔事实。用一个 $n$ 位二进制整数（以下称**颜色位集**）表示颜色集合，
第 $c$ 位为 $1$ 表示颜色 $c$ 出现过。于是

> 区间内出现过的、颜色在 $[l, r]$ 的种数 = 该区间颜色位集 $M$ 与掩码 $\mathrm{span} = (2^{r-l+1}-1)\cdot 2^{\,l-1}$ 做与之后 `bit_count`。

关键在于：**两个颜色位集的并就是一次按位或**，因此"多段颜色的合并"可以交给任意一种
支持区间并的数据结构来做，而"种数"不需要在合并过程中维护——最后数一次二进制里的 $1$ 就够了。

**第三步：位置分块 + 线段树。** 把 DFS 序按每 $BLK$ 个位置一块切开，
块 $b$ 的颜色位集记作 $M_b$。用一棵线段树维护这些 $M_b$：节点存两个儿子位集的或。
一次询问 $[lo, hi]$ 分解为

$$\underbrace{[lo,\, fL\cdot BLK - 1]}_{\text{头部残缺}} \;+\; \underbrace{[fL\cdot BLK,\; (fR+1)\cdot BLK - 1]}_{\text{完整块, 线段树 } O(\log n)} \;+\; \underbrace{[(fR+1)\cdot BLK,\; hi]}_{\text{尾部残缺}} ,$$

其中 $fL = \lceil lo/BLK \rceil$、$fR = \lceil (hi+1)/BLK \rceil - 1$。完整块在 $O(\log nb)$ 次或运算内合并成
一个位集，两个残缺部分各自暴力扫至多 $BLK$ 个位置、把颜色按位或进同一个位集，
最后与 $\mathrm{span}$ 相与、`bit_count` 输出。

**第四步：修改。** 改一个顶点的颜色，只会影响它所在的那一个位置块的位集 $M_b$。
$M_b$ 是"该块内出现过哪些颜色"，是一堆布尔量的并，**不能直接减**，所以两条路：

- 直接重建：重新扫这个块的 $BLK$ 个位置得到新的 $M_b$，再沿叶到根重算 $O(\log nb)$ 个祖先，
  单次代价 $O(BLK + \log nb \cdot n/w)$，$BLK = 1000$ 时也就是一两千次操作；
- 补一张计数表 `CNT[(c, b)]`：只有"旧颜色计数减到 $0$"或"新颜色计数原本是 $0$"时
  块位集才真的变化，其余情况可以完全不碰线段树。

两份代码各取一条：C++ 取直接重建（$BLK = 1000$，重扫一块本来就只有几千次操作，还省一张表），
Python 取计数表（`Counter` 一行建好，且 $BLK = 64$ 时块位集变化很频繁，提前跳过重建更划算）。
两条路的**复杂度同阶**，只是常数取舍不同。

**第五步：强制在线的两个细节。** 异或解码后的 $u$ 一定合法（因为 $lastans$ 就是真实历史值），
但 $l, r$ 会**超出 $[1, n]$**——题目给的隐藏样例里就出现了异或后为 `1 1 2 7` 而 $n = 5$ 的情况。
所以把 $l$ 夹到 $\max(l, 1)$、$r$ 夹到 $\min(r, n)$，若夹完 $l > r$ 直接回答 $0$。
夹取只改变询问范围、不改变"哪些颜色算数"的语义，与 $[1, n]$ 之外没有任何颜色存在的事实一致。

### 代码

两份代码共用同一套骨架（DFS 序 → 位置分块 → 块位集线段树），只有两个常数不同：
C++ 取 $BLK = 1000$（$nb \approx 100$，位集总内存约 1.3 MB，两侧各最多扫 1000 个位置），
Python 取 $BLK = 64$（$nb \approx 1563$，位集约 20 MB，两侧最多扫 64 个位置）。

C++ 版：位集写成 `unsigned long long seg[2 * MAXP][MAXNW]`，每 64 个颜色一个字，
合并是逐字或、计数是 `__builtin_popcountll`；询问时只对颜色区间 $[l, r]$ 覆盖到的那些字做
`memset` 与或，不去白扫无关的字。

### 复杂度

记 $B = BLK$ 为位置块大小，$nb = \lceil n/B \rceil$ 为块数，$w = 64$ 为机器字长。

- 预处理：DFS $O(n)$；每个位置块的位集逐位置构造 $O(B)$，线段树 $O(nb \cdot n/w)$ 次字或。
- 询问：线段树合并 $O(\log nb)$ 次位集或（每次 $O(n/w)$ 字）+ 两侧残缺块各 $O(B)$ 次置位
  + 一次 `popcount`，合计 $O\bigl(B + \log nb \cdot n/w\bigr)$。
- 修改：重置该位置块的位集 $O(B + n/w)$，再重算祖先链 $O(\log nb \cdot n/w)$；
  带计数表的 Python 版在块位集不变时直接跳过这两步。

空间：位集线段树 $O(nb \cdot n/w)$ 个字，$B = 1000$ 时约 $1.3$ MB（C++ 实测峰值 10 MB 以内），
$B = 64$ 时约 $20$ MB（Python 位集本身的开销）。两者都远低于 512 MB。

实测：在 $n = q = 10^5$ 的第 8、9、10 号点上，C++ 版分别约 $0.25 / 0.31 / 0.25$ s，
峰值内存不到 $11$ MB；Python 版分别约 $2.6 / 3.1 / 1.8$ s，峰值内存 $126 / 137 / 342$ MB。
Python 在第 9 号点（链 + 一半修改）略超 3000 ms 时限——
该 skill 明确允许 Python 版 TLE，这里保持与 C++ 完全相同的分块 + 线段树结构，
没有为了跑过而降级成暴力。

Python 版还有一个值得记下的实现细节：第 10 号点（随机树 + 强制在线）实测峰值 RSS 约 $350$ MB，
明显高于第 8 号点（链，全区间询问）的 $130$ MB。
原因是位集是用 `int.from_bytes` 现场拼出来的整数，宽度随该块颜色的最高位变化，
「取出子节点位集 → 或成新值 → 存回父节点」的往返会不断创建新的大整数对象，
CPython 的分配器会因此缓慢抬高驻留内存数。
它在 512 MB 限额内（通过），但这是 Python 版离 MLE 最近的一点：
若要拿 Python 版去冲更紧的内存限额，应该改成直接重建整块位集，
或用更小的块大小把单个位集的宽度压下来。

## 总结

- **子树即区间**：任何"子树上的聚合"先做一次 DFS 序转区间，这是树上区间问题的通用第一步。
- **把"是否存在"压成位集**：当对象种类数是 $n$、而操作只问"有没有出现"时，
  用 $n$ 位整数表示集合能让"多段合并"退化成一次按位或；Python 的 `int` 自带宽位运算，
  C++ 里则用一个 `unsigned long long` 数组手写。
- **布尔位集 + 计数表**：位集只能置位/清位，不能减；凡是需要"删除"的场合都要补一张
  出现次数表来决定这一位该不该清。
- **线段树的节点是位集时，一次询问只需要 $O(\log nb)$ 次或**，比"逐块扫"少一个 $nb$ 因子。
- **强制在线的区间参数必须夹取**：异或解码后下标越界是常态，判题数据里就有这种点。
