## 形式化题目

有 $n$ 个节点的有根树，根为 $1$。对每个 $i \in [2, n]$ 给出 $i$ 的父亲 $p_i$，其中 $\{p_2, \dots, p_n\}$ 由题目直接给出，**不保证 $p_i < i$**。对每个 $1 \leqslant i \leqslant n$，求以 $i$ 为根的子树中除 $i$ 自身以外的节点数，即 $\mathrm{size}(i) - 1$。

## 正解

### 思路

**朴素做法。** 对每个节点 $u$ 各跑一遍 DFS/BFS 数它有多少后代，单次 $O(n)$，总计 $O(n^2)$。当树退化成一条长链 $1 \to 2 \to \dots \to n$ 时总步数约为 $n^2/2 = 2 \times 10^{10}$，在 $1000\text{ ms}$ 时限下必然超时。

**瓶颈在哪。** 节点 $u$ 的后代集合与它儿子 $v$ 的后代集合大量重叠，同一棵子树被反复遍历。

**关键观察：** 子树大小天然满足自底向上的递推

$$\mathrm{size}(u) = 1 + \sum_{v \in \mathrm{children}(u)} \mathrm{size}(v)$$

即每个节点的答案**只依赖它直接孩子的答案**。于是只要保证「孩子先于父亲被算完」这个顺序，每个节点就只需处理一次，总时间降到 $O(n)$。

**怎么拿到这个顺序。** 注意输入并不保证 $p_i < i$（第 10 组数据就是标签置换后的链，$p_i$ 经常大于 $i$），所以**不能**简单地按编号从 $n$ 倒着扫。正确做法是建出邻接表后从根 $1$ 做一次 BFS：

- BFS 队列的一个天然性质是「入队时父亲一定先于孩子入队」，因此 BFS 序就是一组可行的拓扑序；
- 反过来逆序遍历这个 BFS 序，就得到「孩子一定先于父亲」的处理顺序，可以放心地做 `size[boss[u]] += size[u]`。

这个写法还有两个好处：一是顺序来自显式队列，不写任何函数调用栈，$n = 2\times 10^5$ 的链状数据不会递归爆栈；二是递推只是数组加法，常数极小。

下面用一个 5 人的小例子（$p_2 = 1, p_3 = 1, p_4 = 2, p_5 = 3$，即题面样例的结构）展示一次「BFS 序 + 逆序累加」的过程：

| 轮次 | 动作 | 数组变化 |
| --- | --- | --- |
| 建树 | $1 \to \{2, 3\}$，$2 \to \{4\}$，$3 \to \{5\}$ | `size = [_,1,1,1,1,1]` |
| BFS | 队列依次得到 | `order = [1, 2, 3, 4, 5]` |
| 逆序 1 | 处理 5，上司是 3 | `size[3] = 2` |
| 逆序 2 | 处理 4，上司是 2 | `size[2] = 2` |
| 逆序 3 | 处理 3，上司是 1 | `size[1] = 3` |
| 逆序 4 | 处理 2，上司是 1 | `size[1] = 5` |
| 输出 | $i = 1..5$ 输出 `size[i] - 1` | `4 1 1 0 0` |

与样例输出完全一致。注意员工 3 也是员工 1 的子树成员，它把自己算完的 `size = 2` 交给父亲 1 时，已经把下属 5 含在里面了——这正是「只上报一次、不重复遍历」的体现。

### 复杂度

建树读入 $n-1$ 条边为 $O(n)$；BFS 与逆序累加各遍历每个节点一次，为 $O(n)$；输出 $n$ 个数也为 $O(n)$。总时间 $O(n)$，空间 $O(n)$（邻接表 $n-1$ 条边 + 三个长度 $n$ 的数组）。$n = 2 \times 10^5$ 时内存仅几 MB，远低于 $512\text{ MB}$ 限制；CPython 实测最坏点（$n = 2\times10^5$ 的置换标签链）也在 $0.3\text{ s}$ 量级。

## 总结

本题是「树上子树大小」的模板题。两个要点：一是把「下属人数」翻译成 $\mathrm{size}(u) - 1$，把 $O(n^2)$ 的逐点搜索换成自底向上的一次累加；二是**不要假设输入满足 $p_i < i$**，用 BFS（或迭代 DFS）显式建出「父先于子」的顺序，既兼容任意标签顺序，又避开了递归深度限制。

`main.py` 用的是 `for u in order` 边遍历边追加的写法——Python 的 `list` 迭代器会在追加元素时继续读到新元素，效果与队列完全相同。若换成递归 DFS，在 $2\times 10^5$ 的长链上必须 `sys.setrecursionlimit`，本解法直接回避了这个问题。
