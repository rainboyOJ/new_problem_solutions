## 形式化题目

给定一个 IEEE-754 双精度实数 $x$，按十进制四舍五入保留小数点后 12 位，并固定输出恰好 12 位小数：位数不足补 `0`，负数保留符号。

输入样例：

```
3.1415926535798932
```

输出样例：

```
3.141592653580
```

样例推演如下表，展示从"解析出的 double"到"12 位小数字符串"的每一步：

| 步骤 | 操作 | 结果 |
| --- | --- | --- |
| 读入 | `float("3.1415926535798932")` | 最近的 double：`3.1415926535798930352…` |
| 定宽截取 | 保留前 12 位小数 | `3.141592653579`，第 13 位是 `8` |
| 四舍五入 | 第 13 位 $\geqslant 5$，末位进 1 | `3.141592653580` |
| 补零定宽 | 小数位不足 12 位补 `0` | `3.141592653580` |

观察重点：进位把 `…653579` 推成 `…653580`，而末尾的 `0` 是**补零**出来的，不是原输入里就有的——舍入与补零是两个独立动作，格式化工具必须同时做对。

## 正解

### 思路

这道题的计算只有"解析 → 舍入 → 输出"三步，没有任何可以退化的朴素版本：任何写法最终都要走同一条链路，再写一个"暴力解"只会得到与正解一模一样的代码。所以本文不设暴力层，按直接正解型组织；真正要学的是**输出格式化**这条链路的语义。

1. **读入**：`float(input())` 把文本解析成 IEEE-754 双精度数。Python 的 `float` 与 C++ 的 `double` 是同一种表示，同一段十进制文本在两边解析出同一个二进制数——这是"Python 输出能与出题人 C++ 参考解逐字一致"的前提。
2. **舍入**：`:.12f` 是定点格式，它对 double 的**精确二进制值**做十进制四舍五入取 12 位小数。注意舍入依据的是解析后的精确值，而不是输入文本的字面量：`-173.2225541516315` 解析后精确值是 `-173.22255415163149905…`，第 13 位小数实际是 `4`，所以答案是 `-173.222554151631` 而不是 `…632`（真实数据 problem1 正是此例）。若手工按文本截取字符串，这类边界全会做错。
3. **补零与符号**：`.12f` 保证输出恰好 12 位小数（样例末位 `0` 即由此而来），负号自动保留。

排除的备选写法：

| 写法 | 为什么不行 |
| --- | --- |
| `print(x)` | 输出"最短可还原"变长串，不定宽、不舍入 |
| `print(round(x, 12))` | `round` 返回 float，`3.14159265358` 只有 11 位小数，尾随 0 被吃掉 |
| `split('.')` 后截 12 位 | 只截不进位，第 13 位 $\geqslant 5$ 时答案错 |
| `"%.12f" % x` | 正确，但与 f-string 等价，写法更旧 |

C 的 `printf("%.12f")` 同样按精确值舍入（round-half-to-even），所以 Python 的 `:.12f` 与参考解产生相同字符串；真实数据 10 组全部逐字比对通过。

- 时间复杂度：$O(1)$，只读入一个常数长度的数，做一次解析与一次格式化。

## 总结

- 单值格式化题，直接正解型：`float(input())` 读入，`f"{x:.12f}"` 输出，两行到位。
- `:.12f` 一次完成三件事：按**精确二进制值**四舍五入到 12 位小数、不足补 0、保留符号——这正是 C 参考解 `printf("%.12f")` 的语义。
- 舍入看的是解析后的 double，不是输入文本的字面量；`round()` 加 `print()` 会丢尾随 0，手工截字符串不会进位，两种常见错误都源于没搞清格式化的语义。
