## 形式化题目

给定一个长度为 $n$ 的正整数序列 $a_1, a_2, \dots, a_n$，其中 $1 \le n \le 1000$，且对于任意 $1 \le i \le n$，均有 $a_i \le 2^{32}-1$。
求出该序列中最大数所在的位置下标（采用 1-based 编号，即第 1 个元素位置为 1）。如果有多个相同的最大数值，输出它们之中第一次出现的位置（即最小的下标）。

## 正解

### 思路

本题的本质是一个打擂台求最大值及对应位置的题目。我们需要从前往后遍历序列，用变量记录当前遇到的最大数值的下标 `max_pos`（和其对应的值 `max_val`）。
每遇到一个元素 $x$（其下标为 $i$），如果 $x > max\_val$，则更新 `max_pos = i`。因为只有在严格大于时才更新，所以如果遇到相同的最大值，不会覆盖第一次记录的位置，这天然满足了题目「并列时取第一次出现位置」的隐含需求。

**这道题的核心陷阱在于数值范围：**
题面说明“每个数在 $2^{32}-1$ 之内”。而 $2^{32}-1 = 4294967295$。
在 C++ 中，普通的带符号 `int` 类型能表示的最大正整数为 $2^{31}-1 = 2147483647$。
由于数据点中包含超过 `INT_MAX` 的值（如 $4294967295$），如果使用普通的 `cin >> int` 来读取，**由于读入的值超出了 `int` 的上界，`cin` 不会发生“回绕成负数”的现象，而是会将该变量钳位为 `INT_MAX`（$2147483647$），并锁死输入流的 `failbit`**。这会导致此后所有的读入全部失败（读入值为 0），从而把最大值错误地“冻结”在已经成功读入的前缀里，结果与真实值无关，必然算错。
（如果是 `scanf("%d")` 或对 `long long` 读入后强制转 `(int)`，则会发生真实的截断回绕现象，例如 $4294967295$ 会回绕变成 $-1$）。
因此，在 C++ 实现中，我们必须使用范围更大的数据类型，即 `long long`。相对而言，Python 支持任意精度的大整数，因此使用 Python 的整型不会存在溢出问题。

### 复杂度

- **时间复杂度**：$\mathcal{O}(n)$。我们需要遍历 $n$ 个数进行比较，每次比较的操作时间是常数的。
- **空间复杂度**：$\mathcal{O}(n)$。本题在代码实现中，开辟了数组 `a[1..n]` 来储存输入的数据，空间消耗随数据规模线性增长。

## 总结

- **数值范围与类型（本题核心）**：
  - 本题中数据的最大值达到了 $4294967295 = 2^{32}-1$。实测显示数据点 2、5、6、8、9、10 均含有超过 `INT_MAX` 的值。
  - **`cin >> int` 的行为与溢出危害**：在处理超限数据时，`cin >> int` 不会像 `scanf` 或强转那样回绕成负数，而是会把值钳位在 `INT_MAX` 并且置位 `failbit`。一旦置位，后续所有的读入均会被忽略。实验表明，如果本题把变量类型换成 `int`，会导致 $4/10$ 个测试点直接错误（输出的位置错误地停留在由于报错而停止读取的前面部分）。
  - **为什么不用 `unsigned int`？**：虽然 `unsigned int` 的上限刚好是 $2^{32}-1$，但在打擂台算法中，我们通常需要一个初值。如果沿用习惯的无符号负一初值 `max_val = (unsigned)(-1)`，其值等于 $4294967295$ —— 恰好等于题面上限。这会导致没有任何一个元素能大于这个哨兵值，导致 $10/10$ 全错（全输出 $-1$）。直接用数组第一个元素作初值可以规避，但为了稳妥且遵守项目规范，统一使用 `long long` 处理超过 `int` 的数据更加安全。
- **并列最大值的处理**：题面只规定了输出“最大数所在位置”，但未对多个相同的最大值做显式说明。通过实测验证：
  - 在全相等的测试点（如 `p9`，1000 个 $2^{32}-1$），输出是 `1`。
  - 在最大值出现多次的测试点（如 `p7`，最大值出现 24 次，最先出现在位置 116），输出为 `116`。
  - 结论：**并列时应当输出第一次出现的位置**。我们在条件判断中使用严格大于 (`>`) 天然契合这一逻辑。
- **1-based 编号与末尾位置验证**：
  - 题面明确提到“存放在数组 $a[1]$ 至 $a[n]$ 中”，因此要遵循 1-based 索引。样例输出以及最大值出现在末尾的测试点（如 `p10` 的最大值恰好在第 1000 位，正确输出了 `1000`）都证实了输出位置不应减 1。
- **验证强度**：
  - 异源验证：采用 Python 的内置 `max()` 加 `index()` 算法与 C++ 的单遍流式打擂台算法对比，对 373 组穷举测试点（$n \le 5$, 取值 $\{1,2,3\}$ 加上边界点）实现了 0 分歧。
  - 非硬编码验证：移除硬编码字面量，且代码内的常量如 `{0,1,2,1005}` 均不包含任一正确答案。
