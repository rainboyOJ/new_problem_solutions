## 形式化题目

给定进制 $N$（$2 < N \leqslant 10$ 或 $N = 16$）与一个首位不为零的 $N$ 进制数 $M$（数码用 `0`–`9`、`A`–`F` 表示）。定义一次操作为：把当前数与"将其数码反转得到的数"做一次 $N$ 进制加法。求最少经过多少次操作能得到回文数（从左向右读与从右向左读相同）；若 $30$ 步以内（含 $30$ 步）得不到回文数，输出 `Impossible`。注意：若 $M$ 本身就是回文数，答案为 $0$。

## 正解

### 思路

**一句话本质**：把 $M$ 的数码放进数组，反复执行「$a \leftarrow a + \operatorname{reverse}(a)$（带 $N$ 进制进位）」，每一步先判回文，最多判 $31$ 次（第 $0$ 次到第 $30$ 次）。

以题面的 $10$ 进制 $87$ 为例（注意：本题输入样例是 $9$ 进制的 `9 87`，两者答案不同，后文用真实样例推演），操作就是：

$$87 + 78 = 165,\quad 165 + 561 = 726,\quad 726 + 627 = 1353,\quad 1353 + 3531 = 4884$$

$4$ 步得到回文数 $4884$。每一步只涉及两件事：**$N$ 进制加法**和**回文判断**，没有任何可以"优化"的算法层——步数上限 $30$ 已经由题面给出，所以这就是一道纯模拟题。

**问题？** 既然是模拟，用 Python 的整数直接算不就更快吗？

恰恰相反，这里藏着本题**最容易踩的坑**。真实测试数据里存在"M 的数码值 $\geqslant N$"的输入，例如 `2 37`、`5 45`、`8 63`。对这些输入：

- `int(m, base)` 直接抛 `ValueError`（`'37'` 不是合法二进制串）；
- 即使先做字符面值转换再转整数（把 `37` 当作 $3 \times 2 + 7$），"整数反转再相加"的数值语义也与评测机不同——数值反转等价于**先把非法数码规范化**再反转，而评测机（一本通标准解）的语义是**把每个字符的面值直接放进数码数组**，靠加法进位慢慢消化越界数码。实测 `2 37` 按数值法 $2$ 步出回文，而正确答案是 `Impossible`。

因此正解必须像 C++ 手写高精一样，老老实实维护**数码数组**：

1. **读入**：字典 `VALUES` 把 `0`–`9`、`A`–`F`（含小写）映到面值 $0$–$15$，`a = [VALUES[c] for c in m][::-1]` 得到低位在前的数码数组；
2. **加法**：`s = [x + y for x, y in zip(a, a[::-1])]` 完成 $a + \operatorname{reverse}(a)$ 的逐位求和，再从低位到高位 `divmod(s[i], base)` 归化进位，最高位溢出就 `append`；
3. **主循环**：`for step in range(31)`——先判 `a == a[::-1]`（第 $0$ 步覆盖"M 初始即回文"的情形，如样例 `7 55` 输出 $0$），`step == 30` 仍未回文则输出 `Impossible`，否则执行一次加法。

进位链为什么正确？每位和 $s_i$ 至多 $2 \times 15 = 30$，`divmod` 按 base 归化后进位累加到 `s[i+1]`，而更高位的 `divmod` 尚未执行，会在轮到它时把这笔累加一并归化——从低位到高位的单趟扫描就能把所有越界数码消化干净。

用真实样例 `9 87`（$9$ 进制）推演每一步，表格列是：步数、当前 $9$ 进制数、是否回文：

| 步数 | 当前数（9 进制） | 是否回文 |
| --- | --- | --- |
| 0 | 87 | 否 |
| 1 | $87 + 78 = 176$ | 否 |
| 2 | $176 + 671 = 857$ | 否 |
| 3 | $857 + 758 = 1726$ | 否 |
| 4 | $1726 + 6271 = 8107$ | 否 |
| 5 | $8107 + 7018 = 16126$ | 否 |
| 6 | $16126 + 62161 = 78287$ | ✅ |

第 $6$ 步得到回文数 $78287$，输出 `6`。所有加法都按 $9$ 进制进位（如 $8+7=15=1\times 9+6$，本位写 $6$ 进 $1$）。

再验证含越界数码的 `5 45`：数码 $5$ 本身超过进制 $5$，面值直接进数组，模拟得 $45 \to 204 \to 1111$，$2$ 步出回文——这正是"数码数组模拟"与"转整数"分道扬镳的地方。

### 复杂度

- 时间复杂度：至多 $30$ 次加法，每次 $O(L)$（$L$ 为数码长度，每步至多增长 $1$），总量 $O(31L)$，为常数级；与 C++ 手写高精度加法同阶。
- 空间复杂度：$O(L)$，只存数码数组。

## 总结

本题是 NOIP 1999 初赛题的经典模拟：维护数码数组、反复做「$a + \operatorname{reverse}(a)$」的 $N$ 进制加法，$30$ 步内判回文。真正的考点有两个：一是 $N$ 进制高精度加法的进位处理（C++ 手写数组，Python 用 `zip` 逐位相加 + `divmod` 归化）；二是**数据语义陷阱**——测试数据存在数码值 $\geqslant N$ 的输入（如 `2 37`），`int(m, base)` 会直接崩溃，而"转整数再数值反转"即使能算也会得到与评测机不同的答案，必须按字符面值直接建数码数组模拟。实测 10 个评测点全部一致，单点约 $0.02$ s、峰值内存 $14.7$ MB，相对 1000 ms / 128 MB 的限制十分宽裕。
