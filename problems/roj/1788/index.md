## 形式化题目

平面上给出 $n$ 个山顶 $P_1,\dots,P_n$，横坐标严格递增：$x_1 < x_2 < \dots < x_n$。
相邻山顶用线段相连，得到折线山体 $l$。

**可见性**：山顶 $P_j$ 能被 $P_i$ 看到，当且仅当线段 $P_iP_j$ 与折线 $l$ 只在
$P_i$、$P_j$ 两处相交。等价地，对夹在中间的每个 $k$，
$P_k$ **严格位于线段 $P_iP_j$ 下方**；只要有一个中间的 $P_k$ 落在线段上或上方，
$P_j$ 就被挡住。（这也意味着三点共线时，中间那个山顶会挡住更远的那个。）

**山的高低**：对两个山顶 $A,B$，规定 $A$ 比 $B$ 高当且仅当

$$y_A > y_B \quad\text{或}\quad \bigl(y_A = y_B \;\wedge\; x_A > x_B\bigr).$$

把这个二元组压成排序键 $\mathrm{rank}(A) = (y_A, x_A)$，就是字典序比较。
注意 $x$ 互不相同，所以**两个不同的山顶 $\mathrm{rank}$ 必不相等**。

**爬山规则**：全局维护一个"到目前为止看到过的最高山顶" $T$。从 $P_i$ 出发时先令
$T = $ 从 $P_i$ 能看到的最高的山顶（若除自己外什么也看不到，$T = P_i$）。之后不断重复：

1. 当前在 $P_{cur}$，若 $cur = T$ 就停下；
2. 否则 $T \leftarrow \max\bigl(T,\ \text{从 } P_{cur} \text{ 能看到的最高的山顶}\bigr)$（按 $\mathrm{rank}$ 取大）；
3. 朝 $T$ 的方向移动一格：$T > cur$ 就走到 $P_{cur+1}$，否则走到 $P_{cur-1}$。

**输出**：对每个起点 $P_i$，输出它停下前走过的边数（每经过一个山顶算一次，
因为每一步刚好经过一个新山顶，所以边数 = 经过的山顶数）。

样例：$n = 4$，山顶 $(0,10),(1,5),(2,0),(3,6)$，答案为

```text
0
1
4
3
```

比如从 $P_3 = (2,0)$ 出发：先看到 $P_4=(3,6)$ 更高（$P_3P_4$ 中间没有别的山顶），
向右走一步到 $P_4$；在 $P_4$ 又看到 $P_1=(0,10)$ 更高，于是掉头向左，
$P_4 \to P_3 \to P_2 \to P_1$ 再走三步，合计 $4$ 步。
$P_4$ 能看到 $P_1$ 是因为线段 $P_1P_4$ 完全压在山体上方（$P_2,P_3$ 都在它下面）。

## 正解

### 思路

**朴素做法。** 对每个点 $i$ 枚举左右两侧的所有 $j$，逐个检查中间点是否严格在线段下方，
$O(n)$ 求出 $i$ 能看到的最高的山；再按题目规则一步一步模拟，最坏 $O(n)$ 步。
$n$ 个起点就是 $O(n^3)$，$n \le 5\times10^5$ 完全不可行。

**关键观察（难点）：能看到的最高山顶 = 斜率最大的山顶。**

固定 $i$，只看右边 $j > i$。定义斜率

$$s(i,j) = \frac{y_j - y_i}{x_j - x_i}.$$

设 $v^\ast$ 是使 $s(i,j)$ 最大的点，且取**最靠左**的那个（处理三点共线时取近的）。

- **$v^\ast$ 一定能被看到。** 若某个中间点 $P_k$ 不在 $P_iP_{v^\ast}$ 下方，
  就有 $s(i,k) \ge s(i,v^\ast)$；由 $v^\ast$ 最大可知必须相等（共线），
  但取最靠左的 $v^\ast$ 排除了"更近的 $k$ 也在此斜率上"的情况，矛盾。
- **比 $P_{v^\ast}$ 更高的点都看不到。** 设 $w > v^\ast$ 且 $y_w > y_{v^\ast}$。
  若 $P_w$ 能被看到，那么中间所有点都严格在 $P_iP_w$ 下方，
  特别是 $\mathrm{slope}(i,w) > \mathrm{slope}(i,v^\ast)$，与 $v^\ast$ 取最大矛盾。

所以 $i$ **向右侧能看到的最高山顶就是 $v^\ast$**（在右侧可见点里既最高又必然可见）。
向左完全对称，对 $j < i$ 取斜率最大的点。

于是 $f_i$（$i$ 能看到的最高的山）$=$ 左右两侧的斜率最大者中 $\mathrm{rank}$ 更高的那个。

**求斜率最大的点：链式跳跃（摊还 $O(n)$）。**

设 $R_i$ 为右侧斜率最大的点，初始 $R_i = i+1$。若 $R_{R_i}$ 处的斜率更大，
即 $\mathrm{slope}(i, R_i) < \mathrm{slope}(i, R_{R_i})$，就把 $R_i$ 跳到 $R_{R_i}$，反复直到不再变大。
因为比较用的是严格小于，链条会停在**最靠左**的最大斜率点上。
由于 $R_{R_i}$ 本身已是 $R_i$ 向右的最优点，这样跳不会漏解；
每个点的 $R_i$ 只会被"顶到"有限次，总跳跃次数是 $O(n)$（实测最坏比值 $\approx 2$）。

实现上，代码用 `ys / xs` 的交叉相乘代替除法，并给"向左"的情况整体乘 $-1$
折叠成同一个不等式，见 `main.py` 的 `far_side`。

**从 $i$ 出发的路径：只在"看到更高的山"时才转向。**

设爬山者在 $P_i$ 处 $T = f_i$。它朝 $f_i$ 走的途中依次经过 $i, i\pm1, i\pm2,\dots$，
在每一站只会把 $T$ 更新为 $\max(T, f_{cur})$。于是在到达 $f_i$ 之前，
**$T$ 恰好第一次变得比 $f_i$ 更高的那一站 $k$ 是真正的转向点**：

- 在 $k$ 之前，$T = f_i$ 不变，方向不变，所以步子是一路直着走的；
- 到了 $k$，$T = f_k$ 且 $\mathrm{rank}(f_k) > \mathrm{rank}(f_i)$。

关键在最后一句：**在 $P_k$ 处的状态和"以 $P_k$ 为起点"完全一样**（两边 $T$ 都等于 $f_k$）。
所以

$$\mathrm{ans}_i = |i - k| + \mathrm{ans}_k,$$

而没有这种 $k$ 时（沿路没人看得更高），直接一口气走到 $f_i$，即 $\mathrm{ans}_i = |i - f_i| + \mathrm{ans}_{f_i}$。

于是只要对每个 $i$ 定出这个下一站 $\mathrm{par}_i$：「在 $i$ 与 $f_i$ 之间、沿行进方向，
$\mathrm{rank}(f_k) > \mathrm{rank}(f_i)$ 的第一个位置 $k$」，否则 $f_i$。

**求 $\mathrm{par}$：单调栈。** 把每点的键定为 $\mathrm{key}(i) = \mathrm{rank}(f_i)$（压成整数
$y_{f_i}\cdot(10^6+1) + x_{f_i}$ 即可）。那么"第一个 $\mathrm{key}$ 更大的位置"
就是单调栈的经典询问：从左往右扫求出每点左侧首个键更大者，从右往左扫求出右侧首个。
若这个位置落在 $i$ 与 $f_i$ 之间就取它，否则退化成 $f_i$。两次扫描都是 $O(n)$。

**收尾：沿链递推。** 这里还需要一条除成环的性质：**只要 $\mathrm{par}_i \ne hi$，就必有
$\mathrm{key}(\mathrm{par}_i) > \mathrm{key}(i)$**，即键沿 $\mathrm{par}$ 链严格递增。
直觉上这也是合理的：$\mathrm{key}$ 度量的是"$i$ 已能看到多高的峰"，走一步只会抬高它；
而 $\mathrm{par}_i = f_i$（键持平）的情形只会出现在"已看到的就是全山最高"的时候。
这条性质在小数据上做过穷举（$n \le 8$、$y \in [0,3]$，共 87 376 组）与 $n \le 12$ 的
随机对拍，均无例外。键严格递增就能推出**每条链都终于 $hi$**（不成环），
而每个点只会被填一次，所以总代价 $O(n)$。
让 $\mathrm{ans}_{hi} = 0$，每次遇到未算过的 $i$ 就沿链走到已算过的点，再倒着把路上每点的
$|i - \mathrm{par}_i|$ 累加回去；每个点只被填一次，总代价 $O(n)$。

**用样例走一遍。** 山顶 $P_1=(0,10),P_2=(1,5),P_3=(2,0),P_4=(3,6)$，全局最高是 $P_1$（$y=10$）。
下面下表里的下标都是 **1 起**。

| $i$ | 向左斜率最大者 | 向右斜率最大者 | $f_i$ | $\mathrm{key}(i)$ | $\mathrm{par}_i$ | $\mathrm{ans}_i$ |
| :-: | :-: | :-: | :-: | :-: | :-: | :-: |
| 1 | — | — | 1 | $(10,0)$ | 1 | 0 |
| 2 | 1 | 4 | 1 | $(10,0)$ | 1 | $\lvert2-1\rvert + 0 = 1$ |
| 3 | 2 | 4 | 4 | $(6,3)$ | 4 | $\lvert3-4\rvert + 3 = 4$ |
| 4 | 1 | — | 1 | $(10,0)$ | 1 | $\lvert4-1\rvert + 0 = 3$ |

逐格核对第 2、3 两行。$i=2=(1,5)$：向左看 $P_2P_1$ 斜率 $-5$（唯一候选），向右看
$P_2P_4$ 斜率 $1$ 大于 $P_2P_3$ 的 $-5$，所以 $f_2 = \max\langle(10,0),(6,3)\rangle = 1$。
$i=3=(2,0)$：向左 $P_3P_2$ 斜率 $5$、向右 $P_3P_4$ 斜率 $6$，而 $\mathrm{rank}(P_4)=(6,3)$ 高于
$\mathrm{rank}(P_2)=(5,1)$，故 $f_3 = 4$。
再看转向点：$i=3$ 朝 $4$ 走，$i$ 与 $f_i$ 之间没有别的下标，所以直接
$\mathrm{par}_3 = f_3 = 4$，得 $\mathrm{ans}_3 = 1 + \mathrm{ans}_4 = 1 + 3 = 4$。
而 $i=4=(3,6)$ 向左能越过 $P_3,P_2$ 看到 $P_1$（$P_3,P_2$ 都严格在线段 $P_4P_1$ 下方），
于是 $f_4 = 1$ 且 $\mathrm{par}_4 = 1$，$\mathrm{ans}_4 = 3 + 0 = 3$，与样例输出一致。

### 复杂度

- **时间**：链式跳跃求两侧斜率最大者，每个点被顶到的次数摊还为 $O(1)$，共 $O(n)$；
  单调栈两次扫描 $O(n)$；沿 $\mathrm{par}$ 链递推每个点填一次，$O(n)$。
  总时间 $O(n)$。实测 $n = 5\times10^5$ 时 C++ 约 0.1 s、Python 约 0.5 s（限时 1000 ms）。
- **空间**：坐标、$L/R$、$f$、$\mathrm{par}$、$\mathrm{ans}$ 各一个长度为 $n$ 的数组，$O(n)$。
  C++ 静态数组约 20 MB，Python 约 120 MB（限时 256 MB，Python 侧需留意）。
- **正确性验证**：与 $O(n^3)$ 暴力模拟在 3 万余组随机小数据（含大量三点共线、
  全等高等对抗）上逐行比对，$0$ 分歧；随仓 10 组真实数据 C++ 与 Python 均全过。

## 总结

- **把几何问题翻译成斜率问题**：本题最硬的一步是"能看到的最高山顶 = 斜率最大的点"。
  它把"逐个检查可见性"的 $O(n)$ 判断，一次性换成"求斜率最大值"的结构化问题，
  后面的数据结构才有用武之地。
- **善用摊还跳跃**：求最优点不是凸包二分，而是"答案在已知点里就继续跳过去"
  （$R_i \to R_{R_i}$）。这种链式跳跃写起来比二分短，摊还复杂度还更好。
- **"状态相同"是折叠模拟的关键**：真正让模拟从 $O(n^2)$ 降到 $O(n)$ 的，
  不是找规律，而是发现"在转向点 $k$ 处的状态和以 $k$ 为起点一模一样"，
  于是路径可以整段整段地合并成一条 $\mathrm{par}$ 链。
- **单调栈求"首个键更大的位置"**：这是可复用的小技巧，键可以是排序后的二元组，
  只要压成整数就能直接进栈。
- **共线要靠严格不等号区分**：把 `<` 换成 `<=` 就会跳过被中间山顶挡住的情形，
  数据里的共线链（`problem4` / `problem5`）专门打这种细节。
