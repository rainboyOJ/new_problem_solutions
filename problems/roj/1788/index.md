## 形式化题目

给出 $n$ 个山顶 $P_1, P_2, \dots, P_n$，横坐标严格递增，相邻山顶用线段相连构成折线 $l$。

定义「$P_j$ 能被站在 $P_i$ 的人看到」为：线段 $P_iP_j$ 与折线 $l$ 只在端点 $P_i$、$P_j$ 处相交。注意中间若有山顶恰好落在线段 $P_iP_j$ 上（三点共线），也算挡住视线。

爬山规则：站在 $P_{curr}$ 上先左右张望，更新「到目前为止看到过的最高山顶」$T$（比较标准是 $y$ 大者更高，$y$ 相同时 $x$ 大者更高），然后朝 $T$ 的方向走一步到相邻山顶；当 $curr = T$ 时停下。求以每个山顶为起点时走过的总步数。

数据范围：$1 \leqslant n \leqslant 5 \times 10^5$，$0 \leqslant x_i, y_i \leqslant 10^6$。

## 正解

### 思路

朴素做法是每次张望枚举所有山顶判可见性、再一步一步模拟移动，最坏 $O(n^2)$ 判可见性乘 $O(n)$ 步乘 $n$ 个起点，完全不可行。突破口是两点：**张望时到底该看哪个点**，以及**走的过程中什么时候会改主意**。

**观察一：可见点集的斜率是单调整的。**

站在 $P_i$ 向右看。若 $P_j$ 与 $P_k$（$i < j < k$）都能看到，则 $j$ 落在线段 $P_iP_k$ 的下方，即

$$k(i, j) < k(i, k), \qquad k(i, t) = \frac{y_t - y_i}{x_t - x_i}$$

所以向右能看到的那些点，按位置排序后斜率**严格递增**（共线的中间点斜率相等，被判为挡住，因此不会同时出现）。同理向左看时，可见点到 $P_i$ 的斜率也是严格递增的。

于是「向右看到的最高山顶」就是**右侧斜率最大的那个可见点**：斜率最大的点必然可见（中间点都更缓，挡不住），而比它更高的点若可见就得有更大的斜率，矛盾。向左同理。

**观察二：链式跳跃求出这两个端点。**

记 $R[i]$ 为从 $P_i$ 向右看到的最高山顶，$L[i]$ 为向左看到的最高山顶。由观察一，它们分别是某条「斜率严格递增的链」的终点，而链可以只存一个端点：从 $P_{i+1}$ 出发，若 $k(i, R[i+1]) < k(i, R[R[i+1]])$ 就说明 $R[i+1]$ 挡不住更远的那个点，直接跳过去。每个点最多被跳过一次，均摊 $O(1)$，所以 $L, R$ 数组可以 $O(n)$ 求出（比较斜率用交叉相乘，避免浮点误差；坐标差最大 $10^6$，乘积 $10^{12}$ 需 64 位整数，Python 无此问题）。

- $R[i]$：$R[i] \leftarrow i+1$，然后不断令 $R[i] \leftarrow R[R[i]]$，直到斜率不再增大。
- $L[i]$：链的两端共享右端点 $i$，从 $L[i] = i-1$ 出发，若 $k(L[L[i]], i) < k(L[i], i)$ 就令 $L[i] \leftarrow L[L[i]]$，直到不再增大。

**观察三：徒步过程是一条笔直的路，由「张望目标的秩」分段。**

记 $f(v) = seen[v]$，并给每个点 $v$ 配一个排序键 $\mathrm{key}(v) = \big(y_{f(v)},\; x_{f(v)},\; v\big)$ —— 也就是「我张望到的目标有多高」，目标一样高时用编号兜底保证唯一。出发点是下面这条可以单独验证的性质：

> 从 $P_i$ 出发朝 $T = f(i)$ 走，在走过第一个 $\mathrm{key}(j) > \mathrm{key}(i)$ 的山顶 $j$ 之前，行走者既不会掉头，目标也一直是 $T$。

原因是这一路上新看到的点都在 $P_i$ 张望时的那一侧，而 $P_i$ 在该侧能看到的最高点已经被 $f$ 取走，故新点的高度只能更矮或相等（等高时按 $x$ 大者取胜，越靠近起点越不吃亏）；于是目标不会更新成比自己张望目标更高的东西，方向自然不变。

所以每个点只需要记一个**落点** $g(i)$：走完这段直线后停在哪里。它就是「朝 $f(i)$ 方向、第一个 $\mathrm{key}$ 大于 $\mathrm{key}(i)$ 的位置」，没有这样的位置时就是 $f(i)$ 本身。于是

$$\mathrm{ans}(i) = \mathrm{ans}(g(i)) + |i - g(i)|$$

反复展开：每次落点的 $\mathrm{key}$ 都比上一段大，所以 $i \to g(i) \to g(g(i)) \to \dots$ 是一条 $\mathrm{key}$ 严格递增的链，最终必然到达全局最高山顶（它的 $\mathrm{key}$ 无人能及、$f$ 就是自己，答案 0）。这些边构成以全局最高山顶为根的树，答案就是树上到根的距离之和。

**观察四：不用显式建树。**

按 $\mathrm{key}$ 从小到大处理所有非根点，并用双向链表维护「还没处理过的点」：处理 $i$ 时把它从链表中摘除，则 $i$ 在朝 $f(i)$ 那一侧的最近未处理邻居，恰好就是上面定义的落点 $g(i)$——因为「未处理」与「$\mathrm{key}$ 不小于 $\mathrm{key}(i)$」在这套处理顺序下等价。父指针取这个邻居，边权取 $|i - g(i)|$。

**观察五：倒序累加。**

由观察四，$g(i)$ 的处理次序一定在 $i$ 之后（它的 $\mathrm{key}$ 更大，或者就是 $f(i)$ 而 $f(i)$ 永远比自己晚被处理），因此把处理顺序**逆序**走一遍，轮到 $i$ 时父节点的答案已经就绪，直接

```text
ans[root] = 0
for i in reversed(order):
    ans[i] = ans[parent[i]] + |i - parent[i]|
```

即得全部答案，不必显式建树、也不必真的模拟行走。

**几个容易写错的细节：**

- **共线必挡**：可见性要求折线只在线段端点处与线段相交，中间点落在线上也算相交，所以斜率相等时链条立即停止，不能跳过等斜率的点（代码里用严格小于 `<` 判断）。
- **秩的平局规则**：$y$ 相同时取 $x$ 大者更高，所以左右候选等高时选右侧那个（其 $x$ 必然更大）；排序键用 $(y,\; x,\; i)$ 三键，保证处理顺序唯一确定。
- **边界**：$i = 0$ 只有右侧候选，$i = n-1$ 只有左侧候选；$n = 1$ 时根即自身、答案 $0$。

### 复杂度

- 求 $L, R$：每个点最多被跳过一次，均摊 $O(n)$。
- 排序：$O(n \log n)$。
- 双向链表摘点 + 倒序累加：$O(n)$。

总时间 $O(n \log n)$，空间 $O(n)$。$n = 5 \times 10^5$ 时 C++ 实测约 $0.1$ s，余量充足。

## 总结

本题的关键是把「张望看到的最高点」翻译成**斜率单调链的终点**，从而每个点只需记住左右两个候选；再发现「每一段直路都由张望目标的秩划开」——走过第一个目标键更大的点之前，行走者不掉头、目标也不变，于是整条路径缩成以全局最高点为根的树，答案就是树上距离。求树边时只需按目标键升序 + 双向链表摘点，连落点都没必要求出来，整体 $O(n \log n)$（只花在排序上）。

举一反三是这类「可见性 + 单调链」模型：凡是「两点之间连线不能被中间点挡住」的可见性判定，都可以按斜率单调整理成链，用带路径压缩的跳跃把每层询问压到均摊 $O(1)$。
