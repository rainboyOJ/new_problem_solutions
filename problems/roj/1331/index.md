## 形式化题目

给定一个**后缀表达式**（逆波兰式）字符串，求它的值。字符集只有：

- 运算数：由 `0`-`9` 组成的非负整数；
- 运算符：`+`、`-`、`*`、`/` 四种；
- 结束标志：`@`，它之后的内容一律忽略。

约束是：

- 表达式长度 $L < 250$；
- 参与运算的整数及结果的绝对值都 $< 2^{64}$；
- 除法保证整除（被除数是除数的整数倍）；
- 输入保证合法，不需要做合法性判断。

后缀表达式的求值语义是标准的栈式归约：从左到右扫描，遇运算数压栈，遇运算符则弹出栈顶两个数、**先弹出的是右操作数、后弹出的是左操作数**，做「左 $\circ$ 右」后把结果压回；扫描结束时栈里恰好剩一个数，它就是答案。

题面样例：

```text
输入：16 9 4 3 +*-@
输出：-47
```

它对应的中缀形式是 $16 - 9 \times (4 + 3)$。**注意 `+*-` 三个运算符是连写的**——题面只承诺「每个运算数之间用一个空格隔开」，没有承诺运算符之间也有空格。

一次完整的扫描过程（栈写成「栈底 → 栈顶」）：

| 字符 | 动作 | 栈 |
| --- | --- | --- |
| `1` | 数字位 1：拼数中 `number=1` | `[]` |
| `6` | 数字位 6：拼数中 `number=16` | `[]` |
| ` ` | 运算数结束：把 16 压栈 | `[16]` |
| `9` | 数字位 9：拼数中 `number=9` | `[16]` |
| ` ` | 运算数结束：把 9 压栈 | `[16, 9]` |
| `4` | 数字位 4：拼数中 `number=4` | `[16, 9]` |
| ` ` | 运算数结束：把 4 压栈 | `[16, 9, 4]` |
| `3` | 数字位 3：拼数中 `number=3` | `[16, 9, 4]` |
| ` ` | 运算数结束：把 3 压栈 | `[16, 9, 4, 3]` |
| `+` | 弹出右 3、左 4，$4+3=7$ 压回 | `[16, 9, 7]` |
| `*` | 弹出右 7、左 9，$9\times7=63$ 压回 | `[16, 63]` |
| `-` | 弹出右 63、左 16，$16-63=-47$ 压回 | `[-47]` |

表中可以看到两件事：多位数 `16` 是一边扫描一边拼出来的，中间出现过 `1` 但从未以 `1` 入栈；三个运算符虽然没有空格分隔，仍然被逐个处理。

## 正解

### 思路

求值逻辑本身没有难度，难点全在**怎么把字符串切成 token**。

**朴素做法：用空格 `split()`，再判断每个 token 是不是运算符。**

```python
for token in expr.split():
    if token in '+-*/':
        ...          # 运算符
    else:
        stack.append(int(token))   # 运算数
```

这个写法**在样例上就会崩**。把 `16 9 4 3 +*-@` 去掉 `@` 后 `split()`，得到的是

```text
['16', '9', '4', '3', '+*-']
```

最后一项是 `'+*-'` 一整个 token：它不等于 `'+-*/'` 中任何一个单字符，于是走到 `else` 分支执行 `int('+*-')`，直接 `ValueError`。

根因是空格的作用被误解了。题面的原文是「**每个运算数之间**用一个空格隔开」——空格只用来分隔运算数，**运算符是可以连写的**。真实的三份测试数据 `16 9 4 3 +*-@`、`16 9 4 3 +*+@`、`16 9 4 3 +**@` 全部使用连写运算符，说明这是本题的常规输入形态而非样例特例。

**第一步改进：用正则按字符类别切。**

```python
for token in re.findall(r'\d+|[+*/-]', expr):
```

`\d+` 优先吃掉整段连续数字位，`16` 因此保留为一个整体；`[+*/-]` 一次只匹配一个运算符，`+*-` 就被拆成 `'+'`、`'*'`、`'-'`。写法正确，代价是要引入 `re` 并让读者额外理解一条正则。

**最终做法：逐字符扫描，用「正在拼数」的状态代替切分。**

既然 token 的边界本质上由**字符类别变化**决定（数字位 → 非数字位），那就不必先切出 token 列表，边扫边维护两个变量即可：

| 变量 | 含义 |
| --- | --- |
| `number` | 正在拼装的运算数的值 |
| `reading` | 当前是否处于一个运算数内部 |

每个字符只做三种转移之一：

1. **是数字位**：`number = number * 10 + int(ch)`，并置 `reading = True`。这里**不能立即入栈**——后面可能还有数字位，`16` 的 `1` 和 `6` 必须拼在一起。
2. **是空格或运算符，且 `reading` 为真**：当前运算数到此结束，把 `number` 压栈，然后清空状态。
3. **是运算符**：弹出栈顶两个元素，先弹出的是右操作数、后弹出的是左操作数，算完把结果压回。

第 2 步必须排在第 3 步之前，这是本题最容易写错的地方。看 `3 4+@`：扫到 `4` 时 `number=4, reading=True`，但 4 **还没入栈**，此时栈里只有 `[3]`。紧接着扫到 `+`，如果先处理运算符，就会连续 `pop` 两次，第二次在空栈上抛出 `IndexError: pop from empty list`。把「结算待入栈的运算数」放在「处理运算符」之前，正是为了在运算符动作开始前，保证两个操作数都已经在栈上。

与顺序同样重要的是**触发条件的写法**。第 3 步不能写成「只要不是数字位就归约」或「只要不是空格就归约」，而应当**正面判定「是四种运算符之一」**。原因是题面只承诺运算数之间有空格，运算符之外还可能出现换行、制表符、首尾空白等字符；若把这些也当成运算符，就会多弹一次栈。因此代码里用 `OPERATORS = '+-*/'` 加成员判断来界定运算符，其余字符一律跳过。

`reading` 这个标志不能省成 `number != 0`：`0` 是合法的运算数，`0 1+@` 和 `0 0-@` 都能出现在数据里，必须能区分「正在读的数就是 0」和「还没开始读数」。

还有一处收尾：`@` 可能直接紧跟运算数（如 `12@`），此时 `reading` 仍为真、`number` 尚未入栈，所以扫描结束后要补一次收尾入栈（`main.py` L40-41 的 `if reading: stack.append(number)`）。

最后是除法。题面保证整除，此时 `//`（向下取整）与 C++ 的 `/`（向零截断）结果相同，负数也不会有分歧（`-6 / -3`、`6 / 3` 都无余数），所以直接用 `left // right` 即可。

**为什么这套做法是对的（归纳）。** 设表达式有 $n$ 个运算符，对 $n$ 归纳。$n=0$ 时表达式是单个运算数，扫描把它拼好并收尾入栈，栈为单元素且值正确。$n>0$ 时表达式必可唯一分解为 $E = E_1\,E_2\,\circ$，其中 $E_1$、$E_2$ 是运算符数更少（因而都 $< n$）的合法后缀子表达式。由归纳假设，扫描完 $E_1$ 后栈顶是 $E_1$ 的值；扫描完 $E_2$ 后栈顶是 $E_2$ 的值、它下面紧挨着是 $E_1$ 的值。此时遇到 $\circ$，按后进先出先弹出的是 $E_2$ 的值（右操作数）、后弹出的是 $E_1$ 的值（左操作数），压回 $E_1 \circ E_2$，正好是 $E$ 的值。归纳成立。

**几个边界情况的处理**（都在 `main.py` 里落实）：

| 情况 | 例子 | 处理 |
| --- | --- | --- |
| 运算符连写 | `+*-` | 逐字符扫描逐个处理，与空格无关 |
| 多位数 | `16` | `number * 10 + 位值` 逐位拼装 |
| 运算数是 `0` | `0 1+@` | `reading` 标志区分「读的是 0」与「没在读数」 |
| `@` 紧跟运算数 | `12@` | 扫描结束后收尾补一次入栈 |
| 中间值为负 | `16 9 4 3 +*-` | 栈里存 Python `int`，负数无特殊处理 |
| 大数（$<2^{64}$） | `18446744073709551615@` | Python `int` 任意精度，不会溢出 |
| 末尾有换行 | `...@\n` | 只取 `@` 之前的部分，后面一律不看 |
| `@` 前有换行/制表符 | `3 4+\n@` | 只有四种运算符会触发归约，其余字符一律当分隔符 |
| 首尾有多余空白 | `  3 4+@\n` | 非运算符字符跳过，不影响结果 |

倒数两行值得单独说：题面只承诺「运算数之间用空格隔开」，那么**除运算符外的任何字符都应当被当作分隔符**。如果把「非运算符」等同于「运算符」来处理（例如写 `if ch != ' '` 就归约），那么输入里出现换行、制表符或首尾空白时会多执行一次归约，在空栈上崩溃。因此判定「是否触发归约」必须**正面列出四种运算符**，而不是用 `ch != ' '`、`not ch.isdigit()` 这类反条件。同理，判定数字位写成 `'0' <= ch <= '9'` 而不是 `ch.isdigit()`：后者对 `'²'` 这类 Unicode 上标数字也返回 `True`，而 `int('²')` 会抛 `ValueError`。

顺带对照一下题面给出的参考实现 `std.cpp`（它也是逐字符扫描 + 栈，思路一致），有三处可以改进：

- 它用 `while (str[i] != ' ')` 手工吃数字，**隐含假设运算数后面一定有空格**，并靠外层循环上界 `len - 3` 跳过末尾的「空格、`@`、`\n`」三个字符来避免越界；本解用 `reading` 标志代替这个假设。
- 它写 `stack[--top] += stack[top+1]`，在同一个表达式里既修改 `top` 又读取 `top+1`，求值顺序未指定，在 C++17 中是**未定义行为**。本解用两次显式的 `pop`，语义无歧义。
- 它用 `int stack[256]` 存中间结果，而题面允许结果到 $2^{64}$ 量级，`int` 会溢出；Python 的 `int` 不受此影响。

### 复杂度

- **时间复杂度**：$O(L)$，其中 $L$ 是表达式长度。循环扫过每个字符一次：数字位做一次常数时间的乘法加法，运算符做一次常数次 `pop`/`append` 和一次算术。$L < 250$，所以总操作数是常数级。这与 `split()` 切分法**同阶**（那一版只是多付一次 $O(L)$ 的切分），本题不存在可消除的算法瓶颈——改进全部发生在正确性与常数层面。
- **空间复杂度**：$O(L)$。栈里最多同时存放约 $\lceil L/2 \rceil$ 个中间数（如 `1 1+1+1+...` 这种形态），再加上输入字符串本身。
- **实测**：三份官方数据各约 $0.017$ s、峰值 $14.6$ MB，相对 1000 ms / 128 MB 的限制余量极大。

## 总结

后缀表达式求值与栈是**双向唯一**的对应关系：后缀式的定义就是「运算符作用于它前面最近的两个已完成求值的子表达式」，而栈顶恰好是「最近两个」的存放处，所以「遇数入栈、遇运算符归约两个再压回」是唯一自然的实现。本题是本仓库里表达式求值这条线的起点，往后拓括号匹配、中缀转后缀、表达式树都是同一套栈思想。

真正值得记住的是**输入格式的读法**。题面只承诺「运算数之间用空格隔开」，那么空格就只是数字 token 的**可选分隔符**，而不是 token 的统一切分依据；`split()` 把「按空格切」偷偷当成了「按 token 切」，于是把 `+*-` 粘成一坨。正确的心智模型是：**token 的边界由字符类别变化决定**——读到数字位表示进入运算数状态，读到非数字位表示离开。一旦这样建模，切分与求值就合并成一次扫描，既不需要 `re`，也不需要中间的 token 列表。

实现上有四处细节是这类题反复出现的坑：一是 `reading` 状态不能用 `number != 0` 顶替，因为 `0` 是合法运算数；二是「结算待入栈运算数」必须排在「处理运算符」之前，否则 `3 4+` 就会空栈崩溃；三是末尾要收尾，因为 `@` 可能紧跟运算数；四是触发归约的判定要正面写成「是四种运算符之一」，否则 `@` 前的换行或制表符也会多弹一次栈。把这几条都处理掉，本题就没有别的分支了。
