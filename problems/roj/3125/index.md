## 形式化题目

给定 $n$ 个边与坐标轴平行的闭矩形 $R_i = [x_{i1}, x_{i2}] \times [y_{i1}, y_{i2}]$，
求并集

$$
U = \bigcup_{i=1}^{n} R_i
$$

的边界总长度（周长）。$0 \leqslant n < 5000$，所有顶点坐标是绝对值不超过 $10000$ 的整数。

并集的边界是一条分段水平或垂直的闭折线，所以周长可以拆成**水平边总长**与**竖直边总长**
两部分分别计算：

$$
P = P_{\text{横}} + P_{\text{竖}}
$$

本题的规模要求 $O(n \log n)$ 量级。

## 正解

### 关键观察

**观察 1：边界可以按方向拆开。** 边界上的每一小段要么水平、要么竖直，两者的长度只做加法，
互不干扰。所以只要能算清「所有水平边加起来多长」，把整个图形连同坐标轴一起转 $90^\circ$
再算一次，就得到竖直边总长。下面只讨论水平边。

**观察 2：把水平边按条带积分。** 所有矩形的竖直边横坐标只有 $O(n)$ 个不同取值。把它们
排序成 $x_0 < x_1 < \dots < x_m$，在任意开条带 $(x_i, x_{i+1})$ 内部，没有任何矩形在此
开始或结束，因此**竖直线 $X = x$ 与并集的交集结构在整个条带内完全不变**。

记 $c_y(x)$ 为竖直线 $X = x$ 与 $U$ 相交所成的极大区间个数。取其中一个极大区间
$[a, b]$，它有两个端点 $(x, a)$ 与 $(x, b)$；当 $x$ 在这个条带内移动时，这两个端点分别
扫出下端与上端的两条**水平边**，每条长度恰好是条带宽 $x_{i+1} - x_i$——因为条带内没有
竖直边插入，边不会中途断掉。于是

$$
P_{\text{横}} = \int 2\,c_y(x)\,\mathrm{d}x
             = \sum_{\text{条带}} 2\,c_y \cdot \text{条带宽}
$$

积分退化成有限和，而且每个条带里的 $c_y$ 是常数，只需在条带处查一次。

用一个十字形的例子看得更清楚：横条 $[0,5] \times [1,2]$ 加上竖条 $[2,3] \times [0,4]$。

```text
并集轮廓（# = 被覆盖的单位格，y 轴向上）：
  y= 3 ..#..
  y= 2 ..#..
  y= 1 #####
  y= 0 ..#..
       01234  <- x
```

沿 $x$ 方向扫描，三个条带的截面各有 1 个极大区间：

| 条带 | 宽 | 截面极大区间数 | 贡献 $2 \times \text{区间数} \times \text{宽}$ |
| :-- | :-: | :-: | :-: |
| $[0,2)$ | 2 | 1 | 4 |
| $[2,3)$ | 1 | 1 | 2 |
| $[3,5)$ | 2 | 1 | 4 |
| **水平边合计** | | | **10** |

这 10 正好是 $y=1$ 与 $y=2$ 处的各 4（横条上下边界，被竖条切掉中间一段），加上 $y=0$
与 $y=4$ 处的各 1。把图形转 $90^\circ$ 再扫一次得到 8，就是四条竖直边
（$x=0$、$x=5$ 各 1，$x=2$、$x=3$ 各 3）。$10 + 8 = 18$，与直接在单位格上数边界一致。

**观察 3：$c_y$ 是可以合并的。** 观察 2 把一个二维问题压成了一维：维护一个布尔区间集合，
支持「区间加 1 / 区间减 1」，并随时回答**极大区间个数**。这个量可以自底向上合并。
设节点被中点切成左右两半，左半有 $\text{seg}_L$ 个极大区间、其最右元区间是否被覆盖记为
$\text{right}_L$；右半对称地有 $\text{seg}_R$、$\text{left}_R$，则

$$
\text{seg} = \text{seg}_L + \text{seg}_R - [\,\text{right}_L \ \text{且}\ \text{left}_R\,]
$$

减掉的这一项是必要的：只有当两半在交界处**都**被覆盖时，它们才其实是同一个极大区间，
必须去重。比如把元区间 $[0,0]$ 和 $[1,1]$ 都覆盖上，答案是 1 个区间而不是 2 个。

**注意这不是「被覆盖的总长度」。** 一个常见的错误写法是维护被覆盖总长 `len`，用水平边
$= \sum |\Delta \text{len}|$ 来算。它对本类问题是有陷阱的：同一个横坐标上可能既有矩形
开始又有矩形结束，`|Δlen|` 的算法必须先加后删，否则会算错。例如矩形
$(0,0,1,2)$、$(1,0,2,2)$、$(1,1,2,3)$ 构成的 T 形并集周长是 10，先删后加的写法会给出 14。
本解法用条带**区间计数**，同一坐标上的事件顺序完全不影响结果，不必关心这个排序陷阱。

### 思路

**线段树节点。** 用线段树维护四个量：

| 量 | 含义 |
| :-- | :-- |
| `cover` | 整段被多少个矩形完全盖住 |
| `seg` | 该节点范围内「被盖住的极大区间」个数 |
| `left_on` | 最左边那个元区间是否被盖住 |
| `right_on` | 最右边那个元区间是否被盖住 |

`pull` 分三种情况：`cover > 0` 时整段被盖住，`seg = 1`、两个端标志都为真，
**不必看孩子**；是叶子（且没被盖住）时 `seg = 0`；否则按观察 3 的式子合并。
`cover` 只加在完整覆盖的高层节点上，**不需要下传**——这是本题不必写 `push` 的原因，
也是 Python 能跑得动的前提。

**建树与查询。** 把「下端 / 上端」坐标排序去重，相邻两个坐标之间叫一个**元区间**，
共有 `leaves = len(coords) - 1` 个。每个矩形的 $[y_1, y_2]$ 对应元区间下标区间
$[\text{index}(y_1), \text{index}(y_2) - 1]$。区间的覆盖次数用 `cover` 加减，
树根上的 `seg` 就是当前的 $c_y$。

**扫描。** 每个矩形在起点处产生一个 $+1$ 事件、终点处产生一个 $-1$ 事件，按位置排序后
线性扫过：

```text
total = 0 ; last = events[0].pos
for (pos, lo, hi, val) in events:
    total += 2 * seg[1] * (pos - last)   # 先按当前截面结算条带 (last, pos)
    last = pos
    update(1, 0, leaves-1, lo, hi, val)  # 再让 pos 处的事件生效
```

顺序不能反：结算条带时必须还是**条带内部**的状态，而事件要到条带右端点才起作用。
第一个事件开出的是宽度为 0 的空条带，天然贡献 0；同一位置上的多个事件除第一个外，
条带宽也是 0，所以它们的先后顺序无所谓。

实现说明：

- `COVER`、`SEGMENT`、`LEFT_ON`、`RIGHT_ON` 是模块级数组，`build` 用 `global`
  一次性重建，避免把大数组当参数在递归里反复传递。
- 数组长度取 `4 * leaves + 4`；`leaves = 1` 时子节点下标也不会越界。
- `leaves <= 0` 提前返回 0，覆盖了 $n = 0$、$n = 1$ 和「所有矩形退化到同一条竖线」等情形，
  顺带避免了 `events[0]` 越界。
- 读入时用 `min` / `max` 归一化，题面保证 $(x_1, y_1)$ 是左下角，这样写不增加成本但更稳。
- 第二趟扫描直接把每个四元组重排成 `(lo, hi, start, end)`，复用同一个 `sweep`。

### 复杂度

- 时间：坐标排序 $O(n \log n)$；$2n$ 个事件各做一次 $O(\log n)$ 的区间更新，共 $O(n \log n)$。
  两趟扫描同阶，总计 $O(n \log n)$。
- 空间：线段树四个数组与坐标表、事件表都是 $O(n)$。
- 实测：题面样例（7 个矩形）输出 `228`，与标准答案一致；5 组真实数据（最大 $n = 4912$）
  全部一致，总耗时 0.17 s、峰值内存 18.5 MB，在 1000 ms / 128 MB 限制内。

## 总结

- 求并集周长时，先把边界按方向拆成水平、竖直两组；每组都能写成对截面极大区间个数的积分，
  再转 $90^\circ$ 复用同一段代码。
- 关键在于「条带内截面不变」：它把积分变成有限和，也让扫描线上的线段树只需回答
  「截面上覆盖了多少段」这一个问题。
- 「极大区间个数」必须靠 `cover` / `seg` / `left_on` / `right_on` 四个量维护，
  合并时要减掉交界处的重复；它和「覆盖总长」是两回事，后者会引入同坐标事件排序的陷阱。
- `cover` 不需要下传，单次更新 $O(\log n)$，这是 Python 能过掉本题的原因。
