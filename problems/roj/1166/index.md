## 形式化题目

给定实数 $x$ 与正整数 $n$，定义 $n$ 层嵌套根式

$$
f(x,n) = \sqrt{n + \sqrt{(n-1) + \sqrt{(n-2) + \sqrt{\cdots + 2 + \sqrt{1+x}}}}}
$$

最内层为 $\sqrt{1+x}$，自内向外共 $n$ 层根号，求 $f(x,n)$。

等价地，令 $g_1=\sqrt{1+x}$，$g_k=\sqrt{k+g_{k-1}}$（$2 \leqslant k \leqslant n$），则 $f(x,n)=g_n$。

输入样例与输出样例：

```
4.2 10
```

```
3.68
```

## 正解

### 思路

**1. 先把递归结构认出来。** 照着题面写，$f$ 天然是递归的：

$$
f(x,n)=\sqrt{n+f(x,n-1)},\qquad f(x,1)=\sqrt{1+x}
$$

计算 $f(x,n)$ 必须先得到 $f(x,n-1)$，而后者又必须先得到 $f(x,n-2)$……调用会一路压栈到
$f(x,1)$ 才开始逐层返回，**栈深度正好是 $n$**。

这一步没有性能问题：每次调用只再调用一次自己，不存在重复子问题，不会出现指数级展开。
但它把"结果依赖语言默认的递归深度上限"变成了隐患——Python 默认递归上限约 1000，
$n$ 稍大就会 `RecursionError`（C++ 则可能爆栈），而每一层做的其实是完全相同的运算。

**2. 关键观察：递归是一条链，不是一棵树。** 每一层只从它的下一层取一个数，
层与层之间没有别的依赖，所以整串根号退化成一棵"只有一个孩子的树"：

```text
        sqrt(n + g_{n-1})          <- 最外层，答案 f(x,n)
              |
        sqrt(n-1 + g_{n-2})
              |
             ...
              |
        sqrt(2 + g_1)
              |
        sqrt(1 + x) = g_1          <- 最内层，迭代起点
```

链上的求值只需要"上一个数"，历史值算完就可以丢掉。因此可以把递归的返回过程
显式写成循环：**从最内层开始，一层层往外折叠**。

**3. 从内到外折叠。** 记 $g_1=\sqrt{1+x}$，第 $k$ 层把层号加进去再开方：
$g_k=\sqrt{k+g_{k-1}}$。注意第 $k$ 层根号里的加数恰好就是 $k$，所以循环变量可以直接
充当这个加数，不需要预先准备 $1,2,\dots,n$ 这个序列。

样例 $x=4.2,\ n=10$ 的折叠过程（数值保留 4 位小数）：

| 层 $k$ | 根号内 $k+g_{k-1}$ | 折叠结果 $g_k$ |
| --- | --- | --- |
| 1 | $1+x=1+4.2=5.2$ | 2.2804 |
| 2 | $2+2.2804=4.2804$ | 2.0689 |
| 3 | $3+2.0689=5.0689$ | 2.2514 |
| 4 | $4+2.2514=6.2514$ | 2.5003 |
| 5 | $5+2.5003=7.5003$ | 2.7387 |
| 6 | $6+2.7387=8.7387$ | 2.9561 |
| 7 | $7+2.9561=9.9561$ | 3.1553 |
| 8 | $8+3.1553=11.1553$ | 3.3400 |
| 9 | $9+3.3400=12.3400$ | 3.5128 |
| 10 | $10+3.5128=13.5128$ | 3.6760 |

表格的一行对应"已经折叠到第 $k$ 层"，中间列是这一层根号里的数，右列是该层的结果。
观察两件事：一是每层的输入只来自上一行的右列，这正是"状态只有一个数"的含义；
二是数值**并不单调**——$g_1=2.2804$ 反而大于 $g_2=2.0689$，因为 $x=4.2$ 较大，
而第 2 层只加了 2，开方的收缩占了上风；从第 3 层开始加数逐渐变大，数值才一路回升。
最后 $g_{10}=3.6760$，保留两位小数得 `3.68`，与输出样例一致。

**4. 循环方向不能反。** 必须让 $k$ 从 $2$ 递增到 $n$。若写成 $k$ 从 $n$ 递减，
第一层就会用到尚未算出的内层值，得到的是错误的数。

**5. 输出格式。** "保留两位小数"包含四舍五入与**固定两位**两件事，
`f"{total:.2f}"` 一次完成（例如 $n=1,\ x=8$ 时输出 `3.00`，末尾的零不能省，
这是 `round(total, 2)` 做不到的）。

**正确性。** 循环不变式是"进入第 $k$ 次迭代前 `total` $=g_{k-1}$"：
初始 $k=2$ 时 `total` $=\sqrt{1+x}=g_1$ 成立；每次迭代把 `total` 更新为
$\sqrt{k+g_{k-1}}=g_k$，为下一次迭代保持了不变式；$k$ 递增到 $n+1$ 时退出循环，
`total` $=g_n=f(x,n)$。又因为迭代与递归在每一层做的是同一次"加法 + `math.sqrt`"，
运算次序一一对应，浮点结果逐位相同——这次改造只去掉了调用栈，没有改变任何一次数值运算。

### 复杂度

- 时间复杂度：$O(n)$。循环体执行 $n-1$ 次，每次一次加法与一次 `math.sqrt`，均为常数时间；
  与标准 C++ 递归解法同阶，但省掉了函数调用开销。
- 空间复杂度：$O(1)$。只保留 `x`、`n`、循环变量 `k` 与当前层数值 `total` 四个标量；
  相比朴素递归的 $O(n)$ 调用栈，这一项被完全消除。

对本题规模（真实数据中 $n \leqslant 10$）来说两种写法都绰绰有余；
把递归改写成折叠循环的价值在于**不受递归深度限制**，$n$ 取到 $10^6$ 也不会 `RecursionError`。

## 总结

- 嵌套根式 $f(x,n)$ 的本质是递推 $g_1=\sqrt{1+x}$、$g_k=\sqrt{k+g_{k-1}}$，答案就是 $g_n$。
- 递推只在相邻两层之间传递一个数，递归表达式树因此退化成一条链：
  可以舍弃调用栈，用**一个变量从内向外折叠**。
- 循环方向必须是内 $\to$ 外（$k$ 递增）；写成外 $\to$ 内会用到还没求出的值。
- 层号 $k$ 同时就是该层根号里的加数，循环变量直接复用，不需要额外数组。
- 输出用 `f"{total:.2f}"`，一次完成四舍五入与固定两位补零。

## 图示解析

这张图串起本题从题面到答案的主线：

```text
题面嵌套根式 f(x,n)
`- 认出递归关系 f(x,n) = sqrt(n + f(x,n-1))
   |- 递归写法：自顶向下要值，栈深 = n，受语言递归上限约束
   `- 关键观察：每层只依赖下一层一个数 -> 递归树退化成一条链
      `- 自底向上折叠：g = sqrt(1+x); for k in 2..n: g = sqrt(k+g)
         `- g 即 f(x,n)，:.2f 输出
```

先看第二个节点：它决定了算法的方向是"从内往外"而不是"从外往内"，写反就得不到正确答案。
再看第三个节点：链式依赖意味着状态只有一个数，于是空间从递归的 $O(n)$ 降到 $O(1)$，
同时也摆脱了递归深度限制。最后一个节点只做格式化，不改变数值本身。
