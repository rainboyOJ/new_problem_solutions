## 形式化题目

给定平面上两点 $A(X_a, Y_a)$ 与 $B(X_b, Y_b)$，求线段 $AB$ 的长度

$$|AB| = \sqrt{(X_a - X_b)^2 + (Y_a - Y_b)^2},$$

并把结果四舍五入到小数点后 $3$ 位。所有坐标的绝对值不超过 $10000$。

输入样例：

```
1 1
2 2
```

输出样例：

```
1.414
```

样例解释：坐标差 $dx = 1 - 2 = -1$、$dy = 1 - 2 = -1$，计算链路如下表。

| 步骤 | 表达式 | 值 |
| --- | --- | --- |
| 坐标差 | $dx = 1-2$，$dy = 1-2$ | $-1$，$-1$ |
| 平方和 | $dx^2 + dy^2$ | $2$ |
| 开方 | $\sqrt{2}$ | $1.414213\ldots$ |
| 定点格式 | `:.3f` 四舍五入到 3 位 | `1.414` |

注意平方前的坐标差可以是负数，平方后自然变正；最后一步是"四舍五入 + 补零"，
而不是简单截断。

## 正解

### 思路

这道题的公式就写在题面里，朴素做法是把勾股定理直译成代码：

```python
length = math.sqrt((xa - xb) ** 2 + (ya - yb) ** 2)
```

这也是数据仓里标准解 `std.cpp` 的写法。它没有循环、没有子问题、没有需要比较
的选择，因此不存在"暴力版暴露瓶颈、正解消除瓶颈"的链条——再写一个暴力只会得到
逐字相同的代码，本题的学习价值全部在**把这条链路写稳**的三个实现细节上。

**坑一：输入排版与题面不一致。** 题面说"第一行两个实数、第二行两个实数"，
而真实测试数据是"一行四个实数"。逐行读的写法会被这种排版差异绊倒。正解用
`sys.stdin.buffer.read().split()` 一次读入整份输入、按空白切分，行结构被完全抹平：
`"1 1\n2 2\n"` 和 `"1 1 2 2\n"` 得到同一个四 token 序列。再用
`xa, ya, xb, yb = map(float, ...)` 解包，把"恰好四个实数"这条格式约定直接写进代码
（token 数量不对会立刻报错），而"顺序即题面顺序"摆在名字里，肉眼即可核对。


**坑二：开方的写法。** $\sqrt{dx^2+dy^2}$ 在 Python 里有现成的 `math.hypot(dx, dy)`，
它就是为勾股距离设计的，内部带缩放防止中间量溢出，表达式也比
`math.sqrt(dx*dx + dy*dy)` 短。精度上不必担心：本题 $|dx|,|dy| \leqslant 20000$，
于是平方和 $dx^2+dy^2 \leqslant 8\times10^8 < 2^{53}$，在 double 里是**精确可表示
的整数**，误差只来自最后一步开方（相对量级 $10^{-16}$），而 3 位小数的舍入边界
相距至少 $0.0005$，开方末位的差异根本影响不到输出，所以与标准解的朴素 `sqrt`
在全部测试点上结果一致。

**坑三：输出格式。** "保留到小数点后 $3$ 位"是**定点格式**：既四舍五入、又要在
末尾补 $0$（$1.0$ 必须打成 `1.000`，$0$ 必须打成 `0.000`）。f-string 的 `:.3f`
一次完成这两件事；不要改用 `round(x, 3)`——它不补尾零，`print(round(1.0, 3))`
会输出 `1.0` 而不是 `1.000`。这与 C++ 的 `fixed << setprecision(3)` 完全对应。

### 复杂度

- 时间复杂度：$O(1)$，固定四个实数的读入、一次减法与开方、一次格式化输出。
- 空间复杂度：$O(1)$，只保存读入的字符串、四个 float 和输出串。

## 总结

- 这是一道常数时间的浮点入门题，考点不在算法而在实现：**读入链路、数学库、输出格式**。
- 读固定个数实数的固定路线：`read()` 读全部 → `split()` 按空白切分 →
  `map(float, ...)` 转换 → 元组解包。这条写法天然容忍"两行还是一行"的排版差异。
- $\sqrt{dx^2+dy^2}$ 直接用 `math.hypot(dx, dy)`；本题范围内平方和小于 $2^{53}$，
  精度完全够用。
- "保留 $k$ 位小数"用定点格式 `f"{x:.3f}"`，它同时负责四舍五入与补零，
  等价于 C++ 的 `fixed << setprecision(3)`；`round` 做不到补零。
