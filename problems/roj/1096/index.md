## 形式化题目

给定两个正整数 $L \le R$。定义 $c(n)$ 为 $n$ 的十进制写法中数字 $2$ 出现的个数
（按位重复计数，例如 $c(22) = 2$），求

$$\sum_{n=L}^{R} c(n)$$

## 正解

### 思路

**朴素做法**就是把区间里每个数都拆一遍十进制位：

```python
ans = sum(str(n).count("2") for n in range(L, R + 1))
```

它对每个数独立扫描一遍，代价是 $O\big((R-L+1)\log_{10} R\big)$。即便按同类题常见的
$R \leqslant 10^5$ 估计，这行代码实测也只要几毫秒就能跑完，所以它并不是"过不了"的算法，
而是一个**把区间长度直接乘进代价**的算法：区间扩大十倍，时间就扩大十倍。
下面把代价从"与区间长度有关"降到"与数字位数有关"。

朴素做法的浪费之处在于相邻的数之间信息高度重复：$12$ 与 $112$ 的高位贡献完全一样。
既然答案只由两端点决定，就先把它写成前缀函数之差：

$$F(x) = \sum_{n=1}^{x} c(n), \qquad \sum_{n=L}^{R} c(n) = F(R) - F(L-1)$$

区间被消掉了，剩下"怎么算一个 $F(x)$"。把 $x$ 写成

$$x = 10q + r, \qquad q = \left\lfloor \frac{x}{10} \right\rfloor,\quad r = x \bmod 10$$

那么 $1 \ldots x$ 里的数**按个位分块**后不重不漏地分成两类：

- **完整块** $[10j, 10j+9]$，$j = 0, 1, \ldots, q-1$；
- **残块** $[10q, 10q+r]$，共 $r+1$ 个数。

第一块 $[0,9]$ 里含着 $0$，而题面统计的是正整数；因为 $c(0) = 0$，多算一个 $0$
不影响结果（换成统计数字 `0` 就不能这样偷懒了）。

看一个完整块：块内每个数的十位以上部分都是 $j$，$j$ 里的每个 $2$ 都被这 $10$ 个数
各复制一遍，贡献 $10\,c(j)$；个位则从 $0$ 走到 $9$ 恰好一次，其中只有 $2$ 算数，
贡献 $1$。所以单个完整块贡献 $10\,c(j) + 1$，把 $j$ 求和得

$$10\sum_{j=0}^{q-1} c(j) + q = 10\,F(q-1) + q$$

残块的高位恒为 $q$，共 $r+1$ 个数，高位贡献 $(r+1)\,c(q)$；个位走过 $0, 1, \ldots, r$，
只有 $r \ge 2$ 时才会路过 $2$。合起来就是递推式（$x \ge 10$）：

$$F(x) = 10\,F(q-1) + q + (r+1)\,c(q) + [r \ge 2]$$

三个地方容易写错，值得单独确认：

1. **参数是 $q-1$，不是 $q$**。$j = q$ 对应的块是 $[10q, 10q+9]$，它不一定被 $x$ 填满，
   所以不能整块计入。取 $x = 24$ 试一下：$q = 2$，若写成 $10F(2) = 10$，已经超过
   正确答案 $F(24) = 8$。
2. **残块也要拆成"高位 + 个位"两笔**，不能只算个位，因为 $q$ 本身可能含 $2$。
   例如 $x = 100$ 时残块 $[100,100]$ 的高位 $q = 10$ 不含 $2$，但 $x = 201$ 时
   残块 $[200,201]$ 的每个数都带一个来自高位的 $2$。
3. **递归基要单独处理一位数**：$x < 10$ 时 $q = 0$，$F(q-1)$ 没有定义，
   此时答案就是 $[x \ge 2]$。

下面用样例 `2 22` 验证一遍。区间内真正贡献了 $2$ 的数只有五个：

| $n$ | $n$ 中的 `2` | 累计次数 |
| --: | :-: | --: |
| 2 | 1 | 1 |
| 12 | 1 | 2 |
| 20 | 1 | 3 |
| 21 | 1 | 4 |
| 22 | 2 | 6 |
| **其余 16 个数** | 0 | — |
| **合计** | — | **6** |

表格给出的是 `2` 到 `22` 的枚举结果：只有这五个数贡献了 `2`，其余 $16$ 个数贡献 $0$。
递推式只算两个前缀：

$$F(1) = 0, \qquad F(22) = 10F(1) + 2 + (2+1)c(2) + [2 \ge 2] = 0 + 2 + 3 + 1 = 6$$

两者吻合。题面第二个样例 `2 100` 同样能对上：$F(9) = 1$（一位数里只有 $2$ 算一个），
于是 $F(100) = 10 \cdot 1 + 10 + (0+1) \cdot c(10) + [0 \ge 2] = 10 + 10 + 0 + 0 = 20$。

再看一个位数更多、且高位真的含 $2$ 的例子 $x = 2024$（$q = 202$，$r = 4$）：

| 部分 | 覆盖的数 | 高位贡献 | 个位贡献 | 小计 |
| --- | :-: | --: | --: | --: |
| 完整块 $j = 0 \ldots 201$ | $0 \ldots 2019$ | $10F(201) = 420$ | $202$ | 622 |
| 残块 $j = 202$ | $2020 \ldots 2024$ | $(4+1)c(202) = 10$ | $1$ | 11 |
| **合计 $F(2024)$** | — | — | — | **633** |

这张表的每一列对应递推式的一项：`完整块 & 高位贡献` 是 $10F(q-1)$，`完整块 & 个位贡献`
是 $+q$，`残块 & 高位贡献` 是 $+(r+1)c(q)$，`残块 & 个位贡献` 是 $+[r \ge 2]$。
残块那 $11$ 个 `2` 拆开看是：$2020, 2021, 2023, 2024$ 各 $2$ 个、$2022$ 有 $3$ 个，
其中 $10$ 个来自高位 $q = 202$ 自身含的两个 `2` 被 $5$ 个数各复制一遍，剩下 $1$ 个是
$2022$ 的个位。

递归参数每层从 $x$ 变成 $\lfloor x/10 \rfloor - 1$（比如
$F(2024) \to F(201) \to F(19) \to F(0)$），严格变小，所以深度等于 $x$ 的十进制位数；
$F(R)$ 与 $F(L-1)$ 两条链重合的部分由 `functools.cache` 复用。

### 复杂度

- 时间复杂度：$O(\log^2 R)$。递归层数是 $x$ 的位数 $O(\log R)$，每层做一次
  `str(quotient).count(TARGET)`（长度同为位数）。与朴素做法的
  $O\big((R-L+1)\log_{10} R\big)$ 相比，代价不再随区间长度增长。
- 空间复杂度：$O(\log R)$，`cache` 里只保存每一位数对应的一个结果。

## 总结

- 区间询问先用前缀函数差分：$\sum_{n=L}^{R} c(n) = F(R) - F(L-1)$，把区间问题变成单点问题。
- 单点问题的关键是**按个位分块**：写 $x = 10q + r$ 后得到
  $F(x) = 10F(q-1) + q + (r+1)\,c(q) + [r \ge 2]$，其中 $[r \ge 2]$ 是布尔值，
  在 Python 里可以直接当 $0/1$ 参与加法。
- 递推参数必须取 $q-1$（已完整走完的最后一个块），并用 `@cache` 记忆化；
  代价只与 $R$ 的位数有关，与 $L, R$ 的大小无关。
- 本题测试数据规模很小，朴素枚举同样能过；这里给出的数位写法是为"数字位数"这一类
  统计问题准备的标准模型。
- 代码里把被统计的数字单独命名为 `TARGET = "2"`，这样 `str(...).count(TARGET)` 这行
  仍然能看出"在数哪个数字"；换题目只需改常量。
