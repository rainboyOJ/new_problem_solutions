## 形式化题目

给定正整数 $n$ 与 $k$，求把 $n$ 写成恰好 $k$ 个正整数之和的方案数：

$$n = a_1 + a_2 + \cdots + a_k, \qquad a_i \geqslant 1,$$

其中加法的顺序不计，即 $\{a_i\}$ 作为多重集合来数。等价地，求满足

$$1 \leqslant a_1 \leqslant a_2 \leqslant \cdots \leqslant a_k, \qquad \sum_{i=1}^{k} a_i = n$$

的非降序列个数，也就是 $n$ 的恰好 $k$ 部分分拆数。

> **题面更正说明**：本站点该题挂出的题面是「$2 \times N$ 棋盘用 $1 \times 2$ 骨牌覆盖的方法数」，标题为「骨牌1」，但它的真实测试数据与官方标程实现的是上面的整数拆分问题：标程读入 `n k`，DFS 枚举非降序列并判断总和为 $n$；10 组真实输入形如 `106 6`、`200 5`、`189 7`，输出为 `189509`、`583464`、`15552247`，与斐波那契式的骨牌计数无关。
>
> 这些数据与本站的另一道题 **ROJ 1675「数的划分」完全一致**（同一份 `std.cpp`、同一批测试点），本文因此按整数拆分来讲解。骨牌题的答案是 $2 \times N$ 覆盖的斐波那契数，与本题数据对不上，不能按题面标题作答。

## 正解

### 思路

**先解决“顺序不计”这件事。** 加法可交换，所以任何一个方案 $\{a_i\}$ 把它从小到大排一遍，就得到唯一的非降序列；反过来每个和为 $n$ 的非降正整数序列也都是一个合法方案。于是

$$\text{分拆方案数} = \text{和为 } n \text{ 的非降 } k \text{ 元正整数序列个数}.$$

去重问题就此消失，后面只需要数非降序列，不需要再收集方案去重。

**再看朴素做法卡在哪。** 最直接的做法是写 $k$ 层循环枚举 $a_1, \dots, a_k$，每层从上一层的值开始枚举以保证非降，最后判断总和是否为 $n$。这有两个毛病：

1. $k$ 是输入，循环层数写不死；
2. 不同的前缀只要「剩余和、剩余段数、下一段下界」相同，后继填法就完全相同，但朴素循环每次都要重数一遍。

**把“填到哪了”压缩成三个数。** 从左到右填每一段，只需要记住：

| 参数 | 含义 |
| --- | --- |
| `rest` | 还没分配出去的剩余和 |
| `parts` | 还要填几段 |
| `low` | 下一段允许的最小值（就是上一段的值，初始为 1） |

设 $f(\text{rest}, \text{parts}, \text{low})$ 为在这个状态下把剩余部分填完的方案数。枚举当前这一段 `head`，填完之后状态变成 $(\text{rest}-\text{head},\ \text{parts}-1,\ \text{head})$——注意下界更新为 `head`，非降约束就是这样被传递下去的。

**关键观察：`head` 的枚举上界可以收紧到 $\lfloor \text{rest}/\text{parts} \rfloor$。** 当前段取 `head`，后面还有 `parts-1` 段，每段都不小于 `head`，所以必须有

$$\text{head} + (\text{parts}-1)\cdot \text{head} \leqslant \text{rest} \iff \text{head} \leqslant \left\lfloor \frac{\text{rest}}{\text{parts}} \right\rfloor.$$

这把上界从 `rest` 压到 `rest // parts`，是本题唯一的剪枝，也是状态数远小于理论上界的原因。

**终止条件。** 只剩一段时（`parts == 1`），和为定值，方案唯一，只要 `rest >= low` 就返回 1，否则返回 0；一段都不剩时（`parts == 0`），只有 `rest` 恰好归零才算一种方案。

以 $n=7,k=3$ 为例，转移的展开过程如下。第一行是入口，后面每行是把 $f(\text{rest},2,\text{low})$ 再拆一层：

| 调用的状态 | 求和区间 | 各项的值 | 结果 |
| --- | --- | --- | --- |
| $f(7,3,1)$ | $\text{head}=1..2$ | $f(6,2,1)+f(5,2,2)$ | 4 |
| $f(6,2,1)$ | $\text{head}=1..3$ | $f(5,1,1)+f(4,1,2)+f(3,1,3)=1+1+1$ | 3 |
| $f(5,2,2)$ | $\text{head}=2..2$ | $f(3,1,2)=1$ | 1 |

三个叶子值都是 1，因为它们都满足 `rest >= low`，对应 $7 = 1+1+5$、$1+2+4$、$1+3+3$、$2+2+3$ 这 4 个方案。注意 `head` 的上界 $7//3=2$、$6//2=3$ 把大量非法分支直接截掉。

再看一次「非降 ↔ 分拆」的一一对应，$n=6,k=3$ 的全部方案：

| 非降序列 | 对应的分拆 | 排序后会重复的写法 |
| --- | --- | --- |
| $1,1,4$ | $6=1+1+4$ | $1,4,1$、$4,1,1$ 等都不再单独计数 |
| $1,2,3$ | $6=1+2+3$ | $2,1,3$、$3,2,1$ 等都不再单独计数 |
| $2,2,2$ | $6=2+2+2$ | 本身已经非降 |

因此只有 3 种，正是 $f(6,3,1)$。

**记忆化。** 三个参数都是小整数，用 `functools.cache` 按状态缓存即可，不需要手工建表，也不需要处理哈希。

### 复杂度

状态数上界为 $O(n \cdot k \cdot n) = O(n^2k)$，每个状态求和至多 $n$ 项。实测 $n=200,k=7$ 时只访问约 $1.4\times 10^4$ 个状态，远低于理论上界。空间同为 $O(n^2k)$，实测峰值约 17MB；递归深度不超过 $k+1 \leqslant 8$。

## 总结

- 加法可交换，因此把方案统一写成**非降序列**，一个多重集合就只有一种写法，「分拆方案数 = 非降序列个数」，去重问题在建模阶段就消失了。
- 填段过程只需要「剩余和 + 剩余段数 + 下一段下界」三个数就能描述，于是 $k$ 层循环被一个三元组状态取代，$k$ 不再需要写死在代码里。
- 两处必须记住的边界：`parts == 1` 时方案唯一（`rest >= low` 则为 1）；`parts == 0` 时只有 `rest == 0` 才计 1。
- 枚举当前段的区间是 `range(low, rest // parts + 1)`：下界来自非降约束，上界来自「余下每段都不小于当前段」这一必要条件。
- 用 `@cache` 记忆化后，时间与空间都只与 $n,k$ 的多项式相关，不再随方案数增长。
