## 形式化题目

给定长度为 $n$ 的小写字母串 $S = S_1 S_2 \cdots S_n$，依次执行 $m$ 次操作。
每次操作给出 $l, r, x$（$1 \leqslant l \leqslant r \leqslant n$，$x \in \{0, 1\}$）：

- $x = 1$：把子串 $S_l \cdots S_r$ **升序**排序；
- $x = 0$：把子串 $S_l \cdots S_r$ **降序**排序。

排序会覆盖原来的字符，后续操作看到的是上一步的结果。求全部操作结束后的完整字符串。

$n, m \leqslant 10^5$，其中 $40\%$ 的数据 $n, m \leqslant 10^3$；串只含小写字母。

> **输入顺序的坑。** 题面散文写"接下来 $m$ 行每行三个整数 $x, l, r$"，
> 但【输入样例】两行是 `1 3 1` 和 `3 5 0`，
> 只有按 $(l, r, x)$ 解释才能得到样例输出：
> $l=1, r=3$ 升序把 `cab` 排成 `abc`，$l=3, r=5$ 降序把 `ccd` 排成 `dcc`，
> 全串变成 `abdcc`。若按 $(x, l, r)$ 解释，第一行就要求 $l=3 > r=1$，非法。
> 因此本题实际输入顺序是 **$l\ r\ x$**，正文以下的推导都按这个顺序。

本题与 **Codeforces 558E "A Simple Task"** 同源：题面、样例、数据范围（$40\%$ 时
$n,m \leqslant 10^3$，$100\%$ 时 $n,m \leqslant 10^5$）逐项一致。

样例的逐步过程：

| 步骤 | 串 | 说明 |
| :-: | :-: | --- |
| 初始 | `c a b c d` | |
| $l=1, r=3, x=1$ | `a b c c d` | `cab` 升序 → `abc` |
| $l=3, r=5, x=0$ | `a b d c c` | `ccd` 降序 → `dcc` |

## 正解

### 思路

**先看朴素做法的瓶颈。** 最直接的做法是每次把区间内的字符取出来排序再写回：
`S[l:r+1] = sorted(S[l:r+1])`，单次 $O((r-l+1)\log(r-l+1))$，
最坏（每次都排整串）$O(nm\log n)$，$n = m = 10^5$ 时是 $10^{10}$ 量级，必然超时。
瓶颈非常清楚：**一次排序只关心 26 个字母各有多少个，却被展开成了对每个位置的单独搬运。**

**关键观察：排序的输入只需要"计数"。** 一次排序 $(l, r, x)$ 的**输出**是确定的，
只要知道 $cnt_c = $（$c$ 在 $[l, r]$ 中的出现次数），$c = 0 \dots 25$，
结果就是"把 $cnt_0$ 个 a、$cnt_1$ 个 b……按顺序连续摆放"：
$x = 1$ 时 a 在最左、z 在最右，$x = 0$ 时反过来。**每个位置只属于一个字母**，
所以 $cnt$ 是对区间长度的一个划分，不会有重叠或遗漏。

于是真正需要维护的只有两件事：**区间内 26 个字母的计数**，和**区间被整段覆盖成某个字母**。
这两个需求正是"区间求和 + 区间赋值"，线段树（或树状数组 + 并查集）能办。

**两种实现路线。**

| 路线 | 维护什么 | 单次操作代价 |
| --- | --- | --- |
| 计数型（`main.cpp`） | 26 棵线段树，第 $c$ 棵的位置 $i$ 为 1 当且仅当 $S_i = c$ | $O(26 \log n)$ |
| 段型 / ODT（`main.py`） | 直接维护"同字母的连续段"列表 | 均摊 $O(26 \log n)$，常数小 |

**计数型（`main.cpp`）。** 每个字母 $c$ 一棵线段树，维护 0/1 序列
"$S_i$ 是不是 $c$"。一次操作分三步：

1. 对 $c = 0 \dots 25$ 求出 $cnt_c = $ 第 $c$ 棵树的区间和；
2. 把 $[l, r]$ 中**出现过的**字母整段清零（$cnt_c > 0$ 的那些）。
   这一步不能省：26 棵树彼此独立，"给 a 树赋值"不会顺手清掉 b 树里的旧标记，
   残留字符会和新的区间划分冲突；
3. 从 $pos = l$ 出发，$x = 1$ 时 $c$ 从 0 枚举到 25，$x = 0$ 时从 25 枚举到 0，
   对每个 $cnt_c > 0$ 的字母把 $[pos, pos + cnt_c - 1]$ 整段赋值成 1，$pos$ 右移。

区间赋值需要懒标记：整段被覆盖成常量后，该节点的和可以直接算出，
直到下一次需要下探才把标记推给孩子。这样单次操作 $O(26 \log n)$，总 $O((n + 78m)\log n)$。

**段型 / ODT（`main.py`）。** 换个更贴合题意的表示：把整串切成若干**同字母的连续段**，
只存每段的起点和字母。例如 `cabcd` 是 5 段，而样例第一次排序后 `abccd` 只有 4 段。
一次排序 $(l, r, x)$ 要读的"区间内 26 个字母的计数"就是这个段列表上的一段切片：

1. 先按 $l$ 与 $r + 1$ 把边界切开（二分找到落点，必要时把一段拆成两段），
   这样区间 $[l, r]$ 恰好由若干完整段拼成；
2. 累加这些段的长度得到 $cnt$；
3. 删掉这些段，按 $x$ 的顺序用 $cnt$ 重建最多 26 个新段；
   首尾与区间外同字母的邻段合并，避免段数虚增。

段数不会爆：初始最多 $n$ 段，**每次操作最多新增 26 段**，而被删除的段不会再回来，
所以"删除的总量"被"新增的总量" $O(n + 26m)$ 兜住 —— 这就是为什么它虽然看着是暴力，
复杂度却是均摊正确的。它和线段树路线**同阶**，而且免去了懒标记、下传和递归，
在 Python 里常数小得多。

**为什么两个版本都写？** 本题的 `data/` 由 `data.py` 生成、标程是 26 棵线段树的版本，
顶格数据 $n = m = 10^5$。`main.cpp` 直接对应"区间求和 + 区间赋值"的线段树主线，
`main.py` 用同一套计数思想换一个更省常数的表示，两条路线互为对照。

> **关于素材源。** `new_ROJ/problems/1751/` 同时带着 `data.py`（数据生成脚本）与
> `std.cpp`。这说明 `data/` 是**自造**的（生成脚本已注明分层与随机种子），
> 题面则是按 CF558E 重建的。`std.cpp` 的输入顺序读作 `l r x`，与样例互证，
> 与 `data.py` 一致；本解按同一顺序读入，实测 10 个测试点全部与 `.out` 吻合。
> 官方原题的出题意图可能与这份重建题面有细微出入，但算法主线不受影响。

### 复杂度

- **时间**：$O\big((n + 26m)\log n\big)$。
  C++ 版把"26 次求和 + 26 次清零 + 26 次覆盖"折成常数 $78$，
  实测 $n = m = 10^5$ 的顶格点约 0.5 s（限时 3000 ms）。
  Python 版每次操作用 $O(\log n)$ 次二分定位边界，加上均摊 $O(26)$ 次段的重建，
  段的总新增量被 $O(n + 26m)$ 兜住，所以同样是均摊 $O\big((n + 26m)\log n\big)$；
  常数比线段树小，但 $m = 10^5$ 时 Python 仍需数秒，属于本 skill 允许的
  "Python 可以比 C++ 慢"的范围，**算法没有降级**。
- **空间**：C++ 版 $O(26n)$（`26 × 4n` 个线段树节点，
  每个节点只有 `int sum` 与 `signed char lazy`）；
  Python 版 $O(n + 26m)$ 个段，顶格下实际段数远小于此（每次操作后区间内至多 26 段）。
- **与 40% 档的关系**：$n, m \leqslant 10^3$ 时两份代码都在 0.1 s 以内，
  40% 的部分分不需要额外写法。

## 总结

- **排序只需要计数。** 一次区间排序的输出完全由"26 个字母各有多少个"决定，
  把"排 $r-l+1$ 个字符"换成"数 26 个数字，再整段铺回"，是本题全部优化的出发点。
- **计数用区间求和，结果用区间赋值。** 26 棵 0/1 线段树同时提供这两种操作；
  赋值必须带懒标记，否则每次都要改 $O(r-l+1)$ 个叶子。
- **清零不能忘。** 26 棵树彼此独立，覆盖新字母之前必须把区间里出现过的旧字母整段清掉，
  否则会出现"同一个位置在两棵树里都是 1"的矛盾状态。
- **换个表示就是换个常数。** 把"26 棵树"换成"同字母连续段列表"，
  同一套计数思想就得到了一个不用懒标记、不用递归的写法；
  它的正确性靠"每次操作最多新增 26 段、删除总量被新增总量兜住"这条均摊论证。
- **先校输入格式再写代码。** 本题散文里的 $(x, l, r)$ 与样例的 $(l, r, x)$ 矛盾，
  只有样例是可信的：按样例顺序读入才可能拿到 `abdcc`。
