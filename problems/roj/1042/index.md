## 形式化题目

给定一个可见字符 $\text{ch}$，设 $c$ 为它在 ASCII 表中的编号，输出其奇偶性标签：

$$
f(\text{ch}) = \begin{cases} \text{YES}, & c \bmod 2 = 1 \\ \text{NO}, & c \bmod 2 = 0 \end{cases}
$$

样例：$\text{ch} = \texttt{A}$ 时 $c = 65$ 为奇数，输出 `YES`；题面另举 $\text{ch} = \texttt{B}$（$c = 66$）应输出 `NO`。

## 正解

### 思路

C++ 的标准程序只有一句判断：`char` 是整数类型，参与算术时自动整型提升为 `int`，所以 `ch % 2` 直接得到奇偶。把这句话原样搬到 Python 会立刻撞上本题唯一的坑：Python 的字符是长度为 1 的字符串，没有数值语义，`ch % 2` 不是判断而是 `TypeError`。于是全部工作浓缩成一次语言语义翻译——先用内建函数 `ord(ch)` 显式取出码点。可见 ASCII 字符的 Unicode 码点就是它的 ASCII 值（前 128 个码点完全重合），一次 `ord` 就完成了"查 ASCII 表"。

判定用哪条式子是等价选择题：`c % 2 == 1` 是算术写法，`c & 1 == 1` 是二进制写法。非负整数写成二进制后 $c = 2k + b_0$（$b_0$ 是最低位），奇偶恰好由最低位决定，所以一次按位与就能回答。判定量先命名 `is_odd` 再进条件表达式，不在 `print` 里裸做位运算。全题没有循环、状态或数据范围，朴素做法就是最终做法，不存在可优化的瓶颈。

下表用题面的两个例子和几组真实数据中的字符核对判定结果：

| 字符 | ASCII 值 | 二进制最低位 | 奇偶 | 输出 |
| --- | --- | --- | --- | --- |
| `A` | 65 | 1 | 奇 | `YES` |
| `B` | 66 | 0 | 偶 | `NO` |
| `S` | 83 | 1 | 奇 | `YES` |
| `s` | 115 | 1 | 奇 | `YES` |
| `D` | 68 | 0 | 偶 | `NO` |
| `!` | 33 | 1 | 奇 | `YES` |

表里值得多看一眼的是 `S` 与 `s` 两行：ASCII 表连续编号，同一字母块内（大写 `A`–`Z` 为 65–90，小写 `a`–`z` 为 97–122）相邻码值相差 1，奇偶逐位交替；而同一字母的大小写相差 32——一个偶数——不改变奇偶。所以 `S`（83）与 `s`（115）同为奇，`D`（68）与 `d`（100）同为偶：判定只看字符在表中的位置，与大小写无关。真实测试数据大小写混合出现，`!`、`#` 这类符号也在生成字符表里，对它们而言同样只是一次 `ord` 查询。

读入沿用姊妹题 1020 的路线：`sys.stdin.buffer.read().split()[0].decode()`——读出全部字节、按空白切分顺带吞掉行尾换行、取第一个 token、转回 `str`。切分不会把字符本身吞掉，前提是输入字符非空白，这一点由题面（可见字符）与生成字符表（大小写字母与 `!*&^%$#`）共同保证。若要连空格都按输入处理，应改用 `sys.stdin.read(1)`：只取一个字符，与 C 的 `scanf("%c")` 语义完全一致；本题数据下两条路线等价。

### 复杂度

- 时间复杂度：$O(1)$：读入 2 个字节、一次 `ord` 转码、一次按位与、一次输出。
- 空间复杂度：$O(1)$：一个长度为 1 的字符串与一个布尔值。

## 总结

- Python 的字符没有数值语义，判断 ASCII 奇偶前必须 `ord(ch)` 显式取码点；这是 C（`char` 自动整型提升，`ch % 2` 即可）与 Python 的主要差别。
- 奇偶就是二进制最低位：`ord(ch) & 1 == 1` 与 `ord(ch) % 2 == 1` 等价，前者把这一点直接写进代码。
- 输出是严格匹配的 `YES`/`NO`，大小写不可改动；判定量先命名（`is_odd`）再进条件表达式。
- 实测 10 个评测点全部一致，单点约 0.015 s、峰值内存 14.4 MB，相对 1000 ms / 128 MB 的限制十分宽裕。
