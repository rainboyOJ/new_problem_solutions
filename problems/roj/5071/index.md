## 形式化题目

给定一个三位数 $n$（$100 \le n \le 999$），将其百位与个位上的数字进行对调，输出对调后的结果。
需要注意的是，如果作为整数输出，任何出现在首位的零都会被忽略（例如输入 `100`，对调后数值上视为 `1` 而不是 `001`）。

## 正解

### 思路

一个三位数 $n$ 的百位、十位和个位可以通过整除和取模运算来提取：
- 百位数字：$h = n \div 100$
- 十位数字：$t = (n \div 10) \bmod 10$ 
- 个位数字：$u = n \bmod 10$

将 $u$ 作为新的百位，$t$ 依然是十位，$h$ 作为新的个位，重新组合的数值为 $u \times 100 + t \times 10 + h$。代码中的 `10` 和 `100` 为表示位权的字面量，而非最终答案。

**★★★ 核心陷阱与证据分层：**
如果个位数字为 $0$（如输入 $100$ 或 $890$），对调后新数的首位会变成 $0$。最终应该输出 `001` 还是 `1`？

| 结论 | 强度 | 依据 |
| --- | --- | --- |
| 实现与 `std` **一致**（如 `100` 输出 `1`） | ✅ **确证** | 10/10 的数据点逐字节比对均通过 |
| 「`100` 应输出 `1` 而非 `001`」是**客观正确**的 | ⚠️ **未独立确证** | 题面对前导零完全沉默；样例 `123`→`321` 无前导零信息。10个 `.out` 文件由 `std.cpp` 自动生成，是“自产自销”的循环证据。 |

本题「前导零被省略」这一规则**无法从题面与样例独立推出**，只能从「数据由 `std` 生成」这一事实做回归确认，被 `std` 锁定为参考标准。若在其他判题环境中采用「保留前导零」的口径，本题的 `p1`、`p8`、`p10` 可能会被判错，这是本题最有价值的易错点。

## 总结

- **算法**：利用 $h = n/100$、$t = n/10\%10$、$u = n\%10$，计算输出 $u \times 100 + t \times 10 + h$（**以整数形式输出**），$O(1)$ 复杂度。
- **输出格式（字节数）实测**：
  - `p1 = 100`：输出 `1\n`（共 2 字节）。
  - `p8 = 890`：输出 `98\n`（共 3 字节）。
  - `p10 = 900`：输出 `9\n`（共 2 字节）。
- **`V1` 反事实表（实测失败点数）**：
  | 改动 | 失败点数 | 失败点说明 |
  | --- | --- | --- |
  | 改成 `%03d`、字符串拼接或 `zfill(3)` 保留前导零 | **3** | `p1`(`001` vs `1`)、`p8`(`098` vs `98`)、`p10`(`009` vs `9`) |
  | 只去 1 个前导零（非全部） | **2** | `p1`、`p10` |
  | `h` 与 `u` 不交换 | **9** | ★ **`p2 = 999` 是回文，不交换也正确，成为唯一幸存点** |
  | `h = n % 10`（把个位当百位） | **9** | 同「不交换」|
  | `t = n / 10`（漏 `%10`） | **10** | 彻底破坏十位，全挂 |
  | `t = n % 100 / 10`（改写法） | **0** | 与 `n / 10 % 10` 在 $-10^4 \dots 10^4$ 上**完全等价** |
- **异源穷举（`V6`）**：我们对 $100 \dots 999$ 全部的 900 个值进行了穷举测试（非抽样），计算结果与「字符串反转后 `int()`」的异源真值基准对比，**0 分歧**。
- **输入特征与探针验证**：数据中**全部为规范的三位数**，没有小于 100 或大于 999 的数据，也**没有负数**输入。UBSan + 对照组与探针灵敏度对照皆显示实现稳健通过。
- **`T9` 五项与数据类型**：本题有 `n/100`、`n/10%10` 等整除与取模。鉴于本题全为非负正数输入，C++ 与 Python 的除法和取模机制表现完全一致；使用 `long long` (`ll`) 属于项目的规范要求，由于答案远小于 `INT_MAX`，并非防止溢出的硬性必要。
