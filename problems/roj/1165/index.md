## 形式化题目

给定整数 $x$ 与阶数 $n$，按二阶线性递推计算 $h_n(x)$：

$$h_0(x)=1,\qquad h_1(x)=2x,\qquad h_n(x)=2x\,h_{n-1}(x)-2(n-1)\,h_{n-2}(x)\quad(n>1)$$

要求求 $h_n(x)$ 的值。真实测试数据满足 $1 \leqslant n \leqslant 10$、$1 \leqslant x \leqslant 10$。

## 正解

### 思路

答案就是 $h_n(x)$，按两位小数输出：题面样例 `1 2` 求的是 $h_1(2)=2\times2=4$，输出 `4.00`。

**第一步：把公式照抄成递归。** 递推式已经给了边界和转移，最直接的实现就是逐字翻译，
和题目"用递归的方法求"的字面要求完全一致：

```python
def calculate(n, x):
    if n == 0:
        return 1
    if n == 1:
        return 2 * x
    return 2 * x * calculate(n - 1, x) - 2 * (n - 1) * calculate(n - 2, x)
```

在本题数据 $n \leqslant 10$ 上，这份代码瞬间出答、结果正确。要看清它的问题，得数调用次数。

**第二步：展开调用树，找出重复子问题。** 以 $h_4$ 为例（每条边是一次函数调用）：

```text
h(4) = 2x*h(3) - 6*h(2)
├── h(3) = 2x*h(2) - 4*h(1)
│   ├── h(2) = 2x*h(1) - 2*h(0)
│   │   ├── h(1)  边界
│   │   └── h(0)  边界
│   └── h(1)      边界
└── h(2)          ← 和上面那棵 h(2) 子树一模一样，却整棵重算
    ├── h(1)      边界
    └── h(0)      边界
```

同一个 $h_2$ 被算了两遍，$h_1$、$h_0$ 被算得更多。原因是递推有一项 $h_{n-2}$：
$h_{n-1}$ 展开时已经要到它，公式右边又直接要它。设 $C(n)$ 为求解 $h_n$ 的调用次数：

$$C(0)=C(1)=1,\qquad C(n)=1+C(n-1)+C(n-2)$$

这与 Fibonacci 只差常数，解得 $C(n)=2F_{n+1}-1$，按 $\varphi^n\approx1.618^n$ 增长。
实测调用次数印证了这条曲线：

| $n$ | 5 | 10 | 15 | 20 | 25 | 30 |
| --- | --- | --- | --- | --- | --- | --- |
| 调用次数 $C(n)$ | 15 | 177 | 1973 | 21891 | 242785 | 2692537 |

表中每个 $n$ 是阶数，第二行是朴素递归求解 $h_n$ 的函数调用总次数。$n$ 每加 5，调用量大约乘 11；
$n$ 再大下去，即使正确也会超时。数据范围给了 $n \leqslant 10$，恰好掩盖了这个指数级缺陷。

**第三步：消除重复子问题。** 关键观察是 $h_k$ 的值只取决于下标 $k$ 和常数 $x$，
与"是谁调用它"无关：第一次算完之后，第二个来问的调用完全可以查表返回。
于是给递归函数加一层缓存即可——状态空间只有 $n+1$ 个，每个状态求值一次，
总调用次数从 $O(\varphi^n)$ 降到 $O(n)$：

```python
@cache
def hermite(n: int, x: int) -> int:
    if n < 2:
        return 1 if n == 0 else 2 * x
    return 2 * x * hermite(n - 1, x) - 2 * (n - 1) * hermite(n - 2, x)
```

`@cache` 就是把"重复子问题"变成"查表"；`hermite` 内部仍然只写题面那一条转移，
所以返回值和朴素递归必然一致。因为递推只用到前两项，也可以不递归、直接用两个变量滚动：

```python
a, b = 1, 2 * x                             # a = h_0, b = h_1
for i in range(2, n + 1):
    a, b = b, 2 * x * b - 2 * (i - 1) * a   # 同时右移一步，b 变成 h_i
```

这两种写法状态定义和转移完全相同、复杂度同为 $O(n)$，所以这里不把它们当成两个解法比较；
`main.py` 取记忆化版本，因为它与题面"用递归的方法求"的表述最贴近，也不必手写循环。

**第四步：逐步核对一个测试点。** 用迭代写法把真实测试点 `6 2`（即求 $h_6(2)$）走一遍，
$a$、$b$ 两列分别是滚动中保留的 $h_{i-1}$ 与 $h_i$，最后一列是这一步的转移值：

| $i$ | $a=h_{i-1}$ | $b=h_i$ | $2x\,b-2(i-1)a$ |
| --- | --- | --- | --- |
| 0 | — | 1（边界 $h_0$） | — |
| 1 | 1 | 4（边界 $h_1=2x$） | — |
| 2 | 4 | 14 | 14 |
| 3 | 14 | 40 | 40 |
| 4 | 40 | 76 | 76 |
| 5 | 76 | -16 | -16 |
| 6 | -16 | -824 | -824 |

最后一行给出 $h_6(2)=-824$，与 `problem1.out` 的 `-824.00` 一致：
正解每一步都在做精确整数运算，没有中间取整。

**最后一步：输出。** $x$ 是整数，$h_0=1$、$h_1=2x$ 是整数，而整数对乘法和减法封闭，
所以 $h_n(x)$ 一定是整数，两位小数就是整数后面补 `.00`。
代码因此写 `f"{value}.00"` 而不是 `f"{value:.2f}"`：后者会先把大整数变成 `double`，
$h_7(10)=1\,148\,943\,200$ 还落在 $2^{53}$ 里看不出问题，但阶数稍大就会丢低位数字
（例如 `f"{10**30:.2f}"` 输出 `1000000000000000019884624838656.00`，已经不是 $10^{30}$ 了）。
补 `.00` 对任意 $n$ 都不会失真，负答案如 `-824.00` 的符号位置也正确。

### 复杂度

- 时间复杂度：$O(n)$。缓存后有 $n+1$ 个状态，每个状态做 $O(1)$ 次整数乘减；
  朴素递归的对照是 $O(\varphi^n)$。本题 $n\leqslant 10$，两者都瞬间完成。
- 空间复杂度：$O(n)$。缓存存 $n+1$ 个值，递归深度与 $n$ 同阶；
  若改用上面的滚动变量迭代，额外空间为 $O(1)$。

## 总结

- 题面给了递推式，先照字面写成递归是合理的第一步；但只有数清重复子问题的规模，
  才知道这份代码能不能直接交。
- 二阶递推 $h_n=2x h_{n-1}-2(n-1)h_{n-2}$ 的朴素递归调用次数满足
  $C(n)=1+C(n-1)+C(n-2)$，是 $O(\varphi^n)$ 的 Fibonacci 型增长；$n$ 稍大就必然超时。
- 消除办法是记住 $h_k$：加 `functools.cache`（记忆化搜索）或改成两个变量滚动（自底向上迭代），
  两者复杂度同为 $O(n)$。
- 结果落在整数上时，不要为了"两位小数"绕道浮点；直接补 `.00` 才是对大 $n$ 也正确的输出方式。
