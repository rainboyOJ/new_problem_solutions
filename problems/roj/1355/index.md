## 形式化题目

给出 $n$ 个字符串，每个串只由 `(` `)` `[` `]` `<` `>` `{` `}` 八种字符组成，长度不超过 $255$。
对每个串判定它是否匹配，匹配需要同时满足两条规则：

1. **配对规则**：每个左括号都有同类型的右括号与它配对，且配对不交叉错位。
2. **嵌套优先级规则**：若括号存在互相包含的形式，则**从内到外**的类型顺序必须是
   `< >`、`( )`、`[ ]`、`{ }`。例如 `[()]` 是匹配的，而 `([])` 不是。

题面输入样例的 5 个串能看清两条规则各自在起作用（完整输入见 `problem.md`）：

| 串 | 输出 | 靠哪条规则判出 |
| --- | --- | --- |
| `{}{}<><>()()[][]` | `YES` | 全是并列的括号对，没有嵌套 |
| `{{}}{{}}<<>><<>>(())(())[[]][[]]` | `YES` | 有嵌套，且内层优先级逐层不低于外层 |
| `{{}}{{}}<<>><<>>(())(())[[]][[]]` | `YES` | 同上（题面把这一行重复了一次） |
| `{<>}{[]}<<<>><<>>>((<>))(())[[(<>)]][[]]` | `YES` | 同上，栈轨迹见思路一节 |
| `><}{{[]}<<<>><<>>>((<>))(())[[(<>)]][[]]` | `NO` | 首字符就是 `>`，栈空 —— 配对规则 |

真实数据里还有两个更小的串，它们才是两条规则的分水岭：`([])` 与 `<[<>]>` 都只因为
**嵌套优先级**不合法而输出 `NO`（第 5 组数据的 16 个串里就有它们），题面则点名
`[()]` 是 `YES`、`([])` 是 `NO`。

## 正解

### 思路

**先只做一半：标准栈匹配。** 判断括号能否配对，标准做法是维护一个栈：遇到左括号入栈，
遇到右括号就要求它与栈顶同种并把栈顶弹出，最后栈空即配对成功。栈的「后进先出」
正好对应括号不允许交叉错位，所以规则 1 用它是完备的。

**但规则 2 会漏掉。** 拿真实数据里的 `([])` 试一下：`(` 入栈，`[` 入栈，`]` 弹掉 `[`，
`)` 弹掉 `(`，栈空 —— 标准匹配说它合法，可题目要求输出 `NO`。原因在于题面那句
「从内到外必须是 `<>,(),[],{}`」：`[ ]` 的优先级比 `( )` **低**，只能待在外层，
不能出现在 `( )` 里面。反过来 `[()]` 外层是 `[ ]`、内层是 `( )`，就合法。

所以规则 2 的精确含义是：**内层括号的优先级 $\geqslant$ 外层括号的优先级**。
四类括号恰好构成一个全序，可以给它们各分配一个整数：让数值表示「允许待在多内层」，
越靠内数值越大。

$$\texttt{\{} < \texttt{[} < \texttt{(} < \texttt{<}
\qquad\Longleftrightarrow\qquad 0,\ 1,\ 2,\ 3$$

最外的 `{ }` 编号最小，最内的 `< >` 编号最大，于是题面那句「从内到外依次是 `<>,(),[],{}`」
就被压缩成了一条不等式。

**为什么只需比较栈顶。** 扫描过程中，栈里装的正是当前所有还没闭合的左括号，
**从底到顶就是由外到内的嵌套顺序**，而且栈内已经满足单调性——这是之前每一步都检查过的
累积结果。新来的左括号只能插在最内层，也就是栈顶之上，所以只需要它和栈顶比一次：

- `code >= stack[-1]`：它不比当前最内层更靠外，合法，入栈；
- `code < stack[-1]`：它比外层还靠外，违反规则，整串判 `NO`。

不用遍历整个栈：既然栈内更深的元素本来就 $\leqslant$ 栈顶，那么「$\geqslant$ 栈顶」
自动意味着「$\geqslant$ 栈内全部元素」。

**右括号的判等压成一个减法。** 右括号要判的只有「栈非空」和「与栈顶同种」两条。
让同类右括号的编码等于左括号编码 $+\,4$（四类左括号占用 $0..3$，右括号顺势落在 $4..7$），
于是「与栈顶同种」就是「编码差等于 4」，一个减法就够；而 `code < 4` 同时充当「这是左括号」
的类型测试，省掉一次字符串比较。

**在样例里出现过的片段 `{<>}{[]}` 上走一遍。** 表中「栈」一列从底写到顶，
即当前嵌套的由外到内顺序：

| 读入字符 | 编码 | 栈（底 → 顶） | 判定 |
| --- | --- | --- | --- |
| `{` | 0 | `{` | 左括号，栈空，入栈 |
| `<` | 3 | `{` `<` | 左括号，$3 \geqslant 0$，入栈 |
| `>` | 7 | `{` | 右括号，$7 - 3 = 4$，弹栈 |
| `}` | 4 | （空） | 右括号，$4 - 0 = 4$，弹栈 |
| `{` | 0 | `{` | 左括号，栈空，入栈 |
| `[` | 1 | `{` `[` | 左括号，$1 \geqslant 0$，入栈 |
| `]` | 5 | `{` | 右括号，$5 - 1 = 4$，弹栈 |
| `}` | 4 | （空） | 右括号，$4 - 0 = 4$，弹栈 |

扫完后栈为空，输出 `YES`。全过程没有任何一次不等式或减法失败。

再看 `([])` 与 `[()]` 的分岔点 —— 两者都在读到第 2 个字符 `[` 时停下比较栈顶：

| 串 | 读入 `[` 时的栈 | `[` 的编码 vs 栈顶 | 结果 |
| --- | --- | --- | --- |
| `([])` | `(`（编码 2） | $1 < 2$，比外层还靠外 | `NO` |
| `[()]` | `[`（编码 1） | —— | 继续，最终 `YES` |

`<[<>]>` 是同一个道理被更早抓住的例子：`<`（编码 3）入栈后紧接 `[`（编码 1），
$1 < 3$，第二步就判 `NO`。

**完整流程。**

1. 逐字符映射成编码（`map(LEVEL.get, s)`）。
2. 编码 $< 4$：若栈非空且小于栈顶则返回 `False`，否则入栈。
3. 编码 $\geqslant 4$：栈空则返回 `False`；否则弹出栈顶 $t$，$code - t \neq 4$ 也返回 `False`。
4. 扫完若栈为空返回 `True`，否则 `False`（有左括号没闭合）。

三条 `return False` 分别对应「内层优先级不够」「右括号没有对象可配」「左右括号不同种」，
任何一条触发都直接判 `NO`，不必把整个串扫完。

### 复杂度

设第 $i$ 个串长为 $m_i$：

- **时间复杂度**：$O\!\left(\sum_{i=1}^{n} m_i\right)$。每个字符只做一次字典查询和一次
  $O(1)$ 的栈操作；任何一步失败都立刻返回，不增加上界。
- **空间复杂度**：$O\!\left(\max_i m_i\right)$。栈最深等于最长串的长度（最坏是 255 个左括号
  全在栈里）；迭代实现，没有递归深度风险。

## 总结

- `([])` 是本题的关键反例：**标准栈匹配只判「配对」，判不出「嵌套优先级」**。
- 把「从内到外依次 `<>,(),[],{}`」翻译成整数全序 `{ < [ < ( <`（$0,1,2,3$），
  规则 2 就变成一条不等式：内层编码 $\geqslant$ 外层编码。
- 栈从底到顶天然就是「由外到内」，且栈内已单调，所以新左括号只需与栈顶比一次，
  一次 $O(\text{长度})$ 扫描即可判定，无需回溯。
- 让右括号编码 $=$ 同类左括号 $+\,4$，则「同种」退化为差值等于 4，
  `code < 4` 还可兼作左右括号的类型判定。
- 这套「给嵌套层级一个全序、再用栈的单调性做局部检查」的思路，可以推广到任何
  「嵌套结构必须遵守固定内外顺序」的判定题。
