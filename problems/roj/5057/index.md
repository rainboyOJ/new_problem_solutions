## 形式化题目

给定一个浮点数 $w$，代表行李的重量（公斤）。
计算收费 $c$ 如下：
- 若 $w \le 20$，则 $c = w \times 1.68$；
- 若 $w > 20$，则 $c = w \times 1.98$。

输出 $c$，要求保留 $2$ 位小数。

## 正解

### 思路

本题是一道非常基础的分支结构题目。
首先根据输入重量 $w$ 的大小，判断其属于哪个计费区间。
如果 $w \le 20$，就用 $w$ 乘以 $1.68$；否则，用 $w$ 乘以 $1.98$。注意，题意表明一旦重量超过 $20$ 公斤，是**全部重量**按 $1.98$ 元/公斤计费，而非仅超出的部分（例如 $20.01$ 公斤的费用是 $20.01 \times 1.98 = 39.6198$，保留两位小数为 $39.62$）。

对于输出保留两位小数：
- 在 C++ 中，可以使用 `<iomanip>` 中使用 `cout << fixed << setprecision(2) << c`。
- 在 Python 中，可以使用 f-string 格式化 `f"{c:.2f}"`。

由于本题没有在舍入规则上做限制，并且数据的测试点也未能对不同的舍入行为起到判别效果。因此在实际实现中，直接依赖语言默认的浮点格式化行为即可通过所有的测试点。跨语言不需要任何兼容层处理。

## 总结

本题是分支结构基础题，主要涉及简单的条件判断和浮点运算格式化。
- **算法设计：** 按重量档位选单价，乘以**全部重量**，最终结果保留 2 位小数，复杂度 $O(1)$。
- **★★ 规则是「全部重量 $\times$ 单价」而非分段：**
  $w > 20$ 的测试点均能区分这两种做法（$w \le 20$ 的测试点两种读法结果相同）。通过精确复算得出：
  | 测试点 | $w$ | 测试输出 | 全量精确值 | 分段 | 判别力 |
  |---|---|---|---|---|---|
  | `p4` | **20.01** | **39.62** | 198099/5000 | **33.62** | **★** |
  | `p6` | **69.31** | **137.23** | 686169/5000 | **131.23** | **★** |
  | `p7` | **317.83** | **629.30** | 3146517/5000 | **623.30** | **★** |
  | `p8` | **599.44** | **1186.89** | 741807/625 | **1180.89** | **★** |
  | `p9` | **1000.00** | **1980.00** | 1980 | **1974.00** | **★** |
  | `p10`| **999.99** | **1979.98** | 9899901/5000| **1973.98** | **★** |
  上述数据点严格验证了题目意指全量计费，非分段累加。
- **★★★ 舍入模式：数据无法裁定：**
  测试数据 10 个点的 3 位小数依次为 `0, 0, 3, 9, 8, 3, 3, 1, 0, 0`，**无一是精确平局**。在穷举的 $w = 0.00 \dots 100.00$（10001 值）与扩充到 1000.00（100001 值）中，分别有 160 个和 1960 个十进制平局，但**测试数据命中 0 个**。
  机理上，`printf` / f-string 等**对【二进制值】做精确舍入**，仅当二进制值恰好等于十进制平局（如可被 2 的次幂除尽的值）时，才表现为十进制平局取偶。反例如 $20.25 \times 1.98$，其 double 值为 `40.094999999999998863…` < 40.095，最终会被舍入成 `40.09`；这与十进制的 half-up 和 half-even（两者皆为 40.10）不同。
  **在 1960 个十进制平局点中，实测结果与 half-even 相同的为 564，与 half-up 相同的为 416，与两者都不同的达 532。**
  **实用结论：** C++ 和 Python 标准舍入在这类计算上在 **100001 组不同取值 + 10 个二进制中点**测试上**逐字节完全一致**，无需编写特殊兼容层。
- **★★ 一个真实缺陷（已修）：**
  Python `float(sys.stdin.buffer.read())` 直接转换整个标准输入流，在面临“空输入”、“多余 token”时，与 C++ 取第一个 token 的做法语义差异过大。目前已将 Python `sys.stdin.buffer.read().split()` 取第一个 token 作为标准逻辑（与 `std.cpp` 口径一致）。这确保了 13 组异常 I/O 边界（空、纯空白、多余 token 等）的三方行为表现完全一致。
- **★ 精度：**
  经过 100001 个不同值的大规模测试，非平局点 0 分歧。针对边界 $w=20.00$，通过验证比较得出 `float(20.00) <= 20.0` 为 `True`。且其浮点比较误差窗口大概在 $3.55 \times 10^{-15}$，这对于固定输入两位小数的情形，永不可能被触发产生误差。
- **★ 验证强度摘要：**
  - **异源对照：** 使用精确整数的思路（`(num + 50) // 100`，`num = rate × w` 的按分计价逻辑）与 `double` 对比，在 100001 值下 0 分歧。
  - **硬编码防御（V2）：** 非硬编码的全部字面量为 `{0, 1.68, 1.98, 2, 20.0}`，全部命中非答案（零答案命中）。
  - **反事实校验（V1）：** 篡改判断 `if (false)` 挂掉 6 点；修改为 `w < 20.0` 挂 `p2`；用分段挂 6 点。
  - **运行时安全（V9）：** UBSan 检查 100001 次操作，stderr 全空，确认无未定义行为（UB）。
- **格式：** 输入点正则匹配 `^\d+\.\d\d\n$`（固定 2 位小数），无空行或多重数据问题；输出样例 `od -c` 即为 `3 3 . 6 0 \n`（6 字节，包含后缀 `0`），未存在 CRLF 或多余尾空字符。
