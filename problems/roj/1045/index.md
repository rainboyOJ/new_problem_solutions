## 形式化题目

给定两个整数 $a$（“幸运”瓶盖数）与 $b$（“鼓励”瓶盖数）。满足下列两条之一即视为可以兑换大奖：

$$a \geqslant 10 \quad \text{或} \quad b \geqslant 20.$$

判定能否兑换：能输出 `1`，不能输出 `0`。

注意两条规则是**或**的关系——不需要同时满足。官方样例 `11 19` 正是这一点的试金石：鼓励瓶盖 19 个，离 20 差一个，但幸运瓶盖 11 个已过线，所以答案仍是 `1`。

## 正解

### 思路

输入只有一组数、阈值是两个写死的常量，"朴素做法"就是直接比较两条规则——它同时也是最终做法，中间不存在可以单独教学的瓶颈层（再写一个"暴力版"只会得到一模一样的代码），因此按直接正解型组织。

真正要读对的是**逻辑连接词**。把两条规则写成两个布尔谓词：

- 幸运达标：$a \geqslant 10$；
- 鼓励达标：$b \geqslant 20$。

题面说"拥有 10 个幸运、**或** 20 个鼓励"即可兑换，所以判定式是 $\text{can} = (a \geqslant 10) \lor (b \geqslant 20)$，一个 `or` 收拢两条路径。四种组合的判定结果如下表：

| $a \geqslant 10$ | $b \geqslant 20$ | $\text{can}$ | 例子 | 输出 |
| :---: | :---: | :---: | --- | :---: |
| ✓ | ✓ | 真 | `25 21` | `1` |
| ✓ | ✗ | 真 | `27 2` | `1` |
| ✗ | ✓ | 真 | `9 20` | `1` |
| ✗ | ✗ | 假 | `9 19` | `0` |

前三种情况都输出 `1`：只要有一条路径成立即可兑奖。初学者最容易犯的错是写成 `and`——那会把第二、三种"单条达标"的情况错判成 `0`，样例 `11 19` 就落在这个陷阱上。另外比较要用 $\geqslant$ 而非 $>$：恰好 10 个或 20 个也够兑换，卡线值属于达标。

落到代码上只有三步：`read()` 一次读完输入、`split()` 切分、`map(int, ...)` 转换后解包成 `lucky`、`encourage` 两个名字；两个阈值命名成模块级常量 `LUCKY_NEED = 10`、`ENCOURAGE_NEED = 20`（命名本身就是"幸运要 10、鼓励要 20"这条题面格式的注解）；最后 `print(1 if can_reward else 0)` 把布尔值翻译成题面要求的 `1`/`0`。

## 总结

- 双阈值"或"判定：两条兑换路径满足任意一条即可，判定式是 $(a \geqslant 10) \lor (b \geqslant 20)$，写成 `and` 会把"单条达标"错判成不可兑换。
- 阈值写成命名常量 `LUCKY_NEED` / `ENCOURAGE_NEED`，比较用 $\geqslant$：恰好 10 或 20 个同样达标。
- 读入记住这条线：`read()` → `split()` → `map(int, ...)` → 解包；单组常数判定，实测 10 组真实数据全部 PASS，每组约 0.016 s，相对 1000 ms / 128 MB 的限制毫无压力。
