## 形式化题目

给定两个非负整数的十进制表示 $A$、$B$，每个数的位数不超过 $100$。
输入为两行，每行一个数；输出一行，即 $A + B$ 的十进制表示（无前导零，结果为 $0$ 时输出单个 `0`）。

即求

$$C = A + B, \qquad 0 \leqslant A, B < 10^{100},$$

并输出 $C$ 的十进制串。样例输入为 $A = 22222222222222222222$、$B = 33333333333333333333$，输出 $55555555555555555555$。

## 正解

### 思路

**朴素做法及瓶颈。** 直接 `cin >> a >> b` 用整型相加，C++ 里最大的定长类型 `unsigned long long`
上界约 $1.8 \times 10^{19}$，只能容纳 20 位，而本题最大 100 位，必然溢出。
换更大的类型也走不通——这是硬件字长的限制，不是换个声明能绕过的。所以必须换一种**数据表示**：
不用"一个数"来存，而用"一串数位"来存，把一次大数加法降解成一串小整数加法。

**关键观察：十进制加的每一位之间是解耦的，只通过进位耦合。**
第 $i$ 位的输出只依赖 $A$ 的第 $i$ 位、$B$ 的第 $i$ 位和来自第 $i-1$ 位的进位。于是竖式加法
（低位对齐、逐位相加、满十进一）可以逐位模拟：

$$S_i = a_i + b_i + \text{carry}_{i-1}, \qquad c_i = S_i \bmod 10, \qquad \text{carry}_i = \lfloor S_i / 10 \rfloor .$$

因为每一位的和至多是 $9 + 9 + 1 = 19$，进位永远是 $0$ 或 $1$，可以用一个整型变量携带。

**对齐靠倒序。** 人类书写时高位在左，而竖式要从最低位开始。把字符串**倒序**展开成整型数组后，
下标 $0$ 就是个位（$10^0$）、下标 $i$ 对应 $10^i$，两个位数不同的加数自动按个位对齐；
较短的那个数高位位置保持 $0$（C++ 里靠全局数组默认零初始化，Python 里靠 `zip_longest(fillvalue='0')`），
不需要任何长度判断。

**边界之一：最高位进位。** 循环跑完长度较长的那个数之后，进位可能仍是 $1$（例如 $99 + 1$、$10^{100} - 1$ 加自身），
此时必须再补一位，否则结果会少一位。

**边界之二：前导零。** 加法本身不会凭空制造前导零（除 $0 + 0$ 外），但如果黑盒数据里出现带前导零的输入
（本题数据生成脚本会造这种点），输出就要做一次规范化：从最高位往下丢掉前导零，并至少保留一位，
使 $0 + 0$ 输出单个 `0` 而不是空行。

综合起来，整道题的算法就是 $O(L)$ 的一次竖式模拟：读入 $O(L)$、倒序展开 $O(L)$、逐位相加 $O(L)$、
输出 $O(L)$，其中 $L \leqslant 101$。

### 复杂度

- **时间**：$O(L)$，$L \leqslant 101$ 是结果的位数（100 位加数 + 最高位进位）。每轮循环是常数次加减与取模，
  实测整个程序在 $1$ ms 量级（限时 1000 ms）。
- **空间**：$O(L)$，三个长度约 $105$ 的全局整型数组加一个输入字符串，占用在 KB 级（限时 64 MB）。
- **Python 侧**：`main.py` 的算法与 C++ 完全同阶（$O(L)$），但逐位做 `int()` / `divmod` 的常数比 C++ 大，
  好在 $L \leqslant 101$ 时完全无风险；若把 `add_vertically` 换成 `print(int(a) + int(b))` 也是同一阶，
  这里保留竖式写法是为了和题解正文的推导一一对应。

## 总结

- **大数的表示先于大数的运算**：不能用一个整型装下，就退回"每位一个元素"的数组/字符串表示，
  再用人类竖式的规则在数组上重定义加法。
- **倒序展开是通用技巧**：让下标 $0$ 代表个位，既省掉了右对齐的长度讨论，又让"进位往上传递"变成下标自增，
  高精度加法、减法、乘法的低位对齐都靠它。
- **两个必须检查的边界**：循环结束后仍为 $1$ 的进位（补最高位），以及输入或结果里的前导零（规范化输出）。
- **语言差异**：Python 的 `int` 本身是高精度实现，`int(a) + int(b)` 可直接过题；
  但 C++ 必须手写竖式，本题的价值就在于把这套流程写清楚。
