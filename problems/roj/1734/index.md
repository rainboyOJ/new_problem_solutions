## 形式化题目

给一个 $n$ 个点、$m$ 条边的无向图，点与边均从 $0$ 开始编号，允许**重边**与**自环**。
共 $Q$ 次询问，第 $i$ 次给出一个边编号 $x$，要求回答：把第 $x$ 条边删掉之后，
图中有多少**无序点对** $(u, v)$（$u \neq v$）互不可达。答案对 $1000$ 取模（题面写的是"保留后三位"）。

形式化地，设 $G_x$ 是删掉边 $x$ 后的图，$C_x$ 是 $G_x$ 上的连通关系，问的是

$$
f(x) = \#\bigl\{\{u, v\} : u \neq v,\; (u, v) \notin C_x\bigr\}.
$$

注意统计的是**全图**的不可达点对，删边前就已经不连通的点对也算在内——这一点由样例唯一确定：
样例里点 $3$ 是孤立点，删掉非桥边答案仍是 $3$ 而不是 $0$。

## 正解

### 思路

**先处理"删边前"。** 不管删哪条边，删之前全图就已经互不可达的点对始终是同一批，
它们的贡献与 $x$ 无关。把所有连通块的大小记为 $s_1, s_2, \dots, s_k$（$\sum s_i = n$），
那么块内的点对全部可达、块间的点对全部不可达，于是

$$
T_0 = \binom{n}{2} - \sum_{i=1}^{k} \binom{s_i}{2}.
$$

求每个块的大小用**并查集**（带大小合并）即可，$O((n + m)\alpha)$。
注意 $\binom{n}{2}$ 最大约 $5 \times 10^9$，超过了 `int`，必须用 64 位整数（`long long` / Python 任意精度）。
样例里 $n = 4$，块为 $\{0,1,2\}$ 与 $\{3\}$，$T_0 = 6 - 3 - 0 = 3$。

**再看删边带来的变化。** 删一条边 $x$ 只会影响它所在的那个连通块 $B$（大小记作 $C$）。
把这条边从 $B$ 中去掉之后：

- 若 $x$ **不是桥**，$B$ 仍然连通，块结构一点没变，故 $f(x) = T_0$；
- 若 $x$ **是桥**，$B$ 被切成两块 $B_1$、$B_2$，大小分别记 $s$ 与 $C - s$。
  原本 $B$ 内部两两可达（贡献 $0$），现在 $B_1$ 与 $B_2$ 之间的点对全部变成不可达，
  而这些点对的数量正是 $s \cdot (C - s)$。故 $f(x) = T_0 + s(C - s)$。

于是问题变成：**对每条边，$O(1)$ 地回答"它是不是桥"，以及"它是桥时切下的那侧有多大"。**

**判定桥 + 取子树大小。** 这是 Tarjan 求桥的标准做法。对图做 DFS，记 `dfn[u]` 为时间戳、
`low[u]` 为 $u$ 的子树里能通过返祖边回到的最小 `dfn`，则对 DFS 树上的父边 $(p, u)$：

$$
\text{边 } (p,u) \text{ 是桥} \iff \texttt{low}[u] > \texttt{dfn}[p].
$$

为什么这个判据和"切下来的大小"是同一件事：DFS 树中 $u$ 的子树恰好就是"删掉父边后
只靠 $u$ 一侧能找到的点集"。`low[u] > dfn[p]` 说明这棵子树没有任何一条边能通到 $p$ 或更上面，
因此它整个被这条边封住，大小就是 `sub[u]`。所以**一次 DFS 同时得到桥的集合与每条桥的 $s$**，
不需要第二遍遍历。

**重边与自环。** 这两个是本题最容易写错的地方。

- **自环**永远不是桥（删掉它两个端点仍是同一个点，连通性不变）。Tarjan 里自环表现为
  一条 `v == u` 的边，它的 `dfn[v]` 已经赋过值，只会用来更新 `low[u]`，不会影响判定。
- **两条平行边**都不是桥：删掉一条后两个端点还能靠另一条连通。判桥时要跳过**父边**以避免
  "儿子顺着树边爬回父亲"；如果按**父顶点**跳（`v == parent[u]` 就不看），那么第二条平行边
  也会被当成父边忽略掉，于是 `low[u]` 停留在 `dfn[u]`，`low[u] > dfn[p]` 成立 → 误判成桥。
  正确做法是**只跳过父边的编号** `pe[u]`（一条无向边存两条弧 $2i, 2i+1$，
  用 `e >> 1` 还原边号）：这样另一条平行边会被当作返祖边，把 `low[u]` 拉到 `dfn[p]`，判据不成立。
  样例第 $0,1$ 两条边就是一对平行边 $(0,1)$、$(1,0)$，它们的答案 $3,3$ 正好检验这一点。

**实现细节：为什么用迭代 DFS。** $n$ 可达 $10^5$ 且数据里存在链状图（DFS 深度 $10^5$），
递归版 Tarjan 会爆栈。这里用显式栈模拟：栈里存顶点编号，每个点带一个"当前走到哪条出弧"的指针 `it[u]`，
`it[u]` 走完时弹出并回溯——回溯那一瞬间才能拿到子树已经算好的 `sub[u]` 与 `low[u]`，
正是这一瞬间做"累加子树大小 + 判桥"两件事。所以不能用 BFS 顺序代替，必须保序地模拟 DFS。

顺带一提，删边后"互不可达点对"也可以直接从块的分布算：$f(x) = \binom{n}{2} - \sum \binom{s'_i}{2}$，
其中 $s'$ 是删边后的块大小。上式 $T_0 + s(C-s)$ 就是它的化简：
删桥后原来的 $\binom{C}{2}$ 被换成 $\binom{s}{2} + \binom{C-s}{2}$，差值恰为 $s(C-s)$。

### 复杂度

- **时间**：并查集 $O((n+m)\alpha(n))$；Tarjan 每条弧恰好被看一次，$O(n + m)$；
  每次询问 $O(1)$ 查表并取模，$O(Q)$。总计 $O(n + m + Q)$。
  题面上限为 $n \le 10^5$、$m \le 10^6$、$Q \le 8 \times 10^5$，
  C++ 版在 $Q = 8 \times 10^5$ 的两个顶格点上实测 $0.06 \sim 0.14$ s（限时 1000 ms）。
  Python 版在同样的顶格点上实测 $0.55$ s（点 10）与 $1.5$ s（点 9），后者超过 1000 ms 的限时，有 TLE 风险（算法未降级）。
- **空间**：`head`、`dfn`、`low`、`sub` 等按点数开，均为 $O(n)$；
  链式前向星的弧数组为 $2m$；`bridge_child` 按边数开为 $O(m)$。合计 $O(n + m)$，
  顶格约 $20$ MB 量级（限时 256 MB）。
- **与 Python 解法的关系**：`main.py` 与 `main.cpp` 是同一算法——链式前向星、
  带大小的并查集、迭代式 Tarjan 求桥与子树大小、询问时 $s(C-s)$ 累加。
  两版都把桥信息落成一张按边编号索引的表，所以 $Q$ 次询问都是查表。

## 总结

- **把答案拆成"与删边无关的基线 + 单条边的贡献"**：$f(x) = T_0 + [x\text{ 是桥}]\,s(C-s)$。
  这一拆解把 $Q$ 次"删边后重新算连通性"降到 $O(1)$ 查表。
- **只有桥才改变可达性**：删非桥边（环上的边、重边之一、自环）图结构不变，答案就是 $T_0$。
- **一次 DFS 同时得到桥的集合与切下来的子树大小**：`sub[u]` 天然就是删掉父边后被封住的那一侧，
  判据 `low[u] > dfn[p]` 与"这侧有多大"是同一个条件的两个面。
- **重边必须按边编号跳过父边**，不能按父顶点跳过，否则平行边会被误判成桥；自环始终不是桥。
- **大图要用迭代 DFS**：链状数据下递归深度为 $n$，会爆栈；显式栈里保存"当前出弧指针"即可。
- **计数别用 `int`**：$T_0$ 与 $s(C-s)$ 都能到 $10^9$ 量级，C++ 里必须用 `long long`。
