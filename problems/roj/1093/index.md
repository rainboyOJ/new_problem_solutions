## 形式化题目

给定实数 $x$ 与正整数 $n$，求

$$S(x, n) = x^n + x^{n-1} + \cdots + x^2 + x + 1 = \sum_{k=0}^{n} x^k$$

的值，结果保留两位小数输出。

样例 $x = 2.0,\ n = 4$ 的逐项累加过程如下（第三列为前缀积，第四列为部分和）：

| $k$ | $x^k$ | 前缀积 $p$ | 部分和 $S_k$ |
| :-: | --: | --: | --: |
| 0 | $2^0 = 1$ | 1 | 1 |
| 1 | $2^1 = 2$ | 2 | 3 |
| 2 | $2^2 = 4$ | 4 | 7 |
| 3 | $2^3 = 8$ | 8 | 15 |
| 4 | $2^4 = 16$ | 16 | **31** |

观察重点：每一行的前缀积只比上一行多乘了一次 $x$，部分和只比上一行多加了一个前缀积。
这正是本解能做到 $O(n)$ 的全部原因。

## 正解

### 思路

按定义直接写，最自然的做法是对每个 $k$ 各自从 1 开始重复乘 $k$ 次，得到 $x^k$ 再累加：

```python
ans = 0.0
for k in range(n + 1):
    p = 1.0
    for _ in range(k):   # 从零开始重新乘出 x^k
        p *= x
    ans += p
```

第 $k$ 项要乘 $k$ 次，总乘法次数是 $\sum_{k=0}^{n} k = O(n^2)$；$n \leqslant 10^6$ 时约
$5 \times 10^{11}$ 次乘法，1000 ms 内没有完成的可能。

**瓶颈在哪**：算 $x^k$ 的过程中，$x, x^2, \ldots, x^{k-1}$ 已经被陆续乘出来了，却全部扔掉，
下一项又从 1 重新开始。相邻两项其实只差一次乘法：

$$x^k = x^{k-1} \cdot x, \qquad x^0 = 1$$

于是维护一个变量 $p$ 做**前缀积**：初始 $p = 1$（即 $x^0$），每步先 $p \gets p \cdot x$
得到 $x^k$，再把它累加进答案 $S$。一趟扫描同时得到所有 $x^k$ 和所有部分和，
乘法次数降到 $n$，复杂度 $O(n)$。用归纳法可以确认：第 $k$ 步结束时
$p = x^k$ 且 $S = \sum_{j=0}^{k} x^j$，$n$ 步之后 $S$ 正是所求。

**但本题的坑不在复杂度上。** 多数数据的答案远超 double 的有效数字：第 1 组是
$813.97^{61}$，输出整数部分长达 **178 位**，10 组里最大的一组有 247 位。double 只有约
15–17 位十进制有效数字，超出这个范围后印出来的每一位都由 **求和次序**决定，
与数学真值无关。数据生成用的 `std.cpp` 循环是

```cpp
for (i = 1; i <= num; i++) { temp = temp * x; sum = sum + temp; }   // 次数递增
```

也就是**自低次向高次**的左折叠。本解必须复现这个次序，否则末几位会对不上。

拿 `70.17 8`（第 6 组数据）实测：真值是 $596273506208967.2568555\ldots$，
而三种次序的 double 结果各不相同，连小数点后第一位都定不下来：

| 求和次序 | double 结果 | 输出 |
| --- | --: | --: |
| 自低次向高次左折叠（本解，与 `std.cpp` 同序） | 596273506208967.5 | `596273506208967.50` |
| Horner 式，自高次向低次 | 596273506208967.375 | `596273506208967.38` |
| `math.fsum` / `sum()` 精确补偿求和 | 596273506208967.4 | `596273506208967.38` |

三者运算次数相同、渐近复杂度也相同，差别只在加法顺序。可以看到"更准"的 `fsum`
反而与判题数据不合——数据要的正是朴素左折叠的舍入产物。因此本解用
`functools.reduce` 而**不用 `sum()`**：CPython 3.12 起 `sum()` 对浮点改用
Neumaier 补偿求和，会破坏与 `std.cpp` 一致的逐位同序。

落到 Python 上，两步各自对应一个标准库工具：

| 正文概念 | `main.py` 中的实现 |
| --- | --- |
| 前缀积 $x^k = x^{k-1} \cdot x$ | `accumulate(repeat(x, n), mul, initial=1.0)` |
| 自低次向高次的左折叠 | `reduce(add, powers)` |
| 保留两位小数 | `f"{S:.2f}"` |

`initial=1.0` 不能省：省略后首个产出是 $x$ 而不是 $x^0$，会漏掉常数项 1。

### 复杂度

- 时间复杂度：$O(n)$，$n$ 次乘法 + $n+1$ 次加法。对比朴素写法的 $O(n^2)$，
  在 $n = 10^6$ 时从约 $5 \times 10^{11}$ 次乘法降到 $10^6$ 次。官方数据单点
  0.019 s，最坏情况 $n = 10^6$ 实测约 0.04 s，相对 1000 ms 限时余量 20 倍以上。
- 空间复杂度：$O(1)$，`accumulate` 与 `reduce` 都是惰性迭代器，同一时刻只保留当前
  前缀积与累加和，不物化长度为 $n$ 的列表。

## 总结

- 把"每一项独立重算"换成前缀积递推 $x^k = x^{k-1}\cdot x$，是本题唯一需要想到的一步：
  $O(n^2) \to O(n)$，且不改变求和次序。
- 本题的真正难点是浮点口径。当结果的有效数字远超 double 的 17 位时，打印出来的
  各位数字由 **加法次序**决定；数据由 `std.cpp` 的"自低次向高次左折叠"生成，
  所以要用 `reduce(add, ...)` 复现同样的次序，而不是用更准的 `sum()` / `math.fsum`。
- 边界（$x = 0$、$x < 0$、溢出成 `inf`）都由同一递推自然覆盖，不需要特判。
- 官方 10 组真实数据全部 PASS（单点 0.019 s、峰值 14.6 MB）；另与 `std.cpp`
  逐组比对 411 组输入（含 $n = 10^6$ 与各类边界），输出全部一致。
