## 形式化题目

给定整数 $n$（$1 \leqslant n \leqslant 100$）和紧随其后的 $n$ 个整数 $a_1, a_2, \dots, a_n$
（$15 \leqslant a_i \leqslant 25$），求它们的算术平均值

$$
\bar{a} = \frac{1}{n}\sum_{i=1}^{n} a_i
$$

并按"保留到小数点后两位"的格式输出。样例给出 $n = 2$、$a = (18, 17)$，
$\bar{a} = 17.5$，输出 `17.50`——注意补足的那一位 `0` 也是答案的一部分。

## 正解

### 思路

本题没有可以优化的算法：目标是 $n$ 个数的平均值，任何一个正确程序都至少要读一遍这 $n$ 个数，
下界就是 $O(n)$。把 `sum` 手写成一个 `for` 循环累加，得到的程序与正解逐字等价、
复杂度也相同，所以本文不写"暴力版本"，直接讲做法。真正的教学点是这条求和链上
**三处会直接错答案的细节**。

先把流程摊开，用样例走一遍：

| 步骤 | 表达式 | 样例中的值 | 说明 |
| --- | --- | --- | --- |
| 读人数 | `n = next(data)` | $2$ | 第一行，决定后面要读几个年龄 |
| 读年龄 | `ages = islice(data, n)` | $(18, 17)$ | 惰性切出恰好 $n$ 个元素 |
| 求和 | `sum(ages)` | $35$ | 所有年龄一次遍历 |
| 求平均 | `sum(ages) / n` | $17.5$ | **实数**除法，不是整除 |
| 输出 | `f"{...:.2f}"` | `17.50` | 舍入到两位并**补齐**两位 |

这张表里第 4、5 行就是两个坑，后面逐个说。

**第一处：人数只能来自第一行的 $n$。** 输入的形状是"$n$ 后面跟 $n$ 个数"，
所以代码里必须有一个位置承接 $n$。最直接的直译是逐行读：

```python
n = int(input())
s = 0
for _ in range(n):
    s += int(input())
```

对本题而言它完全正确，但循环体只有一句累加——这属于用控制流描述"求和"，
而 Python 的 `sum` 本来就是这件事。把累加交出去之后，剩下的问题是怎么表达
"取后面 $n$ 个元素"：`itertools.islice(data, n)` 正是这个语义，
它按需产出 $n$ 个元素，不物化数组，也不需要额外的下标变量：

```python
data = map(int, sys.stdin.buffer.read().split())
n = next(data)              # 第一行：人数
ages = islice(data, n)      # 其后 n 个年龄
```

`read().split()` 一次拿到全部 token 并按任意空白切分，跨行、行尾换行、
多余空格都被归一化，读入路径压缩成一句；而 $n$ 依然是显式取出的一个具名量，
没有被"把所有 token 全加起来"这种丢掉格式的写法取代。
这样 `n` 在代码里只定义一次、在两处使用——`islice` 的长度和除法的分母，
两处指的是同一个数，不需要第二份拷贝。

**第二处：除法必须是实数除法。** 参考实现用的是 `double sum` 累加后 `sum / n`，
是浮点除法。如果照搬 C 里"整数除整数"的印象写成 `sum(ages) // n`，
样例会输出 `17`、problem7 会输出 `43` 而不是 `43.00`。
Python 的 `/` 对两个 `int` 操作数给出 `float`，写的正是需要的那一步。

**第三处：两位小数要补齐，不是四舍五入到两位有效数字。** `17.5` 要打印成 `17.50`，
`43` 要打印成 `43.00`。两种常见错法：

| 写法 | `17.5` 的输出 | `43.0` 的输出 | 问题 |
| --- | --- | --- | --- |
| `f"{x:.2f}"`（本解） | `17.50` ✅ | `43.00` ✅ | — |
| `print(round(x, 2))` | `17.5` ❌ | `43.0` ❌ | 丢末尾的 `0` |
| `f"{x:.2g}"` | `18` ❌ | `43` ❌ | 有效数字而非小数位 |

`:.2f` 是定点格式：小数点后固定两位，与 C 的 `%.2lf` 同源。
两者都按 IEEE-754 双精度到十进制的"舍入到最近值"规则处理。本题规模很小
（题面 $n \leqslant 100$、$a_i \leqslant 25$；本地数据也只到 $n = 101$、年龄 $\leqslant 100$），
总和不超过 $10100$，是双精度可精确表示的整数，累加不产生误差，
因此本解与参考实现逐位一致：对全部 $1 \leqslant n \leqslant 101$ 与范围内的总和的
489 446 组 $(\text{总和}, n)$ 组合穷举比对 `:.2f` 与 `%.2lf`，差异为 0 组。

**为什么不需要数组。** 平均值是可结合的统计量，只依赖总和与人数，
一趟前向扫描就够，把 $n$ 个年龄存下来再求和只是多一次内存往返。
`islice` + `sum` 恰好表达这个事实：元素被 `sum` 逐个消费后即丢弃，
算法额外空间是常数。数据规模 $n \leqslant 101$ 时两种写法都对，
但前者不需要为临时数组再取一个名字，也让"求和"这个目标直接写在代码里。

### 复杂度

- 时间复杂度：$O(n)$。一次读入扫描、$n$ 次整数转换、$n$ 次累加、一次除法、
  一次格式化输出，全部与输入规模线性相关；本题 $n \leqslant 101$，实测约 0.015 s/组。
- 空间复杂度：$O(n)$（按输入计）。输入字节串与切分出的 token 列表是 $O(\text{输入长度})$；
  算法自身的额外空间是 $O(1)$——`islice` 惰性产出，没有长度为 $n$ 的年龄数组。

## 总结

- 平均值 = 一次遍历求和 + 一次除法，读取下界 $O(n)$；把 `sum` 手写成 `for` 循环与正解逐字等价，所以本题没有值得单独写出的“暴力层”。
- 人数由第一行的 $n$ 决定，用 `n = next(data)` 显式承接，再用
  `islice(data, n)` 惰性取出其后 $n$ 个年龄——既校验了长度，又不需要数组。
- Python `/` 是真除法，`sum(ages) // n` 会退化成整除并输出 `17` 而不是 `17.50`。
- 输出用 `f"{x:.2f}"`：定点两位、补齐末尾的 `0`，与参考实现的 `%.2lf` 语义一致；
  `round` 和 `:.2g` 都会丢格式。
- 验证：数据仓 10 组真实数据全部 PASS（约 0.015 s/组、峰值 14.5 MB，
  限额 1000 ms / 128 MB）；`.2f` 与 `%.2lf` 的一致性由 489 446 组穷举核对确认，差异 0 组。
