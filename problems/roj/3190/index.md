## 形式化题目

给定一棵 $n$ 个节点的树。
有 $m$ 个玩家，第 $i$ 个玩家从起点 $S_i$ 沿着唯一的最短路径走向终点 $T_i$，速度为 $1$ 条边每秒。所有玩家在第 0 秒同时出发。
每个节点 $j$ 有一个观察员，在时间 $W_j$ 时刻进行观察。
一个玩家能被节点 $j$ 观察到，当且仅当该玩家在第 $W_j$ 秒恰好到达节点 $j$。
求每个节点的观察员能观察到的玩家数量。

数据范围：$1 \le n, m \le 3 \times 10^5$。

## 正解

### 思路

对于一个玩家，他的路径是 $S \to T$。设 $L = \text{LCA}(S, T)$。
这条路径可以拆分为两段：从 $S$ 向上走到 $L$，以及从 $L$ 向下走到 $T$。
我们可以在树上建立四个事件表 `ev_add1`，`ev_del1`，`ev_add2`，`ev_del2` 进行树上差分：

1. **上行段（$S \to L$）**：
   玩家在到达位于该段路径上的节点 $u$ 时，已经走过的边数为 $depth[S] - depth[u]$。
   要在 $W_u$ 时刻被观察到，需要满足：
   $$depth[S] - depth[u] = W_u \implies depth[u] + W_u = depth[S]$$
   这说明，对于节点 $u$ 而言，$depth[u] + W_u$ 是一个定值，只要子树中以此为特征的路径起点 $S$ 满足条件，就能被贡献 1。
   我们在 $S$ 处通过 `ev_add1` 加入值 $depth[S]$，在 $up[L][0]$ 处通过 `ev_del1` 移除值 $depth[S]$。

2. **下行段（$L \to T$）**：
   玩家到达位于该段路径上的节点 $u$ 时，走过的边数等于 $S \to L$ 的距离加上 $L \to u$ 的距离，即 $(depth[S] - depth[L]) + (depth[u] - depth[L])$。
   要在 $W_u$ 时刻被观察到，需要满足：
   $$depth[S] + depth[u] - 2 \cdot depth[L] = W_u \implies depth[u] - W_u = 2 \cdot depth[L] - depth[S]$$
   同理，我们在 $T$ 处通过 `ev_add2` 加入值 $2 \cdot depth[L] - depth[S]$。在 $L$ 处通过 `ev_del2` 移除，避免 $L$ 点被上行和下行段重复计算。

最后，建立全局桶 `cnt1` 和 `cnt2`。利用迭代方式进行树的后序遍历，当进入子树时记录所需值的当前桶计数，退出子树时再次查询对应的桶计数，两次计数之差即为子树内净增加的满足条件的玩家数，将其累加到 `ans[u]`。

### 复杂度

- **时间复杂度**：预处理 BFS 和计算倍增 LCA 为 $O((n+m) \log n)$。树上差分的事件添加与后序遍历（手工栈避免爆栈）时间为 $O(n + m)$。总体时间复杂度 $O((n+m) \log n)$。
- **空间复杂度**：存储邻接表、倍增数组、各个节点的 4 个事件表、桶等，总体空间复杂度为 $O(n \log n + m)$。

## 总结

### 1. 核心算法与推导
本题核心采用了**树上差分 + 倍增 LCA + 桶 + 手工栈后序遍历**。完整推导如下：
- 上行段条件为 `depth[S] - depth[u] == W[u]`。
- 下行段条件为 `depth[S] + depth[u] - 2 * depth[LCA] == W[u]`。
通过 4 个事件表 `ev_add1, ev_del1, ev_add2, ev_del2`，将查询转为对子树事件的进出统计。代码结构中采用 `bfs()` 求 `depth` 及 `up[][]`，`get_lca()` 使用倍增算法，全局桶 `cnt1, cnt2` 配合手工栈实现统计。

### 2. V7 算法指纹与反事实证明
通过操作计数证明了实现的复杂度确为 $O((n+m) \log n)$ 而非 $O(nm)$：
- `p1(n=992)`：`get_lca` 调用 992 次，邻接表边访问 3964 次。
- `p9(n=299998)`：`get_lca` 调用 299998 次，邻接表边访问 1199988 次。
**反事实（决定性）**：若将倍增 LCA 替换为暴力爬深度的 LCA（同样正确，输出逐字节相同），会导致 `p9` 耗时增至 **60s 超时**，而现实现仅为 **0.386s**。这证明了产物使用的是对数级 LCA。

### 3. 特殊数据点与递归限制（p6 纯链）
`p6` 的数据结构为**纯链**（`n = 99994`, `maxdeg = 2`, 深度 = `99994`）。
实测表明：在 8MB 栈下可以运行，但**在 4MB 栈限制下普通递归 DFS 会直接报 rc=139 爆栈**。因此，树上差分遍历必须改用**迭代 DFS（手工栈后序遍历）**，避免受不同判题机栈空间限制的影响。

### 4. V4 结构不变量与输入输出格式
- 本题的 `.in` / `.out` 全部为 **LF**（无 CRLF）。
- 每个 `.in` 都被完整消费：`token 数 == 2 + 2(n-1) + n + 2m`，`remain == 0`，全 20 点一致。
- 逐行结构：行数恒为 `n + 1 + m`。首行 2 token；接着 `n-1` 行各 2 token；第 `n+1` 行恰有 `n` token；最后 `m` 行各 2 token（`struct_ok=True`，`blank_lines=0`）。
- 图连通性验证：20/20 点 `reached == n`，证明输入必定为连通的树，不是森林。
- `.out` 行数始终为 1，含 `n` 个 token。
