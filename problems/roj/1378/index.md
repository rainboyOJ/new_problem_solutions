## 形式化题目

给定一个包含 $n$ 个顶点的有向图 $G = (V, E)$，顶点编号从 $1$ 到 $n$，并给定源点 $v_0$。图以邻接矩阵的形式给出，矩阵中 `-` 表示没有直接连接的边，非 `-` 元素表示边的权值。权值可能存在负数，但保证图中的所有的有向环权值和都是正的（即不存在负权环）。要求计算从源点 $v_0$ 到图 $G$ 中其他所有顶点的最短路径长度，并按顶点编号从小到大的顺序输出。

**数据范围**：
$2 \le n \le 80$。边权极大（例如可能达到 $1.5 \times 10^{12}$），可能会超过 32 位整数的表示范围。

## 正解

### 思路

本题为单源最短路径（SSSP）问题。
因为图中的边权可能为负数，因此不能使用无法处理负权边的 Dijkstra 算法。题目明确保证了所有的有向环权值和都是正的（即不存在负权环），我们可以直接使用 **Bellman-Ford 算法**。对于 $n \le 80$ 的数据规模，邻接矩阵和 $O(n^3)$ 的复杂度非常快且不容易出错。

**算法步骤**：
1. **安全且鲁棒的读入**：
   - 数据中存在远超 32 位整数范围的极大权值，并且存在表示不连通的占位符 `-`。
   - 数据极其坑人：某个测试点中的某一行数据在行尾 **缺失了 1 个元素**。如果按照整个文件分割 token 连续读入，会导致后面的数据全部提前一个位置读入（即发生了整个矩阵元素的错位），引发越界甚至在最后一轮读空时崩溃。因此，**必须按行读入**矩阵。读取每行并分割其自身的 token，如果缺失元素，缺失的部分自然会被视作 `-` (无边)，且绝不会影响后续行的读入。
2. **初始化**：定义数组 `dist`，将源点 `source` 的距离设为 0，其余点设为极大值（例如 $10^{18}$ 避免与负权相加产生下溢）。
3. **松弛操作**：最多执行 $n-1$ 轮迭代。每轮遍历邻接矩阵中的所有存在且从源点可达的边 $(i, j)$，如果 `dist[i] + adj[i][j] < dist[j]`，则更新 `dist[j]`。如果某一轮中没有任何顶点被更新，说明已经达到了最短路，可以提前跳出。
4. **输出结果**：按题目要求的格式 `(s -> i) = d` 输出除了源点外的所有顶点的最短距离。

### 复杂度

- **时间复杂度**：建图复杂度为 $O(n^2)$。Bellman-Ford 算法最多执行 $n-1$ 轮，每轮需要遍历整个 $n \times n$ 邻接矩阵耗时 $O(n^2)$，因此总时间复杂度为 $O(n^3)$（或 $O(n \cdot m)$）。由于 $n \le 80$，运算量最大约 $5 \times 10^5$，执行极快。
- **空间复杂度**：需要存储邻接矩阵和一维距离数组，空间复杂度为 $O(n^2)$。

## 总结

1. **含有负边权的最短路**：图中若有负边，绝不能使用 Dijkstra。题目保证没有负权环时，使用 **Bellman-Ford** 或 **SPFA**，最多松弛 $n-1$ 轮即可。
2. **按行读入的鲁棒性（本题最大的坑）**：测试数据 `SHOPTH8.IN` 是一组“脏数据”，其第 10 行的数据缺少了最后 1 个元素。如果用 C++ 的 `cin >> token` 或 Python 的 `f.read().split()` 将整个文件当做 token 流一口气读入，缺少的这 1 个元素会导致其后所有行的读取发生**整体错位**，并在读取最后一行时因超出边界抛出异常崩溃。而**按行读取**（C++ 的 `getline` 结合 `istringstream`，Python 的 `splitlines` 分行解析）即使遇到了元素缺失，也只会影响当前行的最后几列，绝不会污染后续其他行，具有极好的工程鲁棒性。
3. **未定义的不可达点输出**：题目并没有规定如果某些点不可达应该输出什么。在官方数据的 10 个测试点中，所有点相对于源点实际上**全部可达**。现有代码直接保留无穷大标志 `1e18`，这是由我们约定的处理方式，而不是数据支持和要求的结论。
4. **素材陷阱**：在测试过程中发现，附带的 `std.cpp` 使用了 `scanf` 读取并且对 `-` 处理有 Bug（无法成功回退或处理字符），导致在面对所有测试点时都会产生读入错误，输出全部不对。请以 `cin/istringstream` 和 Python 的字符串解析为准。
5. **输出格式**：注意输出 `(s -> i) = d` 时各个部分之间的空格，不要打印源点到自身的距离，并且需按照顶点编号 $i$ 升序输出。对角线上的 $0$ 或负数被当做权值为 0 或对应的自环即可，并不影响最短路径逻辑。
