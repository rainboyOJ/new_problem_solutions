## 形式化题目

给定 $n$（$1 \le n \le 17$）个三元组 $(g_i,s_i,b_i)$，分别表示第 $i$ 天获得的金、银、铜牌数。记三列的和为

$$
G=\sum_{i=1}^{n} g_i,\qquad S=\sum_{i=1}^{n} s_i,\qquad B=\sum_{i=1}^{n} b_i
$$

要求输出 $G$、$S$、$B$ 以及它们的总和 $G+S+B$。

## 正解

### 思路

先看读入：题面说“其后 $n$ 行”，但每天的 3 个数只由它们在输入中的先后顺序决定，
换行在哪里并不影响结果，所以把全部内容按空白切一次、转成整数迭代器 `data`，
再顺序取数即可，连行结构都不用解析。

在此基础上写出最直白的做法：开三个计数器 `gold`、`silver`、`bronze`，
每读一天就把当天的三个数分别加进去，读完后输出三个计数器和它们的和。

```python
import sys

data = iter(map(int, sys.stdin.buffer.read().split()))
days = next(data)          # 天数 n
gold = silver = bronze = 0
for _ in range(days):
    g, s, b = next(data), next(data), next(data)
    gold += g
    silver += s
    bronze += b
```

每个输入数只被读一次、只参加一次加法，所以这段代码已经是 $O(n)$ 的最优复杂度，
本题没有“再优化一步”的余地。它唯一的问题是**重复**：三个计数器的更新是同一件事
写了三遍，而 $n$ 小到 $17$，这两点说明差异只在写法而不在算法。

要消掉重复，换一个角度看输入：把 $n$ 天的数据排成一个 $n \times 3$ 的矩阵，
行是一天，三列依次是金、银、铜。要求的东西——金牌总数、银牌总数、铜牌总数——
正是这个矩阵的**三列列和**。样例的矩阵与列和如下表，行是输入的三天，
最后一列写的是该行的和（仅供对照，不是输出的第四个量）：

| 天 / 列 | 金牌 | 银牌 | 铜牌 | 当天合计 |
| --- | --- | --- | --- | --- |
| 第 1 天 | 1 | 0 | 3 | 4 |
| 第 2 天 | 3 | 1 | 0 | 4 |
| 第 3 天 | 0 | 3 | 0 | 3 |
| **列和（答案）** | **4** | **4** | **3** | **11** |

可以看出，三列之间互不干扰：金牌只和金牌相加，银、铜同理。
所以只要能把“按行存的矩阵”变成“按列存的三组数”，剩下的就是对每组数求和。
这一步用 `zip` 完成：

```python
zip(*rows)          # n 行 3 列  ->  3 行 n 列（转置）
```

`*rows` 把 $n$ 个行列表展开成 $n$ 个位置参数，`zip` 再取每个参数的
第 $k$ 个元素拼成新元组，于是**第 $k$ 个元组恰好就是第 $k$ 列**。
接着对每个元组调用 `sum`，就同时得到三种奖牌的总数：

```python
rows = [[next(data), next(data), next(data)] for _ in range(days)]  # n 行 × 3 列
gold, silver, bronze = map(sum, zip(*rows))
```

一行顶掉原来的三个计数器加三条累加语句。

最后是输出：题面要的 4 个整数是 $G$、$S$、$B$ 和 $G+S+B$。
第四个量是前三者之和，不是矩阵的第 4 列（矩阵只有 3 列），
所以它由已经算出的三个列和相加得到，不必在读取时另开一个累加器：

```python
print(gold, silver, bronze, gold + silver + bronze)
```

整套流程只消费 `data` 一遍，没有回头重读，也没有为了“第四个数”多存一份数据。

### 复杂度

- 时间复杂度：$O(n)$。读入 $3n+1$ 个数值，转置后三次求和各扫描 $n$ 个元素；
  没有嵌套的两层循环。$n \le 17$ 时实测约 0.015 s/组（主要开销是解释器启动），限额 1000 ms。
- 空间复杂度：$O(n)$。`rows` 保存 $n$ 个三元组，共 $3n$ 个整数；
  其余是常数量级的局部变量。$n \le 17$ 时峰值约 14.5 MB，远低于 128 MB。

## 总结

- 本题的计算任务是**按列求和**：把 $n$ 天的三列数据分别累加，再输出三列之和。
- 三列彼此独立，因此可以用 3 个（或一组）累加器分别处理，读入时只需逐行消费 token。
- Python 里“按列求和”的惯用写法是 `map(sum, zip(*rows))`：
  `zip(*rows)` 是矩阵转置，`map(sum, ...)` 对每一列求和；这正是 C++ 参考实现中
  `a[0][k] += a[i][k]` 那句“按列汇总”的表达式版本。
- 总奖牌数是三个列和相加，不是输入中的第四列，这一点最容易看错题意。
- 验证：数据仓 10 组真实数据（$n$ 覆盖 1、2、3、4、6、8、10、11）全部 PASS；
  另有 $n=1$、当天奖牌全为 0 的手工边界检查。
