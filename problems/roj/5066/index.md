## 形式化题目

给定三个整数 $a$、$b$ 和 $c$，求这三个整数的和 $a + b + c$。

数据范围未在题目中显式声明。实际测试点中，单个数字的最大绝对值为 $10^6$，三个这样的数字之和不会超过 $3 \times 10^6$。

## 正解

### 思路

这是一道非常基础的语法题，核心在于基本的输入输出和算术运算（加法）的使用。
只需要从标准输入按顺序读入三个整数，将其相加后输出即可。

题目未明确给出数值范围。在处理此类范围不明的问题时，通常有两种选择。由于实测最大单值绝对值为 $10^6$，则三项之和至多 $3 \times 10^6$，该范围完全被 32 位有符号整数（`int`，范围约 $\pm 2 \times 10^9$）包容，因此本题**真实数据 `int` 亦不溢出**。尽管如此，采用 64 位有符号整数（如 C++ 中的 `long long`）来完成计算属**规范 / 防御性**选择，而非正确性要求，这是在竞赛中针对「未明示范围的求和题」时的一种良好习惯。

## 总结

- **算法与复杂度**：读入 $a, b, c$，输出 $a+b+c$，时空复杂度均为 $\mathcal{O}(1)$。
- **数据规模实勘**：真实数据中，单个值的最大绝对值为 $10^6$，三个数的和绝对值最大不超过 $3\times10^6$。10 个测试点中，负数共有 14 个。输出格式均为「一个十进制整数 + 单个换行符 `\n`」，无多余行尾空格和回车。
- **关于 `long long` 的使用**：根据项目“题目数据默认 `long long`”的技能点指引，本题代码采用了 `long long`。但这纯粹是一个**规范问题**，不是正确性问题，真实数据中最高达到 $3\times10^6$ 的和距离 `int` 的上界 $2^{31}-1$ 有着近 715 倍的余量。
- **溢出临界点锚定**：三数和越出 `int` 的条件为每项分摊 $\ge 715827883$：
  - $715827882 \times 3 = 2147483646 \le \text{INT\_MAX}$（安全）
  - $715827883 \times 3 = 2147483649 > \text{INT\_MAX}$（溢出）
  - 本题无溢出、无整除/浮点/排序相关语义风险。
- **UB的“双层表象”**：在使用包含三个 `INT_MAX` 相加的 V9 探针验证 C++ `int` 版本溢出行为时，发现其结果既在后台显形（通过 UBSan 会提示 `runtime error: signed integer overflow`），又在前端输出表现为**静默回绕**。例如三个 `INT_MAX` 错误地输出 `2147483645`，且程序退出码 `rc=0`，不会引发显式的崩溃。因此对于未开 UBSan 的本地测试，溢出极其隐蔽。而提供的主解 `long long` 版本在全部真实点中通过了无任何报错的洁净运行。
- **对比与验证机制有效性**：
  - 当实现被故意改错（如 `+ 1`）时，`check_bytes` 与 `check_new_analysis` 两条自动化检查路径均报告 0/10 的惨烈失败，这反证了两个验证闸门不是在空转，尤其是对 `check_new_analysis` 的规则重要补充：它确实对空白差异免疫，但对**实质内容错误**是完全有效的捕捉器。
  - **幸存点陷阱**：在把代码错误地改成 `a - b - c` 的反事实测试（V1）中，除了 `p9` 这个点以外全部失败。`p9`（输入 `1000000 1000000 -1000000`）因为 $1000000 - 1000000 - (-1000000)$ 恰好等于真实答案 $1000000$，在这个特定错误逻辑下成了幸存点。这个点完全丧失了区分度，警示出题及测试数据的构造要有针对性。
- **异源多维验证**：不仅通过改变加法实现顺序或调用 Python `sum()`，还在随机生成的 600 组 $[-10^9, 10^9]$ 样本，以及穷举的 $[-6, 6]^3$ 全 2197 组数据中都达成 0 冲突，确证加法的纯正性。
- 跨语言一致性排查显示：本题类型转换无风险（无 cast）；不存在由于整除取模、浮点运算、排序稳定性带来的差异。
