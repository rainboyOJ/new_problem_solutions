## 形式化题目

给定 $10$ 个整数 $h_i$（苹果离地高度）和 $1$ 个整数 $h$（陶陶伸直手能到的最大高度）。

苹果 $i$ 能被摘到，当且仅当

$$h_i \leqslant h + 30$$

求能被摘到的苹果个数。

样例 `100 200 150 140 129 134 167 198 200 111` 与 `110`：有效高度为 $110 + 30 = 140$，满足 $h_i \leqslant 140$ 的是 $100, 140, 129, 134, 111$，共 $5$ 个，与样例输出一致。

## 正解

### 思路

陶陶有两个"够高"的手段：直接伸手（高度 $h$），或者踩上 $30$ 厘米的板凳再伸手（高度 $h + 30$）。所以每个苹果只需要做一次判定：它的离地高度是否 $\leqslant h + 30$。

```text
伸手高度 h ─┐
            ├─> 能碰到的最大高度 = h + 30
板凳  30  ─┘

苹果 i 能摘到  ⇔  h_i ≤ h + 30
```

于是整道题变成两步：

1. 读入 $10$ 个苹果高度和伸手高度，先算出"够得着线" $\text{reach} = h + 30$；
2. 扫一遍苹果高度，数出有多少个 $h_i \leqslant \text{reach}$。

不需要排序、不需要分类讨论"直接够 / 踩凳够"——板凳只影响"够得着线"这一个数字。朴素到优化这里没有量级变化：$10$ 个苹果一遍扫描本来就是正解，$O(10)$ 常数规模，重点在于把"两种方式取最好"正确合并成一条判定不等式。

判定用「碰到即掉」的规则，所以"高度恰好等于够得着线"也算摘到，不等式必须取 $\leqslant$ 而不是 $<$。把板凳高度命名成常量 `STOOL`，公式 $h + 30$ 在代码里就以 `reach = h + STOOL` 的形式出现，含义一目了然。

## 总结

- 这是一道典型的"翻译题"：把生活描述（踩板凳再试试）翻译成一条判定不等式 $h_i \leqslant h + 30$，剩下的就是计数。
- 关键观察只有一个：板凳的效果是"够得着线整体抬高 $30$ 厘米"，不需要分别讨论两种方式。
- 边界注意"碰到即摘到"，判定取 $\leqslant$；板凳高度 $30$ 命名为常量，避免魔法数字。
- Python 实现里 `sum(height <= reach for height in heights)` 把「扫描 + 判定 + 计数」压成一个表达式，`bool` 参与求和即 $0/1$ 计数，这是 Pythonic 计数的惯用写法。
- 验证：真实测试数据 10/10 全部 PASS（约 0.016 s/组，远低于 1000 ms 限时）。
