## 形式化题目

给定一个包含 $n$ 个整数的序列 $a_1, a_2, \dots, a_n$，要求按照 $a_n, a_{n-1}, \dots, a_1$ 的顺序输出这些整数。

**数据范围**
- 整数个数 $n \le 100$。
- 输入数据未指明具体的数值范围。根据实际数据点观测，存在负数以及到达 `int` 范围极值的数据。**具体地：`problem10.in` 同时含 `-2147483648`（`INT_MIN`）与 `2147483647`（`INT_MAX`）；其余 9 个点的值域在 $[-10000, 10000]$ 内。**

## 正解

### 思路

题目要求我们将输入的数字反序输出。由于题目并未直接给出数字的个数 $n$，我们需要在程序中自行判断输入是否结束。
- 在 C++ 中，可以使用 `while (cin >> x)` 来持续读入直到文件结束（EOF）。
- 对于读取到的所有数字，我们可以将其存放在一个数组（或 `std::vector`）中。读取完毕后，再从数组的最后一个元素向前遍历并输出。
- 在 Python 中，可以通过 `sys.stdin.read().split()` 一次性读取所有的输入并处理。

按项目 skill「题目数据默认 `long long`」，代码统一用 `ll` 存储（题面未指定数值范围，优先按规范写）。本题真正的坑不是数值范围，而是**一旦对读入的数做任何算术**（`abs`、取负、求和、排序键），`-2147483648` 就会让 32 位 `int` 溢出：实测 `abs(INT_MIN)` 在 `int` 下输出 `-2147483648`、在 `ll` 下输出 `2147483648`，UBSan 会直接报 “negation of -2147483648 cannot be represented”。本题只做原样回显、对数值零运算，所以 **`int` 也能过（这是规范问题，不是正确性问题）**。

### 复杂度

- **时间复杂度:** $\mathcal{O}(n)$，其中 $n$ 为输入的数字个数。需要读入 $n$ 个数字并遍历输出一次。
- **空间复杂度:** $\mathcal{O}(n)$，因为我们需要用数组存储这 $n$ 个输入数字。

## 总结

- **算法**：读到 EOF 后存入数组，逆序遍历输出即可。复杂度 $\mathcal{O}(n)$。
- **输入个数不定**：数据并未给出 $n$ 的大小（实测数据个数从 $1$ 到 $100$ 都有），因此不能只读入一定数量就结束，**必须读到 EOF**。
- **极端数据**：尽管题目里说是"整数"，没给范围，但实际测试数据里会有 `-2147483648` 这种极小值。本题只做原样回显、对数值不做任何算术，因此 32 位 `int` 实际上也不会溢出；不过按 skill 规范仍统一用 `long long`，Python 侧用自动大整数。
  - **V1 反事实实测**：如果对数字取绝对值 `abs` 或取负，`-2147483648` 会立刻导致 `int` 溢出。实测 `abs(INT_MIN)` 输出错误、UBSan 报 UB、`-ftrapv` 会直接 abort。有趣的是，**纯取负变体因补码回绕输出恰好相同**（UB 但不显形），这是一个极易忽视的陷阱。
- **跨语言语义一致性**：原实现 Python 采用字符串回显，而 C++ 采用 `int` 解析。这就存在语义差异（如对于 `+5` 或 `007` 这种 token，字符串回显会原样输出，而 C++ `int` 解析后会输出 `5` 和 `7`）。新实现统一规范为整数类型处理；另外因真实数据的 469 个 token 恰好全部规范（无 `+` 号、无前导零、无 `-0`、无小数等），所以**未显形**，这是一个很好的「潜伏 bug」案例。
- **验证强度摘要**：异源（Python 切片）对比 10/10 全过；随机对拍 500/500（含 `int32` 两极）全过；V2 字面量非硬编码（不含答案 token）；V5 去掉逆序、V1 去掉空格分支全部失败承重。
- **格式细节**：输出逐个数字以单空格分隔、行尾无多余空格，并以单个换行符结尾。
