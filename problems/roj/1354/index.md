## 形式化题目

给定一个只由圆括号 `( )` 与方括号 `[ ]` 组成的串 $s = c_1 c_2 \cdots c_n$，判断它是否是**合法括号串**：

- 每个右括号都能在它**左边**找到尚未被使用、且**类型相同**的左括号与它配对；
- 配对区间两两不交叉（不能出现 `[ ( ] )` 这种跨越）；
- 所有括号都被配对，不留落单的左括号或右括号。

答案是二值的：`OK` 表示匹配，`Wrong` 表示不匹配。串长 $n < 255$。

题面给出的两个样例（数据里用的是全角括号，但它们与 `()` `[]` 是同一个字符）：
`［（］）` 应输出 `Wrong`，`［（［］［］）］` 应输出 `OK`。理由见下一节的栈轨迹表。

## 正解

### 思路

**先看一个直觉上很像、但错的做法。** 最省事的判据是“数一数”：`(` 与 `)` 的个数相等、`[` 与 `]` 的个数也相等，
就输出 `OK`。它对样例二 `［（［］［］）］` 确实通过，但把题面样例一 `［（］）` 交给它，会输出 `OK`
（两个圆括号、两个方括号，数量都对），而正确答案是 `Wrong`。问题出在**数量相等不等于配对**：
这种写法把“谁在谁左边”“谁跟谁同类配对”两条信息全丢了。

**再补一条信息试试。** 另一个常见直觉是“括号深度”：`(` 与 `[` 让深度 $+1$，`)` 与 `]` 让深度 $-1$，
只要深度从不降到 $0$ 以下、且最终回到 $0$ 就 `OK`。这条判据在只有一种括号时完全正确
（参见 [ROJ 1353](https://roj.ac.cn/problem/1353)），但两种括号混在一起就不够用了：
对 `（］` 来说深度是 $+1$ 再 $-1$，最终为 $0$、中途也没变负，于是判成 `OK`——可它的圆括号配了方括号，显然错。

**真正的约束是“内层先闭合”。** 想清楚嵌套的本质：在 `[ ( [ ] [ ] ) ]` 里，一定是**最内层**的 `[ ]`
先配好，再去配外层的 `( )`，最后才轮到最外层的 `[ ]`。也就是说，当前所有还没闭合的左括号里，
**只有最靠右（最内层）的那一个能拿来配**。这正是“后进先出”——用一个**栈**存放尚未闭合的左括号。

为什么只能是栈顶那个？设此刻没闭合的左括号从左到右是 $L_1, \dots, L_k$（$L_k$ 最内层），
当前右括号是 $c$。若 $c$ 与 $L_j\ (j<k)$ 配对，那么排在更右边的 $L_k$ 就必须在 $c$ 左边闭合，
设它配 $c'$，于是 $L_j \cdots L_k \cdots c' \cdots c$ 形成一个“你套我、我套你”的交叉，正是题目不允许的。
所以 $c$ 的配对对象只可能是 $L_k$，即栈顶。

于是算法只有四行规则：

| 遇到的字符 | 动作 |
| --- | --- |
| 左括号 `(` 或 `[` | 压栈（连同类型一起放进去，等它对应的右括号） |
| 右括号，栈非空且**栈顶与它同类** | 弹出栈顶，这一对配对成功 |
| 右括号，栈空或栈顶是**另一类**左括号 | 立即判 `Wrong` |
| 其它字符（空格、换行等） | 忽略，不影响结构 |

预先列出“右括号 → 它唯一能配的左括号”这张表 $\{ \texttt{)} \to \texttt{(},\ \texttt{]} \to \texttt{[} \}$，
第 2、3 行就合并成一句“栈非空**且**栈顶 $=$ 表里查到的左括号”。

扫描结束后再看一次栈：**非空说明有左括号没人配**（如 `([]()`），空则通过。两类失败点——“弹空”与“扫完没空”——
恰好对应“右括号多了”和“左括号多了”。

下面用四个字符串走一遍，表里每列是“读完该字符后的栈”（栈底在左）；
为便于阅读，栈一律用折算后的半角字符书写：

| 输入 | 结果 | 逐步的栈变化 |
| --- | --- | --- |
| `［（］）` | `Wrong` | 读 `［` → `[`；读 `（` → `[(`；读 `］` → 栈顶是 `(` 不是 `[`，**失败** |
| `［（［］［］）］` | `OK` | `[` → `[(]` → `[(` → `[([` → `[(]` → `[(` → `[([` → `[(]` → `[(` → `[` → 空 |
| `[[]])` | `Wrong` | 前 4 个字符配完后栈空，再读 `)` 时**栈空弹栈**，失败 |
| `([]()` | `Wrong` | 一路都能配对，但扫完后栈里还剩 `(`，**结束非空**，失败 |

表格第一行对应题面样例一，失败点是“栈顶异类”：`］` 想配最外层的 `［`，得先跨过内层还没闭合的 `（`，
这正是被禁止的交叉。注意它的两类括号数量确实相等（各两个），所以“数个数”在这里必然误判。
第二行对应题面样例二 `［（［］［］）］`，即上表的 `[([][])]`：栈来来回回，
但每次弹出的都是栈顶那个同类左括号，最后恰好清空，所以是 `OK`。

### 复杂度

- 时间复杂度：$O(n)$。每个字符恰好被看一次，入栈、出栈、跳过都只花 $O(1)$；没有回溯，没有嵌套循环。
- 空间复杂度：$O(n)$，即栈的最大深度（最坏形如 `[[[[...`，栈深等于串长）。本题 $n<255$，
  实测峰值内存 14.6 MB（含解释器本身），远低于 128 MB 限制。

实现上有两个与算法无关但会影响正确性的输入细节：题面样例写的是**全角括号**
（`［` 是 $\texttt{U+FF3B}$，不是 ASCII 的 `[`），数据里也可能出现全角字符，
所以读入后先做一次全角→半角的折算；另外数据行是 CRLF、还可能出现空行，
空格与换行不属于括号字符，在滤波阶段被直接丢弃。

## 总结

- 判断括号匹配，看的是**配对关系**，不是数量：`［（］）` 两类括号数量都对，却不匹配。
- 两种括号必须**共用一个栈**，并检查栈顶类型；只用一个“深度”计数器分不出类型，`（］` 会误判。
- 核心不变量是“右括号只能配栈顶”，它一条就同时排除了**类型错配**和**交叉嵌套**。
- 两类失败点要分别检查：**中途弹空**（右括号多了）与**扫完栈非空**（左括号多了）。
- 只要题目里出现“某种东西必须两两配对且不能交叉”，先想栈；只有一种括号时才退化成一个计数器。
