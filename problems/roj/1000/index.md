## 形式化题目

给定两个整数 $a$ 与 $b$，求它们的和 $a+b$。

## 正解

### 思路

这道题的计算只有一步：把输入里的两个整数加起来输出，算法上没有任何可以优化的地方，也没有"先写朴素做法、再消除瓶颈"的空间——再写一个暴力版本只会得到一模一样的代码。

因此本题真正要练的是**把输入文本变成整数**这条链路。以样例 `1 2` 为例：

| 步骤 | 表达式 | 结果 |
| --- | --- | --- |
| 一次读入整份输入 | `sys.stdin.buffer.read()` | `b'1 2\n'` |
| 按空白切分 | `.split()` | `[b'1', b'2']` |
| 逐个转成整数 | `map(int, ...)` | `1`、`2` |
| 解包到两个名字 | `a, b = ...` | `a = 1, b = 2` |
| 相加输出 | `print(a + b)` | `3` |

这张表说明了为什么用 `split()` 而不是手工找空格：按空白切分能把行尾换行、连续空格、甚至"两个数分两行写"都统一处理成同一个 token 序列，代码不必关心输入的具体排版。写成 `a, b = ...` 而不是 `nums = list(...)` 再取下标，则是把"输入恰好是两个整数"这条格式约定直接写进代码：万一 token 数量不是两个，程序会立刻报错，而不是悄悄算出错误答案。

题面没有给出数据范围；测试数据里两个加数都是 $1 \leqslant a,b \leqslant 10^6$。C++ 用 `int` 足够，Python 的 `int` 本身就是任意精度整数，所以即便加数远大于 32 位也不会溢出，不需要做任何额外处理。

## 总结

- 本题是"读入 $\to$ 计算 $\to$ 输出"的最小版本，算法上没有优化空间。
- Python 读固定个数的整数记住这条线：`read()` 读全部 $\to$ `split()` 切分 $\to$ `map(int, ...)` 转换 $\to$ 解包。
- 用元组解包而非下标取值，可以让"输入格式恰好是两个整数"的约定在代码里显式可见。
- Python 的整数是任意精度的，本题不必考虑溢出。
