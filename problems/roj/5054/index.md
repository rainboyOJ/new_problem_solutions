## 形式化题目

给定一个整数 $a$。
若 $1 < a < 100$，输出 `yes`（加一个换行符，共 4 字节）；若不满足条件，则不产生任何输出（即 0 字节输出）。
输入数据范围：$a \in [-2147483648, 2147483647]$，即 32 位有符号整数的全域。

## 正解

### 思路

本题是一道最基础的条件分支判断题，算法核心就是读入整数 $a$，判断 `a > 1 && a < 100` 是否成立。成立输出 `yes`，否则**什么都不输出**。

在实现时，有两个极易踩坑的关键点需要注意：

1. **严格区间**：题目所指的区间为开区间 $(1, 100)$，在整数域下等价于 $2 \le a \le 99$。对于边界值 $a=1$ 和 $a=100$，都必须处于假分支中。
2. **0 字节空输出**：题目描述中的「否则不输出」，意味着在假分支里不仅不能输出 `no`，连换行符也不能输出。这是一个硬性要求，许多人在假分支中习惯性输出空行，从而导致 Wrong Answer（见下方总结分析）。

对于变量类型选择，输入的极值覆盖了 32 位有符号整数的整个范围（`INT_MIN` 与 `INT_MAX`）。虽然 `int` 也不会溢出，但我们按照常规规范统一使用 `long long`（`ll`）来接收，这样能天然防范很多潜在越界风险，是更为稳妥和规范的选择。

## 总结

- **V8 验证：开区间 $(1,100)$ 被相邻候选排除唯一确定**
  实测各变体的失败点集合完全不同，四个边界点 $1, 2, 99, 100$ 恰好构成了完美的判别器。唯一能在测试集上 10/10 通过的是严格区间写法：
  | 变体 | 失败点 | got / want |
  |---|---|---|
  | `a >= 1 && a <= 100`（宽松） | **`p2`, `p5`** | `p2(a=1)` 和 `p5(a=100)` 错误输出 `yes\n`，应为 `b''` |
  | `a >= 1 && a < 100`（左闭右开） | **`p2`** | `p2(a=1)` 错误输出 `yes\n`，应为 `b''` |
  | `a > 1 && a <= 100`（左开右闭） | **`p5`** | `p5(a=100)` 错误输出 `yes\n`，应为 `b''` |
  | 删除条件判定（全为真） | **`p2, p5, p7, p8, p9, p10`** | 统统输出 `yes\n`，应为 `b''` |
  | **`a > 1 && a < 100`（严格）** | **$\emptyset$（0 失败）** | **唯一同时 10/10 的正解** |

- **不满足时输出 0 字节的陷阱与假绿灯实证**
  当条件不满足时，要求输出 0 字节。测试点 `p2, p5, p7, p8, p9, p10` 的正确答案均为 0 字节。
  如果在 else 分支习惯性地打一个换行，会在上述点失败（got `b'\n'` / want `b''`）。
  **值得警惕的是，本仓库的 token 级比较器（如 `got.split() == want.split()`）会对该 bug 完全免疫，产生 10/10 PASS 的“假绿灯”**。必须使用 `check_bytes.py` 逐字节交叉确认，才会发现该代码在字节级只有 4/10 PASS。
  此类同族要求 0 字节输出的题目还包含：`5019`、`5029`、`5032`、`5044`、`5053`，均应特别防范。

- **数值范围与规范**
  实测数据的最小值恰为 `INT_MIN`（$-2147483648$），最大值恰为 `INT_MAX`（$2147483647$）。题面虽然未限正负，但表明覆盖了有符号 32 位整数的全域。两个极值本身均在 `int` 表示范围内，因此 `int` 也不会溢出。这里统一按规范使用 `long long` 是为了养成良好习惯，而非为了修 bug。

- **验证强度摘要**
  异源的两种不同机制（区间表达 / 集合查表）的答案逐字节 10/10 一致。
  全范围扫描：穷举 $609$ 值（$[-300, 300]$ 全枚举 + $8$ 个 $2^{31}/2^{63}$ 邻域）、$300$ 个随机 $32$ 位值以及 $12$ 个边界值，产生的输出 0 分歧。
  V2 代码无硬编码答案风险，字面量仅有 `{0, 1, 100}`，不包含答案对应的任意数值。

- **跨语言 `T9` 清单**
  - 类型转换：**无风险**。C++ `long long` ↔ Python 任意精度，无显式转换问题。
  - **溢出**：**有 ⇒ 已由 `long long` 消除风险**。虽然边界点不会让 `int` 溢出，但 `ll` 保证了扩展场景下的绝对安全。
  - 整除 / 取模：**无风险**。无对应操作。
  - 浮点格式化：**无风险**。无对应操作。
  - 排序稳定性 / 字典序：**无风险**。无对应操作。
