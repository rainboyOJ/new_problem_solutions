## 形式化题目

给定三个整数 $a, b, c$（可能为负），输出三者中的最大值 $\max(a, b, c)$。

样例 `10 20 56` 中 $56 > 20 > 10$，故输出 $56$。

## 正解

### 思路

这道题的输入长度固定、计算只有"三个数取最大"一步，**没有任何值得单独教一层暴力
的优化空间**——写一个暴力版本只会得到与正解几乎逐字相同的代码，所以本文直接给做法，
把重点放在两件事上：把输入文本变成三个整数，以及**用 Python 的方式表达"取最大"**。

读入链路沿用 [ROJ 1000](../1000/index.md) 的写法，以样例 `10 20 56` 为例：

| 步骤 | 表达式 | 结果 |
| --- | --- | --- |
| 一次读入整份输入 | `sys.stdin.buffer.read()` | `b'10 20 56\n'` |
| 按任意空白切分 | `.split()` | `[b'10', b'20', b'56']` |
| 逐个转成整数 | `map(int, ...)` | `10`、`20`、`56` |
| 解包到三个名字 | `a, b, c = ...` | `a=10, b=20, c=56` |

表格里的 `split()` 按任意连续空白切分，行尾换行、多余空格都被归一化；
写成 `a, b, c = ...` 的解包则把"输入恰好是三个整数"这条格式约定直接写进代码——
token 数量不是三个会立刻抛 `ValueError`，而不是悄悄取错值输出错误答案。

"取最大"这一步，最容易想到的是模仿 C++ 的比较链：参考实现用两个 `if`，
先让 `m` 取 $a, b$ 中较大者，再用 $c$ 尝试更新 `m`。翻译成 Python 的条件表达式
就是 `m = a if a > b else b` 再 `m = c if c > m else m`——正确，但"二元取大"
这个模式重复写了两遍，还引入了中间变量 `m`。

能一步写完的依据是 $\max$ 满足**结合律**：

$$\max(\max(a, b),\, c) = \max(a, b, c)$$

所以链式的两次二元比较与一次三元取最大完全等价。而 Python 把"取最大"做成了
**内建的可变参数函数**：`max(a, b, c)` 直接接受任意多个位置参数，
不需要先打包成列表（写 `max([a, b, c])` 反而多建一个列表）。于是归约压成一个
表达式 `max(a, b, c)`，中间变量 `m` 与两遍比较模式都消失。

两点细节说明这个写法是安全的：

1. **负数不需要特判**：`int` 解析负号（`int(b'-766')` 得 `-766`），
   比较运算对负数、零语义一致；真实数据里大量两负一正、三数接近的组，
   行为完全一样。
2. **相等不需要特判**：若最大值出现多次，`max` 返回其中任意一个，
   数值相同，输出无差别。

### 复杂度

- 时间复杂度：$O(1)$，输入长度固定，一次切分、三次整数转换、两次比较、一次输出。
- 空间复杂度：$O(1)$，输入字符串、token 列表与三个整数都是常数大小。

## 总结

- "三个数取最大"没有算法瓶颈，重点是表达：链式两次二元比较（C++ 的 `if` 链）
  由 $\max$ 的结合律折叠成一次 `max(a, b, c)` 调用。
- Python 的 `max` 是可变参数内建，直接传 $a, b, c$，不要先打包成列表。
- 读入链路一行完成：`read()` 读全部 $\to$ `split()` 切分 $\to$ `map(int, ...)`
  转换 $\to$ 元组解包命名，token 数不是 3 会立刻报错而不是输出错答案。
- 负数、相等、32 位边界都无需特判：`int` 任意精度且天然解析负号。
- 验证：真实测试数据 10/10 全部 PASS（约 0.02 s/组，远低于 1000 ms 限时）。
