## 形式化题目

给定一个不为 0 的数的书写串 $s$（单独一个 token，可能以 `-` 开头，可能含小数点），要求输出串 $t$，满足：

- $t$ 是负数的书写，即以 `-` 开头；
- 去掉符号后的数字部分与 $s$ 的数字部分逐字符相同（小数位、尾随零原样保留）。

等价地说：$s$ 以 `-` 开头时 $t = s$，否则 $t$ 为 `-` 拼接 $s$。变换只作用于符号，不触碰数字。

## 正解

### 思路

看到"输出负数"，第一反应往往是数值做法：

```python
x = float(input())
print(-abs(x))
```

它能过掉本题全部评测数据，却是一个陷阱：`float` 往返会改写**书写格式**。`"1.50"` 会变成 `-1.5`（尾随零丢失）；题面没有给数值范围，21 位有效数字的数远超 `float` 的往返精度，输出直接变成科学计数法。本题数据恰好都是 6~9 位有效数字、能被 `float` 无损表示，数值法只是侥幸没被踩中。

正确的视角藏在题面第一句话里：**"负数就是在正数前加负号"**——这本身就是一个词法规则，说的是符号字符的操作，与数值大小无关。于是规则只有两条：输入已以 `-` 开头，它已是负数书写，原样输出；否则在最前面补一个 `-`。两种情况共用同一条不变式：数字部分逐字符不动。

下面表格展示这条分派规则在两个样例和一个真实评测数据上的效果：

| 输入 token | 首字符 | 输出 |
| --- | --- | --- |
| `1` | `1` | `-1` |
| `-3.01` | `-` | `-3.01` |
| `198510.0` | `1` | `-198510.0` |

前两行是题面样例；第三行取自真实评测数据，注意尾随的 `.0` 被原样保留——这正是字符串分派与数值往返的本质区别。同时要小心两个反向错误：对负数再取相反数会输出 `3.01`，无脑拼 `'-' + s` 会输出 `--3.01`，都与样例 2 不符。

实现上，`sys.stdin.read().strip()` 读入唯一 token 并剥掉首尾空白（等价于 C++ 标准程序的 `scanf("%s")`），存成 `num_str`；`already_negative = num_str.startswith('-')` 把符号判定命名成局部变量，再用条件表达式 `num_str if already_negative else '-' + num_str` 完成分派——两个分支共享 `num_str`，数字部分天然不动。

### 复杂度

- 时间复杂度：$O(L)$，$L$ 为输入串长度；读入、`strip()`、`startswith()` 与拼接各扫描常数次，与 C++ 版逐 token 读写同阶。
- 空间复杂度：$O(L)$，只保存输入串与至多多一个字符的结果串。

## 总结

这道题考的是分清**数值运算**与**书写形式**：题面要的是"负数形式的原样书写"，答案就藏在"负数就是在正数前加负号"这句定义里——一个首字符判断加一次字符串拼接，不需要也不应该经过 `float`。已为负数时保持原样、为正时补号，数字部分逐字符不变，`-0` 的歧义又被"输入不为 0"排除。实测 10 个评测点全部一致，单点约 0.02 s、峰值内存 14.6 MB，相对 1000 ms / 128 MB 的限制十分宽裕。
