## 形式化题目

给定长度为 $N$ 的数列 $A_1, A_2, \ldots, A_N$，需要在线处理 $M$ 条指令，
指令只有两种：

- 查询：给出 $x, y$，求 $\displaystyle \max_{l \leqslant i \leqslant j \leqslant r}\ \sum_{t=i}^{j} A_t$，
  其中 $l = \min(x, y)$、$r = \max(x, y)$；
- 修改：给出 $x, y$，令 $A_x \leftarrow y$。

注意子段必须**非空**：$i \leqslant j$，所以当区间内全是负数时，
答案是该区间内的最大单元素值，而不是 $0$。

## 暴力解法

### 思路

约束是 $N \leqslant 500000$、$M \leqslant 100000$、$|A_i| \leqslant 1000$，时限 1 秒。
先看最朴素的做法：查询就是「最大连续子段和」的经典问题，扫一遍用 Kadane 在线求出：

```text
best = -inf ; cur = -inf
for v in A[l..r]:
    cur  = max(v, cur + v)    # 要么从 v 重新开始, 要么把 v 接到前面
    best = max(best, cur)
```

初值取 $-\infty$ 而不是 $0$，保证选出的子段非空。

### 复杂度

- 时间：一次查询 $O(r - l + 1)$，$M$ 次查询合计
  $O\!\left(\sum (r - l + 1)\right)$，最坏 $O(NM) = 5 \times 10^{10}$ 次加法。
- 空间：$O(1)$ 额外空间（不算原数组）。

### 瓶颈

慢只是表象，真正的瓶颈是**区间答案不可合并**：

$$\text{best}(l, r) \neq \max\bigl(\text{best}(l, m),\ \text{best}(m + 1, r)\bigr)$$

因为最优子段可能**跨越中缝** $m$，它的一部分在左半、一部分在右半。
正因如此，$\text{best}$ 既不能做前缀和相减，也不能直接挂到线段树上。
要提速，必须先想办法把「区间答案」补齐成可合并的信息。

## 正解

### 思路

#### 第一步：给区间补上两个贴边的量

跨越中缝的子段一定形如「左段的一个后缀 + 右段的一个前缀」。于是我们对每个区间
$[l, r]$ 记录四元组：

| 量 | 定义 | 含义 |
| :-- | :-- | :-- |
| $\text{sum}$ | $\sum_{t=l}^{r} A_t$ | 整个区间之和 |
| $\text{pre}$ | $\max_{l \leqslant j \leqslant r} \sum_{t=l}^{j} A_t$ | 必须**贴着左端**的子段最大和 |
| $\text{suf}$ | $\max_{l \leqslant i \leqslant r} \sum_{t=i}^{r} A_t$ | 必须**贴着右端**的子段最大和 |
| $\text{best}$ | $\max_{l \leqslant i \leqslant j \leqslant r} \sum_{t=i}^{j} A_t$ | 题目要的答案 |

`pre` 和 `suf` 的「贴边」约束不是装饰：只有贴着边，两块拼起来才是连续的一段。

#### 第二步：写出合并式

设左段 $L$、右段 $R$，则

$$\text{sum} = L.\text{sum} + R.\text{sum}$$

$$\text{pre} = \max\bigl(L.\text{pre},\ L.\text{sum} + R.\text{pre}\bigr)$$

$$\text{suf} = \max\bigl(R.\text{suf},\ R.\text{sum} + L.\text{suf}\bigr)$$

$$\text{best} = \max\bigl(L.\text{best},\ R.\text{best},\ L.\text{suf} + R.\text{pre}\bigr)$$

以 `pre` 为例：贴着左端的前缀要么没越过中缝（最优是 $L.\text{pre}$），
要么整段吃掉 $L$ 再加 $R$ 的一个前缀（最优是 $L.\text{sum} + R.\text{pre}$）。
`best` 的第三项 $L.\text{suf} + R.\text{pre}$ 正是「跨越中缝」的最优解。
四个量互相封闭——合并结果仍然只需要这四个量，不依赖区间长度，所以这个运算可以
在树上任意嵌套。

用样例 $A = [1, 2, -3, 4, 5]$ 按 `main.py` 的补位方式补到 8 个叶子，自底向上逐层算出的
四元组如下（数字由 `problem-analysis-workspace/viz_render.py` 打印，与代码一致）：

| 层 | 节点 | 区间 | sum | pre | suf | best |
| :-: | :-: | :-: | :-: | :-: | :-: | :-: |
| 根 | #1 | [1,8] | 9 | 9 | 9 | 9 |
| 1 | #2 | [1,4] | 4 | 4 | 4 | 4 |
| 1 | #3 | [5,8] | 5 | 5 | 5 | 5 |
| 2 | #4 | [1,2] | 3 | 3 | 3 | 3 |
| 2 | #5 | [3,4] | 1 | 1 | 4 | 4 |
| 2 | #6 | [5,6] | 5 | 5 | 5 | 5 |
| 2 | #7 | [7,8] | 0 | 0 | 0 | 0 |
| 叶子层 | a1 | [1,1] | 1 | 1 | 1 | 1 |
| 叶子层 | a2 | [2,2] | 2 | 2 | 2 | 2 |
| 叶子层 | a3 | [3,3] | -3 | -3 | -3 | -3 |
| 叶子层 | a4 | [4,4] | 4 | 4 | 4 | 4 |
| 叶子层 | a5 | [5,5] | 5 | 5 | 5 | 5 |
| 叶子层 | 补位叶 | [6,6] | 0 | 0 | 0 | 0 |
| 叶子层 | 补位叶 | [7,7] | 0 | 0 | 0 | 0 |
| 叶子层 | 补位叶 | [8,8] | 0 | 0 | 0 | 0 |

叶子的四元组全是同一个数 $a_i$：单元素区间的 sum、pre、suf、best 都只能是它本身。最底层多出来的三个「补位叶」填 0，它们占据的整块区间都超出 $[1,5]$，任何查询都选不到，所以填什么都不会影响答案。倒数第二层里，节点 $[3,4]$ 的 $\text{pre}=1$ 而 $\text{suf}=4$：贴左的前缀最优是 $-3+4$，贴右的后缀最优是 $4$，同一个区间里两个贴边量可以完全不同，这正是「贴边」含义的直接体现。

#### 第三步：搬进线段树

线段树只要满足「任意区间的答案 = 覆盖它的那些节点依次合并」，而上面的合并式满足
结合律，于是：

- **建树**：叶子填 $(A_i, A_i, A_i, A_i)$，内部节点自底向上 push up。
  叶子层长度补到 $\geqslant N$ 的最小 $2$ 的幂 $B$；补位叶子填四元组 $(0,0,0,0)$，
  因为它所在的整块区间都超出 $[1, N]$，任何查询都选不到它。
- **修改**：改叶子后沿父链 push up，$O(\log N)$。
- **查询**：把 $[l, r)$ 自底向上拆成 $O(\log N)$ 个节点。

#### 第四步：查询的左右两个暂存区

自底向上分解时，收下的节点会**分别**属于两个方向：左端点决定「左暂存区」，
右端点决定「右暂存区」。下面是样例数组补到 8 个叶子后的线段树区间划分
（$[6,6]$、$[7,7]$、$[8,8]$ 是补位叶，它们不参与任何答案）：

![样例数组的线段树：区间划分与查询 [2,5] 取到的节点](./segment-tree.svg)

查询 $[2, 5]$ 时依次收下 $[2,2]$、$[5,5]$、$[3,4]$ 三个节点，推演过程是：

```text
左吞 [2,2] → 左暂存区 sum=2  pre=2  suf=2  best=2
右吞 [5,5] → 右暂存区 pre=5  best=5
左吞 [3,4] → 左暂存区 sum=3  pre=3  suf=4  best=4
收尾        → max(best=5, lu+rp=9) = 9
```

左暂存区吞下的顺序是 $[2,2]$、$[3,4]$，说明自底向上分解给出的节点一定是
**从左到右**排列的；左暂存区的 `suf` 变成 4，是因为它贴着右侧的 $[3,4]$ 全取了。
最后 $lu + rp = 4 + 5 = 9$ 把两段连起来，正好对应子段 $A_4 + A_5$。

关键在于**左暂存区整体在右暂存区左边、不能调换顺序**：要合并两块必须写成
$L$ 在前、$R$ 在后。而合并结果的 $\text{best}$ 恰好只用到三项，即
「左段的 best」「右段的 best」「跨越中缝的 $L.\text{suf} + R.\text{pre}$」，
所以收尾不需要真的构造出完整四元组：

$$\text{答案} = \max\bigl(L.\text{best},\ R.\text{best},\ L.\text{suf} + R.\text{pre}\bigr)$$

上面那次查询里 $L.\text{suf} = 4$（对应 $[3,4]$，正好贴着左暂存区右端）、
$R.\text{pre} = 5$，交叉项 $9$ 就是 $4 + 5$。

用题面样例把整条输出对一遍：

| 指令 | 拆出的节点 / 效果 | 答案 |
| :-- | :-- | --: |
| `1 2 3` | 左吞 $[2,2]$，右吞 $[3,3]$ | $\max(2,\ -3,\ 2+(-3)) = 2$ |
| `2 2 -1` | 把 $a_2$ 改成 $-1$，沿父链 push up | — |
| `1 3 2` | 交换成 $[2,3]$，同上两片叶子 | $\max(-1,\ -3,\ -4) = -1$ |

后一行说明了两件事：$x > y$ 必须先交换；当区间全为负数时，答案只能是
「贴边的单个元素」$-1$（$\text{best}$ 用 $L.\text{best} = -1$ 胜出，
交叉项 $-4$ 落选）。若允许空段，这里会错误地输出 $0$。

把节点 $C$ 并入暂存区时必须用**旧值**，两侧都一样：

```text
# C 并入左暂存区（C 在暂存区右边）
new_suf  = max(C.suf,  C.sum + old_suf)
new_best = max(old_best, C.best, old_suf + C.pre)   # 这里也是 old_suf

# C 并入右暂存区（C 在暂存区左边）
new_pre  = max(C.pre,  C.sum + old_pre)
new_best = max(old_best, C.best, C.suf + old_pre)   # 同理用 old_pre
```

若先更新了 `suf`（或 `pre`）再用新值算 `best`，交叉项就变成「两段的后缀拼在一起」
（或「两段的前缀拼在一起」），区间中部的元素会被重复计入，答案偏大。
代码里用局部变量 `u`（左）和 `p`（右）先存下旧值，就是为了这个。

最后，$x > y$ 时先交换再查询；子段非空由叶子值和初值 $-\infty$ 共同保证——
暂存区空的时候 $\text{best}$ 取 $-\infty$，所以它永远不会冒充一个真实答案。

实现说明：

- `NEG = -(1 << 60)` 是空区间的哨兵。答案最小可能是 $-1000 \times 500000 = -5 \times 10^8$，
  比 $-2^{60}$ 大得多，所以 $-\infty$ 不会被真实答案顶替。
- 节点 $p$ 的四个量存在数组槽位 `4p, 4p+1, 4p+2, 4p+3`（依次为 sum/pre/suf/best），
  左孩子 `2p` 的起点就是 `8p`。用 `array('q')` + `memoryview` 是为了在 128 MB 内存
  限制下存下 $8 \times B$ 个 64 位整数。
- `build_leaves` 与 `update` 里的合并式是同一段，各自内联展开而没有抽成函数：
  最坏情况 $10^5$ 次修改 $\times 19$ 层，Python 的函数调用开销不可忽略。
- `query` 收尾那两行没有用暂存区的 `sum`，因为 $\text{sum}$ 不参与最终答案；
  同理右暂存区只需要维护 `pre`/`best` 两个量，不需要 `suf` 和 `sum`。

### 复杂度

- 建树 $O(N)$：自底向上处理 $2B - 1$ 个节点。
- 单次修改 $O(\log N)$，单次查询 $O(\log N)$（分解出 $O(\log N)$ 个节点，每次 $O(1)$ 归并）。
- 总计 $O(N + M \log N)$，空间 $O(N)$，与标准 C++ 正解同阶。

## 总结

- 最大连续子段和不能直接相减或取 $\max$，是因为最优子段可能跨越中缝；
  补上**贴左的 `pre`** 和**贴右的 `suf`** 之后，跨越中缝的候选
  $L.\text{suf} + R.\text{pre}$ 就能被显式表达，四元组因此封闭、可结合。
- 有了结合律，单点修改 + 区间查询就落在标准线段树上：修改沿父链 push up，
  查询把区间拆成节点后归并。
- 两个容易写错的点：查询的左右暂存区在树上并不相邻，收尾只能取
  $\max(\text{best}, L.\text{suf} + R.\text{pre})$；归并时 `best` 必须用
  暂存区的**旧** `suf`/`pre`，否则中部元素被重复计算。

从建模到答案的完整路线：

```text
            区间最大连续子段和
                    |
                    v
      一个区间只要 4 个量: sum / pre / suf / best
                    |
                    v
      合并: pre  = max(L.pre, L.sum + R.pre)
            suf  = max(R.suf, R.sum + L.suf)
            best = max(L.best, R.best, L.suf + R.pre)
                    |
                    v
            线段树: 叶子 = (a, a, a, a)
                    |
        +-----------+-----------+
        v                       v
  修改: 改叶子            查询: 自底向上拆成若干节点
        沿父链 push up          落进左右两个暂存区
                                max(best, lu + rp)
```

图中第一层是题目要求的目标；第二层说明「一个区间需要携带哪些信息才能被合并」，
这是全题唯一的建模决定；第三层是三个合并式，其中 `best` 的第三项来自跨越中缝
的子段；第四层把合并式交给线段树，左边是修改路径，右边是查询路径。
查询末尾的 $\max(\text{best}, \text{lu} + \text{rp})$ 提醒读者：
两个暂存区是有先后顺序的（左段在前、右段在后），而收尾只需要合并结果的
$\text{best}$ 这一项，不必真的拼出完整四元组。
