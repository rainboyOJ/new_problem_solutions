## 形式化题目

给定两个十进制串 $A = a_{n-1}\cdots a_1a_0$ 与 $B = b_{m-1}\cdots b_1b_0$，其中
$n, m \leqslant 200$，$a_i$ 与 $b_i$ 都是 `0` 到 `9` 的字符，且两串**可能带前导 `0`**。
求 $A$ 与 $B$ 的算术和，并输出其**不含多余前导 `0`** 的十进制表示。

形式化地，令进位 $c_0 = 0$，对 $i = 0, 1, 2, \dots$ 定义

$$s_i = a_i + b_i + c_i,\qquad \text{答案第 } i \text{ 位} = s_i \bmod 10,\qquad c_{i+1} = \left\lfloor \frac{s_i}{10} \right\rfloor$$

其中越界位取 $0$。这就是竖式加法：低位向高位单向传递进位，每位只依赖低位。

## 正解

### 思路

**为什么不能直接存。** 一位十进制数需要约 $3.32$ bit，$200$ 位约 $665$ bit；而 64 位整数
的上限 $2^{64}-1 \approx 1.8 \times 10^{19}$ 只有 $20$ 位。所以 `long long` 装不下，
浮点会丢精度。题目本身已经说明"必须自己处理进位"。

**朴素做法。** 把两个串补 `0` 对齐到等长，再逐位相加并把进位带到下一位。这是最直接的
写法，题面自带的 C++ 标准程序就是这么做的：`a[210]`、`b[210]`、`c[210]` 三个数组，
`str1 = "0" + str1` 循环补零，然后 `c[lenc] = a[lenc] + b[lenc] + x` 一位一位算。
它是对的，但写起来有三个容易出错的地方：

1. **对齐**：两个数位数不同，要先补零补到等长（多一次长度比较和一趟字符串构造）。
2. **进位不能丢**：循环跑完后还要再检查一次最高位是否产生新进位；漏掉就会把
   $999 + 1$ 算成 `000`。
3. **去前导 `0`**：题面明确允许输入带前导 `0`，输出又不能有；而且 $0+0$ 这种输入如果
   直接去掉所有 `0`，会输出一个空行。

**瓶颈分析。** 这里**没有可以消除的算法瓶颈**：每个数字至少要读一次，$O(n+m)$ 就是
下界，不存在"优化到更优复杂度"的空间。所以"优化"的方向是把上面三个易错点在实现层面
直接消掉，而不是换算法。

| 易错点 | 消法 |
| --- | --- |
| 补零对齐 | **不补零**。用双指针 `i`、`j` 分别从两串末尾起步，越界的一侧按 $0$ 参与运算 |
| 循环外补进位 | 把 `carry` **写进循环条件**：`while i >= 0 or j >= 0 or carry` |
| 前导零 | 输出阶段一次 `lstrip('0')`，再用 `or '0'` 兜住"结果被删空" |

第二条是关键技巧：把进位看成"还有一个隐藏的低位操作数没处理完"，循环就自动覆盖了
$99+1=100$ 这类**位数增加**的情形，循环外不需要任何收尾代码。第三条把"去前导零"
归约成一次纯字符串操作，因为前导 `0` 在逐位加法里本来就会原样传递下来：

$$0 + 0 + 0 = 0 \;\Longrightarrow\; \text{结果的每一位前导零仍是 } 0$$

所以输入 `0000123` 和 `0000077` 根本不需要预处理，相加得到 `0000200`，最后统一 `lstrip`。

**进位只有 0 或 1。** 因为 $s_i = a_i + b_i + c_i \leqslant 9 + 9 + 1 = 19 < 100$，
所以 $c_{i+1} = \lfloor s_i / 10 \rfloor$ 只可能取 $0$ 或 $1$。进位可以用一个整数变量承载，
不需要数组，也不会有"进位再进位"的连锁问题。

题面样例的两个数每一位都是 `2` 和 `3`，$2+3 = 5 < 10$，**进位自始至终是 $0$**，
所以样例其实没考进位。真正的进位过程要看下面这张表（以 $1234 + 6789$ 为例）：

| 轮次 | $a_i$ | $b_i$ | 进位 $c_i$ | $s_i = a_i+b_i+c_i$ | 输出位 $s_i \bmod 10$ | 新进位 $c_{i+1}$ |
| --- | --- | --- | --- | --- | --- | --- |
| 第 1 位（个位） | 4 | 9 | 0 | 13 | `3` | 1 |
| 第 2 位 | 3 | 8 | 1 | 12 | `2` | 1 |
| 第 3 位 | 2 | 7 | 1 | 10 | `0` | 1 |
| 第 4 位 | 1 | 6 | 1 | 8 | `8` | 0 |

输出位按低位到高位依次是 `3`、`2`、`0`、`8`，反转后得到 `8023`。注意第 2、3 位连续
吃到了进位，而"新进位"这一列始终是 0 或 1。

下面再把四种典型数据放一起对照，重点看**进位链**和**位数变化**：

| 输入 | 进位链（低位 → 高位） | 答案 | 考点 |
| --- | --- | --- | --- |
| `999` + `1` | $9{+}1{=}10 \to 1$，$9{+}0{+}1{=}10 \to 1$，$9{+}0{+}1{=}10 \to 1$，**再补一轮** $0{+}0{+}1{=}1 \to 0$ | `1000` | **最高位进位使位数从 3 变 4** |
| `0000123` + `0000077` | $3{+}7{=}10 \to 1$，$2{+}7{+}1{=}10 \to 1$，$1{+}0{+}1{=}2$ | `200` | 前导 `0` 无需预处理 |
| `5` + `0000000` | 无进位 | `5` | 位数不等，短的按 0 补齐 |
| `0` + `0` | 无进位 | `0` | 结果去零后为空，必须补回 `0` |

第一行说明了为什么 `carry` 必须进循环条件：前三轮把两串都读完了，但 `carry` 仍是 `1`，
循环还要**再转一轮**，才把这个 `1` 补到最高位、使答案从 3 位变成 4 位。第四行是唯一的
陷阱：只写 `lstrip('0')` 会得到一个空串。

三处设计决定与推导一一对应：

- `ord(a[i]) - ZERO if i >= 0 else 0` 处理越界位，**等价于补零对齐但不多分配内存**；
- `while i >= 0 or j >= 0 or carry` 把进位并入终止条件，**自然覆盖最高位进位**；
- `''.join(reversed(out))` 的反转不是装饰：`out` 是从低位往高位追加的，必须翻回正常
  书写顺序；随后 `.lstrip('0') or '0'` 去前导零并兜住"和为零"。

### 复杂度

设 $L = \max(n, m) \leqslant 200$。

- **时间**：$O(L)$。循环执行 $L$ 轮，若最高位产生进位则多一轮，即至多 $L+1$ 轮，
  每轮 $O(1)$。反转、拼接、`lstrip` 各 $O(L)$，不改变总阶。这也是下界——每个数字
  至少要读一次。
- **空间**：$O(L)$。`out` 至多保存 $L+1$ 个字符。相比补零写法少了一份 $O(L)$ 的对齐副本。
- **实测**：限时 $1000$ ms、内存 $128$ MB；真实测试点单点耗时约 $0.018$ s、峰值 $14.6$ MB。

Python 侧无 TLE/MLE 风险：$L \leqslant 200$ 的规模下，逐位模拟的总运算量只有几百次。
同样的算法在 C++ 里就是题面自带的 `std.cpp`：定长数组补零对齐后逐位相加；本实现
用双指针省掉了补零这一步。

## 总结

大整数加法不需要任何数据结构，就是**位置计数制进位规则的直接模拟**：从最低位起单向
扫描，每位算 $s = a_i + b_i + c$，留下 $s \bmod 10$、把 $\lfloor s/10 \rfloor$ 传给下一位。
由于和不超过 $19$，进位恒为 0 或 1，用一个变量即可。实现上的三个关键点是：越界位按 0
处理来省掉补零、把进位写进循环条件来省掉循环外的收尾、最后统一 `lstrip('0')` 去前导零
并用 `or '0'` 兜住全零结果。
