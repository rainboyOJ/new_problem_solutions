## 形式化题目

给定一个实数 $x$，要求输出它的**向零舍入**值：

$$
\operatorname{trunc}(x) = \operatorname{sign}(x) \cdot \lfloor |x| \rfloor
$$

即保留整数部分、丢弃小数部分：正数向下（$2.3 \to 2$）、负数向上（$-2.3 \to -2$）。注意它既不是四舍五入（$2.5$ 也应得 $2$），也不是向下取整 $\lfloor x \rfloor$（$-2.3$ 的 $\lfloor x \rfloor$ 是 $-3$，而题目要 $-2$）。

样例：输入 `2.3`，小数部分 `0.3` 直接丢弃，输出 `2`。

## 正解

### 思路

朴素想法是自己分符号处理：取绝对值、去掉小数、再按符号补回去，等价于手写

```python
import math
r = math.floor(x) if x >= 0 else math.ceil(x)   # 朴素：分符号 + floor/ceil
```

或者用 `math.modf` 拆出小数部分再按符号加减。这类写法在本题没有任何收益，反而埋着两个坑：用 `floor` 处理负数会得到 $-3$ 而不是 $-2$；分支方向写反就全错。

关键观察是：**题面定义的"向零舍入"就是截断（truncate）语义**——正数向下、负数向上，恰好等价于"丢掉小数部分"。而几乎所有语言的浮点→整数强制类型转换做的正是截断：

| 写法 | $2.3$ | $-2.3$ | 语义 |
| --- | --- | --- | --- |
| `int(x)`（Python）、`(int)x`（C++） | 2 | -2 | 向零截断，即题目要求 |
| `math.floor(x)` | 2 | -3 | 向下取整，负数方向错 |
| 四舍五入（`round`） | 2 | -2 | $2.5$ 会进位到 3，与题意不符 |

所以不需要任何分支或算术：读入后直接用内置转换。题目提示"可以使用强制类型转换来实现"，C++ 写 `cout << (int)x;`，Python 对应的就是 `int(x)`——两者对有限浮点数的截断语义一致。

还有一个容易多想的点：题面说"单精度浮点数"，真实数据却给了 `5350.355397409546` 这样超过单精度 7 位有效数字的长小数。用 Python 的 `float`（双精度）读入只会更精确；截断只依赖整数部分，而这些数的整数部分在 $10^3$ 量级，双精度可精确表示，整数位不会因舍入误差错位。

最终整道题就是"读入 → 转换 → 输出"三步，一行核心语句完成。

### 复杂度

- 时间复杂度：$O(1)$，一次读入、一次字符串到浮点的解析、一次截断、一次输出，与数值大小无关；实测单点约 0.017~0.018 s，远小于 1000 ms 限制。

## 总结

这道题的本质是认出"向零舍入 = 截断"这个语义等价：`int(x)` 对浮点数丢弃小数部分、向零取整，正数向下、负数向上，与题面定义逐字对应，因此一行 `print(int(x))` 即为正解。写题时要区分开三个近邻概念——截断（`int`）、向下取整（`floor`）、四舍五入（`round`），负数和 `.5` 恰好是它们分道扬镳的地方。实测 10 个评测点全部输出一致，单点约 0.018 s、峰值内存约 14.5 MB，相对 1000 ms / 128 MB 的限制十分宽裕。
