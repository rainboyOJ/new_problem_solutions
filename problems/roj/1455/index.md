## 形式化题目

给定两个只含大写字母的字符串 $s_1, s_2$，统计 $s_1$ 在 $s_2$ 中作为**子串**出现的次数，
出现允许重叠。样例 $s_1=\texttt{ABA},\ s_2=\texttt{ABAABA}$，答案为 $2$
（位置 $1$ 和位置 $4$，其中位置 $4$ 的 `ABA` 与位置 $1$ 的 `ABA` 共享了字母 `A`——重叠出现要计入）。

数据范围：$1 \le |s_1| \le 10^4$，$1 \le |s_2| \le 10^6$。

## 正解

### 思路

**朴素做法**：对 $s_2$ 的每个起点 $i$（共 $|s_2|$ 个），逐字符比较 $s_2[i..i+|s_1|)$ 与 $s_1$。
最坏 $O(|s_1|\cdot|s_2|) = 10^{10}$（例如 $s_1=\texttt{AAA...}$、$s_2=\texttt{AAA...}$），
必然超时。瓶颈在于：某次比较在很长一段前缀都匹配成功、只在末尾失配时，
朴素做法把已匹配的信息全部丢掉，从起点 $i+1$ 从零再来。

**保留已匹配信息**：设某时刻已经确认 $s_2$ 的一个片段与 $s_1$ 的前 $k$ 个字符逐位相同。
失配（$s_2$ 的下一个字符 $\ne s_1[k]$）时，不必回退 $s_2$ 的指针，
只需要把 $k$ 换成一个更小的"还可能继续匹配的前缀长度"。哪些候选值得试？

定义 $\mathrm{fail}[i]$ 为 $s_1[:i]$ 的**最长相等真前后缀**长度，即最大的 $j < i$
使 $s_1[:j] = s_1[i-j:i]$。失配时按 $\mathrm{fail}[k-1] \to \mathrm{fail}[\mathrm{fail}[k-1]-1] \to \cdots$
沿失配链回退，直到某处能接上当前字符（或 $k$ 归零）。回退链上每个值严格递减、
而 $k$ 每读一个字符至多增加 $1$，所以整个过程**均摊** $O(|s_2|)$。

以 $s_1=\texttt{AZA}$ 为例，$\mathrm{fail} = [0,0,1]$：

| 读到 $s_2$ 的字符 | 匹配长度 $k$（读后） | 说明 |
| --- | --- | --- |
| `A` | 1 | 接上 $s_1[0]$ |
| `Z` | 2 | 接上 $s_1[1]$ |
| `A` | 3 = \|s₁\| | 完整出现一次，计数 +1；回退 $k \leftarrow \mathrm{fail}[2] = 1$ |
| `A` | 0 | `A` ≠ $s_1[1]$=`Z`，沿链回退到 0 后仍失配 |
| `Z` | 1 | ... |

正是"匹配满 $|s_1|$ 后回退到 $\mathrm{fail}$ 而不是归零"保证了**重叠出现**也被数到。
$|s_2|=9$ 的样例 `AZAAZAAZA` 共出现 $3$ 次，与期望一致。

统计次数只要在扫描里加一个判断：$k = |s_1|$ 时计数加一。
总复杂度：预处理 $\mathrm{fail}$ 是 $O(|s_1|)$（同样的均摊论证），扫描是 $O(|s_2|)$，
合计 $O(|s_1|+|s_2|)$。

**读入格式**：题面样例首行是组数 $T$，但官方测试数据每个文件只有两行
（第 1 行 $s_2$、第 2 行 $s_1$，恰好与题面顺序相反）。代码按"首 token 是否是纯数字"
区分两种格式，两种都能跑。

## 总结

- 朴素匹配的瓶颈是"失配即弃"，KMP 用最长相等真前后缀（fail 数组）
  把已匹配信息转化为失配后的跳转目标，单趟扫完 $s_2$。
- 匹配满 $|s_1|$ 后回退到 $\mathrm{fail}[|s_1|-1]$ 而非清零，重叠出现天然被计入。
- Python 逐字符循环在 $10^6$ 量级下实测约 0.09 s/组，10/10 真实数据 PASS。
