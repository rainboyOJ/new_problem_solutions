## 形式化题目

给定 $n$ 个互不相同的二元组

$$(id_1, s_1),\ (id_2, s_2),\ \dots,\ (id_n, s_n)$$

其中 $id_i$ 是学号（编号，允许前导零），$s_i$ 是成绩。保证

$$s_i \neq s_j \quad (i \neq j), \qquad 1 \leqslant k \leqslant n$$

要求找出成绩第 $k$ **大**的那个学生，输出它的学号与成绩，两数之间用一个空格分隔；
成绩按 `%g` 格式输出（最多 6 位有效数字，去掉无意义的尾零）。

## 正解

### 思路

题面已经把答案说得很直白：**第 $k$ 名就是成绩降序排好后第 $k$ 个学生**。
所以最朴素的想法是"每轮挑出剩下的最大成绩"，也就是选择排序，做 $k$ 轮后位置 $k$
上就是答案——C++ 参考实现正是这么写的：

```text
for i in 1..k:
    max_pos = i
    for j in i+1..n:
        if score[j] > score[max_pos]:
            max_pos = j
    swap(stu[i], stu[max_pos])
输出 stu[k]
```

$n \leqslant 100$，比较次数不到 5000，这个写法当然能过。但它在本题里**没有把力气花对地方**：

- 手写双重循环和 `temp` 交换，写出来的是一段通用的排序代码，而不是本题的内容；
- 直接 `sort` 一遍再读下标，复杂度从 $O(nk)$ 降到 $O(n \log n)$，代码还更短；
- 本题真正会让人**答错**的地方根本不在循环上，而是下面三个细节。

**细节一：成绩必须按数值比较。** 测试数据里成绩的写法不统一，`61`（没有小数点）、
`63.100`（多余的尾零）、`15.45`（两位小数）都会出现。如果拿字符串去比：

- `"63.100" < "63.2"`，因为第 3 个字符 `'1' < '2'`，但数值上 $63.1 < 63.2$；
- `"9.5" > "10.5"`，因为 `'9' > '1'`，但数值上 $9.5 < 10.5$。

排名会彻底乱掉。真实数据 `problem2`（$n = 71$、$k = 60$）里，正确答案是 `499 15.45`；
若按字符串排序取第 60 个，输出的是 `170 24.22`。所以每个成绩都必须显式 `float(...)`。

**细节二：学号要原样保留。** 数据里的学号形如 `092`、`071`、`030`，是三位编号而不是数值。
把它读成整数会让前导零消失（`092` 变成 `92`），与答案文件不一致。所以整个学号列都当作
字符串（在 Python 里就是 `bytes`）原样读出、原样写出。

**细节三：输出格式是 `%g`。** 题面特意注明请用 `%g`，因为 C++ 的 `cout << double`
默认就是这个格式：`68.4` 输出 `68.4` 而不是 `68.400000`，`61.0` 输出 `61` 而不是 `61.0`。
Python 的 `f"{score:g}"` 与之等价。

把这三条和"排序取第 $k$ 个"合起来，就是最终做法：

```text
读入 n, k
students = [(原样保留的学号, float(成绩)) for 每个学生]
students 按成绩降序排序
输出 students[k-1] 的学号与 %g 格式的成绩
```

注意 `k` 是 1-based 而 Python 下标是 0-based，所以取 `k - 1`；题面已保证成绩互不相同，
不存在并列，排序结果唯一。

下面用样例 $n = 5,\ k = 3$ 走一遍这个过程，重点看"输入顺序"和"名次"是怎么脱钩的：

| 输入行 | 学号 | 原始成绩字符串 | 转成 float | 降序名次 |
| --- | --- | --- | --- | --- |
| 1 | 90788001 | `67.8` | 67.8 | 4 |
| 2 | 90788002 | `90.3` | 90.3 | 1 |
| 3 | 90788003 | `61` | 61.0 | 5 |
| 4 | 90788004 | `68.4` | 68.4 | **3** ← $k = 3$ |
| 5 | 90788005 | `73.9` | 73.9 | 2 |

第 4 行输入拿到了第 3 名，说明名次只由成绩数值决定、与输入先后无关；同时可以看到
`61` 这种写法转成 float 后是 `61.0`，与其他成绩比较毫无障碍，输出时 `%g` 又会把它
还原成 `61`。

### 复杂度

| 步骤 | 时间 | 空间 |
| --- | --- | --- |
| 读入 + 组装二元组 | $O(n)$ | $O(n)$ |
| 排序（Timsort） | $O(n \log n)$ | $O(n)$ |
| 取第 $k$ 个并输出 | $O(1)$ | $O(1)$ |
| **合计** | $O(n \log n)$ | $O(n)$ |

其中 $O(n)$ 的空间就是存 $n$ 个 `(学号, 成绩)` 二元组的列表。当 $n = 100$ 时，
排序 100 个元素是微秒级的工作，距离 1000 ms 的限制有三个数量级的余量，
128 MB 的内存限制也远远用不到。

## 总结

- 本题的算法内核只有一句话：**按成绩降序排序，取第 $k$ 个**，复杂度 $O(n \log n)$。
- 用 Python 写时，`list.sort(key=..., reverse=True)` 替掉了参考实现里的双重循环与交换，
  但复杂度并未退化——它是同阶更优，而不是把算法换成暴力。
- 真正容易出错的是三个"格式细节"：**成绩转 `float`**（否则字符串比较给出错误名次）、
  **学号保持字符串**（否则丢失前导零）、**成绩用 `f"{x:g}"`**（否则尾零或多位小数与答案不符）。
- 题面保证成绩互不相同，因此不需要任何并列处理。
