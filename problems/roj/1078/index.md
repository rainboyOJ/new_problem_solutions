## 形式化题目

给定递推定义的分数序列 $(a_i)$：

$$p_1 = 1,\quad q_1 = 2,\qquad p_{i+1} = q_i,\quad q_{i+1} = q_i + p_i,\qquad a_i = \frac{q_i}{p_i}.$$

求前 $n$ 项之和 $S_n = \sum_{i=1}^{n} a_i$（$1 \leqslant n \leqslant 30$），结果保留小数点后 4 位。

前 6 项为 $\frac{2}{1}, \frac{3}{2}, \frac{5}{3}, \frac{8}{5}, \frac{13}{8}, \frac{21}{13}$；样例 $n = 2$ 时 $S_2 = 2 + 1.5 = 3.5$，输出 `3.5000`。

## 正解

### 思路

题面的递推只用到当前项的一对整数 $(p_i, q_i)$：分母换成旧的分子，分子换成旧分子与旧分母之和。所以**状态就是一个二元组**，不需要数组保存历史项，也不需要分数类——每次迭代 $O(1)$，$n$ 次迭代即得全部项。时间上这已经是最优：答案依赖全部 $n$ 个比值，任何正确算法都必须至少生成 $n$ 项。

把"生成项"和"求和"拆开写会更容易对照题面。用一个生成器 `fraction_terms(n)` 负责递推并逐项 `yield q / p`，主流程只写 `sum(...)`：

```python
p, q = 1, 2          # p_1, q_1
for _ in range(n):
    yield q / p      # 第 i 项 q_i / p_i
    p, q = q, p + q  # 下一项的分母 = 当前项分子
```

关键在最后一行：Python 的元组赋值会**先整体求右值再赋值**，所以 `p + q` 用的是旧 `p`、旧 `q`，恰好等于 $q_{i+1} = q_i + p_i$，而 `p` 拿到旧的 `q`，即 $p_{i+1} = q_i$。两式一行，不必引入临时变量（C++ 里要写 `c = a + b; a = b; b = c;`）。

另外注意**起点与产出顺序的搭配**：本题从 $(1, 2)$ 出发、先产出再递推。这两件事是一个整体——从 $(1,1)$ 出发时就必须先递推再产出，两种自洽写法结果完全相同；一旦混用（从 $(1,1)$ 出发却先产出），序列会多出 $1/1 = 1$ 而少掉最后一项 $q_n/p_n$，$n = 2$ 时得到 $3$ 而不是 $3.5$。

还有两个实现细节：

- **整数状态、只在产出时做一次除法**。也可以把序列写成纯分数递推 $a_{i+1} = 1 + 1/a_i$，但那会让每一项都继承上一项的浮点误差；保持 $(p,q)$ 为整数，误差只来自 $n$ 次求和，$S_{30} = 48.8406\ldots$，double 精度绰绰有余，不可能影响第 4 位小数。
- **不判除零**。$p_1 = 1$ 且 $p_{i+1} = q_i \geqslant 2$，分母恒为正。

### 样例解释

以 $n = 5$ 走一遍，关注 $p$、$q$ 如何被递推式更新，以及累加和与期望输出的关系：

| $i$ | $p_i$ | $q_i$ | $a_i = q_i/p_i$ | $S_i$ |
| --- | --- | --- | --- | --- |
| 1 | 1 | 2 | $2/1 = 2.0000$ | 2.0000 |
| 2 | 2 | 3 | $3/2 = 1.5000$ | 3.5000 |
| 3 | 3 | 5 | $5/3 \approx 1.6667$ | 5.1667 |
| 4 | 5 | 8 | $8/5 = 1.6000$ | 6.7667 |
| 5 | 8 | 13 | $13/8 = 1.6250$ | 8.3917 |

表格里能读出两点：其一，第 $i+1$ 行的 $p$ 列等于第 $i$ 行的 $q$ 列（"分母接上一项分子"），第 $i+1$ 行的 $q$ 列等于第 $i$ 行两列之和——这正是 `p, q = q, p + q` 一行所做的两件事；其二，$p,q$ 序列是 $1,2,3,5,8,13,\dots$ 斐波那契数，相邻两项之比趋向黄金比 $\varphi \approx 1.618$，所以和大致按每项 $1.618$ 线性增长。上表第 2 行给出 $S_2 = 3.5000$，与题面样例一致；$S_5 = 8.3917$ 也与真实数据 `problem1.in` 的期望输出相同。

### 复杂度

- 时间复杂度：$O(n)$，每项只做常数次整数运算和一次浮点除法；$n \leqslant 30$ 时实测单点 0.015--0.016 s（含解释器启动）、峰值内存 14.5 MB。与 C++ 参考解同阶。
- 空间复杂度：$O(1)$，只有 `p`、`q` 两个整数状态与一个累加值；生成器惰性产出，不保存序列。

## 总结

本题是"线性递推 + 累加"的入门模板：先确认递推只依赖当前项，把状态压成整数对 $(p, q)$，用一行元组赋值 `p, q = q, p + q` 同时完成"分母接上一项分子"和"分子取两数之和"，再逐项求商累加。两个易错点都在细节而非算法——起点 $(1,2)$ 必须与"先产出后递推"的顺序搭配，以及保持整数状态、只在产出时做一次除法以避免误差积累。若用 C++ 落地，把 `yield` 换成循环内的 `sum += 1.0 * b / a;`，递推写成 `c = a + b; a = b; b = c;`，最后 `printf("%.4lf\n", sum)` 即可。
