## 形式化题目

给定两个整数 $x$ 与 $y$，判断它们的大小关系：$x > y$ 输出 `>`，$x = y$ 输出 `=`，$x < y$ 输出 `<`，三者必居其一。

两个数的取值范围**不对称**：$0 \leqslant x < 2^{32}$ 是无符号 32 位范围，恒非负；$-2^{31} \leqslant y < 2^{31}$ 是有符号 32 位范围，可为负数。

样例：输入 `1000 100`，因为 $1000 > 100$，输出 `>`。

## 正解

### 思路

先看朴素做法：读入两个整数，比较大小，把三种结果分别输出——计算上只有一步比较，**没有任何瓶颈可消除**，再写一个"暴力版"只会得到和正解一模一样的代码，所以本题不设暴力层，直接讲最终做法（直接正解型布局的依据）。

这道题真正的考点不在算法，而在**两个数的类型范围不同**：

- $x$ 落在无符号 32 位区间 $[0,\ 2^{32}-1]$，$y$ 落在有符号 32 位区间 $[-2^{31},\ 2^{31}-1]$。
- 在 C/C++ 里把 `unsigned int` 和 `int` 直接比较，编译器会把 $y$ **隐式转换**成无符号数：$y = -1$ 变成 $4294967295$，于是 $x=0$ 时会判成 $0 < 4294967295$，而实际 $0 > -1$——方向恰好判反。正确写法必须先把两边统一成 `long long` 再比。
- Python 的 `int` 是任意精度的**有符号**整数，$2^{32}-1$ 和 $-2^{31}$ 都能精确表示，也不存在无符号/有符号两种类型，直接用 `<`、`==` 比较结果天然正确，上面的陷阱在 Python 里根本不存在。

读入部分沿用本系列的标准链路：`sys.stdin.buffer.read()` 一次读完整份输入，`.split()` 按空白切成 token，`map(int, ...)` 转成整数后解包成 `x, y`。

剩下的问题是怎么把三态结果压成最短的输出。`x < y` 和 `x == y` 由三歧性保证至多一个为真，把它们当作 0/1 参与算术，就得到互不冲突的下标：

| 比较结果 | `is_less` | `is_equal` | 下标 `2 * is_less + is_equal` | 输出字符 `MARKS[下标]` |
| --- | --- | --- | --- | --- |
| $x < y$ | 1 | 0 | 2 | `<` |
| $x = y$ | 0 | 1 | 1 | `=` |
| $x > y$ | 0 | 0 | 0 | `>` |

这张表说明：三种情形算出的下标 $2/1/0$ 恰好是字符串 `MARKS = '>=<'` 中 `<`、`=`、`>` 的位置，于是整个输出不需要任何 `if/elif/else` 分支，一个下标表达式就完成了"比较 → 编码 → 字符"的全链路。

### 复杂度

- 时间复杂度：$O(1)$，读入固定两个 token，一次整数解析加两次比较。

## 总结

- 题目只有一组输入、一次比较，朴素做法即正解，本题考点是**无符号/有符号混合比较的类型陷阱**：C 里 `unsigned` 与 `int` 比较会把负数隐式转换成大正数判反方向，Python 的任意精度 `int` 没有这个问题。
- 读固定个数整数的标准链路：`read()` 读全部 → `split()` 切分 → `map(int, ...)` 转换 → 解包。
- 三态结果用两个互斥布尔量编码成下标 $2/1/0$，配合常量字符串 `'>=<'` 查表输出，比三分支 `if/elif/else` 更短，也把映射含义集中在模块级常量一处。
