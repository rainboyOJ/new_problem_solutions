## 形式化题目

给定 $m, k$，求正整数 $n$，使得区间 $(n, 2n]$ 中的整数恰好有 $m$ 个在二进制下含有 $k$ 个 $1$。
多组询问，每组输出**任意一个**满足条件的 $n$（要求 $n \leqslant 2^{64}-1$），
以及满足条件的 $n$ 的**总个数**（无穷多时输出 $-1$）。

记 $\mathrm{popcount}(x)$ 为 $x$ 的二进制中 $1$ 的个数，并定义

$$
f(n) \;=\; \#\{\,x : n < x \leqslant 2n,\ \mathrm{popcount}(x) = k\,\}.
$$

那么每组询问就是一个方程：

$$
\text{求 } n \geqslant 1 \text{ 使 } f(n) = m, \qquad
\text{并给出解的个数（} 0 \leqslant m \leqslant 10^{18},\ 1 \leqslant k \leqslant 64\text{）}.
$$

题面保证 $10^{18}$ 以内存在满足条件的 $n$。以样例 $m=1,\ k=2$ 为例：
$n=2$ 时区间是 $\{3,4\}$，其中 $3 = 11_2$ 有 2 个 $1$、$4 = 100_2$ 有 1 个 $1$，
恰有 $1$ 个符合，故输出 `2 1`。

### 数据来源说明

本题与 Codeforces 431D *Random Task* 同源（题面逐字对应）。
但 $10^{18}$ 内的测试数据由 `data.py` 现场生成，本仓库的 `std.cpp` 也出自同一次整理，
**并非官方数据**；额外追问的「解的个数」一项更是原题所无（原题只要求输出一个 $n$）。
本文的推导独立于 `std.cpp`，结论已用暴力枚举在 $n \leqslant 3000$、$k \leqslant 13$ 范围内逐点核对。

## 正解

### 思路

**朴素做法。** 从 $n = 1$ 开始枚举，对每个 $n$ 扫一遍 $(n, 2n]$ 统计 $\mathrm{popcount} = k$ 的个数。
单次统计就要 $O(n)$ 步，而 $n$ 可达 $10^{18}$，且 $m$ 所对应的 $n$ 还未必小
（$k=31$ 时合法 $n$ 已逼近 $10^{18}$）。枚举路线完全没有利用区间滑动时的代数结构。

**关键恒等式。** 把 $f(n+1) - f(n)$ 算出来。$f(n)$ 统计 $(n, 2n]$，$f(n+1)$ 统计 $(n+1, 2n+2]$，
两者做差只剩三个元素：

$$
f(n+1) - f(n) = [\mathrm{popcount}(2n+1)=k] + [\mathrm{popcount}(2n+2)=k] - [\mathrm{popcount}(n+1)=k].
$$

而 $2n+2 = 2(n+1)$ 是左移一位，左移不改变 $1$ 的个数，所以后两项恒等、直接抵消：

$$
f(n+1) - f(n) = [\mathrm{popcount}(2n+1) = k] = [\mathrm{popcount}(n) = k-1]. \tag{1}
$$

（最后一步因为 $2n+1$ 就是 $n$ 左移一位再补个 $1$。）于是 $f$ 单调不减、每次至多涨 $1$，
且能直接展开前缀：

$$
f(n) \;=\; \sum_{j=1}^{n-1} [\mathrm{popcount}(j) = k-1]
\;=\; \#\{\,j : 0 \leqslant j < n,\ \mathrm{popcount}(j) = k-1\,\}. \tag{2}
$$

**这一步把「区间计数」变成了「排名」**：$f(n) = m$ 就是说「恰有 $m$ 个『含 $k-1$ 个 $1$』的数
严格小于 $n$」。把所有 $\mathrm{popcount} = p$（$p = k-1$）的非负整数从小到大排成

$$a_0 < a_1 < a_2 < \cdots, \qquad a_0 = \underbrace{1\cdots1}_{p} = 2^{p}-1,$$

则 $f(n) = m$ 等价于 $a_{m-1} < n \leqslant a_m$，于是解的集合是一段**连续区间**：

| $m$ | 合法 $n$ 的范围 | 最小 $n$ | 解的个数 |
| :-: | --- | :-: | :-: |
| $m \geqslant 1$ | $[\,a_{m-1}+1,\ a_m\,]$ | $a_{m-1}+1$ | $a_m - a_{m-1}$ |
| $m = 0$ | $[\,1,\ a_0\,] = [\,1,\ 2^{p}-1\,]$ | $1$ | $2^{p}-1$ |

这也顺带解释了为什么解一定是「连续一段」而不是零散分布——因为 $f$ 每次只涨 $0$ 或 $1$，
值 $m$ 只可能被一整段 $n$ 连续取到。

**特例 $k = 1$。** 此时 $p = 0$，而含 $0$ 个 $1$ 的非负整数只有 $j = 0$ 一个，
由 (2) 得 $f(n) \equiv 1$（$n \geqslant 1$）。所以 $m = 1$ 时**所有**正整数 $n$ 都合法，
个数为无穷多，输出 `1 -1`。

**求第 $\text{rank}$ 个候选数 $a_{\text{rank}-1}$：按位贪心。** 从最高位到最低位扫描，
维护「已经放下的 $1$ 的个数 `used`」。在第 $i$ 位，如果这一位取 $0$，
那么低 $i$ 位里还要凑出 `need = p - used` 个 $1$，方案数是组合数 $\binom{i}{\text{need}}$：

- 若 $\text{rank} \leqslant \binom{i}{\text{need}}$，目标落在这支里，本位取 $0$；
- 否则减去这一支的方案数，本位取 $1$、`used` 加一。

扫完 64 位得到的就是 $a_{\text{rank}-1}$，单次 $O(64)$。这就是「组合数进制的第 $k$ 小」，
和 LeetCode 的「字典序第 $k$ 小数」是同一套贪心。

以样例 $m = 1,\ k = 2$ 走一遍：$p = 1$，$a_{m-1} = a_0$ 是最小的含 1 个 $1$ 的数
（贪心从最高位看，第 0 位方案数 $\binom{0}{1} = 0 < 1$，只能取 $1$，得 $a_0 = 1$）；
$a_1 = 2$。于是最小 $n = a_0 + 1 = 2$，个数 $= a_1 - a_0 = 1$，输出 `2 1`，与样例一致。

**无解的处理。** 题面保证 $10^{18}$ 内有解，但 $k = 64$ 时含 $63$ 个 $1$ 的数只有
$2^{63}-1$ 一个，故 $m \geqslant 1$ 必然无解。代码统一用
$\binom{64}{p} < m+1$ 判断「$2^{64}$ 范围内凑不出第 $m+1$ 个候选」，输出 `0 0` 兜底。

### 复杂度

- **时间**：C++ 版预处理组合数表 $O(64^2)$，每组询问两次按位贪心各 $O(64)$，
  故单组 $O(\log n)$，总计 $O\big(64^2 + t\log n\big)$；Python 版省掉建表、
  每次现调 `math.comb`，仍是每组 $O(\log^2 n)$ 的量级，复杂度同阶。
  $t = 2000$ 时约 $10^6$ 次基本运算，实测远低于 1000 ms 限时。
  注意本解法**完全不依赖 $m$ 的大小**——$m$ 只作为「第几名」参与组合数比较，
  所以 $m$ 取到 $10^{18}$ 与取到 $1$ 的代价完全相同。
- **空间**：组合数表 $65 \times 65$，$O(64^2)$，常数量级。
- **数值范围**：答案 $n$ 允许取到 $2^{64}-1$，超出 `long long` 上界，
  故 C++ 里用 `unsigned long long`；组合数最大为 $\binom{64}{32} \approx 1.83 \times 10^{18}$，
  同样在无符号 64 位内不溢出。Python 侧整数无上界，不需要额外处理。

## 总结

- **(1) 式是本题的全部内容**：$f(n+1) - f(n) = [\mathrm{popcount}(2n+1)=k]$。
  它的证明只用了一条性质——**左移一位不改变 $1$ 的个数**，
  这条性质让区间的「一进一出」精确抵消掉一半，剩下的半边恰好是 $n$ 的排名。
- **从「区间计数」转向「排名」**：一旦看出 $f(n) = \#\{j < n : \mathrm{popcount}(j) = k-1\}$，
  单调性与连续性就是显然的（$f$ 每次只涨 $0$ 或 $1$），
  解的集合也必然是一段连续区间 $[a_{m-1}+1,\ a_m]$。
- **数位贪心求第 $k$ 小**：判断「第 $\text{rank}$ 个候选在哪一支」时，
  低位自由位的方案数恰好是组合数 $\binom{i}{\text{need}}$，
  于是每个询问只需从高到低扫 64 位。这类「组合数进制」贪心
  在「第 $k$ 小的二进制含 $k$ 个 $1$ 的数」「字典序第 $k$ 小」等问题上可复用。
- **特例要单独想**：$k=1$ 时 $f$ 是常函数 $1$，二分或贪心都不会自然报错，
  必须在入口处特判，否则「最大合法 $n$」会一路跑到 $2^{64}$ 之外。
