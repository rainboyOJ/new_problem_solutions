## 形式化题目

给定一个整数 $n$（$-1{,}000{,}000 < n < 1{,}000{,}000$，含负数与 $0$）。判定是否**同时**有 $3 \mid n$ 且 $5 \mid n$：都是输出 `YES`，否则输出 `NO`。

样例：$15 = 3 \times 5$，是最小的正"双整除"数，输出 `YES`。

## 正解

### 思路

最直接的翻译就是最终做法：两个取余、一个 `and`——

$$\text{divisible} = (n \bmod 3 = 0) \land (n \bmod 5 = 0).$$

单组输入、常数判定，$O(1)$ 已经是下界，不存在需要消除的瓶颈，因此按直接正解组织（再写一个"暴力版"只会得到一模一样的代码）。

真正值得学的是把两个条件**折叠成一个**。3 与 5 互质，于是"同时被 3 和 5 整除"等价于"被 $\operatorname{lcm}(3,5) = 15$ 整除"：

- **必要性**：$3 \mid n$ 且 $5 \mid n$，而 3 与 5 没有公共质因数，$n$ 的质因数分解里必须同时含 $3$ 和 $5$，故 $15 \mid n$；
- **充分性**：$15 \mid n$ 时由整除的传递性得 $3 \mid 15 \mid n$、$5 \mid 15 \mid n$。

判定式收敛成一次取余 $n \bmod 15 = 0$。这不是复杂度优化（两种写法同为 $O(1)$），而是整除问题里"多个条件的且 ⇒ 最小公倍数的倍数"这条常用合并手段。注意它依赖互质：若改成"被 4 和 6 整除"，合并值是 $\operatorname{lcm}(4,6)=12$ 而不是乘积 24。

"且"关系是本题的第一个坑。四种组合的判定结果如下表（真实测试数据恰好把四个分支全部覆盖）：

| $3 \mid n$ | $5 \mid n$ | 同时成立？ | 真实数据例子 | 输出 |
| :---: | :---: | :---: | --- | :---: |
| ✓ | ✓ | 是 | `-918420`（数码和 $24$、末位 $0$） | `YES` |
| ✓ | ✗ | 否 | `373506`（数码和 $24$、末位 $6$） | `NO` |
| ✗ | ✓ | 否 | `785375`（数码和 $35$、末位 $5$） | `NO` |
| ✗ | ✗ | 否 | `237826`（数码和 $28$、末位 $6$） | `NO` |

表中用整除口诀核对例子：被 3 整除 ⇔ 数码和被 3 整除，被 5 整除 ⇔ 末位是 $0$ 或 $5$。容易犯的错是把"且"写成 `or`——`785375` 只被 5 整除，期望 `NO`，`or` 会错判成 `YES`；反过来 `373506` 只被 3 整除，同样只该得 `NO`。

第二个坑是符号与零。范围含负数和 $0$：$-721155$ 是真实的 `YES` 数据；$0 = 15 \times 0$ 也算双整除。Python 的 `%` 对负数返回**非负**余数（$-721155 \bmod 15 = 0$），所以 `n % BOTH == 0` 对负数天然成立，不需要先取绝对值。

落到代码上只有三步：`sys.stdin.buffer.read().split()[0]` 一次读完取首个 token，`int(...)` 转成 `n`（负号自动处理）；15 命名成模块级常量 `BOTH`（命名本身就是"3 与 5 的最小公倍数"这条事实的注解）；`n % BOTH == 0` 先命名成局部变量 `divisible` 再判断，最后 `print("YES" if divisible else "NO")` 把布尔翻译成题面要求的两个词。

### 复杂度

- 时间复杂度：$O(1)$，一次读入、一次取余、一次输出，与 C++ 正解同阶。
- 空间复杂度：$O(1)$，只保存一个整数、一个布尔与常量 `BOTH`。

## 总结

- "且"的整除合并：$3 \mid n \land 5 \mid n \Leftrightarrow 15 \mid n$，互质两数的多个整除条件折叠成对最小公倍数的一次取余；两数不互质时要用 $\operatorname{lcm}$ 而非乘积。
- 判定词是"同时"：写成 `or` 会在"只整除其中一个"的数据上翻车，真实数据 `785375`（只被 5 整除）正是这个分支的试金石。
- 负数与 $0$ 不用特判：Python `%` 的非负余数语义让 `n % 15 == 0` 直接覆盖全部符号；实测 10 组真实数据全部 PASS，每组约 0.016 s，相对 1000 ms / 128 MB 的限制毫无压力。
