## 形式化题目

输入两行字符串，分别是一棵二叉树（字符互不重复）的先序和中序序列。按凹入表示法输出这棵树：按先序，每个结点占一行，该行由它的字符重复「结点长度」次，行数等于结点数；叶结点长度为 $1$，非叶结点长度等于左右子树长度之和，即长度等于子树中的叶子数。样例输入 `ABCDEFG` 与 `CBDAFEG`，样例输出依次为 `AAAA`、`BB`、`C`、`D`、`EE`、`F`、`G`。

## 解法总览

两种解法共用同一条观察：**先序首字符是根，它在中序里的位置把左右子树切开**。差别在「长度（子树叶子数）什么时候算」——递归直接输出时现算，建树时顺手算进结点里。

| | 解法一：区间递归直接输出（原实现） | 解法二：先建树再输出（正式主解） |
| --- | --- | --- |
| 做法 | `walk()` 按先序往下走，走到一个子树就先现算它的叶子数，输出「字符 × 长度」 | `build()` 建出 `Node{val, lch, rch, len}`，长度在建树时算好，`walk(root)` 只负责输出 |
| 长度来源 | 单独一个 `length()` 递归（Python 加 `@cache` 记忆化） | `node[u].len`，叶子 1、非叶左右之和 |
| 时间 | C++ 版每结点现算 O(子树大小)，链状最坏 O(n²)；Python 版记忆化后 O(n) | pos 表 O(1) 定位，建树与输出都是 O(n) |
| 代码 | `direct.py` / `direct.cpp` | `main.py` / `main.cpp` |

正式主解是 `main.py` / `main.cpp`。

## 解法一：区间递归直接输出

### 思路

先序首字符是根，它在中序序列中的位置把左右子树切开，递归下去就能还原整棵树；空子树叶子数记 $0$，于是 $n \leqslant 1$ 时长度就是 $0/1$，只有一个孩子的结点无需分情况讨论。先求出每个结点的长度（子树叶子数），再按先序输出「字符 × 长度」。

### 复杂度

- 空间：递归栈 O(树高)。

## 解法二：先建树再输出

### 思路

观察相同，区别在于**先序 + 中序还原这棵树时就把长度算好**：`build(pl, il, cnt)` 用先序首字符定根、`pos[]` O(1) 定位切分点，递归接上左右孩子；叶子长度置 1，非叶取左右之和——长度与结点同时诞生，后面 `walk(root)` 只需按先序输出「字符 × len」，一次遍历，不必回头重算。

结点的字符、左儿子、右儿子、长度收进同一个 `Node`，编号即下标（静态数组 + `node_cnt` 动态开点）。

## 复杂度对比

| | 解法一 | 解法二 |
| --- | --- | --- |
| 时间 | Python 记忆化 O(n)；C++ 无记忆化最坏 O(n²) | 两种语言都 O(n) |
| 空间 | 递归栈 + 缓存 | 结点表 O(n) |
| 能否复用树结构 | 不能 | 能 |
| 适合场景 | 只求一次凹入输出 | 后续还要在树上做别的事（改遍历序、统计） |

解法一少一层结构、写起来短；解法二把「长度 = 子树叶子数」这条定义直接物化进结点，任何语言都能稳定 O(n)，也是后续树题的标准起点。

## 总结

1. **先序 + 中序还原二叉树**的套路：首字符定根、中序位置切分，`pos[]` 表让切分从 O(n) 降到 O(1)。
2. 「递归返回值」和「结点字段」是存同一个信息的两种方式：`length()` 现算 vs `node[u].len` 预存，差别在于会不会被重复调用——这正是 C++ 版解法一最坏 O(n²)、解法二稳定 O(n) 的原因。
3. 结点用 `Node` 聚合、编号即下标，是这本仓库建二叉树的标准写法（见《树的存储》）。
