## 形式化题目

给定三个正整数 $a, b, c$，表示三条线段的长度。判断它们能否构成一个三角形，即三条**严格**不等式

$$a + b > c, \qquad a + c > b, \qquad b + c > a$$

是否全部成立：全部成立输出 `yes`，否则输出 `no`。

样例 `3 4 5` 中 $3 + 4 = 7 > 5$、$3 + 5 = 8 > 4$、$4 + 5 = 9 > 3$，三条都成立，输出 `yes`。

## 正解

### 思路

输入长度固定为三个正整数，判定逻辑就是三角形的定义，没有任何值得单独教一层暴力的优化空间，
所以按直接正解型组织：把朴素写法与最终写法一起讲清，重点放在**如何把三条不等式化简成一条**。

先把定义逐字翻译。设输入为 $a, b, c$，三角形要求三条不等式同时成立：

```python
can_form_triangle = a + b > c and a + c > b and b + c > a
```

这是参考实现 `std.cpp`（`(a+b>c)&&(a+c>b)&&(b+c>a)`）的 Python 翻译，正确，且 $O(1)$。
但它做了三次加法、三次比较，而其中**两次比较是多余的**——只要知道谁是最长边，
另外两条不等式不可能被违反。障碍在于 $a, b, c$ 是无序的，代码不知道该拿哪一条真的去查。

**第一步：用排序消灭"无序"。** 把三边升序排列成 $a \leqslant b \leqslant c$，那么 $c$ 一定是最长边：

```python
a, b, c = sorted(map(int, sys.stdin.buffer.read().split()))  # a <= b <= c，c 即最长边
```

排序只改变三条边的书写顺序，不影响"三条不等式是否全部成立"这个合取式的真值（合取对三边对称）；
但排序之后，"最长边"这个概念在代码里有了名字，不必再逐条试探。

**第二步：用正性与单调性推理掉冗余的两条。** 在 $a \leqslant b \leqslant c$ 且 $a, b > 0$ 时：

- $a + c > b$：由 $c \geqslant b$ 得 $a + c \geqslant a + b > b$，恒成立（用到 $a > 0$）；
- $b + c > a$：由 $b > 0$ 得 $b + c > c \geqslant a$，恒成立。

这两条推理都只用到"三边是正数"（题面限定正整数）与 $c$ 是最大者。于是三条不等式的合取
坍缩成一条：

$$a + b > c .$$

**第三步：注意是严格不等式。** $a + b = c$ 时三条线段首尾相接恰好共线，退化成一条线段，
不构成三角形，必须输出 `no`，所以判据写 `>` 而不是 `>=`。

用真三角、退化和其他不成三角的情形对照，可以看清哪一条才是真正起作用的判据：

| 三边（升序） | $a+b>c$ | $a+c>b$ | $b+c>a$ | 输出 |
| --- | --- | --- | --- | --- |
| `3 4 5` | $7 > 5$ 真 | $8 > 4$ 真 | $9 > 3$ 真 | `yes` |
| `1 2 3` | $3 > 3$ **假** | $4 > 2$ 真 | $5 > 1$ 真 | `no` |
| `1 2 10` | $3 > 10$ **假** | $11 > 2$ 真 | $12 > 1$ 真 | `no` |

表格三行的第二、三列（即被推理掉的两条不等式）全部为真，只有第一列 $a+b>c$ 在
两行 `no` 上取假——区分 `yes` 与 `no` 的信息完全由"短边之和与最长边"这一条承载，
另外两条不必再算；第二行还显示 $a+b=c$ 的取等情形必须落在 `no` 一侧。

最后一点实现细节：参考实现把三边读成 `double`，而本题输入是整数，用整数读入更准确——
"取等即退化"的判断不含任何浮点舍入，也不依赖具体常量取值。

## 总结

- 三角形判定就是三条严格不等式同时成立；$a + b = c$ 是共线退化，必须判 `no`。
- 先 `sorted` 升序定出最长边，再用正性与单调性推理掉两条恒真的不等式，
  判据只剩 `a + b > c`；这条恰好是唯一会失效的不等式，化简时不能漏。
- 朴素写法里最容易写漏的是第三条；化简后只剩一条，反而更不容易漏。
- 三边是正整数，"取等"的边界语义用整数精确判定，不涉及浮点舍入。
- 验证：真实测试数据 10/10 全部 PASS（约 0.015 s/组，峰值内存 14.4 MB，
  限额 1000 ms / 128 MB）。
