## 形式化题目

给定一行字符串 $s$，字符集混合了大小写字母、数字、空格与英文标点，长度满足
$|s| \leqslant 255$。求 $s$ 中属于字符集合 `'0'`--`'9'` 的字符个数：

$$
\text{ans} = \#\{\, i \mid s_i \in \{\texttt{'0'}, \texttt{'1'}, \dots, \texttt{'9'}\} \,\}
$$

样例：`Peking University is set up at 1898.` 中的数字字符依次是 `1`、`8`、`9`、`8`，
共 4 个，输出 `4`。

## 正解

### 思路

**朴素做法。** 整行读入，从左到右扫一遍，遇到 `'0'` 到 `'9'` 的字符就让计数器加一。
计数是逐字符独立的：某个位置算不算数只取决于它自己，与其它位置无关，所以一遍扫描
就能得到精确答案，不需要任何额外数据结构。

复杂度上也没有优化空间——每个字符都必须至少被看一次，$O(|s|)$ 就是下界。所以
本题值得讲清楚的不是算法，而是三个容易写错的地方。

**坑一：不能按空白分词。** 输入的字符集里有空格（样例 `Peking University ...`
就是空格分隔的）。若用 `sys.stdin.read().split()` 之类按空白切分的读法，空格会被
吃掉，读进来的已经不是「那一行字符串」了。本题空格恰好不影响数字的个数，但这种
读法在概念上就是错的，正确姿势是整行读入、按字符处理。

**坑二：只能统计前 255 个字符。** 这一点最隐蔽，也是本题真正的考点。原题的参考实现是

```cpp
char ch[256];
fgets(ch, 256, stdin);   // 缓冲区 256 字节（含结尾 '\0'），最多读入 255 个字符
```

`fgets` 的第二个参数是**缓冲区大小**而不是字符数，缓冲区还要留一个字节放 `'\0'`，
因此它只能装下 255 个字符，超出部分被直接丢弃。题面写「总长度不超过 255」，
但官方数据里确实存在超长输入，其标准答案就是按**前缀 255 个字符**统计出来的：

| 测试点 | 输入字节数 | 全部字符中的数字个数 | 前 255 字符中的数字个数 | 官方答案 |
| --- | --- | ---: | ---: | ---: |
| problem3 | 359 | 39 | 30 | **30** |
| problem4 | 291 | 35 | 34 | **34** |
| problem5 | 301 | 31 | 29 | **29** |
| problem9 | 453 | 55 | 27 | **27** |

表中前三列分别表示：该测试输入的字节总数、若统计整行得到的答案、若只统计前 255 个
字符得到的答案。对比最后一列的官方答案可以看出，**只有截断到 255 的前缀口径**才
能与官方答案逐组吻合；若按「统计整行」实现，problem3 会输出 39（正确是 30）、
problem9 会输出 55（正确是 27），直接 WA。其余 6 组输入本身不超过 255 字节，
两种口径结果相同，所以不会暴露这个问题。

因此「长度上限 255」在本题不是一个用来剪枝的规模条件，而是**参与正确性判定的读取
语义**：必须先把字符串截到前 255 个字符，再在截断结果上计数。

**坑三：`str.isdigit()` 比「数字字符」宽。** Python 的 `str.isdigit()` 对 `'²'`
（上标二）、`'٣'`（阿拉伯-印度数字三）都返回 `True`，而题面要的是 ASCII 十进制数字，
参考实现写的也是 `ch >= '0' && ch <= '9'`。本题数据只含 ASCII，两种写法同分，但语义
上应该用区间比较 `'0' <= ch <= '9'`。

**把它们写短。** 先把截断表达成一次切片 `line[:255]`——这样「读取语义」就变成一个
纯粹的数据变换，而不是藏在循环条件里的下标判断；再让生成器表达式配合 `sum` 完成计数：
Python 的 `bool` 是 `int` 的子类（`True == 1`、`False == 0`），把判断式直接求和就是
计数，省掉 `if` 与 `count += 1`：

```python
kept = line[:255]
count = sum('0' <= ch <= '9' for ch in kept)
```

这两步都不改变复杂度（仍是 $O(\min(|s|, 255))$），只是让「截断」和「计数」各自成为
一个一眼可读的表达式。

### 复杂度

- 时间复杂度：$O(\min(|s|, 255))$。切片 `line[:255]` 复制至多 255 个字符，随后的
  求和也最多遍历 255 个字符；在题面的 $|s| \leqslant 255$ 约束下即 $O(1)$，
  常数上界是 255 次字符比较。
- 空间复杂度：$O(\min(|s|, 255))$，用于保存整行字符串与它的前缀副本；在题面约束下
  即 $O(1)$，实测峰值约 14.6 MB（几乎全部是 Python 解释器自身开销），远低于 128 MB。

## 总结

- 计数类问题没有比线性扫描更快的做法，值得推敲的是读取语义和表达方式。
- 本题的「长度上限 255」是**正确性条件**而非剪枝条件：参考实现用
  `fgets(ch, 256, ...)` 读入，缓冲区含结尾 `'\0'` 只能装 255 个字符，官方超长数据的
  答案正是按截断后的前缀计算的，所以必须先 `line[:255]` 再计数。
- 输入含空格，必须整行读入，不能按空白分词。
- 判「数字字符」用 `'0' <= ch <= '9'` 而非 `str.isdigit()`：后者的语义更宽，
  会接受上标、其它文字的十进制数字等非 ASCII 字符。
- `bool` 是 `int` 的子类，`sum(条件 for ch in 序列)` 可以直接把布尔判断求和成计数，
  比手写 `if` + `+=` 更短且不损失可读性。
