## 形式化题目

给定长度 $1 \leqslant n \leqslant 20$ 的字符串 $s = c_0 c_1 \cdots c_{n-1}$，字符集中不含空白符。判定 $s$ 是否属于

$$R = \{\, c_0 c_1 \cdots c_{n-1} : c_0 \in L,\ c_1, \dots, c_{n-1} \in L \cup D \,\}$$

其中 $L$ 是 ASCII 字母与下划线 `_`，$D$ 是 ASCII 数字。属于则输出 `yes`，否则输出 `no`。

题面另有一条“C 语言保留字不合法”，但**输入被保证不是保留字**，所以这条约束在本题中永远不发生，判定问题退化为纯粹的字符串形状判定。

以样例 `RKPEGX9R;TWyYcp` 为例（长度 15，下标从 0 到 14）：

| 下标 | 0 | 1 | … | 7 | 8 | … | 14 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 字符 | `R` | `K` | … | `R` | `;` | … | `p` |
| 属于 $L \cup D$？ | 是 | 是 | — | 是 | **否** | — | 是 |
| 判定 | 首字符合法，但第 8 位 `;` 既不是字母、数字也不是下划线 → 输出 `no` |

观察重点：第一位和其余位受**不同**的字符集约束，而“其余位”这条约束必须一直检查到最后一位。样例正好演示了“首字符通过、中段失败”这一类，它说明首字符的判定不能单独决定答案。

真实数据里还存在另一类：`63qn!&d2VQ7p08f` 与 `esoC_nOCd3tI`，前者首字符 `6` 直接出局（且后文还有 `!`、`&`），后者字母、下划线、数字混合全部通过。`x` 则是最短的正例，用来检验“只有首字符”这一端。

## 正解

### 思路

**第一版：逐条翻译题面。** 最直接的想法是把三条要求各写一段：

```python
ok = True
if s[0].isdigit():          # 不以数字开头
    ok = False
for ch in s:                # 只含字母、数字、下划线
    if not (ch.isalnum() or ch == '_'):
        ok = False
```

它的复杂度是 $O(n)$，读一遍输入即可给出答案。由于任何判定都要看完所有字符，$O(n)$ 已经是**理论下界**——本题不存在“朴素做法太慢、需要优化”的瓶颈，逐字符版本和最终版本是同一档复杂度、同一份算法，只是写法不同。这也是本文不设暴力层、不写 `brute.cpp` 的原因：它不会比正解更简单，也不会暴露正解消除了什么瓶颈。

真正需要修的是上面这段的**三个正确性坑**：

1. `'²'.isalnum()` 和 `'一'.isalnum()` 都返回 `True`——`str.isalnum()` 是 Unicode 语义，而 C 标识符只允许 ASCII 字母；
2. `s[0]` 在空串上会直接抛 `IndexError`；
3. 首字符被“条件 3”和“条件 2 的循环”各判一次，读代码的人要来回对照才知道最终由谁说了算。

**第二版：重排成合取式。** 注意条件 2 约束**全部**下标，条件 3 只约束下标 0，于是可以把它们重排成两句话：

> $s$ 合法 $\iff$ 第 0 个字符属于 $L$，**且** 每个字符都属于 $L \cup D$。

这一步是全文的关键观察：重排之后，“位置”从判定里消失了，剩下的两条各自都只是**字符集约束**——不含计数、不含跨位状态。一个只由字符集拼接而成的约束，恰好就是正则语言的形状：

$$s \in \texttt{[A-Za-z\_]}\;\texttt{[A-Za-z0-9\_]}^*$$

`*` 表示零次或多次，于是 $n = 1$ 的短串（如 `x`）由“首字符类 + 零次重复”覆盖，空串由“首字符类必须匹配一个字符”自然失败，两个边界都不需要额外分支。

**第三版：把字符集钉死在 ASCII，并锚定整串。** 直接落地成 Python 正则就是

```python
IDENTIFIER = re.compile(r'[A-Za-z_]\w*\Z', re.ASCII)
```

两个参数各自解决一个坑，缺一不可：

- `re.ASCII`：不加它，`\w` 会接受 Unicode 字母、数字（`²`、`一` 都算），等于把坑 1 原封不动搬进正则。加上后 `\w` 精确等于 `[A-Za-z0-9_]`。
- `\Z`：`re.match` 只锚定**开头**，`abc!` 会被 `[A-Za-z_]\w*` 匹配到前缀 `abc` 而错判成 `yes`。`\Z` 把匹配强行拉到串尾，保证是整串判定。

用 `\Z` 而不是 `fullmatch`，是因为它让“整串”这件事在表达式里**可见**：读者扫一眼模式就知道末尾有锚点，不必再去回忆 `match` 与 `fullmatch` 的语义差别。

最后把 `re.compile` 提到模块级。这样做不只是省一次编译：它让规则有了一处可命名的落点——读完 `IDENTIFIER` 那一行，全部判定条件就都看完了，`solve()` 里只剩读入和输出。

### 复杂度

- 时间复杂度：$O(n)$。无捕获组、无嵌套量词的单字符类正则，匹配成功与失败都是线性扫描；这是理论下界。
- 空间复杂度：$O(n)$，输入串本身；正则对象为 $O(1)$ 状态，无回溯栈增长。

## 总结

- 本题的约束（$n \leqslant 20$）说明它考的不是性能，而是**判定条件的精确表达**：能不能把“首字符一条规则、其余字符另一条规则、全部字符都要检查”这三件事一次说清。
- 关键动作是把条件重排成「首字符 $\in L$」$\wedge$「每个字符 $\in L \cup D$」。重排后位置信息消失，判定变成“整串属于某个正则语言”，一条表达式即可写完。
- 两个必须显式处理的陷阱：`str.isalnum()` / `\w` 的 **Unicode 语义**（用 `re.ASCII` 收窄），以及 `re.match` 的**前缀匹配**（用 `\Z` 锚定到串尾）。
- 边界 `n = 1` 与空串都由正则的量词语义自动覆盖，不需要特判；保留字条件由题面保证，不需要实现。
- 官方 10 组真实数据全量比对通过（`PASS=10, FAIL=0`，单测例约 0.018s / 14.5MB，限制为 1000ms / 128MB）。
- 同类问题的 C++ 落地建议：同样是“首字符单独判一次 + 其余字符循环判一次”，`isalnum()` 在 C++ 里本来就只认 ASCII，但要注意 `char` 的有符号扩展（`a[i] < 0` 时不要让它落进合法区间）——Python 侧用 `re.ASCII` 规避的正是同一类“字符集比预期更大”的问题。
