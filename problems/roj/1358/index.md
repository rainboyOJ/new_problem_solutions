## 形式化题目

给定一个以 `@` 结束的中缀表达式，字符集只有三类：

- 运算数：`0`-`9` 组成的非负整数，前面可以带一个一元负号 `-`（题面说明 `-` 也可作为负数的标志）；
- 运算符：`+`、`-`、`*`、`/`，其中 `* /` 优先级高于 `+ -`，同级从左到右结合；
- 括号：`(`、`)`。

要求先判定表达式是否**语法合法**（括号配对、运算符与运算数的位置正确）：不合法输出 `NO`；合法则把它转换成后缀表达式，再用**栈**求出它的值。题面明确「必须用栈操作，不能直接输出表达式的值」，所以不能用语言自带的求值器。`@` 只是结束符，取它之前的字符串即可——题面样例省略了 `@`，真实数据都带着它，两种写法都要接受。

运算按整数语义进行；参考实现的除法是 C++ `int / int`，向零取整。

题面样例与五组真实测试数据的判定结果如下（表达式已省略结尾的 `@`）：

| 表达式 | 输出 | 说明 |
| --- | --- | --- |
| `1+2*8-9` | `8` | 题面样例：$1+2\times8-9 = 1+16-9 = 8$ |
| `4+5-9+10*2` | `20` | 合法：$4+5-9+20 = 20$ |
| `(5*(5-9))+3-9-4` | `-30` | 合法：$5\times(-4)+3-9-4 = -30$ |
| `(5*5-9)+30-9+*4` | `NO` | `+` 后紧跟 `*`：运算符出现在了运算数的位置 |
| `-4+5-9+10/*2` | `NO` | 开头的 `-` 是合法一元负号，错在 `/` 后紧跟 `*` |
| `(5*(5-9)-4)+7-9*2` | `-35` | 合法：$-20-4+7-18 = -35$ |

合法与非法的分界不在字符集——非法表达式的每个字符单独看都合法，错的是**位置**。注意 `-4+5-9+10/*2` 里的一元负号与 `*`：`-4` 的 `-` 站在运算数的位置，是题面允许的负数标志；`10/*2` 的 `*` 同样站在运算数的位置，但运算数位置只允许数字、左括号和一元负号，所以判 `NO`。

## 正解

### 思路

最朴素的做法是**递归下降**：把文法拆成「表达式 → 项（`+`/`-` 项）*」「项 → 因子（`*`/`/` 因子）*」「因子 → 数字 | `(` 表达式 `)` | 一元负号 因子」，边解析边求值。它能算对，但语法分析与求值缠在一起，也没有完成题面要求的「先转后缀、全程用栈」。

真正的瓶颈在于：**中缀形式的求值顺序不等于阅读顺序**。`1+2*8` 中 `+` 先被读到却必须后算；括号会把外层的运算整体挂起。若在一次扫描里同时处理合法性、优先级、括号三层逻辑，每挂起一件事就要多记一份状态，极易写错。调度场算法把「重排」单独拆出来：输出队列记录已确定顺序的记号，运算符栈把「还没轮到」的运算符按优先级压着，扫描结束一次性弹出。对样例 `1+2*8-9`：

| 记号 | 动作 | 输出队列 | 运算符栈 |
| --- | --- | --- | --- |
| `1` | 运算数直接进队列 | `1` | 空 |
| `+` | 栈为空，直接入栈 | `1` | `+` |
| `2` | 运算数直接进队列 | `1 2` | `+` |
| `*` | 栈顶 `+` 优先级低于 `*`，不弹，入栈 | `1 2` | `+ *` |
| `8` | 运算数直接进队列 | `1 2 8` | `+ *` |
| `-` | 栈顶 `*`、`+` 都不低于 `-`，依次弹出，再入栈 | `1 2 8 * +` | `-` |
| `9` | 运算数直接进队列 | `1 2 8 * + 9` | `-` |
| 结束 | 弹空运算符栈 | `1 2 8 * + 9 -` | 空 |

这张表说明了四件事：`*` 没有立刻计算，是因为栈顶 `+` 的优先级不够，它必须压栈等待；`-` 到来时一次性弹出 `*` 和 `+`，这一步同时实现了「先乘除后加减」和「加减从左到右」；产出的后缀序列里已经没有括号和优先级的痕迹——顺序本身就编码了求值语义；每次弹出的运算符都先于当前记号、且两者之间没有未闭合的 `(`，所以输出序列保持了原式的全部运算顺序。

得到后缀序列后，求值只需一个操作数栈从左到右归约：压入 `1`、`2`、`8`，遇 `*` 弹出 $2\times8=16$ 压回，遇 `+` 弹出 $1+16=17$ 压回，压入 `9`，遇 `-` 弹出 $17-9=8$，栈里剩下的 `8` 就是答案。

合法性用一个**记号类别状态机**判定：`expect_operand` 记录当前位置该出现运算数还是运算符，`depth` 记录未闭合的左括号个数。运算数位置只接受数字、`(` 和一元负号，运算符位置只接受二元运算符和 `)`，于是「连续两个运算符」「空括号 `()`」「以运算符开头或结尾」「括号不配对」全都会落到当前状态不允许的记号上。不能图省事改成「相邻两个字符都是运算符就判 `NO`」：`2*-3` 中 `*` 与 `-` 相邻却是合法的负数写法，字符对判断会误杀它。

### 复杂度

- 时间复杂度：$O(n)$，$n$ 为表达式长度。切词校验、转后缀、求值三段各扫描一遍，每个记号入栈出栈各一次，与参考实现的单遍做法同阶。
- 空间复杂度：$O(n)$，记号序列、运算符栈、输出队列、操作数栈在最坏情况（如 `1+1+…+1`）下都与表达式长度同阶。

## 总结

- 表达式求值拆成三段流水线：状态机切词校验 → 调度场转后缀 → 操作数栈求值，每段一遍线性扫描；非法只有一个出口，`tokenize` 或 `eval_postfix` 返回 `None` 就打印 `NO`。
- 中缀的难题（优先级、括号）全部被「重排」吸收，后缀求值退化成机械归约；[[roj/1331]] 正是这条链路的后半段。
- 合法性判断要盯**位置**而不是字符对：运算数位置只允许数字、`(` 和一元负号。
- Python 的 `//` 是向下取整，与 C++ `int / int` 的向零取整在负数上差 1，除法必须单独处理（`-7/2` 要得 `-3` 而不是 `-4`）。
