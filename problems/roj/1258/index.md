## 形式化题目

给定一个 $R$ 层的数字金字塔，第 $i$ 层（$1 \leqslant i \leqslant R$）有 $i$ 个非负整数 $a_{i,1}, \dots, a_{i,i}$。
一条路径从 $(1,1)$ 出发，每步从 $(i,j)$ 走到 $(i+1,j)$ 或 $(i+1,j+1)$，走 $R-1$ 步后停在第 $R$ 层
（走满 $R-1$ 步行号必为 $R$，所以"到底部任意处结束"与"走到第 $R$ 层"等价）。
路径的权值定义为经过的所有点的数字之和，求权值的最大值。

## 正解

### 思路

最直接的做法是枚举所有路径。每步有两个选择，共 $R-1$ 步，所以路径数是 $2^{R-1}$。
写成递归就是：

```text
dfs(i, j) = a[i][j] + max(dfs(i+1, j), dfs(i+1, j+1))
```

这棵递归树是一棵满二叉树，节点数与路径数同阶。$R = 80$ 时已经不可能算完，
而题目允许 $R$ 到 $1000$。

**瓶颈在于子问题被重复求解。** 同一个点 $(i,j)$ 会被左上方的 $(i-1,j-1)$ 和右上方的 $(i-1,j)$
两个前驱分别递归到，越靠下的点被重复访问的次数越多，第 $R$ 层的点最多被访问 $2^{R-j}$ 次。
但每个点"往下走能取到的最大值"是唯一确定的，算一次就够了。

记 $f(i,j)$ 为**从 $(i,j)$ 出发走到第 $R$ 层能取得的最大数字和**。因为 $(i,j)$ 的第一步只有
两个去处，且从某个点出发的最优后缀与前缀怎么走来完全无关，所以：

$$f(R,j) = a_{R,j}, \qquad f(i,j) = a_{i,j} + \max\bigl(f(i+1,j),\, f(i+1,j+1)\bigr)$$

答案就是 $f(1,1)$。由于 $f(i,\cdot)$ 只依赖 $f(i+1,\cdot)$，可以从第 $R$ 层开始**自底向上**逐层递推，
不必递归。

下面用样例走一遍这个过程。原始金字塔与递推得到的 $f$ 值：

| $i$ | 原始 $a_{i,\cdot}$ | $f(i,\cdot)$ |
| --- | --- | --- |
| 1 | 13 | **86** |
| 2 | 11, 8 | 57, **73** |
| 3 | 12, 7, 26 | 39, 46, **65** |
| 4 | 6, 14, 15, 8 | 18, 27, **39**, 32 |
| 5 | 12, 7, 13, 24, 11 | 12, 7, 13, **24**, 11 |

表格每行左侧是金字塔原文，右侧是对应的 $f$ 值，加粗的是当前层的最优选择：
第 5 行 $f$ 就是它自己；第 4 行第 1 列是 $6 + \max(12,7) = 18$；
第 3 行第 3 列是 $26 + \max\bigl(f(4,3), f(4,4)\bigr) = 26 + \max(39,32) = 65$。

关键在于每层比较的**不是原始数字，而是已经含了后续最优的 $f$ 值**——这正是贪心会出错的地方：
第 2 行里 $11 > 8$，但 $f(2,1) = 57 < f(2,2) = 73$，局部选大反而全局更小。
从 $f(1,1) = 86$ 逐层挑较大的分支回溯，得到最优链 $13 \to 8 \to 26 \to 15 \to 24$，
与题面描述完全一致。

**再省一维空间。** 算第 $i$ 层时只用到第 $i+1$ 层的 $f$ 值，第 $i+2$ 层及以下已经永远不再需要，
所以不必开 $R \times R$ 的表。用一个长度为 $R$ 的一维数组 `best` 滚动即可：
`best[c]` 表示"从当前正在处理的这一层第 $c$ 列出发到底部的最大和"，每处理完一层就整体覆盖。
第 $i$ 层需要读的下标是 $c$ 和 $c+1$（$c$ 从 $0$ 到 $i-1$），都落在上一层仍然有效的范围内。
这里有个容易踩的坑：如果原地覆盖 `best`，覆盖方向必须是**从左往右**。处理第 $c$ 列时写入下标 $c$，
而它需要的是旧值 $c$ 与 $c+1$，二者此刻都还没被写过，所以安全；反方向（从右往左）写就会
先覆盖 `best[c+1]`，再用被污染的 $c+1$ 去算 $c$，得到错误答案——样例上会算出 116 而不是 86。
本解用列表推导式，先算完整个新列表再赋值，读旧写新，天然规避这个顺序问题。

### 复杂度

- 时间复杂度：$O(R^2)$。第 $i$ 层做 $O(i)$ 次转移，总计 $\sum_{i=1}^{R} i = \frac{R(R+1)}{2}$。
- 空间复杂度：$O(R)$（DP 滚动数组；保存全部输入另需 $O(R^2)$，$R \leqslant 1000$ 时为约 50 万个整数）。

## 总结

- 数塔问题是"最优子结构 + 无后效性 + 重叠子问题"的最小完整例子，也是记忆化搜索的入门模型。
- 转移方程 $f(i,j) = a_{i,j} + \max(f(i+1,j), f(i+1,j+1))$ 中比较的是 $f$ 而不是 $a$，
  这是从贪心走向 DP 的关键一步。
- 自底向上递推可以天然消除递归，再用滚动数组把空间从 $O(R^2)$ 降到 $O(R)$。
- 滚动数组若改成原地 `for` 循环覆盖，**必须从左往右**：第 $c$ 列要读旧的 $c$ 与 $c+1$，
  而写入位置 $c$ 都排在它们之前。反过来从右往左写会先污染 `best[c+1]`，答案直接算错。
  列表推导式先求值后绑定，读旧写新，天然不存在这个顺序陷阱。

## 图示解析

下图标出 $(i,j)$ 的两个后继坐标与自底向上的递推方向：

```text
            (1,1)                     递推方向 ↑
           /     \                    f 值自下而上计算
       (2,1)     (2,2)
       /   \     /   \
   (3,1)  (3,2)  (3,3)  ...
    ...     ...    ...   ...
   (R,1) ...  ...  ... (R,R)          起点：f(R,j) = a[R][j]

  后继关系：(i,j) -> 左下方 (i+1,j)、右下方 (i+1,j+1)
  即 best[c] 由上一层的 best[c] 与 best[c+1] 共同决定
```

观察重点是每个点只被下一层的两个点引用，因此按层逆序求解时任何时刻只需保留一层。
图中 $(3,2)$ 同时是 $(2,1)$ 和 $(2,2)$ 的后继，这正是朴素递归重复计算同一个子问题的根源；
DP 把它压成"每个状态只算一次"，于是总代价从指数级降到 $O(R^2)$。
