## 形式化题目

容量为 $N$ 的内存，地址 $0, 1, \dots, N-1$ 连续排列。有 $n$ 个进程，每个进程给出三元组 $(T, M, P)$：在时刻 $T$ 申请 $M$ 个单元、上机后连续占用 $P$ 个时间单位，即占据区间 $[T',\ T'+P)$，其中 $T'$ 是它**实际拿到内存**的时刻（可能晚于申请时刻）。数据保证 $M \leqslant N$，且申请时刻非降。

分配与等待规则：

1. **分配**：某进程申请时，若存在能容纳 $M$ 个单元的空闲地址片，立刻分配，并取**首地址最小**的那一片（等价于：地址序扫描第一个长度 $\geqslant M$ 的空闲块，从它的起点切走 $M$ 个单元，余量留在原地）。
2. **入队**：放不下则进入等待队列尾部。**队头优先级最高**——只要任一时刻存在容纳得下队头的空闲片，队头立刻出队上机；队列中其它成员不得先于队头被处理。
3. **归还**：进程在 $T'+P$ 时刻结束，占用的单元立刻变回空闲。

求两个全局量：全部进程都运行完毕的时刻，以及**被放入过等待队列的进程总数**（只要进过队列就计入）。

样例（$N = 10$）：

```text
输入：
10
1 3 10
2 4 3
3 4 4
4 1 4
5 3 4
0 0 0

输出：
12
2
```

输出 `2` 表示有两个进程进过队列：`(3,4,4)` 因当时最长空闲只有 3 而入队，`(5,3,4)` 到达时只差 1 格也入队。结束时刻 `12` 来自最后上机的 `(5,3,4)`：它在时刻 8 才拿到内存，$8 + 4 = 12$。逐时刻推演见下文思路中的表格。

## 正解

### 思路

**先看最直观的做法。** 模拟分配过程，最容易想到的是**沿时间轴逐格推进**：`now` 从 0 每单位时间加一，每个时刻检查有没有进程该归还、有没有进程到达、队头能不能上机。这个做法只在"时间跨度"上花功夫，而题面里 $T$、$P$ 都能到 $10^9$——实测数据的结束时刻有 $35970882$ 这样的量级，逐格推进根本跑不完。**瓶颈很明确：工作量被时间跨度绑架了，而真正有意义的规模是进程数 $n \leqslant 10000$。**

**改成逐事件推进。** 状态只在"事件时刻"变化：两个事件之间，内存布局、队列内容纹丝不动。所以每次直接跳到下一个事件时刻：

$$\text{下一事件时刻} = \min(\text{下一到达时刻},\ \text{最早释放时刻})$$

- **到达事件**已按 $T$ 升序给出，用下标顺扫即可；
- **释放事件**在进程上机时才产生，用小根堆按"结束时刻"排序（二叉堆标签的由来）；
- **派发事件**不必单独排队：它只可能紧随内存状态变化发生，把"队头放得下就立刻上机"实现成**每次释放之后的循环检查**即可，"任一时刻"的无限语义就降成了有限个离散检查点。

事件总数是 $n$ 次到达 $+$ $n$ 次释放 $+$ 至多 $n$ 次队头派发，与 $10^9$ 的时间跨度无关。

**同一时刻的处理顺序是本题的正确性核心。** 题面没写"同一时刻先做什么"，顺序选错输出就变，只能用样例反推，得到固定三步：

1. **先释放**：$T'+P$ 时刻占用已结束，同一时刻的进程可以立即使用这块内存（样例里 $t=5$ 时 B 归还 $[3,7)$ 后，这块空间才存在）；
2. **再派发队头**：反复执行"队头放得下就上机"，直到放不下。若颠倒成"先处理到达"，$t=5$ 到达的 `(5,3,4)` 会 first-fit 抢走刚归还的 $[3,7)$，队头 `(3,4,4)` 只能继续等，结束时刻变成 $13 \ne 12$；
3. **最后处理到达**：放不下才入队并计数。注意**到达者可以越过队头**——$t=4$ 时队头 `(3,4,4)` 需要 4、空闲只有 $[7,10)$ 长 3，而到达的 `(4,1,4)` 只要 1，它直接拿走 $[7,8)$；若强制"队头放不下时到达者也得排队"，进队总数会变成 $3 \ne 2$。**"不能越过队头"只约束队列内部成员，新到达走的是另一条申请通道。**

**空闲区怎么维护。** 分配要"首地址最小"，归还要"与相邻空闲块合并"，两者都要求空闲区按地址有序——这正是题面"链表"标签的用意：C++ 里是一条地址升序的空闲块链表，Python 里用 `bisect` 维护的升序列表同样成立：

- `alloc(need)`：沿地址序扫第一个 `size >= need` 的块，从起点切走 `need`，整块用尽就删除；
- `release(start, size)`：`bisect` 定位插入点，若与左邻**首尾恰好相接**（`左首 + 左长 == start`）或与右邻相接（`右首 == start + size`）就先合并再插回。

占用区只需一个按结束时刻的小根堆，等待队列只需一个 FIFO `deque`——只有队头会被尝试分配。

下表把官方样例完整走一遍，每行展示该时刻按"释放 → 队头 → 到达"三步处理后的内存与队列（空闲片/占用区间均写作 `[首地址, 尾地址)`，`→` 后是该进程的结束时刻）：

| 时刻 | 发生了什么（按释放 → 队头 → 到达） | 处理后空闲片 | 占用中的进程 | 等待队列（累计进队） |
| --- | --- | --- | --- | --- |
| 1 | A `(3,10)` 到达，first-fit 分到首地址 0 | `[3,10)` | A `[0,3)→11` | — （0） |
| 2 | B `(4,3)` 到达，分到首地址 3 | `[7,10)` | A，B `[3,7)→5` | — （0） |
| 3 | C `(4,4)` 到达：最长空闲 3 < 4，入队 | `[7,10)` | A，B | C （1） |
| 4 | 队头 C 放不下（需 4）；D `(1,4)` 到达，越过后分到首地址 7 | `[8,10)` | A，B，D `[7,8)→8` | C （1） |
| 5 | B 归还 `[3,7)`；队头 C 立刻分到 `[3,7)`；E `(3,4)` 到达，放不下入队 | `[8,10)` | A，C `[3,7)→9`，D | E （2） |
| 8 | D 归还 `[7,8)`，右并成 `[7,10)`；队头 E 分到 `[7,10)` | 空 | A，C，E `[7,10)→12` | — （2） |
| 9 | C 归还 `[3,7)` | `[3,7)` | A，E | — （2） |
| 11 | A 归还 `[0,3)`，左并成 `[0,7)` | `[0,7)` | E | — （2） |
| 12 | E 归还 `[7,10)`，并成整段 `[0,10)`，全部结束 | `[0,10)` | 无 | — （2） |

重点看第 4、5 行：第 4 行证明**到达者能越过放不下的队头**（否则 D 也进队，计数变 3）；第 5 行证明**同一时刻队头先于到达拿到刚释放的内存**（否则 E 抢走 `[3,7)`，结束时刻变 13）。两行合起来就是三步顺序的完整依据，其余各行只是 first-fit 与合并的机械执行。

### 复杂度

- 时间：$O(n \cdot B)$，其中 $n$ 为进程数、$B$ 为并存空闲块数；事件 $O(n)$ 个，每次分配沿地址序扫描 $O(B)$，每次归还 $O(\log B)$ 查位加 $O(B)$ 的列表搬运。最坏 $O(n^2)$，与 C++ 正解（空闲块链表 first-fit 线性扫描 + 释放二叉堆）同阶；实测 $B$ 远小于 $n$，5 组真实数据单例 0.019–0.084s。
- 空间：$O(n)$，空闲块表 $O(B)$，释放堆与到达数组各 $O(n)$，等待队列 $O(n)$。

### 正确性

- **内存账本不撒谎**：`alloc` 只从空闲块**前端**切走单元，块要么消失要么起点右移，不会产生重叠；`release` 归还的是刚结束进程的真实占用区，且只与**恰好首尾相接**的邻居合并，不会跨过仍被占用的区段误并。两者维持"占用 $\cup$ 空闲 $= [0, N)$ 且互不相交"。
- **队列语义精确**：`wait` 是 FIFO，只有队头会被 `alloc` 尝试，放不下立即 `break`，队列内不可能插队；而新到达走独立的申请路径，对应"到达者可越过队头"。
- **事件不漏不重**：`now` 取"下一到达"与"堆顶释放"的较小值，保证不会跳过任何释放；到达按升序逐个消费；弹空 `结束时刻 == now` 的堆顶后，该时刻的释放必然全部完成。三步顺序正是样例反推出的题面语义。
- **必然终止且答案正确**：每轮要么消费一个到达、要么至少弹出一个释放，下标与堆都单调推进；循环退出即"到达扫完且堆空"，此时 `now` 恰是最后一个归还时刻，也就是全部进程运行完毕的时刻。

## 总结

本题的本质是**把"逐时间格模拟"改写成"逐事件模拟"**：状态只在事件时刻变化，于是下一事件时刻取"下一到达"与"堆顶释放"的最小值，工作量从 $10^9$ 的时间跨度降到 $O(n)$ 的事件数。题面的三条规则各对应一个结构——"首地址最小"对应**地址升序空闲块表上的 first-fit 扫描**，"$T'+P$ 归还"对应**释放小根堆**，"队头最高优先"对应**FIFO 队列加派发循环**。最容易做错的是同一时刻的顺序：**释放 → 派发队头 → 处理到达**，且**到达者可以越过放不下的队头**——这一条只能从样例的 `12 / 2` 反推出来，是全题的题眼。

## 图示解析

这张图串起本题从读入到得到答案的主线：

```text
读入 N 与按 T 升序的 (T, M, P) 列表
   `- 事件推进：now = min(下一到达时刻, 堆顶释放时刻)
      |- 1) 释放：弹出所有 结束==now 的占用区，release 按地址插回并与左右邻居合并
      |- 2) 派队头：while 队头 alloc 成功 -> 上机，结束时刻入堆
      |      `- 一旦放不下立即停止；队列内其它进程不得插队
      `- 3) 到达：alloc 成功 -> 上机入堆
             `- alloc 失败 -> 进队尾并计数（到达者不受队头约束，可拿走队头放不下的小空闲片）
   `- 到达扫完 且 释放堆为空 -> now 即全部进程运行完毕的时刻，queued 即进队总数
```

先看事件节点：`min` 把"已排序的到达"和"小根堆里的释放"合成一条单调时间线，这是逃离 $10^9$ 时间跨度的唯一入口。中间三个分支是固定顺序的三步，注意第 2 步的 `while` 与第 3 步的失败分支**不对称**：队头只能被队列内部的循环服务，而新到达失败才入队、成功就绕过队列——样例的 `12 / 2` 恰好各验证了其中一半。最后一个节点说明答案的读法：结束时刻来自"堆被排空的那一刻"，进队总数来自第 3 步失败分支的累计。
