## 形式化题目

给定两个十进制非负整数 $a, b$，各不超过 $200$ 位（无多余前导 $0$），求乘积

$$c = a \times b$$

并输出 $c$ 的十进制表示（同样不允许多余前导 $0$）。样例：$12345678900 \times 98765432100 = 1219326311126352690000$。

问题的全部难点在数值范围：$200$ 位十进制数约需 $664$ bit，乘积最多约 $400$ 位（约 $1329$ bit），任何 64 bit 整数类型都装不下，必须采用"高精度"表示。

## 正解

### 思路

**一句话本质**：Python 的 `int` 本身就是任意精度整数，`a * b` 直接给出精确的（最多约 $400$ 位的）乘积——读入、相乘、输出，三行完成。

先看这题在 C++（一本通）环境下的标准做法，它也是理解本题的唯一"算法内容"：**竖式乘法**。把两数按十进制位拆开，$a = \sum_i a_i 10^i$，$b = \sum_j b_j 10^j$，展开乘积：

$$ab = \sum_{i,j} a_i b_j \cdot 10^{i+j}$$

也就是每一位对每一位相乘，把 $a_i b_j$ 累加到结果的第 $i+j$ 位，最后从低位到高位统一进位。用一个小规模例子 $25 \times 4$ 演示"贡献表"（行是 $a = 25$ 的各位，列是 $b = 4$ 的各位，单元格是"贡献值 → 落在结果的哪一位"）：

| 贡献 | $b$ 的第 0 位 $= 4$ |
| --- | --- |
| $a$ 的第 0 位 $= 5$ | $5 \times 4 = 20 \to 2 \times 10^1 + 0 \times 10^0$ |
| $a$ 的第 1 位 $= 2$ | $2 \times 4 = 8 \to 8 \times 10^1$ |

表里行、列分别是 $a$、$b$ 的十进制位，单元格是该位对乘上后的"原始贡献"及其按位拆分。累加各单元格：第 0 位合计 $0$，第 1 位合计 $2 + 8 = 10$——满十进一，第 1 位留 $0$、向第 2 位进 $1$，得 $100$，即 $25 \times 4 = 100$。真实数据中 $a$、$b$ 各约 $200$ 位，这张表就是 $200 \times 200 \approx 4 \times 10^4$ 个单元格，竖式算法对每个单元格做一次一位乘法和一次累加，故为 $O(nm)$。

**问题？** Python 还需要手写这张表吗？

不需要，但要说清楚"为什么不需要"而不是"懒得写"。上面整套"按位展开 → 多项式乘法 → 进位规整"是**进位制的代数性质**，与语言无关；CPython 的 `int` 恰好把这套性质做进了类型语义里：内部用 $2^{30}$ 为基的"数字数组"存储任意大的整数，`*` 运算完成的就是同构的乘法（大数时还升级为 Karatsuba 分治，$O(N^{1.585})$，严格不劣于竖式）。所以"字符串 → `int()` → `*` → `str()`"就是竖式算法的完整等价物，一步都没有省略，只是把实现下推给了语言——这正是用 Python 做 OJ 题时最该利用的语义红利。

**问题？** 前导 0 和边界怎么处理？

三层都免费：解析侧题面保证输入无前导 0（即便有，`int("0086")` 也解析为 $86$，行为安全）；计算侧 $0 \times x = 0$ 精确成立（题面允许非负数，`0` 是合法输入）；输出侧 `str(int)` 是"最简表示"，天然无前导 0。唯一要避开的是浮点路线（如 `float(a) * float(b)`）——只有约 15--16 位有效数字，200 位输入会直接失真，整数运算必须全程留在 `int` 上。

### 复杂度

- 时间复杂度：竖式 $O(nm)$，$n = m = 200$ 时约 $4 \times 10^4$ 次位乘；CPython 对大整数乘法使用 Karatsuba，$O(N^{1.585})$（$N$ 为内部 $2^{30}$ 基的位数，200 位十进制数约 23 位），与 C++ 正解同阶或更优。实测单点约 $0.017$ s。
- 空间复杂度：$O(n + m)$，保存两个操作数与最多约 400 位的结果。

## 总结

本题是"高精度乘法"的模板题，考的是**数值范围意识**：200 位乘 200 位得 400 位，任何固定宽度类型都会溢出。C++ 的解法是把两数按位拆成数组做 $O(nm)$ 竖式乘法再统一进位；而 Python 的 `int` 是任意精度整数，`a * b` 在语义层就是这套竖式的精确等价物（大数还自动走 Karatsuba），于是全程序只剩"读入、相乘、输出"三行，前导 0 也由 `int`/`str` 的最简表示免费解决——只需避开浮点路线。实测 10 组真实数据（位长 150--195）全部一致，单点约 0.017 s、峰值内存 14.5 MB，相对 1000 ms / 128 MB 的限制十分宽裕。
