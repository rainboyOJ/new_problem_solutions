## 形式化题目

给定 $n$ 条病人记录（$n < 200$），每条记录包含三个字段：姓名（字符串，不含空格，最多 8 个字符）、体温（实数）、是否咳嗽（整数，1 表示咳嗽，0 表示不咳嗽）。

按输入顺序输出所有满足"体温 $\geqslant 37.5$ **且** 咳嗽"的病人姓名（每行一个），最后再输出一行入选人数。

## 正解

### 思路

$n < 200$，且每个病人是否入选只依赖自己的三个字段，判定一次 $O(1)$，所以对全部记录做一次线性扫描、用谓词过滤就是最终做法——不存在"朴素做法暴露瓶颈、再逐步消除"的优化链。本题真正的练习价值在于**混合类型输入的解析**和**条件边界的准确翻译**。

先用样例把谓词的两种失败方式和边界看清楚：

| 姓名 | 体温 | 咳嗽 | 体温 $\geqslant 37.5$？ | 判定 |
| --- | --- | --- | --- | --- |
| Zhang | 38.3 | 0 | 是 | 淘汰：不咳嗽 |
| Li | 37.5 | 1 | 是（恰好等于） | **入选** |
| Wang | 37.1 | 1 | 否 | 淘汰：体温不够 |
| Zhao | 39.0 | 1 | 是 | **入选** |
| Liu | 38.2 | 1 | 是 | **入选** |

这张表逐个病人演示"体温达标且咳嗽"的与关系：Zhang 体温够但不咳嗽、Wang 咳嗽但体温不够，都被淘汰——两个条件缺一不可；Li 的体温恰好等于 37.5 仍然入选，说明题面"含等于 37.5 度"必须翻译成 $\geqslant$。这个比较也不用担心浮点误差：$37.5 = 75/2$ 在二进制浮点下可以精确表示，`float("37.5") >= 37.5` 必然成立；而 37.51 这类不可精确表示的小数，解析误差只有 $10^{-15}$ 量级，远小于它到边界的 $0.01$，比较结果不会翻转。

实现按"读入 → 判定 → 输出"三段展开：

1. **读入**：`sys.stdin.buffer.read().split()` 把整份输入按空白切成 token 流。一行虽有三种类型，但它们是独立的 token——姓名 `decode()` 成 `str`，体温 `float()` 转换，咳嗽标记直接与 `b'1'` 比较得到布尔值（token 是 `bytes`，与题面的 1/0 语义一致），不必按行拆分。
2. **判定**：`if temp >= THRESHOLD and cough`，成立就把姓名 `append` 进 `flu` 列表，天然保持输入顺序。
3. **输出**：把 `str(len(flu))` 接到名单末尾，`'\n'.join(...)` 一次 `print` 出全部行；即使没有病人入选，结果也是单独一行 `0`，不会漏掉人数行。

### 复杂度

- 时间复杂度：$O(n)$，每个病人读 3 个 token、做一次谓词判定，$n < 200$。
- 空间复杂度：$O(n)$，`flu` 列表最多存 $n$ 个姓名。

## 总结

- 本题是"一次扫描 + 谓词过滤"的最小模拟题：判定与判定之间无依赖，$O(n)$ 就是终点，没有暴力到正解的推导链。
- 混合类型行（`str` / `float` / `int`）在 token 化之后各转各的类型；判断 1/0 标记时直接与 `b'1'` 比较，比先 `int()` 再比大小更直白。
- 边界"含等于 37.5 度"对应 $\geqslant$；选 37.5 这样的二进制可精确表示数做阈值，浮点比较不会出错。名单和人数合并成一个字符串列表再 `join` 输出，是 Python 里"多行输出"的常用收尾写法。
