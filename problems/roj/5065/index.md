## 形式化题目

给定两个正整数 $a$ 和 $b$（**实测 10 个测试点中最大值为 2147483647，即 32 位 `int` 上限 `INT_MAX`；未出现 `INT_MIN` 和负数**），交换它们的值，并按交换后的顺序输出。

## 正解

### 思路

这道题目是关于变量赋值与数值交换的基础题。通常有以下几种处理方式：
1. **引入临时变量**：定义一个第三个变量 `t`，将 $a$ 的值赋给 `t`，将 $b$ 的值赋给 $a$，最后将 `t` 的值赋给 $b$。即 `t = a; a = b; b = t;`。
2. **语言特性**：在 C++ 中可以直接使用内置函数 `std::swap(a, b)`；在 Python 中可以使用多重赋值 `a, b = b, a`。
3. **改变输出顺序**：在仅仅为了得到正确输出的场合，也可以直接先输出 $b$，再输出 $a$。

作为经典的入门例题，理解“借助空杯子（临时变量）来交换两杯水”的思路最为重要。本题通过临时变量（C++）或元组解包（Python）完成变量赋值交换，不限制实现手段（机械判据全空）。

## 总结

- **算法与输出格式**：核心为交换两个变量的值后输出（即输出先 $b$ 后 $a$）。输出格式为两个数由单空格分隔，无多余文字、行尾无空格，末尾仅有一个 `\n`。
- **判别点与一致性验证 (V1)**：10 个数据点中有 8 个具有判别力（$a \ne b$，`p3`-`p10`），2 个无判别力（$a = b$，`p1`/`p2`）。在 V1 反事实测试（关掉交换逻辑）下，结果为 `PASS=2 FAIL=8`，失败点恰为这 8 个判别点。**失败点集合与判别点集合精确吻合**，证明交换操作承担了全部业务逻辑，无其他干扰因素。
- **加法交换的“UB 但不显形” (V9)**：若使用加法交换（`a = a+b; b = a-b; a = a-b;`），由于包含 `INT_MAX` 的测试点，在 `p2`/`p7`/`p8`/`p9`/`p10` 共 5 个点上会被 UBSan 报 `signed integer overflow`，且在 `-ftrapv` 参数下 `p2` 会直接 `Abort trap: 6`。但**实际运行输出却 10/10 全对**（受补码回绕影响恒等式依然成立），属于**“UB 但不显形”**——即**输出比对完全测不出这个坑**。当前的正式实现使用了无算术运算的临时变量，UBSan 10/10 报错全空，安全无 UB。
- **类型选择规范**：数据观测显示 $\max = \text{INT\_MAX}$ 且无负数。由于本题**只做赋值、无任何算术运算**，故 **`int` 也能过且不溢出**（实测 `int` 版 10/10 逐字节正确且 UBSan 全空）；最终代码中使用 `long long` 仅是**遵循本仓「题目数据默认 `ll`」的规范**，而非为了修 bug。真正的正确性陷阱只有加法交换引起的溢出。
- **算法选择判据**：题面三步机械判据全空（无强制使用的关键字，无括号算法名指定），故不硬性限制实现手段。
