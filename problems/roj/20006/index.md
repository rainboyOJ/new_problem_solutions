## 形式化题目

给定文本 $T$，把其中的 ASCII 双引号 `"` 按从左到右的顺序编号（跨行连续计数），设共
$n \geqslant 0$ 个。要求输出新文本：

- 非双引号字符原样保留（单引号 `'`、反引号都不参与计数与替换）；
- 第 $i$ 个双引号：$i$ 为奇数时换成 TeX 左双引号 ``` ``` `` ```，$i$ 为偶数时换成
  TeX 右双引号 `''`。

样例输入第一行有 3 个双引号，替换后：

```text
输入："To be or not to be," quoth the Bard, "that
输出：``To be or not to be,'' quoth the Bard, ``that
```

（完整样例见 `problem.md`。）

## 正解

### 思路

**朴素做法**：从左到右单遍扫描，维护一个布尔量"下一个双引号是开还是闭"，遇到 `"` 就
输出 ``` ``` `` ``` 或 `''` 并翻转状态，否则原样输出。这已经是 $O(n)$，没有性能瓶颈——
本题不存在"先写暴力、再优化"的层次，写一个 brute 只会得到与正解几乎相同的代码，
所以本文不设暴力层。

**关键观察**：一个双引号是开是闭，只由它的**序号奇偶**决定，与它所在行、前后文、
其它引号字符完全无关。想靠上下文猜也不行：若规定"前一个字符是空格就当开引号"，
测试数据第 5 组的 `strictly "remember. "` 里空格后的引号其实是闭引号，规则当场失效；
而 `` `C' `` 中的反引号与单引号根本不该计数。唯一可靠的规则就是数序号。

**把状态换成数据结构**：按双引号切分全文，交替就变成"切分段与引号对的两两配对"，
计数器直接消失。样例 1 的 6 个双引号逐个看：

| 序号 | 所在上下文（节选） | 奇偶 | 替换结果 |
| --- | --- | --- | --- |
| 1 | 行首 `"To be or not to be,` | 奇 | ``` ``` `` ``` |
| 2 | `be," quoth the Bard,` | 偶 | `''` |
| 3 | 行尾 `Bard, "that` | 奇 | ``` ``` `` ``` |
| 4 | 次行 `is the question".` | 偶 | `''` |
| 5 | `replied: "I must disagree.` | 奇 | ``` ``` `` ``` |
| 6 | 末行 `The Question!"` | 偶 | `''` |

这张表说明两点：奇偶严格交替；序号跨行连续——第一行就有 3 个引号（奇数个），
而第 5、6 个分处两行，所以判断必须依赖全文序号，既不能只数某一行，也不能按上下文猜。切分后第 $i$ 个双引号恰好落在第 $i$ 段末尾，
用 `itertools.cycle` 无限产出 ``` ``` `` ```、`''` 与各段配对，`zip` 以有限的段列表收尾，
正好拼出 $n$ 个引号，不会给最后一段多加。

两个边界顺手处理：输入可能没有结尾换行（测试数据 `p2.in` 就是 `""` 两个字节），因此用
`sys.stdout.write` 原样写出而不 `print`；没有双引号时切分结果只有首段，拼接为空串，
输出等于输入。

### 复杂度

- 时间复杂度：$O(n)$，$n$ 为输入长度：`split`、`join` 各扫一遍，每个双引号常数次操作，
  与朴素单遍扫描同阶。
- 空间复杂度：$O(n)$，保存切分段与拼接结果；测试数据最大 3.4 KB，远低于 128 MB 限制。

## 总结

- 双引号的开闭只看序号奇偶：第奇数个换左引号 ``` ``` `` ```，第偶数个换右引号 `''`，
  其余字符原样输出。
- 正确性靠"数序号"而不是猜上下文：单引号、反引号不计数，跨行的引号继续连着数。
- `split('"')` 把全文切成 $n+1$ 段，`zip(cycle(...), parts)` 一行完成交替拼接，
  不需要手维护计数器；`sys.stdout.write` 保证不补换行。
- 验证：真实测试数据 `p1..p5` 全部 PASS（约 0.02 s/组，峰值约 14.6 MB，远低于
  1000 ms / 128 MB 限制）。
