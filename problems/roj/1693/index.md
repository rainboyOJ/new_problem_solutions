## 形式化题目

给定 $n$ 个长度均为 $m$ 的字符串 $a_1, a_2, \dots, a_n$，每个字符取 `N` 或 `Y`，
以及三个整数 $p, q$（$0 \leqslant p, q$ 且 $p + q \leqslant n$）。
记 $\mathrm{comp}(s)$ 为把 $s$ 中每一位 `N`/`Y` 互换得到的串（$m \geqslant 1$，所以始终有 $\mathrm{comp}(s) \neq s$）。

求长度 $m$ 的字符串 $s$，使

$$
\#\{\,i : a_i = s\,\} = p, \qquad \#\{\,i : a_i = \mathrm{comp}(s)\,\} = q,
$$

在所有这样的 $s$ 中取**字典序最小**者；若一个都不存在则输出 `-1`。

题面里"其余神犇既非满分也非零分"不是额外约束：一旦 $s$ 定下来，每个人都按自己的答案自动
归入满分 / 零分 / 其他三类，$p, q$ 恰好就是上面两个计数。所以整个题目就是**计数恰好匹配**。

两个关键点：

1. 字典序按字符的 ASCII 比较，即 `N < Y`。题面没有明说，但数据第 2 个测点
   （$n = 2, m = 2, p = q = 0$，输入 `NN`、`YY`，答案是 `NY`）正是这个顺序的证据：
   若 `Y < N` 就该输出 `YN` 了。
2. 因为 $m \geqslant 1$，$s$ 与 $\mathrm{comp}(s)$ 必不相等，满分集合与零分集合不会有交叉。

## 正解

### 思路

**先看 $p > 0$。** 满分的人写出的答案就是标准答案，所以 $s$ 必须是某个人写过的串；
又恰有 $p$ 个人满分，所以

$$\mathrm{cnt}[s] = p,$$

其中 $\mathrm{cnt}[x]$ 表示 $x$ 在输入中的出现次数（没出现则为 $0$）。零分条件同理写成
$\mathrm{cnt}[\mathrm{comp}(s)] = q$。于是做法很直接：把所有**出现次数恰为 $p$** 的去重串当作候选，
逐个检查它的反串是不是恰出现 $q$ 次，在通过的候选中取字典序最小。输入里出现次数不是 $p$ 的串
一定当不了标准答案，全部直接排除。如果 $p > 0$ 却一个候选都没有，答案就是 `-1`。

**再看 $p = 0$ 且 $q > 0$。** 此时 $s$ 一次都没在输入里出现过，但它的反串必须出现恰 $q$ 次。
反过来枚举输入中**出现次数恰为 $q$** 的去重串 $x$，则唯一的可能是 $s = \mathrm{comp}(x)$；
再补一个检查 $\mathrm{cnt}[s] = 0$。这个检查不能少：$\mathrm{comp}$ 是自身的逆运算，若 $x$ 与 $s$
都在输入里，则 $\mathrm{cnt}[\mathrm{comp}(s)] = \mathrm{cnt}[x] = q$ 看着像合法解，实际会让
$\mathrm{cnt}[s] > 0 = p$，必须排除。这里 $s$ 不必在输入里出现，所以候选不能再从输入里挑。

**最后是 $p = q = 0$。** 此时 $s$ 与 $\mathrm{comp}(s)$ 都不能出现在输入里，候选从原本的
"输入里挑一个"变成了"在 $2^m$ 个串里任挑一个"，量级上没法枚举。把约束统一成一个**禁止集合**

$$F = A \cup \mathrm{comp}(A), \qquad A = \{\,a_1, \dots, a_n\,\} \text{ 去重},$$

那么要求就是"挑一个不在 $F$ 里的长度 $m$ 串，且字典序最小"。这里 $|F| \leqslant 2n$，
在 $2^m$ 个串里只占极小一撮，所以解通常大量存在。

字典序最小可以**逐位贪心**：从空前缀 $P$ 出发，每一位先试 `N` 再试 `Y`，只要"以当前前缀开头的
串里还有没被禁的"就定下这一位。判断"还能延伸"只需要一个计数：

> 长度为 $d$ 的前缀 $P$ 之下共有 $2^{m-d}$ 个长度 $m$ 的串。若 $F$ 中以 $P$ 为前缀的串有
> $b$ 个，则还有 $2^{m-d} - b$ 个可用，$b < 2^{m-d}$ 就等价于"这个前缀可行"。

因为 $F$ 已经排序，以 $P$ 为前缀的串恰好是 $F$ 里连续的一段——从 `lower_bound(P)` 到
`upper_bound(P + "ZZZ…Z")`（`Z` 比 `N`、`Y` 都大，补满 `Z` 就是该前缀的上界）。
而且这一段一定包含在上一层前缀对应的段里，所以二分时只要在当前 $[\mathrm{lo}, \mathrm{hi})$
区间内查找，区间越缩越窄。$p = q = 0$ 时第一层若连 `N` 和 `Y` 都走不通（等价于 $|F| = 2^m$），
就是无解输出 `-1`。

三个分支各自用一个候选规则，合起来覆盖了 $p, q$ 的全部取值：

| 情况 | $s$ 是否出现在输入中 | 候选怎么来 | 附加检查 |
| :-: | :-: | :-: | :-: |
| $p > 0$ | 必须出现 | $\mathrm{cnt} = p$ 的去重串 | $\mathrm{cnt}[\mathrm{comp}(s)] = q$ |
| $p = 0 < q$ | 必须不出现 | $\mathrm{cnt} = q$ 的去重串取反 | $\mathrm{cnt}[s] = 0$ |
| $p = q = 0$ | 必须不出现 | 前缀计数贪心现场构造 | 逐位确保 $\text{可用} > 0$ |

前两种情况的枚举在代码里合并成了一趟：对每个出现过的串 $x$，把 $s = x$ 与 $s = \mathrm{comp}(x)$
都放进候选池，再用 $\mathrm{cnt}[s] = p \wedge \mathrm{cnt}[\mathrm{comp}(s)] = q$ 统一筛选。
合并不漏解，因为任何合法 $s$ 至少让 $s$ 与 $\mathrm{comp}(s)$ 之一在输入中出现过
（否则 $s$ 就落进 $p = q = 0$ 的情形了），于是它总会被某个 $x$ 生成出来；
而 $p = q = 0$ 时这个筛选会拒绝所有候选，正好交给贪心分支。

**为什么每位的判断是充分的？** 设当前前缀 $P$ 可行（即存在长度 $m$ 的不受禁串以 $P$ 开头）。
若 $P + \texttt{N}$ 不可行，说明以它开头的 $2^{m-d-1}$ 个串**全部**落在 $F$ 里；
那么所有以 $P$ 开头的不受禁串必然以 `Y` 开头，故 $P + \texttt{Y}$ 一定可行。
所以"先试 `N`，不可行再试 `Y`"，只要还有解就绝不会走到两位都不可行的死路；
每一步都选了字典序更小的可行前缀，最终得到的正是全局字典序最小的串。
反过来若两位都不可行，则 $P$ 下方一个可用串都没有，与 $P$ 可行矛盾，说明一开始就无解。
实现里还额外检查了"两位都不可行就返回无解"，这只是在第一层真正无解时给出 `-1`，
逻辑上不会误伤有解的情形。

再看题面样例 $n = 2, m = 2, p = 2, q = 0$：两个人都写 `YY`，所以 $\mathrm{cnt}[\texttt{YY}] = 2 = p$，
且 $\mathrm{cnt}[\texttt{NN}] = 0 = q$，候选 `YY` 通过检查，输出 `YY`。
数据中的第 2 个测点是 $n = 2, m = 2, p = q = 0$，输入 `NN`、`YY`：禁止集合是
$\{\texttt{NN}, \texttt{YY}\}$，第一位试 `N`（`NN` 被禁，但以 `N` 开头的可用串还有 `NY`，可行），
第二位试 `N` 得到 `NN` 被禁、改用 `Y` 得 `NY`，输出 `NY`，与数据一致。

### 复杂度

- **时间**：读入与计数 $O(nm)$。$p + q > 0$ 时只需遍历去重串表，也是 $O(nm)$。
  $p = q = 0$ 时要把 $|F| \leqslant 2n$ 个长度 $m$ 的串排序，字符串比较最坏 $O(m)$，
  共 $O(nm\log n)$；构造时每一位做两次二分，字符串比较的代价累计 $O(m^2\log n)$。
  取 $n = 30000$、$m = 500$，实测 C++ 最大点 0.12 s（输入 15 MB，含进程启动）、
  Python 最大点 0.04 s（限时 1000 ms）。
- **空间**：去重表 / 计数表最多 $2n$ 个长度 $m$ 的串，$O(nm)$，即 15 MB 量级，
  实测 C++ 峰值 35.9 MB；Python 把 15 MB 输入全部读进内存后峰值约 55 MB，
  均在限定的 256 MB 内。
- **与 C++ 解法的关系**：`main.cpp` 与 `main.py` 逐步对应，
  区别只是 C++ 用 `unordered_map` 做计数、用 `lower_bound/upper_bound` 做前缀计数，
  Python 用 `Counter` 与 `bisect`。同阶复杂度，都不存在 TLE 风险。

## 总结

- **把故事翻译成计数**：满分人数就是"标准答案"这个串的出现次数，零分人数就是"标准答案的反串"
  的出现次数，于是 $p > 0$ 时候选只能是输入里出现恰好 $p$ 次的串，问题从 $2^m$ 的搜索空间
  塌缩到 $n$ 个候选。
- **$p = 0$ 时不要把候选来源搞反**：标准答案此时**不在**输入里，只能由"出现 $q$ 次的反串取反"
  得到，还必须额外验证它本身出现 $0$ 次，否则会漏掉这个隐含条件。
- **$p = q = 0$ 是构造而非枚举**：把限制写成禁止集合 $F = A \cup \mathrm{comp}(A)$，
  判据"以 $P$ 为前缀的 $F$ 中串数 $< 2^{m-d}$"把可行性压缩成一次二分计数，
  逐位贪心（先 `N` 后 `Y`）即可得到字典序最小解。
- **充分性来自补集大小**：$P + \texttt{N}$ 不可行意味着它下面的 $2^{m-d-1}$ 个串全被禁，
  那么所有可行解只能走 `Y`，所以"先试 `N`"的贪心不会错过解。
- **先验证再相信 `std.cpp`**：本题 `std.cpp` 在仓库内 10 个真实测点全部通过
  （PASS 10/10），本文的推导与它一致；另外用枚举 $2^m$ 个串的独立暴力做了约 3900 组
  小规模交叉验证（$m \leqslant 6$、$p$ 与 $q$ 遍历 $p + q \leqslant n$，包含输出 `-1` 的无解点），
  `main.cpp` 与 `main.py` 两个实现与暴力均无差异。
