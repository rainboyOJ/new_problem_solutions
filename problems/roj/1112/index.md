## 形式化题目

给定一个**元素可正、可负、可为零**的整数序列 $A = (a_1, a_2, \dots, a_M)$，$M$ 为序列长度。求它的**极差**

$$D = \max_{1 \leqslant i \leqslant M} a_i - \min_{1 \leqslant i \leqslant M} a_i$$

样例输入 `5` / `2 5 7 4 2`：最大值 $7$，最小值 $2$，输出 $7 - 2 = 5$。

## 正解

### 思路

**朴素想法**是把序列排好序，再看两端：

```python
ordered = sorted(values)
print(ordered[-1] - ordered[0])
```

语义上无懈可击，代价却是 $O(M \log M)$ 的时间（外加保存有序序列的空间）。而题目要的只是**两个数**：最大值和最小值。序列中其余元素的相对次序对答案毫无影响——下面这张表说明了每个元素的角色：

| 元素 | 在序列中的角色 | 是否影响答案 |
| --- | --- | --- |
| $2$（第 1 个） | 最小值 $\min A$ | 是（作为减数） |
| $5$ | 普通元素 | 否 |
| $7$ | 最大值 $\max A$ | 是（作为被减数） |
| $4$ | 普通元素 | 否 |
| $2$（第 5 个） | 与最小值相等，不改变 $\min A$ | 否 |

也就是说，只要拿到 $\max A$ 和 $\min A$ 两个数，排序做的其余工作全部是白费。这里可以直接证明答案与次序无关：对任意 $i, j$ 都有 $\min A \leqslant a_i \leqslant \max A$，于是 $a_i - a_j \leqslant \max A - \min A$，取 $i$ 为最大值所在下标、$j$ 为最小值所在下标时取等。所以极差只由两个极值决定。

另一方面，线性扫描就是这道题的**下界**：每个元素至少要被查看一次，否则无法判断它是不是新的极值；而一次扫描正好达到 $\Theta(M)$。因此本题没有"排序 → 更快算法"的优化阶梯，朴素与最优之间只差"放弃排序、改用常数个状态"这一个选择。

**问题？** 那能不能顺手写成"边读边更新 $mx = 0$、$mn = 0$"？

不能。本题元素**可以取负值**，把极值初始化成 $0$ 只有在 $0$ 恰好落在真实值域 $[\min A, \max A]$ 内时才不影响答案，而数据允许出现全负或全正的序列，无法指望这种巧合。下表列出三组输入的后果（「`mx = 0`」一列表示只把最大值的初值写成 $0$、最小值仍取真实极值，另一列同理）：

| 输入 | 正确答案 | `mx = 0` 的结果 | `mn = 0` 的结果 |
| --- | --- | --- | --- |
| `3` / `-5 -1 -9` | $8 = -1 - (-9)$ | $9$：$0$ 越过真实最大值，被当成最大值 | $8$：$0$ 高于真实最小值，不改变最小值 |
| `3` / `3 5 5` | $2 = 5 - 3$ | $2$：$0$ 低于真实最小值，不改变最大值 | $5$：$0$ 被当成最小值 |
| `1` / `-7` | $0 = -7 - (-7)$ | $7$：$0$ 被当成最大值 | $0$：$0$ 高于真实最小值 |

可见只要 $0$ 落在真实值域之外，初始化成 $0$ 就会把答案抬高：全负序列会被 `mx = 0` 抬成 $\max(0, \max A) - \min A$，全正序列会被 `mn = 0` 抬成 $\max A$，而本题两种情况都可能出现。

Python 的内建函数恰好一次性绕开这个陷阱：`max()` / `min()` 都以**第一个元素**作为初始值再逐个比较，不需要任何哨兵常量，也就不存在"哨兵没有落在值域之外"的风险。它们与"边读边更新"是同一模型的实现（极值归约可结合、可交换，任意切分后合并结果不变），只是把逐元素循环下沉到了 C 层，既短又快。

实现上还有两个小决定：

- 用 `m, *values = map(int, ...)` 一次读完整份输入。`read().split()` 按任意空白切分，行尾换行、连续空格、甚至"数字跨行写"都会被统一处理；星号解包则把题面"第一行是 $M$，第二行是 $M$ 个数"的结构直接写进代码——`m` 有了名字，`values` 恰好是紧随其后的 $M$ 个数。
- 不排序、不建桶、不特判。真实数据的 $M$ 最小为 $2$，`max`/`min` 至少有一个元素可比；即便 $M = 1$，两者返回同一个元素，差自然为 $0$。

### 复杂度

- 时间复杂度：$O(M)$。一次切分、$M$ 次整数转换、两遍极值扫描都是线性的；比排序写法少一个 $\log M$。由于每个元素必须至少被读一次，$\Theta(M)$ 是本题下界，无法再快。
- 空间复杂度：$O(M)$。`read()` 的字节串与切分出的 $M+1$ 个 token、`values` 里的 $M$ 个整数各占一份线性空间，归约本身只用常数个游标状态。本题 $M \leqslant 10^4$，实测峰值内存约 15 MB，远低于 128 MB。

## 总结

极差只由最大值和最小值两个下标决定，所以**排序是多余的**：把 $O(M \log M)$ 的排序换成一次线性扫描，只需维护两个状态，而 $\Theta(M)$ 正是本题下界，不能再快。

元素可取负值是本题与同源非负序列版本唯一实质的差别，它让"极值初始化成 $0$"从"恰好能用"变成"会算错"。用 `max()` / `min()` 内建可以让初值自动取自真实元素，从而完全避开这个坑；再用 `m, *values = ...` 按第一行的 $M$ 取出序列，把题面结构显式写进代码。

实测数据仓 10 组评测数据全部一致，单组约 0.019 s、峰值内存约 15 MB，相对 1000 ms / 128 MB 的限制十分宽裕。
