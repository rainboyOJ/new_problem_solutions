## 形式化题目

给定 $n$ 个正整数 $x_1, x_2, \dots, x_n$ 和整数 $k$（$1 \leqslant n \leqslant 20$，$k < n$，
$1 \leqslant x_i \leqslant 5 \times 10^6$）。从 $n$ 个数中任选 $k$ 个（每个数至多选一次、
不计顺序），共有 $\binom{n}{k}$ 种选法；求其中所选 $k$ 个数之和为素数的选法个数。

样例 $n=4, k=3$，数集 $\{3, 7, 12, 19\}$ 的全部组合与判定如下：

| 组合 | 和 | 是否素数 | 计入 |
| --- | --- | --- | --- |
| $\{3, 7, 12\}$ | $22 = 2 \cdot 11$ | 否 | |
| $\{3, 7, 19\}$ | $29$ | 是 | ✓ |
| $\{7, 12, 19\}$ | $38 = 2 \cdot 19$ | 否 | |
| $\{3, 12, 19\}$ | $34 = 2 \cdot 17$ | 否 | |

四个组合恰好全部列出、互不重复，其中只有 $3+7+19=29$ 是素数，故输出 $1$。
注意枚举必须**不重**：$\{3,7,12\}$ 与 $\{12,7,3\}$ 是同一种选法，不能算两次。

## 正解

### 思路

**朴素做法**：把每个数看成 $01$ 选择（选/不选），递归生成全部 $2^n$ 个子集，
到叶子再检查「恰好选了 $k$ 个」且「和为素数」。$n=20$ 时 $2^{20} = 1048576$ 个子集，
而其中大小恰为 $k$ 的只有 $\binom{20}{10} = 184756$ 个——绝大多数枚举对象根本不满足
「选 $k$ 个」的硬性要求，是枚举对象的浪费。

**第一步（枚举对象与需求对齐）**：组合不关心顺序，只要规定「被选下标递增」，
每个 $k$ 元集合就恰好按下标升序出现一次，既不重复也不遗漏。这正是标准库
`itertools.combinations` 的语义，于是不必手写递归，直接产出全部 $\binom{n}{k}$ 个合法组合，
枚举量从 $2^n$ 收缩到 $\binom{n}{k}$（最大 $184756$），且每个生成对象都无需再筛。

**第二步（判素上界）**：单个和的最大值

$$S \leqslant 20 \times 5 \times 10^6 = 10^8, \qquad \sqrt{S} \leqslant 10^4.$$

试除判素只需试到 $\sqrt S$：任何合数 $m$ 都有素因子 $p \leqslant \sqrt m$，
所以先用埃氏筛预处理 $10^4$ 以内的全部 $1229$ 个素数，试除只试这张表，
`all(m % p for p in PRIMES if p * p <= m)` 一旦遇到整除立刻短路返回 `False`。
对比全量试除（每次最多 $10^4$ 次取模），素数表把最坏候选从 $10^4$ 压到 $1229$，
合数平均几次取模就退出。

**第三步（记忆化）**：不同组合可能撞出相同的和（真实测点 `choose2` 是 $9$ 个 $1$ 选 $7$ 个，
$36$ 个组合的和全是 $7$），给判素函数加 `@cache`，每个不同的和只判一次。

下面用样例展示组合枚举的线性路线（每行一个被枚举对象）：

```text
combinations([3, 7, 12, 19], 3)      下标递增，共 C(4,3) = 4 个
├─ (3, 7, 12)  →  sum=22  →  22 % 2 == 0     → 合数，丢弃
├─ (3, 7, 19)  →  sum=29  →  试 2,3,5 后无因子 → 素数，ans += 1
├─ (7, 12, 19) →  sum=38  →  38 % 2 == 0     → 合数，丢弃
└─ (3, 12, 19) →  sum=34  →  34 % 2 == 0     → 合数，丢弃
输出 ans = 1
```

四个组合由库按字典序、下标递增生成，不可能出现 `(12, 7, 3)` 这样的重复；
判素在第一个偶因子处就短路，不会把 $10^4$ 个候选跑满。

`primes_upto` 用 `bytearray` 切片赋值 `sieve[p*p::p]` 一次标掉 $p$ 的倍数完成埃氏筛；

`sum(is_prime(sum(c)) for c in combinations(xs, k))` 一行完成「枚举 → 求和 → 判素 → 计数」。

### 复杂度

- 时间复杂度：$O\!\left(\binom{n}{k} \cdot (k + \pi(\sqrt S))\right)$，
  其中 $\binom{n}{k} \leqslant 184756$、$\pi(10^4) = 1229$ 为常数级、求和 $O(k \leqslant 20)$，
  与标准 C++ 正解（组合枚举 + 试除判素）同阶；`all` 短路与 `@cache` 只降常数。
  实测 5 组真实数据单点约 $0.016\ \mathrm{s}$，相对 $1000\ \mathrm{ms}$ 限制宽裕。
- 空间复杂度：$O(10^4)$，素数表 `bytearray(10001)` 加 1229 个 int 约 $10\ \mathrm{KB}$，
  `combinations` 是生成器只持有当前元组；峰值内存约 $14.8\ \mathrm{MB}$，低于 $32\ \mathrm{MB}$。

## 总结

- **枚举对象要与需求对齐**：$01$ 序列枚举 $2^n$ 个子集再筛「恰好 $k$ 个」，
  改成下标递增的组合枚举后，每个生成对象天然合法，量从 $2^n$ 收缩到 $\binom{n}{k}$，
  且天然不重不漏——这是本题的核心观察。
- **判素范围由和的上界决定**：$S \leqslant 10^8 \Rightarrow \sqrt S \leqslant 10^4$，
  预筛 $10^4$ 内素数表试除即完备；`p * p <= m` 的循环条件恰好试到 $\lfloor\sqrt m\rfloor$。
- **Python 落地**：`itertools.combinations` 免手写递归、`functools.cache` 免手工 memo、
  生成器 + `sum()` 免累加变量；同题的 C++ 写法（递增下标 DFS + 试除）见仓库
  Luogu P1036 题解。
- 实测 5 组真实数据全部一致（含全 1 数据的答案 $36 = \binom{9}{7}$），
  与仓库 P1036 的 `main.py` 在同批数据上交叉对照输出一致。
