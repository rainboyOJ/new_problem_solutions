## 形式化题目

给定数列

$$0,\ 1,\ 1,\ 2,\ 3,\ 5,\ 8,\ 13,\ \ldots$$

即 $a_1 = 0$、$a_2 = 1$、$a_k = a_{k-1} + a_{k-2}\ (k \geqslant 3)$。给定正整数 $n$，求 $a_n$ 的值。

引入标准的零起编号斐波那契

$$F(0) = 0,\quad F(1) = 1,\quad F(k) = F(k-1) + F(k-2),$$

题面数列与它逐项相同，只差一个下标偏移，于是目标等价于

$$a_n = F(n-1).$$

这个偏移必须用样例锁定：样例给出 $n = 3$ 时答案为 $1$，而标准的「斐波那契第 $3$ 项」$F(3) = 2$ 与样例不符；写成 $F(n-1) = F(2) = 1$ 才对得上。若顺手按 $F(n)$ 写，输出会整体前移一位。

下面这张表把「题面第 $n$ 项」和「标准 $F$ 的下标」对齐，它是实现时**必须**用到的一次换算：

| 题面项号 $n$ | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | … |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 答案 $a_n$ | 0 | 1 | 1 | 2 | 3 | 5 | 8 | 13 | … |
| 对应的 $F$ | $F(0)$ | $F(1)$ | $F(2)$ | $F(3)$ | $F(4)$ | $F(5)$ | $F(6)$ | $F(7)$ | … |

两行答案完全相同，但**下标整体差 1**；记住「第 $n$ 项 = $F(n-1)$」而不是 $F(n)$，才能让真实数据里的每一组都对上。

## 正解

### 思路

**朴素做法一：按定义递归。** 直接把递推式写成递归函数，也是题面「用递归函数」的字面翻译：

```python
def fib(n):
    if n <= 2:
        return n - 1
    return fib(n - 1) + fib(n - 2)
```

**朴素做法二：按定义滚动。** 只保留前两项，用两个变量往前推：

```python
a, b = 0, 1
for _ in range(n - 1):
    a, b = b, a + b
print(a)
```

两份都是**正确**的，$n \leqslant 33$ 时都能通过（真实数据 $n$ 落在 $4 \sim 33$，最大一组 $n = 33$）。但它们的结构值得追问一句：

- **递归版**的调用次数满足 $T(k) = T(k-1) + T(k-2) + 1 = O(\varphi^k)$（$\varphi = \frac{1+\sqrt5}{2}$），是指数级。问题的根源不是「用了递归」，而是**递归没有共享结果**——`fib(n-2)` 被 `fib(n-1)` 又算了一遍。$n = 33$ 时实测已需约 $700$ 万次调用，$n = 50$ 就跑不动了。
- **循环版**已经是 $O(n)$ 时间、$O(1)$ 空间的最优递推，本题数据下完全够用；但它按项数摊时间，$n$ 越大线性越贵，而题面并没有承诺 $n$ 的上界。

所以优化的方向很明确：**让每个下标只被求解一次，而且跳着走。**

**关键观察：子问题可以只产生一个。** 朴素递归之所以展开成二叉树，是因为「求 $F(n)$」需要两个子问题。反过来问：如果子问题的答案是**一对相邻项**，能不能把两个子问题合成一个？

可以。斐波那契的倍增恒等式给出

$$F(2m) = F(m)\bigl(2F(m+1) - F(m)\bigr), \qquad F(2m+1) = F(m)^2 + F(m+1)^2.$$

它说明**下标 $2m$ 和 $2m+1$ 的两项，完全由下标 $m$ 和 $m+1$ 的两项决定**。于是递归结构从二叉变成一条单链：求 $F(n)$ 只调用一次「求 $F(\lfloor n/2 \rfloor)$ 那一对」。

**契约的确立：函数返回 $(F(n), F(n+1))$。** 子调用给的是 $(F(m), F(m+1))$，而一次折半能算出相邻的 $F(2m)$ 与 $F(2m+1)$，所以：

- $n = 2m$ 为偶数：要 $F(2m)$，返回 `(F(2m), F(2m+1))`；
- $n = 2m+1$ 为奇数：要 $F(2m+1)$，顺手把下一个相邻项 $F(2m+2) = F(2m) + F(2m+1)$ 也算上，返回 `(F(2m+1), F(2m+2))`。

两支都保持「**返回相邻两项**」这个契约，父层才能原样继续用同一组公式。契约是这份实现的核心不变量，写在函数的 docstring 里。

**边界要顺着契约写。** 底数是 $F(0) = 0$、$F(1) = 1$。但契约要求第二项是 $F(n+1)$：$n = 1$ 时要返回 $(F(1), F(2)) = (1, 1)$，而 $F(2) = F(1) + F(0) = 1$，不是 $2$。所以边界是

```python
if n < 2:
    return n, 1        # (F(0),F(1)) = (0,1)；(F(1),F(2)) = (1,1) 的第二项恒为 1
```

若照直觉写成 `return n, n + 1`，$n = 1$ 会返回 $(1, 2)$，把 $F(2)$ 误当成 $2$，之后整条链全体偏移——这是一个非常容易踩、又必被样例抓住的坑：实测错误边界会让 $n = 3$ 输出 `3`（应为 `1`）、$n = 6$ 输出 `34`（应为 `5`），而 $n = 1, 2$ 恰好还对，错误只在第三个下标之后才冒出来。

**最后做下标偏移。** `fib_pair` 内部只认标准斐波那契 $F$，题面要的是 $a_n = F(n-1)$，所以在调用点写成 `fib_pair(n - 1)[0]`，让「偏移」只出现在一个地方，两个概念不混。函数内部的两个变量 `lo`、`hi` 装的是子调用给的一对 $(F(m), F(m+1))$，`even`、`odd` 装的是折半后算出的 $F(2m)$、$F(2m+1)$；名字直接对应「下标是偶数 / 奇数」的那一项，和 `n & 1` 分支一一对照。

**为什么深度只有 $O(\log n)$。** 每层下标折半，链是一条直链而不是二叉树：

```text
fib_pair(32)
`- fib_pair(16)
   `- fib_pair(8)
      `- fib_pair(4)
         `- fib_pair(2)
            `- fib_pair(1)   <- 边界，返回 (F(1), F(2)) = (1, 1)
```

从上往下只做**一次**子调用，从下往上一路用两条倍增公式拼回两倍下标的相邻项，共 $\lceil \log_2 n \rceil$ 层就回到答案。`@cache` 在这里是「同一参数不重复求解」的显式保险：链本身无重叠，但它让「查表式递归」的意图写在代码上。

### 复杂度

- 时间复杂度：$O(\log n)$ 层递归，每层常数次大整数乘法。真实测试数据中 $n$ 落在 $4 \sim 33$（最大一组 $n = 33$，答案 $2178309$），链长不超过 $5$，实测约 $0.018\sim0.019\,\mathrm{s}$，远低于 $1000\,\mathrm{ms}$ 限制。作为对照，朴素递归是指数级 $O(\varphi^n)$，朴素滚动是 $O(n)$ 次加法。
- 空间复杂度：递归栈与 `@cache` 各 $O(\log n)$ 项，$n = 33$ 时缓存 6 个条目；实测峰值约 $14.5\,\mathrm{MB}$（主要是 Python 解释器自身），远低于 $128\,\mathrm{MB}$。

## 总结

- 先解决**读题**：题面数列首项是 $0$，样例 $n = 3 \to 1$ 与真实数据 $n = 6 \to 5$ 共同证明「第 $n$ 项 $= F(n-1)$」，不是 $F(n)$。这一步错，整张输出表全错。
- 朴素递归慢的根源是**重复子问题**，不是递归本身；把「返回一个值」改成「返回相邻两项」，二叉树就塌缩成单链。
- 倍增恒等式 $F(2m) = F(m)(2F(m+1) - F(m))$、$F(2m+1) = F(m)^2 + F(m+1)^2$ 是折半的理论依据，也是「一次子调用拿到两个相邻项」的接口设计来源。
- 递归函数的**返回值契约**必须两支一致（都返回 $(F(n), F(n+1))$），边界也要顺着契约写：$F(2) = 1$ 而不是 $2$。
- 下标偏移只放在调用点 `fib_pair(n - 1)`，函数内部保持标准定义，便于单独验证。
