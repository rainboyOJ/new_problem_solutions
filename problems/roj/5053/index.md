## 形式化题目

输入一个正整数 $a$。**题面未给数值范围**；本包数据实测 $1 \le a \le 2^{31}-1$（其中 `problem9.in` 顶格恰为 `INT_MAX`，无 $0$ 及负数）。

如果 $a$ 是偶数，则输出字符串 `yes`（末尾带换行）；否则**什么也不输出**（即输出精确的 $0$ 字节，绝对不能输出空行）。

## 正解

### 思路

这是一道考察基本条件分支的题目。

一个整数是偶数的充要条件是它能被 $2$ 整除，因此通过判断余数 `a % 2 == 0` 来决定分支走向。
另一种常见写法是判断二进制的最低位：`(a & 1) == 0`。

需要特别注意题目的输出要求：如果 $a$ 不是偶数则**什么也不输出**。这意味着在奇数情况下，程序直接结束即可，绝对不能输出空格或者单纯的换行符。

## 总结

- **奇数时的输出必须是严格的 $0$ 字节**。实测本包 10 个数据点：5 个奇数点（如 `p1, p4, p5, p8, p9`）的 `.out` 为精确的 $0$ 字节；5 个偶数点为精确的 $4$ 字节（`yes\n`）。
- **反事实测试与闸门盲区提醒**：若修改代码在奇数分支误加 `cout << "\n"`（输出一个换行符），失败点恰好是这 5 个奇数点。然而，**同一带 bug 版本会被仓库旧版 token 级闸门判成 PASS（10/10）**（因为 `got.split() == [] == want.split()`），这是本包实测的第 3 起盲区（见同族「0 字节空输出」题：`5019` / `5029` / `5032` / `5044`）。此类题目必须用**逐字节**检查工具（本仓库内已提供独立工具 `scripts/problem-analysis-tools/check_bytes.py`）。
- **判偶数的两种写法与负数取模的精确刻画**：补码下 `(a & 1) == 0` 对**负数也正确**；而 `a % 2 == 0` 虽然**余数的值**与 Python 不同（C++ `-3 % 2 = -1` 向零取整 vs Python `-3 % 2 = 1` 向下取整），但**「余数是否为 0」的判定跨语言完全等价** —— 实测穷举 $[-2000, 2000]$ 共 $4001$ 个值，两侧 `(v % 2 == 0)` 输出**逐字符相同**，且 `(v & 1) == 0` 与 `(v % 2 == 0)` 也逐字符相同。虽然本题实测全为正数，但这说明即使输入存在负数，用 `a % 2 == 0` 也毫无风险。
- **数值范围与类型选择**：题面没有给定限制，实测最大输入恰好为 `2147483647`（`INT_MAX`）。在 C++ 中 `int` 也不会溢出；按项目 skill 规范默认使用 `long long` 防止未来潜在扩数据风险，这是规范选择而非修 bug。
- **验证强度摘要**：异源位运算验证全枚举（包含边界与海量随机种子）$1408$ 组数据 $0$ 分歧；非硬编码扫描证明程序内不存在答案数值和字符串的泄露；遇到空输入无 UB 静默退出。跨语言判定五项重点（溢出、整除、类型转换、浮点格式化、字典序）全部通过，全无风险。
