## 形式化题目

给定长度为 $N$ 的整数序列 $(a_1, a_2, \dots, a_N)$，取下标严格递增的子序列 $i_1 < i_2 < \dots < i_K$，使得元素值**严格递增**：

$$a_{i_1} < a_{i_2} < \dots < a_{i_K}$$

求最大的 $K$，即最长上升子序列（LIS）的长度。

样例 $1\ 7\ 3\ 5\ 9\ 4\ 8$ 中，$1 < 3 < 5 < 8$ 是一个最长上升子序列，长度为 $4$。

## 正解

### 思路

**从朴素 DP 说起。** 最自然的定义是"以 $a_i$ 结尾"：

$$dp[i] = 1 + \max\{\, dp[j] \mid j < i,\ a_j < a_i \,\}$$

对每个 $i$ 向左扫描所有 $j < i$ 找合法转移，共 $O(N^2)$ 次比较，答案取 $\max_i dp[i]$。这个做法在 $N \leqslant 1000$ 时其实就能过，但它暴露了一个清晰的瓶颈：**每步都在"前缀中找满足 $a_j < a_i$ 的最优 $dp[j]"，逐个比较没有利用任何有序性**——这正是二分查找能接管的查询。

**换一个状态视角。** 不再追问"以哪个下标结尾"，而是按**长度**归类：设 $tails[L]$ 表示已扫描前缀中，长度为 $L$ 的上升子序列的**最小可能结尾**。关键观察是：

- 结尾越小，后续能接上的元素就越多；对同一长度，只保留结尾最小的那个代表不会损失任何答案；
- 由此 $tails$ 数组本身**严格递增**：长度 $L{+}1$ 的子序列去掉末元素就是一条长度 $L$ 的子序列，其结尾必小于 $tails[L{+}1]$，由 $tails[L]$ 的最小性得 $tails[L] < tails[L{+}1]$。

于是每个新元素 $v$ 的去向可以二分确定：在严格递增的 $tails$ 中找第一个 $\geqslant v$ 的位置 $p$（`bisect_left`）——

- $p$ 等于数组长度：$v$ 比所有层的结尾都大，可以再接一层，LIS 长度 $+1$；
- 否则：$v$ 能替代第 $p{+}1$ 层的结尾（同长度下更小，`tails[p-1] < v <= tails[p]` 保证替换后仍严格递增），长度不变。

严格上升的细节正在 `bisect_left` 的语义里：若 $v$ 恰好等于 $tails[p]$，二分落回 $p$ 原地替换而**不追加**，等值元素永远不会被接成更长序列——若题目改成"非降"，这里要换 `bisect_right`。

样例的逐元素演化（表格展示 $tails$ 的"追加 / 替换"两种动作）：

| 扫描元素 $v$ | 二分位置 $p$ | 动作 | 扫描后的 $tails$ |
| :---: | :---: | :---: | :--- |
| 1 | 0（追加） | 追加 | $[1]$ |
| 7 | 1（追加） | 追加 | $[1, 7]$ |
| 3 | 1 | 替换 $7$ | $[1, 3]$ |
| 5 | 2（追加） | 追加 | $[1, 3, 5]$ |
| 9 | 3（追加） | 追加 | $[1, 3, 5, 9]$ |
| 4 | 2 | 替换 $5$ | $[1, 3, 4, 9]$ |
| 8 | 3 | 替换 $9$ | $[1, 3, 4, 8]$ |

观察重点：行与行之间 $tails$ 始终严格递增；`3` 替换 `7`、`4` 替换 `5` 这两步"看不见"——它们没有延长长度，却把同长度的结尾变小，为后面 `5`、`8` 的追加铺路。结束时 `len(tails) = 4`，正是答案。整个过程每个元素只做一次二分，$O(N \log N)$ 完成。

### 复杂度

- 时间复杂度：$O(N \log N)$——扫描 $N$ 个元素，每个元素一次 `bisect_left` 二分加 $O(1)$ 的替换/追加；对比朴素 DP 的 $O(N^2)$，消除了逐个扫描前缀的瓶颈。
- 空间复杂度：$O(N)$——`tails` 长度至多 $N$，加上读入的序列本身。

## 总结

LIS 的经典优化路线：朴素 $dp[i]$ 的瓶颈是"带条件的前缀最值查询"，把状态从"以下标结尾"改写成"按长度保留最小结尾"后，$tails$ 自然严格递增，查询退化为一次二分。落地时 `bisect_left` 同时承载了两条语义——定位层号、以及"严格上升时等值只能替换不能追加"。实测 10 组真实数据全部一致，每组约 0.02 s、峰值内存约 14.7 MB，相对 1000 ms / 128 MB 的限制毫无压力。
