## 形式化题目

给定三个非负整数 $A, B, C$（$0 \leqslant A, B, C \leqslant 100$，且三者都是 $10$ 的整数倍），
求加权和

$$\text{score} = A \times 20\% + B \times 30\% + C \times 50\%,$$

输出它的整数值（满分 $100$，所以结果一定落在 $[0, 100]$ 内）。

三项成绩都是 $10$ 的整数倍这一条，把答案锁成了一个**恒为整数**的量：
$A = 10a$、$B = 10b$、$C = 10c$ 时，

$$\text{score} = 10a \cdot \frac{2}{10} + 10b \cdot \frac{3}{10} + 10c \cdot \frac{5}{10} = 2a + 3b + 5c,$$

右边是整数，说明"总成绩是整数"不是约等于，而是精确成立。
题目只要求输出这个值，没有输入组数、没有多组询问，也不含任何需要搜索或优化的自由度：

- 样例 1：$A = 100, B = 100, C = 80$，答案 $100 \cdot 20\% + 100 \cdot 30\% + 80 \cdot 50\% = 20 + 30 + 40 = 90$；
- 样例 2：$A = 60, B = 90, C = 80$，答案 $60 \cdot 20\% + 90 \cdot 30\% + 80 \cdot 50\% = 12 + 27 + 40 = 79$。

## 正解

### 思路

**为什么没有别的做法。** 公式已经把答案写死了：三个已知数各乘一个常数权重再相加，
是一元一次式的求值，不需要枚举也不需要决策。整道题的"算法"只有一句——
**把百分数换成整数，然后一次乘加**。真正的风险不在算法，而在实现细节上：
怎么表示 $20\%$ 这种权重才既准确又不用引入分数运算。

**第一步：把百分比放大 10 倍变成整数权重。** $20\% = \frac{20}{100} = \frac{2}{10}$，
同理 $30\% = \frac{3}{10}$、$50\% = \frac{5}{10}$。三项权重都只差一个公共分母 $10$，于是

$$\text{score} = \frac{2A + 3B + 5C}{10}.$$

$2, 3, 5$ 就是"放大 $10$ 倍后的整数权重"，它们的和恰好是 $10$——这不是巧合：
百分比分母本来就是 $100$，而 $20 + 30 + 50 = 100$，所以放大后的权重和一定等于放大倍数。
记住这个关系，就能随时验算"除数该写 $10$ 还是 $100$"。

**第二步：既然有全局整除保证，就用整数除法一步收尾。** 约束保证 $A, B, C$ 都是
$10$ 的整数倍，所以 $\frac{2A + 3B + 5C}{10}$ 一定是整数，**不需要四舍五入，也不需要判舍入方向**。
这一步很关键：如果没有"$10$ 的整数倍"这个条件，除法的结果可能出现小数，
就必须先想清楚题面要的是四舍五入还是截断；而有了这个条件，本题的答案唯一确定，
写成 `total // 10`（C++ 里是 `total / 10`）就是精确值。

下表把两个样例的中间量摊开，可以看到整数版本和百分比版本是同一个算式：

| 样例 | $A, B, C$ | 整数权重形式 $2A + 3B + 5C$ | 除以 $10$ |
| --- | --- | --- | --- |
| 1 | $100, 100, 80$ | $200 + 300 + 400 = 900$ | $90$ |
| 2 | $60, 90, 80$ | $120 + 270 + 400 = 790$ | $79$ |

两行的中间值都是 $10$ 的倍数，验证了"整数除法不丢精度"这件事在数据上确实成立。

**第三步（选做）：为什么不写浮点。** 直接用 `0.2 * A + 0.3 * B + 0.5 * C` 也能得到
样例的 $90$ 和 $79$，看起来更贴近题面。但它有两个隐患：

- `0.2`、`0.3`、`0.5` 在二进制浮点里都不是精确值，加权和可能落到真值的**下方**一点点。
  例如 $A = 1, B = 6$ 时 `0.2*1 + 0.3*6 = 1.9999999999999998`，截断成整数就变成 $1$，
  而正确答案是 $2$。本题的 $10$ 的倍数约束恰好排除了这些点（在全部 $101^3$ 个 $[0,100]$
  三元组里，只有那些非 $10$ 倍数的输入会踩到），但把正确性建立在"输入恰好避开了浮点陷阱"上，
  是不必要的赌注。
- 一旦想用截断来对齐整数答案，还要额外判断该 `floor` 还是 `round`；整数权重版本完全不需要这个思考。

所以整数权重写法不只是"更短的技巧"，它是**消除一类误差**的做法：
分母 $10$ 与约束里的 $10$ 的倍数一抵消，浮点、舍入、取整三个议题一起消失。

**Python 侧的一点变化。** Python 版把三个权重命名为模块级常量（`WORK_WEIGHT, TEST_WEIGHT, EXAM_WEIGHT`）
再逐个相乘相加，写成 `work * WORK_WEIGHT + test * TEST_WEIGHT + exam * EXAM_WEIGHT`。
常量名本身就是对题面权重的注解——对照代码就能确认"作业 20%、小测 30%、期末 50%"没有被写串位置；
除以 `FULL_WEIGHT` 时也一并说明了"除的为什么是 $10$"。
C++ 版则按 `2A + 3B + 5C` 直写：三个乘积在 64 位整数里随便放
（最大 $2 \cdot 100 + 3 \cdot 100 + 5 \cdot 100 = 1000$），本题并不真的需要 `long long`，
但按仓库约定题目数据统一用 `ll`，代价为零。

### 复杂度

- **时间**：读入 $3$ 个整数、做 $3$ 次乘法、$2$ 次加法、$1$ 次整数除法，全是常数次运算，
  $O(1)$，与输入规模无关。实测单点（`check_sample.py`，$10$ 个测试点取稳态）：
  C++ 版 $0.010$ s，Python 版 $0.019$ s（限时 $1000$ ms，余量三个数量级）。
- **空间**：只用固定几个整数变量，$O(1)$。实测峰值内存（`check_sample.py` 稳态）：
  C++ 版 $8.4$ MB、Python 版 $14.6$ MB（限时 $64$ MB），
  两者差的那几 MB 几乎全是 CPython 解释器本身的开销。
- **与 C++ 解法的关系**：两边是同一个公式，`main.py` 用常量名标注权重再逐个相乘，
  `main.cpp` 直写 `2A + 3B + 5C`；不存在 Python 特有的 TLE/MLE 风险。

## 总结

- **百分比先换整数**：$20\%, 30\%, 50\%$ 乘以 $10$ 变成 $2, 3, 5$，
  于是 $\text{score} = \frac{2A + 3B + 5C}{10}$，一个乘加式就结束。
- **权重之和就是除数**：放大 $10$ 倍后 $2 + 3 + 5 = 10$，这正是百分比分母 $100$ 除以放大倍数，
  可以用来自查除数写对了没有。
- **整除保证来自题面约束**：$A, B, C$ 都是 $10$ 的倍数，所以 $\frac{2A+3B+5C}{10}$ 恒为整数，
  整数除法不需要讨论舍入方向。
- **能不用浮点就不用**：`0.2/0.3/0.5` 的二进制表示不精确，$0.2 \cdot 1 + 0.3 \cdot 6$ 会算成
  $1.9999999999999998$；本题数据恰好避开了这些点，但整数权重版本从根上不需要这个幸运条件。
- 边界：$A = B = C = 0$ 时输出 $0$，$A = B = C = 100$ 时输出 $100$，
  两种情况都在真实数据里出现过，代码无需任何特判。10 个测试点全部通过。
