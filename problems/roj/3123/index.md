## 形式化题目

在一个存在 $p_1$ 个天神（只说真话）和 $p_2$ 个恶魔（只说假话）的岛上，总人数为 $V = p_1 + p_2$。给出了 $n$ 条提问结果，每条结果包含“问 $x$ 居民 $y$ 居民是否是天神，回答为 `yes` 或 `no`”。

要求判断是否能够唯一确定所有的天神身份。
如果能唯一确定，按升序输出所有天神的编号，并在最终输出一行 `end`。
如果无法确定（存在多解、无解或逻辑自相矛盾），则只输出一行 `no`。

数据范围：$0 \le n < 1000$，$0 \le p_1, p_2 < 300$。以三个 $0$ 结束多组输入。

## 正解

### 思路

天神说真话，恶魔说假话，因此对于任意一次问答，都有：
- 若 $x$ 回答 `yes`，则说明 $x$ 和 $y$ 的身份相同（要么都是天神，要么都是恶魔）。
- 若 $x$ 回答 `no`，则说明 $x$ 和 $y$ 的身份不同（一个是天神，另一个是恶魔）。

这可以转化为一个带有同类和异类关系的并查集问题，我们可以采用**扩展域（种类）并查集**来维护：
1. 将每个居民 $x$ 拆分为两个状态节点：$x$ 表示 $x$ 为天神，$x + V$ 表示 $x$ 为恶魔。
2. 同类关系：合并 $(x, y)$ 和 $(x+V, y+V)$。
3. 异类关系：合并 $(x, y+V)$ 和 $(x+V, y)$。

合并完后进行合法性检查，如果同一个人 $x$ 出现了 $x$ 和 $x+V$ 连通，说明逻辑矛盾（即不存在任何合法的分配方式）。

若无矛盾，则图被划分为了若干个连通块。对于每一个连通块中的人群，其被严格划分为两个互斥的集合 $c_0$ 和 $c_1$。此时必须满足 $c_0 \cap c_1 = \emptyset$（允许有一侧为空，空侧意味着该块的人被全部分配为恶魔，这对于没有被询问过的孤立点极为常见）。此时，要么 $c_0$ 的人全部是天神，要么 $c_1$ 的人全部是天神（二选一）。

问题因此转化为：要从每个连通块对中恰好选出一个集合，使得选出的人数总和正好等于 $p_1$。
这是一个**计数型 0/1 背包问题**：
令 $f(i, j)$ 表示前 $i$ 个连通块中，挑出的总人数恰为 $j$ 的方案数。
转移方程：$f(i, j) = f(i-1, j - |c_0|) + f(i-1, j - |c_1|)$。为了防止溢出，可以将其上限截断，即用 $\min(2, \dots)$ 进行更新，因为我们只关心解是否唯一（$0$ 表示无解，$1$ 表示唯一解，$\ge 2$ 表示多解）。

最后，在所有 $K$ 个连通块处理完毕后：
- 如果 $f(K, p_1) == 1$，意味着解唯一。直接从 $dp$ 状态反向回溯，找出每个连通块选取了 $c_0$ 还是 $c_1$，收集天神编号后排序输出即可。
- 如果 $f(K, p_1) \ne 1$（多解或无解），直接输出 `no` 即可。

### 复杂度

- **时间复杂度：** 构建与合并扩展域并查集的复杂度为 $O(n \alpha(V))$；提取连通块与大小统计可以做到 $O(V \alpha(V))$；背包 DP 与回溯需要遍历连通块进行转移，复杂度上限为 $O(V \cdot p_1)$。因 $V < 600$，单组数据的总耗时均在毫秒级以内。
- **空间复杂度：** 依赖于常数个大小为 $O(V)$ 的辅助数组与大小为 $O(V \cdot p_1)$ 的 DP 表，最高消耗远低于 128MB 的内存要求。

## 总结

- **核心算法**：种类并查集（扩展域）维护连通性 + 连通块 0/1 计数型背包 DP + 方案回溯输出。
- **★★★ 不需要 spj（输出唯一确定）**：本题输出要求为**唯一解才输出该唯一解的天神编号列表并追加 `end`；多解与无解都输出 `no`**。
  - **样张反证**：样例 1（2 1 1，两条互问 no）和样例 2（3 2 1，三条自问 yes）对应的真值分布均存在合法解，但因其属于“多解”，依然被要求输出 `no`。
  - **真值分布**：对规模 `V≤6, n≤2` 的 58995 组数据穷举显示，unique解 10804 组，multi解 24921 组（占比 42%），none解 23270 组。这证明多解是本题极常见的状态，此时必须输出 `no`，无需 SPJ 即可确定性判定。
- **★★ 证据强度声明**：本题**无官方测试数据**，验证基准是【跨源对拍 + 自写参考实现 + 逐字穷举真值】。本报告证明的是『多个独立实现互相一致』，**不是**『与官方标准一致』。若官方数据隐含题面未写的约定（如行尾空白、多组间空行等），本工作流**无法发现**。
- **★★ 对拍规模**：
  - 穷举全部 tiny 输入 58995 组（V≤6, n≤2）0 分歧。
  - 随机小数据 960 组 0 分歧。

- **★★ 防御性修复（$V==0$ bug）**：原初稿代码若遇到 $V==0$ 会立即跳出循环，导致随后的 $n$ 行输入没读而引发错位报错。尽管题面约定 $x_i, y_i \le p_1+p_2$（表明合法 $V=0$ 时必然 $n=0$），但应对极端非法输入时已修复为“读取完所有本组问答后再行特判”。
- **★ 「非空」陈述错误修正**：连通块所划分出的两个互斥集合 $c_0, c_1$ 并非总是“非空”。实际是 $c_0 \cap c_1 = \emptyset$ 且允许一侧为空，空侧意味着该连通块人员全部被视作恶魔（例如对单人无询问的孤立点，实测空侧触发数万次，是分布常态而非常规理解的非空或边角）。
- **★ 死分支等价简化**：原代码在回溯多此一举地判了 `!can1 || sz0 == sz1`。既然此路径是在唯一解的情况下回溯，如果该步存在选择，必定只有唯一的 `can0` 或 `can1` 通路成立，已对其执行了等价删减（突变体 160 组验证确认未影响正常逻辑）。
- **★ `ref` 差异点清单**：worker 采用的 `ref` 与专家实现具有高度的异源对比特征：
  1. **建模**：`ref` 使用邻接表与 BFS 二染色（图边权表示同类/异类），专家采用了扩展域并查集。
  2. **矛盾检测**：`ref` 在 BFS 染色途中若 `par[v] != want` 即报矛盾，专家则在并查集完工后看同一人是否跨越两个状态域。
  3. **连通块枚举**：`ref` 按 BFS 访问顺序收集 $side_0 / side_1$，专家通过提取根节点的并查集 ID 配对。
