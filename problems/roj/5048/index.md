## 形式化题目

给定一行长度不超过 $200$ 的字符串 $S$（可能包含空格、标点符号、大小写字母等），以及第二行的两个以单个空格分隔的非空白可打印字符 $A$ 和 $B$（实测 10 点全是 1 字节 token）。
要求将字符串 $S$ 中出现的所有字符 $A$ 替换为字符 $B$（区分大小写），并输出替换后的结果。

## 正解

### 思路

本题的核心在于**正确读取含有空格的字符串**。
由于原文中可能包含多个连续空格，甚至行首带有空格（点 6/7 实测有行首空格。本包数据不包含行尾空格，但代码仍能正确处理），因此不能使用普通的 `cin >> s`，否则会在遇到第一个空格时截断。

在 C++ 中，需要使用 `getline(cin, s)` 来读取整行字符串。为了防止跨平台评测时换行符（CRLF）在 Linux 环境中带来末尾残留的 `\r` 字符，我们在读取后最好判断一下行末字符，若是 `\r` 则予以剔除。
之后再使用 `cin >> A >> B` 读取第二行的两个字符，`cin` 会自动跳过前导空白符（包含换行），且每个变量只取 1 个字符，故 `A B`、`A  B`（多空格）、`AB` 三种写法等价。

在 Python 中，用 `sys.stdin.buffer.read()` 整体读入后**只按 `\n` 切行**（注意：`str.splitlines()` 会在**单独的 `\r`** 处断行，会把一行原文拆成两行，是**真实陷阱**）；第 1 行用 `rstrip(b"\r")` 剔除 CRLF 残留的 `\r`；第 2 行**丢掉全部空白字节**后取前两个字节作为 $A$、$B$，再 `bytes.replace(A, B)` 完成替换。这样做与 C++ 的 `cin >> char` 语义（**跳过空白、每个变量只取 1 个字符**）严格对齐。

## 总结

1. **题意与读取**：第 1 行是原文（**含空格 ⇒ 必须 `getline`/整行读**），第 2 行是 `A B`（空格分隔的两个字符）；**区分大小写**地全局替换。
2. **两个真实的跨语言 bug（已修）**：
   - **`str.splitlines()` 在裸 `\r` 处断行 ⇒ 静默丢数据**：如 `b'a\rb\nI U\n'` 这一串在调用 `splitlines()` 后会返回 `b'a\n'` 而非完整行。改为 `raw.partition(b"\n")` 修复。
   - **替换单位不一致**：Python 如果按整个 token 作为单位（`str`），在遇到 `a bc` 这种数据时会造成 `xay` 不变（把 `bc` 当作要替换的串），而 C++ `cin >> char` 取第 1 个 char 则会得到 `xby`。已修为单字节切片 `chars[0:1]` 替换，两侧现已一致。
3. **CRLF 与行尾**：实测 10 个 `.in` 全部“恰一个 LF”，无 CR；`z Z\r\n` 与 `z Z\n` 两侧行为一致；`\r` 只可能残留在第 1 行末尾。
4. **大小写敏感性的判别点**：
   - 能够判别大小写的测试点：`p3`（$A$ 为 `I`，原文含 `i`×3/`I`×2）、`p7`（$A$ 为 `f`，原文中 `F`×2 须保留）。
   - **无法判别大小写的测试点**：`p10`（$A$ 为 `a`，$B$ 为 `A`），反事实结果恰好相同。
5. **数据未覆盖的情形**：
   - $A$ / $B$ 为空格：实测 10 点无空白 A/B。若出现，C++ `cin>>char` 会跳过空白、原 Python `.split()` 也会丢掉空格 ⇒ 两侧原先都会输出原样，表现错法相同。
   - 原文为空行：实测最短 `len=1`，无空行。
   - 原文末尾带有空格：实测全部数据 `text == text.rstrip()`。
6. **验证强度摘要**：V6 异源验证（使用 `bytes.translate`）全覆盖实测无差异。随机 400 组加上 282 组边界验证全数通过。V2 代码的数值和字符字面量不含答案字符（`U/Z/Y/b/E/…` 一个都没出现）。
7. **T9 跨语言清单风险排除**：替换单位及裸 CR 的隐患均已修复；UTF-8 多字节实测两侧行为一致（按字节逐一替换）。
