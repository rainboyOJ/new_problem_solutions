## 形式化题目

给定一个长度为 $n$ 的字符串 $S$，字符只可能来自 $\{\texttt{0..9},\ \texttt{','},\ \texttt{'?'}\}$，
其中 $\texttt{'?'}$ 是通配符。要求把每个 $\texttt{'?'}$ 替换成数字或逗号，
得到一个不含问号的串 $T$，满足：

1. $T$ 只含数字和逗号；
2. 逗号把 $T$ 切成若干个非空数字段，首尾都不是逗号；
3. 每个数字段首位不为 `0`（即每个数都是无前导零的正整数）；
4. 各数字段表示的整数序列**严格递增**。

在全部合法 $T$ 中取字典序最小者输出（按 ASCII，`,` $<$ `0` $<$ `1` $< \cdots <$ `9`，
所以 $"1,2"$ 比 $"12"$ 小）；无解输出 `impossible`。多组数据，$T$ 组数 $\leqslant 10$，$n \leqslant 50$。

样例第三组的 `?????????,9` 答案为 `1,2,3,4,5,9`：把第 $0$、$2$、$4$、$6$、$8$ 个问号
各留作数字（1、2、3、4、5），其余问号都换成逗号，得到 5 个数后接末尾固定的 `9`。
注意 `1,2,3,4,5,9` 的第 1 个字符是逗号，比任何以数字开头的可行串都小，
这正是"逗号优先级最高"的体现。

## 正解

### 思路

**本题是"逐位定字符"的结构，不是"逐段定数字"的结构。** 一个常见的错想是：
先在脑子里把串切成数字段，再对每段填最小数。但字典序最小是按字符比较的，
判题只认最终字符串，所以正确的做法是**从左往右逐位确定字符**：
对每个 `?`，按 ASCII 从小到大依次试 `,` `0` `1` … `9`，
留下第一个"仍然能补全成合法串"的字符，之后的 `?` 再继续处理。
这是标准的字典序贪心模板——只要"能否补全"这个判定是**精确**的，
逐位贪心得到的就是字典序最小解（每一位都取到当前能取得的最小值，
且不影响前面已定的前缀）。

剩下的全部难点都在判定：**给定一个前缀已定、后缀还是 `?` 的模式串，能否补全成合法串？**

**判定：按"最后一个逗号位置"递推。** 合法串由一串数字段构成，
段与段之间由逗号分隔，所以一个自然的状态是"逗号落在哪里"。
设 $c$ 为某个逗号的位置（虚拟起点记 $c = -1$，表示还没有任何数字），
$f(c)$ = 当逗号落在 $c$ 时，**它左侧最后一个数字段的最小可能取值**。
这个值之所以够用，是因为下一段数字 $v$ 只受一个约束：$v > f(c)$——
比它更左边的数字（如倒数第二个数）对 $v$ 没有任何直接约束。
因此同一位置只需要保留**最小的** $f(c)$，其余取值更差的路径一律可以丢掉，
判定不会因此变松。

于是转移很直接：从状态 $c$ 出发，枚举下一段的结束位置 $e$（段是 $S[c+1, e)$）：

- 位置 $e$ 若 $e < n$，它必须是逗号位，即 $S[e] \in \{\texttt{','}, \texttt{'?'}\}$；
  $e = n$ 时这一段收尾，串结束，直接判定成功。
- 段内要能填出一个首位非 $0$、不含固定逗号、且数值 $> f(c)$ 的数字；
  取其中**最小**的那个，作为新状态 $f(e)$ 的候选。
- 走到 $e$ 后新逗号位置是 $e$，记入 $g(e+1)$（下标 $c+1$ 是为了让 $-1$ 能存进数组）。

一层层从左往右推进，任一状态能读到最后一段就可行。因为每个状态只留最小值，
状态数 $O(n)$、每个状态枚举 $O(n)$ 个结束位置，一次判定是 $O(n^2)$ 级别
（唯一的额外代价是 $O(n)$ 位的数字串比较，见「复杂度」一节）。

**子问题：在 $S[s, e)$ 上填出"最小的、$> lower$"的数字。** 记 $L = e - s$：

1. 先构造**忽略下界**的最小匹配数字 `base`：`?` 首位填 `1`、其余填 `0`，
   固定数字必须原样接受；出现固定逗号、或首位被固定成 `0`，这一段就废了。
2. 若 `base` 的位数 $\neq$ $lower$ 的位数，位数多则 `base` 一定更大，位数少则一定不可能更大。
   同位数时若 `base > lower`，`base` 就是答案。
3. 否则必须"在某个位置 $j$ 上超过 $lower$"：$j$ 之前与 $lower$ 完全相同，
   第 $j$ 位取比 $lower[j]$ 大的最小可行数字，$j$ 之后取最小。**$j$ 越靠右，得到的数越小**，
   所以从右往左扫第一个可行的 $j$。

第 3 步是常见的"构造恰好大于某数的最小串"的技巧，扫一遍 $O(L)$ 个位置即可。
下面是样例第三组 `?????????,9` 的贪心追踪，
每行的"尝试序列"是这一位按 `, 0 1 … 9` 试下来、判定返回的**可达性序列**，
第一个 `True` 就是留下的字符：

| 位置 | 该位尝试与判定结果 | 留下的字符 |
| :-: | --- | :-: |
| 0 | `,` ✗，`0` ✗，`1` ✓ | `1` |
| 1 | `,` ✓ | `,` |
| 2 | `,` ✗，`0` ✗，`1` ✗，`2` ✓ | `2` |
| 3 | `,` ✓ | `,` |
| 4 | `,0 1 2` 全 ✗，`3` ✓ | `3` |
| 5 | `,` ✓ | `,` |
| 6 | `,0 1 2 3` 全 ✗，`4` ✓ | `4` |
| 7 | `,` ✓ | `,` |
| 8 | `,0 1 2 3 4` 全 ✗，`5` ✓ | `5` |

观察重点有两处。第一，位置 0 试 `,` 会直接失败，因为串首不能是逗号；试 `0` 也不行，因为数字段首位不能是 `0`；
奇数位置试探逗号时立刻成功，因为逗号总是让后面的段更短、更容易满足递增。
第二，偶数位置试 `,` 也失败：它前面的奇数位置已经是逗号，再放一个就是空数字段；
而试 `0` 同样失败（这一位正是某个数字段的首位，会出现前导 `0`）。
剩下第一个能成功的字符就是这一位的最小值：位置 2 试 `1` 时，
这一段夹在两个逗号之间只有一位，必须 $> 1$，所以只能升到 `2`；
位置 4、6、8 同理依次升到 `3`、`4`、`5`。
整个过程与它要填的数值大小无关，纯粹是"先占逗号，占不下才升为数字"。

**不可行与边界。** 判定返回假时输出 `impossible`（判定本身已覆盖了"必须递增"与
"无前导 0"两个硬约束，所以不必额外特判）。全问号短串可以直接手算感受贪心的取舍：
`?????` 的答案是 `1,100` 而不是段数更多的 `1,2,3`——两者第 3 个字符分别是 `1` 与 `2`，
位置 2 处 `,`（空段）和 `0`（前导 `0`）都不可行，而 `1` 已经可行，贪心就停在这里；
`??` 的答案是 `10` 而非 `1`，因为长度是硬性的：填成 `1,` 会以逗号结尾。

### 复杂度

- **时间**：设串长 $n$。每次判定按逗号位置递推，$O(n)$ 个状态、每个状态枚举 $O(n)$ 个段终点，
  段内填数 $O(n)$，数字串比较 $O(n)$，故单次判定 $O(n^2)$。贪心要试 $n$ 个 `?`、
  每个至多试 11 个字符，总复杂度 $O(n^3 \cdot 11)$；$n \leqslant 50$、$T \leqslant 10$ 时
  单个数据点毫秒级完成（C++ 实测 10 个数据点全部 $\leqslant 0.01$ s，限时 1000 ms）。
- **空间**：状态数组存 $O(n)$ 个长度 $O(n)$ 的串，加上模式串与答案串，$O(n^2)$ 字符；
  实测峰值内存 8.4 MB（限时 128 MB）。
- **Python 侧**：同一算法的 CPython 实测最慢数据点 0.16 s（$T = 10$、串长 50 全问号），
  距离 1 s 限时安全，不存在 TLE 风险。

## 总结

- **按位贪心而不是按段构造**：字典序最小由最终字符串逐位决定，
  逗号比所有数字小，所以每个 `?` 的候选顺序必须是 `, 0 1 … 9`，
  不能按"把某个数写小一点"的直觉去调。
- **贪心的正确性完全依赖判定的精确性**：逐位贪心本身是平凡的，
  这道题的思维量在"能否补全"这一问上；判定错一点，整串就会错。
- **状态只需记住一个值**：合法串的约束是"相邻两段递增"，
  所以走到某个逗号位置时，只有"左侧最后一个数最小是多少"会影响未来，
  其余路径一律被支配。这是"只留最优值做可行性判定"的典型用法。
- **"恰好大于某数的最小数字串"**：构造 `base`、比位数、
  再枚举"第一个变大的位置并从右往左取最靠右者"，三步都是 $O(n)$ 级别的技巧，
  在各类字典序 / 数位构造题里反复出现。
- **边界由判定统一处理**：首尾逗号、前导 `0`、空数字段、连续逗号、段内固定逗号，
  全部在 `minNumber` 与转移的合法性检查里自然被排除，不需要额外特判。
