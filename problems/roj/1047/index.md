## 形式化题目

给定一个整数 $n$，设

$$
D(n) = \{\, d \in \{3,\ 5,\ 7\} : d \mid n \,\}
$$

输出 $D(n)$ 中所有元素按从小到大、以单个空格连接的序列；若 $D(n) = \varnothing$ 则输出 `n`。

整除与符号无关（$d \mid n \iff \exists q \in \mathbb{Z},\ n = qd$），真实测试数据一半是负数（如 $-335$、$-986$）。样例：$n = 105 = 3 \times 5 \times 7$，$D(n) = \{3, 5, 7\}$，输出 `3 5 7`。

## 正解

### 思路

朴素做法（也是评测标准程序 `std.cpp` 的写法）：3、5、7 各自"是否整除"是三个独立的布尔量，组合共 $2^3 = 8$ 种。它用 8 个 `if` 把组合编码进变量 `t`（被 3 整除 $t=1$、被 5 整除 $t=2$、……、三个都整除 $t=7$），再用 `switch` 的 8 个分支分别输出 `3`、`5`、`7`、`3 5`、`3 7`、`5 7`、`3 5 7`、`n`。计算上只有三次取余，**没有任何瓶颈可消除**——再写一个"暴力版"只会得到同一组表达式，所以本题不设暴力层，直接讲最终做法（直接正解型布局的依据）。`std.cpp` 真正的负担在表达：8 个 `if` 条件互相重叠，靠书写顺序保证 `t` 取到"最具体"的组合，8 个输出串还各自手抄了一遍除数与顺序。

回到输出本身的定义就能把这 8 路分支压掉：输出就是"$D(n)$ 按升序、空格连接"，与组合枚举无关。三点观察：

1. **顺序免费**：候选除数按 $(3, 5, 7)$ 递增排列，沿这个顺序过滤，留下来的列表天然"小的在前"，不需要排序，也不需要为"3 5 / 3 7 / 5 7"分别写分支。
2. **四种情形合一**：题面的 4 种情形只是结果列表长度 $3/2/1/0$ 的差别。`' '.join(...)` 覆盖前三种（长度为 1 时自然没有空格）；空列表在 Python 中是假值，条件表达式的 `else` 一支收掉"输出 `n`"。
3. **负数判据安全**：Python 的 `%` 余数符号跟随除数（$-335 \% 3 = 1$），C/C++ 的跟随被除数（$-335 \% 3 = -1$），两种语义下"余数为 $0$"都当且仅当整除，所以 `n % d == 0` 在负数输入上跨语言正确。

于是全部逻辑是一行列表推导：`[d for d in DIVISORS if n % d == 0]` 同时完成枚举、过滤、保序；`DIVISORS = (3, 5, 7)` 这个模块级常量把"候选集合"和"输出顺序"两层含义编码在同一处。下表用样例和真实数据推演这条链路（余数按 Python 语义）：

| 输入 $n$ | $n \bmod 3$ | $n \bmod 5$ | $n \bmod 7$ | 过滤结果 | 输出 |
| --- | --- | --- | --- | --- | --- |
| $105$ | $0$ | $0$ | $0$ | `[3, 5, 7]` | `3 5 7` |
| $-335$ | $1$ | $0$ | $1$ | `[5]` | `5` |
| $28$ | $1$ | $3$ | $0$ | `[7]` | `7` |
| $-986$ | $1$ | $4$ | $1$ | `[]` | `n` |

表中值得多看一眼的是 $-335$ 一行：$-335 = 5 \times (-67)$，只被 5 整除；两个非零余数在 Python 里都是正的（除数是正的），在 C 里则都是负的——但零与非零的判定不受影响。$-986 = 2 \times 17 \times 29$ 与三个候选除数都互素，三种余数全非零，过滤结果为空列表，正好走 `else` 一支输出 `n`。若除数扩成四个（如再加 11），分支写法的分支数翻倍到 16，而这行推导只需改常量，结构不变。

输出还有一个语言细节：`' '.join` 只接受字符串序列，整数列表必须先 `map(str, ...)` 转换再连接。读入沿用本系列的标准链路 `sys.stdin.buffer.read().split()[0]`——一次读完整份输入、按空白切分顺带吞掉行尾换行、取第一个 token；`int()` 对 `-335` 这样的字节串直接解析出负数，不需要预处理。

### 复杂度

- 时间复杂度：$O(1)$：读入一个 token、三次取余、至多三个元素的连接与一次输出，与 `std.cpp` 同阶（它的 8 个 `if` 与 `switch` 也是常数个工作）。

## 总结

- 输出即结构：题面的 4 种情形只是"整除除数升序序列"的长度差别，一次列表推导 `[d for d in DIVISORS if n % d == 0]` 替代 8 分支组合枚举 + `switch` 查表，`std.cpp` 的 $2^3 = 8$ 组合分支一行收齐。
- "小的在前"由 `DIVISORS = (3, 5, 7)` 的排列顺序直接保证，过滤保持迭代顺序，不需要排序或按情形分支。
- 空列表是假值：`' '.join(map(str, divisors)) if divisors else 'n'` 用条件表达式收掉落空情形；`join` 只接受字符串，整数需先 `map(str, ...)`。
- 负数安全：Python 与 C 的余数符号约定不同（跟随除数 vs 跟随被除数），但 `n % d == 0` 的整除判据在两种语义、两种符号下都正确；真实数据 10 组中 5 组负数全部通过。
- 实测 10 个评测点全部一致，单点约 0.016 s、峰值内存 14.5 MB，相对 1000 ms / 128 MB 的限制十分宽裕。
