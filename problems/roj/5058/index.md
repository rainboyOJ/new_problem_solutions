## 形式化题目

给定三个实数 $a, b, c$，求其中的最大值 $\max(a, b, c)$。
题面未给数据规模，测试数据自定范围：值域 $[-999999, 999999]$、最大有效数字 6。

## 正解

### 思路

本题是分支结构的经典例题。对于求多个数中的最大值，一种常见且易扩展的做法是“打擂台法”：
1. 假设第一个数是当前最大值，存入变量 $m$。
2. 依次将其与后面的数比较，如果后面的数严格 `>` $m$，则更新 $m$（相等值取先出现者）。
3. 比较结束后，$m$ 中存储的即为最大值。

**隐性坑点：输出格式**
要求按最简十进制写法输出（`%g` / `cout` 默认格式），不可用 `%.2f` 定点。如果使用 `%.2f`，在遇到如 `-999999` 或 `1` 等整数输入时，会错误输出成 `-999999.00` 或 `1.00`。
- 方案(a) 原样回显，与方案(b) `%g` 在本数据域内可证明逐字节相同（域内穷举 400 万值 0 不一致；且生成器 `data.py` 的 `check_token()` 断言了 `("%g"%float(tok))==tok`）。
- 既然两者皆可，选 `%g` 是因其对 `1.50` / `007` 类非最简输入更宽容，且与 `std.cpp` 口径一致。

## 总结

1. **算法**：打擂台求三个数的最大值。复杂度 $O(1)$。
2. **输出格式：(a) 原样回显 $\equiv$ (b) `%g`，且【可证明恒等】**
   - 域内穷举约 400 万值 0 不一致。
   - **构造性根因**：数据生成器 `data.py:120` 的 `check_token()` 断言了 `("%g" % float(tok)) == tok`，生成器强制了二者一致。
   - 选 (b) 有零正确性代价。更硬的理由是：各测试点的 `.out` 本身就是由 `std.cpp` 的 `printf("%g")` 生成，方案 (b) 与数据包**定义上一致**。
   - ⚠ **不可用 `%.2f`**：例如用例 `p2`/`p4`/`p5` 若用 `.2f` 会输出 `-999999.00`/`1.00`/`0.00` 导致 WA。
3. **`%g` 的潜在风险与不可达性**：若数据有效数字 $\ge 7$ 位（或 $|x| < 10^{-4}$、$\ge 10^6$），`%g` 会输出指数形式（如 `1.23457e+06`）而原样回显不会。但在**本数据包不可达**（最大 6 位有效数字、值域 $[-999999, 999999]$、最小非零 $|x| = 0.5$）。
4. **Python 原生 `print` 不可用**：`print(1.0)` 会输出 `'1.0'`，而 `%g` 输出 `'1'`，480 组边界测试中 369 组因此分歧。必须使用 `'%g' % x` 以保证与 C/C++ 语义一致。
5. **数据范围**：题面**未给数据规模**，测试数据自定范围（值域 $[-999999, 999999]$、最大有效数字 6、含 12 个负数、1 个零）。
6. **算法选择**：题面机械判据全空，并未限制实现手段。因此直接打擂台法或调用 `max` 均合法。
7. **验证强度摘要**：V6 **四条独立路径**（含**精确有理数不经浮点**）**1000/1000**一致；480 组边界 C++ vs Python 逐字节一致；`double` 在数据域内为单射。V1/V5 删掉更新则 6/10 发生输出变化；V9（UBSan）在大量级输入下报错全空；V2 代码字面量未硬编码答案值。
8. **相等值**：**严格 `>` $\Rightarrow$ 取先出现者**（如 `p6` 样例：两数并列 `0.81` 时正确选取并输出）。
