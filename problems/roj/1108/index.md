## 形式化题目

给定两个 $n$ 维整数向量

$$a = (a_1, a_2, \dots, a_n), \qquad b = (b_1, b_2, \dots, b_n)$$

求它们的点积，即同下标分量乘积之和：

$$a \cdot b = \sum_{i=1}^{n} a_i b_i = a_1b_1 + a_2b_2 + \cdots + a_nb_n$$

其中 $1 \leqslant n \leqslant 1000$，每个分量的绝对值不超过 $1000$。点积是一个整数，
不取模、不保留小数。

样例 $n = 3$、$a = (1, 4, 6)$、$b = (2, 1, 5)$ 的配对关系：

| 下标 $i$ | 1 | 2 | 3 |
| --- | --: | --: | --: |
| $a_i$ | 1 | 4 | 6 |
| $b_i$ | 2 | 1 | 5 |
| 逐项乘积 $a_ib_i$ | 2 | 4 | 30 |
| 前缀和 $\sum_{j \leqslant i} a_jb_j$ | 2 | 6 | **36** |

表中每一列是一对同下标分量；乘积一行是配对的产物，前缀和一行说明"累加"是从左到右
折叠，最后一格 $36$ 就是输出。

## 正解

### 思路

先按定义直译，最容易想到的写法是用一个下标同时索引两个数组：

```python
result = 0
for i in range(n):
    result += a[i] * b[i]
print(result)
```

它已经完全正确，而且时间复杂度已是 $O(n)$：每个分量至少要被读入并参与一次乘法，
$\Omega(n)$ 是下界，继续琢磨"更快的算法"没有意义。所以这道题真正值得改进的不是
复杂度，而是**写法**里那些不属于题意的零件：

- 手写下标 $i$：读者必须自己核对两处用的是不是同一个 $i$，有没有一边写成 `i + 1`；
- 手写 `result = 0` 再逐步 `+=`：这是把一串值折叠成一个值，Python 里叫 `sum`；
- 两段几乎一样的读入循环：都只是"取 $n$ 个整数组成列表"。

把这三件事交给语言本身：**按位对齐**交给 `zip`，**从左到右累加**交给 `sum`，
于是定义式 $\sum_i a_ib_i$ 可以一字不差地落成一行表达式：

```python
sum(ai * bi for ai, bi in zip(a, b))
```

这不是单纯的"短一点的等价写法"。`zip(a, b)` 的语义就是"第 $i$ 个配第 $i$ 个"，
把原先藏在 `a[i] * b[i]` 两个下标里的**隐含约定**变成了**显式语义**：下标变量
彻底消失，也就不可能出现 `a[i] * b[i + 1]` 这类错位；它还在两个序列中较短的一个
耗尽时停止，因此不会越界（本题两个列表都由同一个 $n$ 生成，长度必然相等，
不存在被静默截断的风险）。

读入部分同样用"顺序消费一个整数流"来表达题面的格式约定。输入 token 的顺序是

$$a_1, a_2, \dots, a_n, \; b_1, b_2, \dots, b_n$$

也就是**前 $n$ 个是 $a$、后 $n$ 个是 $b$**。用 `read().split()` 一次读完并按空白
切分，`map(int, ...)` 转成整数，`iter` 变成只能前进的流，再按同一个 $n$ 连续取两段，
这条顺序就写在代码里了：

```python
data = iter(map(int, sys.stdin.buffer.read().split()))
n = next(data)
a = [next(data) for _ in range(n)]
b = [next(data) for _ in range(n)]
```

用同一个 `data` 先取 $a$ 再取 $b$，等价于说"$b$ 紧跟在 $a$ 后面"；写成两个独立
列表推导而不是 `[next(data) for _ in range(2 * n)]` 再切片，是因为题面明确把两个
向量分成两行，代码里保留这个划分，读者一眼就能对上题面。

最后核对数值范围。$|a_i|, |b_i| \leqslant 1000$ 且 $n \leqslant 1000$，所以

$$|a \cdot b| \leqslant n \cdot 1000 \cdot 1000 = 10^9 < 2^{31} - 1$$

参考程序 `std.cpp` 用 `int` 累加恰好不溢出；Python 的整数是任意精度的，连这个
上界都不需要关心。同时全程只有整数乘加，没有浮点舍入，输出与标准答案逐字符一致。

### 复杂度

- 时间复杂度：$O(n)$。每个分量读入一次，$n$ 对乘积各做一次乘法和一次加法。下界
  $\Omega(n)$，故为最优；$n \leqslant 1000$，实测约 0.02 s/组（限制 1000 ms）。
- 空间复杂度：$O(n)$，用于存放两个长度为 $n$ 的分量列表；`zip` 与生成器都是惰性的，
  不额外产生 $n$ 个元组的列表。峰值内存约 14.6 MB（限制 128 MB）。

## 总结

- 点积的定义就是"按位配对、逐项相乘、全部累加"，读入后按同一下标配对是唯一要点。
- 把定义式的下标循环写成 `sum(ai * bi for ai, bi in zip(a, b))`，等价于把"第 $i$ 个
  配第 $i$ 个"从隐含约定提升为 `zip` 的显式语义，下标错位这类错误无从发生。
- 读入用"顺序消费整数流"表达题面约定：`n` 之后连续 $n$ 个是 $a$，再连续 $n$ 个是 $b$。
- 数值上 $|a \cdot b| \leqslant 10^9$，`int` 不会溢出；整数乘加没有精度问题。
- 验证：10 组真实测试数据全部 PASS（约 0.02 s/组、峰值内存约 14.6 MB，限制
  1000 ms / 128 MB）。
