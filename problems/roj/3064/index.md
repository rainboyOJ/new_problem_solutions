## 形式化题目

给定一个 $16 \times 16$ 的残缺数独矩阵，其中已知位置填有字母 `A` 到 `P`，未知位置填有占位符 `-`。
要求将所有的占位符替换为 `A` 到 `P`，使得：
1. 每一行包含 `A` 到 `P` 各恰好一次。
2. 每一列包含 `A` 到 `P` 各恰好一次。
3. 每一个 $4 \times 4$ 的十六宫格（共 16 个）包含 `A` 到 `P` 各恰好一次。

保证给定的数独有唯一解。输入包含多组测试用例，用例数未知，需要处理到 `EOF` 结束。每个测试用例输出完成后，需额外输出一个空行。

## 正解

### 思路

本题是 $16 \times 16$ 规模的数独问题。由于规模较大，朴素的搜索甚至加入 MRV（选取可选数最少的格子分支）的位运算优化回溯，在特定的深搜树下极易发生指数级爆炸导致 TLE（超时）。

为保证效率，本题的绝对正解是将数独转化为**精确覆盖问题（Exact Cover Problem）**，并使用 **Dancing Links (DLX)** 算法求解：
- **行（决策）**：共有 $16 \times 16 \times 16 = 4096$ 种填法。每一行代表在第 $i$ 行、第 $j$ 列的格子中填入字母 $k$。
- **列（约束）**：共有 $16 \times 16 \times 4 = 1024$ 个约束（分为格子必须有字母、行中 $k$ 唯一、列中 $k$ 唯一、宫中 $k$ 唯一四类，各 256 列）。

每一条有效的填法决策会在对应的 $4$ 个约束列处填上 $1$。利用 DLX 的双向十字链表，通过“每次选择列上 $1$ 最少的约束进行覆盖”的启发式策略，我们可以极大地收敛分支空间，使得在即使是 $16 \times 16$ 这种状态空间庞大的数独问题中，也能保持较小的节点遍历数。

### 复杂度

- **时间复杂度**：精确覆盖问题理论上的最坏复杂度是指数级 $O(c^N)$，但对于确保有唯一解的实际数据，由于强大的启发式剪枝与 DLX 非常优秀的常数，实际运行时间极短，相当于极低常数下的多项式时间。
- **空间复杂度**：由于只分配非零节点的链表节点，$4096$ 行决策最多产生 $4 \times 4096 = 16384$ 个十字节点，加上列头等辅助节点，整体空间需求 $\le 20000$ 个 `int` 规模变量，空间复杂度相当于 $O(N \times M)$，极小。

## 总结

根据在真实数据上利用自动验证框架（T9 工作流）的测试情况，本题包含了许多极为严格的物理特征与边界，关键结论如下：

1. **DLX 是承重的算法核心（`V1` 反事实测试）**：
   实测若降级为“朴素回溯（无 DLX 无 MRV）”，将在 6/8 个点 `TLE`；若使用“位运算 + MRV 回溯”，依然会在 5/8 个点 `TLE`（如 `5.in`、`6.in` 等节点爆炸）。只有 DLX 能稳如磐石。去掉任何一维约束（如宫约束、列约束），立刻触发全盘 8/8 报错。
2. **多组数据分布与空行逻辑（输出格式陷阱）**：
   - 物理输入行数排查证明：`1.in` 实际上是 **16 行无任何后置空行**的数据（第一轮思考时的 17 行系 python `split` 函数尾切分的假象）。`1..7.in` 全都只有单组数据。
   - **`8.in` 是唯一的多组数据点**（共有 3 组数据）。如果代码“只处理第一组”，则只有 `8.in` 会判定失败（测试证实在唯一多组点出错 1/8），所以它构成了测试多组循环逻辑的唯一依据。
   - **空行输出极为严格**：每一组答案输出之后（**包括最后一组之后**）都必须跟随一个空行。如果写成“仅在两组输出之间加入空行”（方案 C），虽然由于 Token 序列完全相同无法被基于 token 的评测器识别出来，但在严格对比字节的闸门下，`1..7.in` 这种单组点会缺少最后的换行（相差一个 LF），导致字节数不匹配。因此，唯一的完全正确方案就是 **每组后一个空行（A 候选）**。
3. **异源验证与元教训 (`V6`)**：
   worker 使用另一套不含精确覆盖、直接基于候选位掩码传播（唯一候选传播）构建的独立求解器对 10 组输入进行枚举统计。结论为：**全部 10 组恰好各自 1 解**，且输出答案与官方 `.out` **逐字节相同**，完美确证了题意“保证唯一解”。
   - **元教训（验证器本身也要被验证）**：worker 的这套独立验证器在第一版中曾因为数组映射错误及缓冲溢出等 bug 导致报出 0 解，是在加入了自检手段（“对一个已知满解的数独跑求解器必须返回 1 解”）并修好错误后才得出了真实结论。
4. **算法指纹确证 (`V7`)**：
   对于极易发生搜素爆炸的测试点（如 `5.in`），位运算程序的探索节点数达到了数十万且超时，而 C++ 实现的 DLX 算法由于进行了精妙的修剪，其 `dfs_nodes`（如 434480）与 Python 代码通过 `cProfile` 跟踪统计得出的 `cover` 调用次数 **精确吻合**。两条异构语言实现的表现证明是**真 DLX，真在搜索**。
5. **非硬编码 (`V2`) 与结构不变量 (`V4`)**：
   代码层面做到了纯净，没有任何字母连续序列。全部 10 份 `.out` 答案对应的 160 行字符序列在源码中 `verbatim` 出现次数为 **0 次**。
   同时，所有测试用例均为 `CRLF=0`，全为纯正的 LF 换行，规避了许多 Windows 数据中含有的混淆点；每行的长度与可用字符 `A~P` 及 `-` 也全部满足验证约束（10 组 $\times$ 5 大类约束满分通过）。
6. **动态与运行安全 (`V9`)**：
   所有的实现（甚至处理 20000 数组越界的风险探测）均在包含 `ASan` 和 `UBSan` 的测试组下零报错通过。作为对照，如果在输出时将字母有意加上一个偏移，则立即触发 8/8 阻截报错，证明闸门校验完全有效。
