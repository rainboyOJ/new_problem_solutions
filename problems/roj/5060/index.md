## 形式化题目

输入两个实数 $a, b$ 和一个字符 $op$。
求表达式 $a \ op \ b$ 的值，其中 $op$ 可能为 `+`、`-`、`*`、`/`。
- 如果 $op$ 不是这四种运算符之一，输出 `Invalid operator!`。
- 如果 $op$ 为 `/` 且 $b = 0$，输出 `Divided by zero!`。
- 其他情况下，输出运算结果，格式要求按默认的 $6$ 位有效数字显示，对大数自动采用科学计数法。

## 正解

### 思路

本题需要实现一个简单的四则运算计算器。
读入三个元素，由于题目给出的操作数可能是小数（如 `0.25 0.75 +` 得 `1`），并且结果在大数据下需要输出科学计数法格式，所以应该使用双精度浮点数（`double`）进行存储与运算。操作符用字符型存储。

- 首先判定运算符是否为合法运算符（即 `+`、`-`、`*`、`/` 之一），如果不是，输出 `Invalid operator!`。
- 其次如果运算符为 `/`，需要特判除数是否为零。若除数为零则输出 `Divided by zero!`。
- 其他情况下，进行正常的加减乘除即可。
- 对于输出格式，观察样例和数据点发现，无论是小数运算的截断还是大整数的指数形式输出，其结果格式均与 C 语言中的 `%g` 格式符保持一致（保留 6 位有效数字，去除多余的尾随 0 和小数点，大数转为科学计数法）。在 C++ 中直接使用 `printf("%g\n", res)`（或依赖 `cout << double` 的默认行为），在 Python 中使用 `print('%g' % res)`，即可完美满足题目对结果展示的要求。

## 总结

- **算法与结构**：读入两个操作数与一个操作符，进行条件分支计算；遇到除零异常输出 `Divided by zero!`；遇到无效操作符输出 `Invalid operator!`。
- **类型与格式化（本题最核心考点）**：
  - 本题要求输出格式严格吻合 `%g`（6 位有效数字、去尾零）。
  - 数据点中的实测验证：`626077 726791 +` 得 `1.35287e+06`，`999999 999999 *` 得 `9.99998e+11`，`1000000 1000000 *` 得 `1e+12`，均触发了科学计数法。
  - **异源复算证明**：使用 `Decimal` 手写 `%g` 逻辑（完全不调用任何格式化函数）异源复算数据点，8/8 吻合数值用例，说明 `%g` 是真实的内在契约，并非巧合拟合。
  - **跨语言注意**：Python 原生的 `print` 行为与 C++ 完全不同（例如 Python 会输出 `1352870.0` 或是将 `1.0` 打印为 `1.0` 而非 `1`），故 Python 侧**必须**使用 `'%g' % x` 才能通过本题。
- **环境差异（本题引发的重大发现）**：
  - 评测机所处的 Linux glibc 环境与 Python 中 `%g` 的行为一致（会去除科学计数法中的尾随零）。
  - 而 **macOS 的 libc 存在已知缺陷**，部分数值在转为科学计数法时**不去尾随零**。例如 `6 999999 +`（值 `1000005.0`），在 macOS 的 C++ 环境下输出 `1.00000e+06`，而在 glibc 与 Python 下输出为正确的 `1e+06`。
  - 经过 8712 组穷举测试，C++ 与 Python 的 4 处差异**全部被定位为 macOS libc 的格式化缺陷**，glibc 侧则是 0 差异。
  - 这再次证明了**在浮点格式化考题中，本机的 C++ 输出不可直接作为真理参照**。好在本题的数据点没有出现触发这一缺陷的值（如 `9.99998e+11` 和 `1e+12` 两端表现一致），故代码无需额外修复即可通过。
- **歧义与不可裁定**：
  - **`/` 是实数除还是整除？** 本题数据中唯一的 `/` 用例是 `5 0 /`，触发了错误分支，没有任何成功的除法用例，因此**数据无法裁定**是哪一种除法。但结合题意有小数输入，我们采用实数除。
  - **两种错误同时出现的优先级**：数据集中未出现同时触发（如 `5 0 %`）。故**数据无法裁定优先级**。但在代码中我们优先验证有效操作符，若操作符无效，则连除数都不是，理应报非法操作符。
  - 事实上，使用 V8 实跑验证，**“实数除/整除”与“先判零/先判操作符” 组合成的 4 种语义，在真实 10 个数据点上的失败点集合完全相同（全为 ∅）**，这意味着这四种语义在本数据集上属于**不可区分等价类**。
- **除零优先级**：尽管上述双重错误未覆盖，但用例 `5 0 /` 证明了除数为 0 时**必须先判除零异常再做运算**，否则会产生无穷大。
- **数据格式**：数据规范，10个点全部为 3 token（单空格分隔），行末含换行符，无 `\r`。
