## 形式化题目

给定一个整数 $s \geqslant 0$，表示这次办事要行走的距离（米）。两种出行方式的耗时为

$$t_{\text{walk}} = \frac{s}{1.2}, \qquad t_{\text{bike}} = \frac{s}{3.0} + 50,$$

其中骑车速度 $3.0$ m/s、步行速度 $1.2$ m/s，固定开销 $50 = 27 + 23$ 秒是找车、开锁、停车、锁车的时间。
按 $t_{\text{bike}}$ 与 $t_{\text{walk}}$ 的大小关系输出 `Bike`（骑车更快）、`Walk`（走路更快）或 `All`（一样快）。

样例：$s = 120$ 时 $t_{\text{walk}} = 100$ 秒、$t_{\text{bike}} = 40 + 50 = 90$ 秒，骑车快，输出 `Bike`。

## 正解

### 思路

先把题面直接翻译成两行公式——这就是朴素做法，同时也是最终做法，因此按直接正解型组织，不另设暴力层：

```python
walk = s / 1.2            # 步行总耗时
bike = s / 3.0 + 50       # 骑车总耗时：路上时间加固定准备时间
```

一次读入、两次除法、一次比较，$O(1)$ 已是下界，不存在"换个算法更快"的空间。它真正的隐患不是速度而是**精度**：
$1.2$ 不是二进制浮点的准确值，`s / 1.2` 必然舍入，而"一样快"要求判断两个浮点数是否**严格相等**，
`==` 是否成立取决于舍入的巧合，而不是数学。本题的常量取值下浮点写法恰好没有出现反例（实测 $s \in [0, 2 \times 10^5]$ 全量与精确判据一致），
但"恰好安全"依赖常量，而不是一条可以依赖的结论，所以优化的目标是"把三态比较变成精确判定"。

**第一步：消去分母。** 分母是 $1.2 = \dfrac{6}{5}$ 与 $3$，最小公倍数是 $6$。两边同乘 6：

$$t_{\text{walk}} \times 6 = 6 \times \frac{5s}{6} = 5s, \qquad t_{\text{bike}} \times 6 = 6 \times \frac{s}{3} + 6 \times 50 = 2s + 300 .$$
（为了与代码对齐，后文把这两个量记作 `walk_x6` 与 `bike_x6`。）

乘 $6$ 是严格单调的双射，$a < b \iff 6a < 6b$、$a = b \iff 6a = 6b$，所以三个分支的判据完全等价，
而左右两边都变成了整数——任何输入都不再有舍入，`All` 有了严格判据。

**第二步：移项，让临界点显形。**

$$5s \gtrless 2s + 300 \iff 3s \gtrless 300 \iff s \gtrless 100 .$$

也就是说：骑车更快当且仅当 $s > 100$，一样快只在 $s = 100$ 这一点。下表给出临界附近的三个相邻距离和官方样例：

| 距离 $s$ | 步行耗时 $t_{\text{walk}}$ | 骑车耗时 $t_{\text{bike}}$ | 放大 6 倍后 $(5s,\; 2s + 300)$ | 结论 |
| :---: | :---: | :---: | :---: | :---: |
| $99$ | $82.5$ s | $83.0$ s | $(495,\; 498)$ | `Walk` |
| $100$ | $\dfrac{250}{3} \approx 83.33$ s | $\dfrac{250}{3} \approx 83.33$ s | $(500,\; 500)$ | `All` |
| $101$ | $84.1\overline{6}$ s | $83.\overline{6}$ s | $(505,\; 502)$ | `Bike` |
| $120$ | $100$ s | $90$ s | $(600,\; 540)$ | `Bike` |

表中第 4 列是代码真正比较的两个整数：它把 $s = 100$ 的相等判据从"两个浮点数恰好一样"变成"$500 = 500$"。
真实测试数据的 10 组距离全部不小于 $2068$（生成范围是 $100 \ldots 10000$），输出都是 `Bike`，所以 `Walk` 与 `All` 两支没有任何测例保护，
必须靠这张表和上面的代数推导来确认——这也是本题最容易"数据过了但其实写错"的地方。

**第三步：三态输出。** "一样快"必须单独判，绝不能被并入另外两支。代码里用两个布尔量把话说清楚：

```python
bike_faster = bike_x6 < walk_x6   # 严格小于才是骑车更快
same_speed = bike_x6 == walk_x6   # 整数相等才是真的 All
```

最后 `print("All" if same_speed else VERDICT[bike_faster])`，其中 `VERDICT = {True: "Bike", False: "Walk"}`——
用 `dict` 表达"严格更快 → Bike，否则 Walk"这条两分支映射，既省掉 `if/elif` 链，也不会像 `bike <= walk`
那样把相等的情况误吞进 `Bike`。另外代码保留的是 $5s$ 与 $2s + 300$，而不是把结论硬编码成 `s <= 100`：
前者每个常量都能指回题面（$5$ 来自 $1.2 = 6/5$ 的耗时倍率 $5/6$ 再乘 $6$，$2$ 来自 $3$ m/s 的耗时倍率 $1/3$ 再乘 $6$，$300 = 50 \times 6$），
读者可以逐项核对固定开销是怎么进入式子的。

### 复杂度

- 时间复杂度：$O(1)$，一次读入、两次乘加、两次整数比较、一次输出，与标准 C++ 解法同阶。
- 空间复杂度：$O(1)$，只保存两个耗时、两个布尔量与三个常量，无数组无递归。

## 总结

- **固定开销与距离无关**：$27 + 23 = 50$ 秒是每次骑车都要付的常数项，距离越短越致命，$s = 0$ 时骑车仍要 50 秒，答案是 `Walk`。
- **同乘 6 把浮点比较变成整数比较**：$t_{\text{walk}} \gtrless t_{\text{bike}} \iff 5s \gtrless 2s + 300$，
  避免在"一样快"这个分支上依赖 IEEE 舍入的巧合；移项后临界距离是 $s = 100$，唯一解。
- **三态输出要单独判相等**：`bike <= walk` 会把 $s = 100$ 错判成 `Bike`；真实数据只覆盖了 `Bike` 一支，
  临界三点 $99/100/101$ 必须自己手测。
