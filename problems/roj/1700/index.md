## 形式化题目

给定 $n$ 个互不相同的非空字符串 $s_1, s_2, \dots, s_n$（均为小写字母串），求

$$
\#\Bigl\{\, T \subseteq \{s_1, \dots, s_n\} \;\Bigm|\; \forall\, x \neq y \in T,\; x \text{ 不是 } y \text{ 的前缀} \,\Bigr\} \bmod 9191 .
$$

空集没有两两前缀的约束，恒合法，因此答案至少为 $1$。约束是 $n \leqslant 50000$、
$|s_i| \leqslant 50$，串的总长不超过 $2.5 \times 10^6$。

## 正解

### 思路

**前缀关系天然长在字典树上。** 前缀是一种传递关系，$x$ 是 $z$ 的前缀且 $y$ 是 $x$ 的前缀
就说明 $y$ 也是 $z$ 的前缀；把 $s_i$ 插进一棵 26 叉字典树、在词尾节点上打标记后，
「$x$ 是 $y$ 的前缀」就等价于「$x$ 对应的标记点是 $y$ 对应标记点的**祖先**」。

于是合法子集 $T$ 的判定被翻译成一棵有根树上的组合条件：

> 任意两个被选中的标记点之间，不能存在祖先关系。

这正是树上的「**反链**」（antichain），只不过这里的树是 trie，且允许选空集。

**树上做 DP。** 设 $f[v]$ 表示「以 $v$ 为根的那棵子树里，只在标记点中挑、且挑出的点两两
不成祖先」的方案数。对 $v$ 分类：

- **选 $v$ 本身**（前提是 $v$ 被标记为词尾）：一旦选了 $v$，它的所有后代都不能再选，
  方案数是 $1$；
- **不选 $v$**：各棵子树完全独立，方案数是 $\prod_{\text{儿子 } c} f[c]$。

两件事互斥且穷尽，所以

$$
\boxed{\;f[v] = [\,v \text{ 是词尾}\,] + \prod_{c \text{ 是 } v \text{ 的儿子}} f[c] \;}
$$

叶子满足 $f = [\,\text{叶子是词尾}\,]$；根（空串对应的节点）不是任何输入的串，
所以 $f[\text{root}] = \prod_{c} f[c]$ 恰好就是答案——空集这一种方案被 $f$ 的「全不选」
分支自动计入，不需要额外加 $1$。

**为什么"不选 $v$"是连乘而不是求和？** 因为子树之间没有公共字符串，
一个方案由「每棵子树里各选一个（可能为空的）合法子集」唯一确定，
乘法原理把它们拼起来。这一点也是本题最容易写错的地方：
写成 $\sum$ 会把"只在某一棵子树里选"误当成唯一选择，漏掉跨子树的搭配。

用样例手算验证一下。三个串 $\{\text{hell}, \text{hello}, \text{hi}\}$ 的 trie 是
`hell` — `hello` 的链挂在 `h` 下、`hi` 另起一枝：

| 节点（前缀） | 是否词尾 | $\prod f[\text{儿子}]$ | $f[v]$ |
| --- | :-: | :-: | :-: |
| `hell` | 是 | $f[\text{hello}] = 2$ | $2 + 1 = 3$ |
| `hello` | 是 | $1$（无儿子） | $1 + 1 = 2$ |
| `hi` | 是 | $1$（无儿子） | $1 + 1 = 2$ |
| 根 | 否 | $3 \times 2 = 6$ | $6$ |

答案 $6$，与题面"只有 $\{$`hell`,`hello`$\}$ 和 $\{$`hi`,`hello`,`hell`$\}$ 两种不合法"
（$2^3 = 8$ 减 $2$）吻合。

**不建树也能建树。** 两个正式解都没有真的开出 26 叉字典树数组：总字符数可达
$2.5 \times 10^6$，如果每个节点都存 26 个儿子编号，光空间就是 $2.6 \times 10^8$ 个
`int`，远超题目内存限制。

关键是注意到：**把串按字典序排序后，同一个节点的所有后代在数组里正好是一段连续的区间**，
而第 $i$ 个串的「父亲深度」就是它与前一个串的最长公共前缀长度（LCP）。
于是只要一个手工栈按深度收拢节点，就能在 $O(1)$ 均摊时间里模拟出树的进出栈次序：

- 处理第 $i$ 个串时，先用相邻 LCP 求出它父亲的深度 `lcp`；
- 把栈里所有深度 $> \text{lcp}$ 的节点弹出，每弹一个就把它的 $f$ 乘进父亲的累乘值；
- 再把当前串作为一个深度为 $|s_i|$ 的词尾节点压栈。

栈里留下的都是"还没算完的祖先"，深度严格递增，一个节点的父亲就是栈中它下面那个。
中间那些「既不是词尾、又只有一个儿子」的节点（如 `hell` 与 `hello` 之间的过渡前缀）
被整段跳过——它们的 $f$ 恒等于唯一儿子的 $f$，跳过不影响答案。

以 `a`、`ab` 为例（答案 $3$）：排序后 `a` 先入栈（深度 1，词尾）；
处理 `ab` 时 LCP 为 $1$，栈顶深度 $1$ 不弹出，直接压入深度 $2$ 的词尾节点；
收尾时先弹 `ab`（$f = 1 + 1 = 2$）乘进 `a`，再弹 `a`（$f = 2 + 1 = 3$）乘进根，
输出 $3$。与 trie 上的 $f$ 完全一致。

### 复杂度

- **时间**：排序 $O(n \log n \cdot L)$ 次字符比较；LCP 的总比较次数不超过各串长度之和的
  常数倍（相邻 LCP 的单调性保证均摊 $O(\text{总长})$）；栈的入出各一次 $O(n)$。
  于是 $O(n \log n \cdot L + \text{总长})$，其中 $L \leqslant 50$。
  真实数据最大点 $n = 50000$、总长 $2.5 \times 10^6$，C++ 实测远低于限时 $1000$ ms。
- **空间**：`word[]` 存全部串 $O(\text{总长})$，手工栈与 Python 的栈各 $O(n)$
  （栈最大深度不超过最长串的长度 $50$）。没有 26 叉儿子数组，内存是 $O(\text{总长} + n)$。
- **与标准 trie 的关系**：常见写法是直接开 26 叉 trie 再 DFS 求 $f$，算法完全一样，
  但空间多一个 $26$ 倍常数；`main.cpp` 与 `main.py` 用「排序 + 相邻 LCP」把这一项省掉，
  代码也更短。注意这里**不需要**考虑 $9191$ 是否为质数：DP 只用到乘法和加法。

## 总结

- **前缀关系 = 祖先关系**：看到「若干串两两不为前缀」，第一反应应该是把串插进 trie，
  题目就从字符串问题变成树上的组合计数问题。
- **树形 DP 的转移由"选不选自己"唯一决定**：选了自己后代全禁（贡献 $1$），
  不选则各子树独立（贡献连乘）。这条 $f[v] = [\text{词尾}] + \prod f[c]$ 是本题的全部内容。
- **子树独立 ⇒ 乘法原理**：一旦把选题拆成"每棵子树各贡献一个子集"，
  乘法就是唯一正确的合并方式；写成加法是本题最典型的错误。
- **不必真的建树**：排序 + 相邻 LCP 能还原 trie 的父子关系，
  对"只需要知道父子关系、不需要按字符转移"的 trie 题，这是省内存省代码的通用技巧。
- 空集恒合法，被 $f$ 的"全不选"分支自动计入，无需单独处理。
