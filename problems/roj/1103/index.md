## 形式化题目

给定 10 个苹果离地高度 $h_1, h_2, \dots, h_{10}$（$100 \leqslant h_i \leqslant 200$），
以及陶陶伸手能达到的最大高度 $x$（$100 \leqslant x \leqslant 120$）。陶陶可以踩上
$30$ cm 高的板凳，碰到的苹果都会掉落。求她最多能摘到几个苹果，即求

$$\text{answer} = \bigl|\{\, i : h_i \leqslant x + 30 \,\}\bigr|$$

以样例为例，$x = 110$，合成阈值 $r = 110 + 30 = 140$，10 个苹果逐一判断如下。

| 苹果高度 $h_i$ | 100 | 200 | 150 | 140 | 129 | 134 | 167 | 198 | 200 | 111 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| $h_i \leqslant 140$？ | 是 | 否 | 否 | 是 | 是 | 是 | 否 | 否 | 否 | 是 |
| 摘到 | ✓ | | | ✓ | ✓ | ✓ | | | | ✓ |

读表要点：第 4 个苹果高度恰好等于 $140$，"碰到就掉"意味着等号必须取到；
表中打了勾的一共 5 个，正是样例输出。每个苹果的判断互相独立，答案就是数勾。

## 正解

### 思路

**朴素做法**照题面字面模拟：对每个苹果判断"高度 $\leqslant$ 伸手高度 $+30$"，
成立则计数器加一。这已经是正确算法——每个苹果只需看一次，没有任何瓶颈可消除，
所以本题按直接正解组织，把力气花在两个表达细节上：

1. **板凳是常数加成，先合成阈值。** $+30$ 只和伸手高度有关，与具体苹果无关。
   先算 `reach = x + 30`，之后所有苹果都和同一个阈值比较，"比较基准唯一"在代码里
   显式可见；若写在每个判断里，既啰嗦又容易在某处忘加。
2. **等号必须取到。** 题面说"碰到苹果，苹果就会掉"，伸手极限恰好够到的苹果也算。
   高度恰好 $r$ 的苹果要计入，判断用 $\leqslant$ 而不是 $<$——样例里 $h = 140$
   的苹果正卡在边界上，写成 $<$ 答案会从 5 变成 4。

计数本身用 Python 的谓词求和压缩成一个表达式：`sum(h <= reach for h in apples)`。
生成器逐个产出 `bool`，而 `bool` 是 `int` 的子类，`True` 参与求和就是 1，
于是"数一数有几个成立"不再需要计数器变量和 `if` 分支。

最终做法：一次读完整份输入（按空白切分转整数），前 10 个 token 是苹果高度、
第 11 个是伸手高度；合成阈值后单遍求和输出。

### 复杂度

- 时间：$O(1)$。苹果个数固定为 10，一次读入加一次单遍计数；一般化到 $n$ 个苹果是
  $O(n)$，已达"每个数至少要看一次"的下界。实测单例约 0.018 s（限制 1000 ms）。
- 空间：$O(1)$。只存 11 个整数；峰值内存约 14.5 MB（限制 128 MB），主要是 Python
  解释器常驻。

## 总结

整道题压缩成两步：**先合成阈值** $r = x + 30$，**再做谓词计数**
$\sum_i [\,h_i \leqslant r\,]$。两个易错点都藏在样例里：

- 忘记板凳 $+30$：阈值只剩 110，只能摘到 100 和 111 两个，输出 2 对不上样例的 5；
- 把 $\leqslant$ 写成 $<$：高度恰为 140 的苹果被漏掉，输出 4 也对不上。

边界上，$x$ 取上限 120 时 $r = 150$，高度 150 的苹果可摘；取下限 100 时
$r = 130$，若苹果都高于 130 则答案为 0（真实数据 case 2 即为 0，程序同样输出 0）。
