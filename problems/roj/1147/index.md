## 形式化题目

给定 $n$ 位学生的记录序列

$$
(s_1, t_1),\ (s_2, t_2),\ \dots,\ (s_n, t_n),
$$

其中 $s_i \in [0, 100]$ 是第 $i$ 位学生的分数，$t_i$ 是不含空白的姓名串（$|t_i| \leqslant 20$）。求分数最高的那位学生的姓名：

$$
t_{i^*}, \qquad i^* = \arg\max_{1 \leqslant i \leqslant n} s_i .
$$

题目保证最高分只有一位同学，所以 $i^*$ 是唯一的，输出 $t_{i^*}$ 即可。

样例 $n = 5$，从左到右扫描时当前最高分与候选姓名如下：

| 第 $i$ 位 | 分数 $s_i$ | 姓名 $t_i$ | 扫描后的最高分 | 候选姓名 |
| :-: | :-: | :-: | :-: | :-: |
| 1 | 87 | `lilei` | 87 | `lilei` |
| 2 | 99 | `hanmeimei` | 99 | `hanmeimei`（更新） |
| 3 | 97 | `lily` | 99 | `hanmeimei` |
| 4 | 96 | `lucy` | 99 | `hanmeimei` |
| 5 | 77 | `jim` | 99 | `hanmeimei` |

观察重点：第 4 位学生的分数 96 **小于**当前最高分 99，只是"没有超过"，所以候选姓名保持不变；整张表里只有第 2 次扫描发生了替换。把这一点抽象出来就是一句话——**只有严格更高的分数才允许换人**。这份保证的唯一性说明数据里不会出现两个并列最高分，因此不需要讨论并列时输出谁。

## 正解

### 思路

**朴素做法。** 直接把"求最大值"的定义抄下来：先用一个变量记下当前见过的最高分，再用另一个变量记下拿到这个分数的姓名；从头到尾看每一位学生，**只有当他严格高于当前最高分时**才同时更新这两个变量。扫描结束时，姓名变量里留下的就是答案。

```python
best_score, best_name = -1, ""
for score, name in students:
    if score > best_score:      # 严格大于才替换
        best_score, best_name = score, name
```

这里 `best_score` 的初值取 $-1$ 就够了：分数保证非负，所以第一位学生一定满足 `score > -1`，一定会被接收，不需要开特判。**比较必须是严格大于而不是大于等于**——如果用 `score >= best_score`，遇到与自己同分的后来者就会把姓名覆盖掉；本题虽然保证最高分唯一，但"严格大于"才是"求最大值、并列保留先到者"的正确语义，写 `>=` 等于把正确性寄托在数据保证上。

**瓶颈在哪里。** 这份循环里没有可以消掉的东西。每一位学生必须被看一次，因为不看完全部记录就无法断定谁最高；$n \leqslant 100$ 时循环体只有一次比较和一次可能赋值，性能上没有任何压力；输入已经按"分数 姓名"成对给出，也不需要排序或建立额外结构。所以本题写成**直接正解**，不设暴力层——再写一份"朴素版"只会得到逐语句等价、连复杂度都一样的代码，讲不出层次。

值得讲的是**这份扫描被压成了什么形态**。既然 `if score > best_score: 更新` 是求最大值的通用模式，Python 就把它固化成了内置原语 `max`：`max(可迭代对象, key=...)` 在内部做的正是同一件事——保存当前最优项，**只在遇到严格更优的项时替换**。本题要比较的是分数、要留下的是姓名，把两个列表 `zip` 成一组 `(分数, 姓名)` 之后，"比分数、留姓名"恰好就是元组比较的默认语义：先比第一个元素（分数），相等才比第二个元素（姓名）。

```python
max(zip(scores, names))    # 等价于上面的循环 + 取 [1]
```

于是整个算法收敛为三步：读入 $\to$ 把序列整理成 `(分数, 姓名)` 的配对序列 $\to$ 取最大值并输出姓名。写成流水线就是：

```python
scores = data[1::2]      # 分数在奇数位
names  = data[2::2]      # 姓名在偶数位
print(max(zip(scores, names))[1])
```

**一个必须解释的陷阱。** 上面的 `zip` 写法只在最高分**唯一**时等价于朴素循环。一旦出现并列最高分，`max` 会比较元组的第二个元素（姓名），输出字典序更大的那个名字——这既不是"输出第一个"，也不是题目想要的结果。真实数据里有 4 组并列（两组 2 人并列、一组 3 人并列），当前数据下最高分的姓名恰好字典序最大，所以流水线能通过；但这属于**运气**，题面的唯一性保证是唯一的依据。`main.py` 因此保留显式循环：它不依赖任何"姓名怎么排序"的隐含事实，语义与题面逐字对应，也更适合作为教学实现。

一句话概括控制流：顺序扫描，候选姓名只被"更高分"改写一次（样例中是 `hanmeimei`）。

实现与推导的对应关系：`data = sys.stdin.buffer.read().split()` 一次读入全部 token，用 `split()` 自动吃掉换行和空格，因此不需要处理行结构；`range(1, 2 * n + 1, 2)` 让下标 $i$ 依次落在每个学生的分数位置上；`data[i + 1].decode()` 取出紧随其后的姓名；`if score > best_score` 就是上文那条"严格更高才换人"的规则。

### 复杂度

- 时间复杂度：$O(n)$，$n \leqslant 100$。每个学生只被读入一次、比较一次，$O(n)$ 也是本题下界（不看完全部记录无法确定最高分）。实测 10 组真实数据最慢 0.019 s，远低于 1000 ms 的限时。
- 空间复杂度：$O(n)$，来自 `read().split()` 切出的 token 表（最长姓名 20 字符、$n \leqslant 100$，总量极小）。若边读边比较可降到 $O(1)$ 额外空间，但本题规模下没有必要。峰值内存实测约 14.5 MB，远低于 128 MB。

## 总结

- **模型**：在有序记录序列上求第一个最大值，$i^* = \arg\max_i s_i$；题目保证唯一，输出 $t_{i^*}$。
- **推导**：线性扫描已是下界，没有可消除的瓶颈，因此采用直接正解，不写暴力层；可讲的只有"维护当前最优 + 严格大于才替换"这一模式的形态。
- **边界**：`best_score` 初值取 $-1$，利用分数非负让第一位学生必然被接收；比较必须是 `>` 而不是 `>=`，否则同分会覆盖先到的姓名。
- **陷阱**：`max(zip(scores, names))[1]` 这类流水线只在最高分唯一时等价（并列时会转而比较姓名），不要用它替代显式循环。
- **复核**：题面样例 `5 / 87 lilei / 99 hanmeimei / ...` → `hanmeimei`；数据仓 10 组真实数据全部输出一致（PASS=10, FAIL=0），其中 4 组存在并列最高分。
