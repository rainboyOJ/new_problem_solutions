## 形式化题目

给定三个整数 $a, b, c$。把每个整数格式化成一个**最小宽度为 8 的右对齐字段**：

- 字段不足 8 个字符时，左侧补前导空格，使数字靠右；
- 字段超过 8 个字符时原样保留，不截断（宽度只是下界）；
- 负号计入宽度，即 $-1$ 占据的是「6 个空格 + `-1`」共 8 列。

再把三个字段**用一个空格连接**成一行输出。样例输入 `123456789 0 -1` 的字段构造如下：

| 数值 | 字符数 | 右对齐到 8 宽时补的空格 | 拼接后的字段 |
| --- | --- | --- | --- |
| `123456789` | 9 | 不补（超出 8，也不截断） | `123456789` |
| `0` | 1 | 左侧补 7 个空格 | 7 个空格 + `0` |
| `-1` | 2 | 左侧补 6 个空格（负号算 1 列） | 6 个空格 + `-1` |

三段字段之间再各插入一个分隔空格，最终输出行（27 字符）：

```text
123456789        0       -1
```

!!! warning 关于题面展示的输出样例
题面【输出样例】展示为 `123456789       0      -1`（25 字符），恰好少了字段间的两个分隔空格。题面文字「之间以一个空格分开」、数据仓标准程序 `printf("%8d %8d %8d", ...)`、全部 10 组公开测试数据（每行 26 字符 = 8+1+8+1+8）、以及同题 noi_openjudge 版本的样例输出（27 字符），四方一致为「宽度 8 的字段 + 一个分隔空格」。评测按测试数据逐字符比较，故本题解输出带分隔空格的版本。
!!!

## 正解

### 思路

**朴素做法**是手工完成格式化：`str(x)` 之后用 `s.rjust(8)` 或
`' ' * (8 - len(s)) + s` 在左侧补空格，最后 `' '.join(...)` 拼接。
方向是对的，但两个边界要自己兜住：

1. 超过 8 位的数会让 `8 - len(s)` 变成负数——`' ' * 负数` 恰好得到空串，
   这是"碰巧正确"，读者需要额外验证才知道超长数不会被破坏；
2. 负号是否占用宽度要逐个确认，否则 $-1$ 可能只补 7 个空格，比 `printf` 少一列。

**关键观察**：Python 的格式说明符正好是题面三句话的直译，两个边界它已经定义好了。

- `>` 表示右对齐——题面「右对齐」；
- `8`（代码里命名为常量 `WIDTH`）表示**最小**字段宽度：不足补空格、超出不截断——
  题面「占 8 个字符的宽度」。这与 C 的 `%8d`、C++ 的 `setw(8)` 是同一语义，
  负号同样计入宽度，所以手写的两个边界都不用再管。

**分隔空格**也不必手写 `' '.join(...)`：`print(*args)` 的默认参数
`sep=' '` 恰好就是题面「之间以一个空格分开」要求的那一个空格。于是
「读入 → 格式化 → 连接」压缩成一行表达式：

```python
print(*(f"{number:>{WIDTH}}" for number in (a, b, c)))
```

另外用 `a, b, c = map(int, ...)` 解包三个名字：输入不是恰好三个整数时立刻抛
`ValueError`，把「恰好读三个数」从注释约定变成代码结构上的硬约束，不会悄悄
少读或错位。

### 复杂度

- 时间复杂度：$O(1)$：固定读入三个整数，一次 `split()`、三次整数转换、
  三个字段格式化和一次输出，全部是常数次操作。
- 空间复杂度：$O(1)$：输入一行约 10～30 字节，token 列表与三个字符串字段
  都是常数大小；生成器逐个产出字段，不建中间列表。

## 总结

- `f"{x:>8}"` 的三个语义缺一不可：`>` 右对齐、`8` 是**最小**宽度（超长不截断）、
  负号计入宽度——正好覆盖题面的全部格式要求，比手工补空格少兜两个边界。
- `print(*args)` 的默认 `sep=' '` 就是字段间那一个空格，不必手写 `' '.join`。
- `a, b, c = map(int, ...)` 解包让"恰好三个整数"成为硬约束，输入不合法立刻报错。
- 验证：真实测试数据 10/10 全部 PASS（约 0.018 s/组，peak 14.5 MB，
  远低于 1000 ms / 128 MB 限制）；样例手工运行输出
  `123456789        0       -1`，与题面文字、`std.cpp` 及测试数据的格式一致。
